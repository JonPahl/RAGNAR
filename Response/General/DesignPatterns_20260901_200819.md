## 1. Specification Pattern — Replace Ad-Hoc Validation

**Where:** `FileValidator.IsValid` currently bundles four boolean checks (extension, excluded file, excluded dir, allowed ext) into one method. As rules grow, this becomes hard to compose, test, and reuse.

```csharp
// A composable, self-documenting alternative
public interface ISpecification<T>
{
    bool IsSatisfiedBy(T input);
    ISpecification<T> And(ISpecification<T> other);
    ISpecification<T> Or(ISpecification<T> other);
    ISpecification<T> Not();
    string Description { get; }
}

public sealed class AllowedExtensionSpec : ISpecification<FileInfo>
{
    private readonly IReadOnlyCollection<string> _exts;
    public AllowedExtensionSpec(IReadOnlyCollection<string> exts) => _exts = exts;

    public bool IsSatisfiedBy(FileInfo file) =>
        _exts.Contains(file.Extension, StringComparer.OrdinalIgnoreCase);

    public string Description => $"extension ∈ {{ {string.Join(", ", _exts)} }}";
    // And / Or / Not implemented via delegate composition…
}

public sealed class NotExcludedFileSpec : ISpecification<FileInfo> { /* … */ }
public sealed class NotInExcludedDirSpec : ISpecification<FileInfo> { /* … */ }

// Usage in FileValidator (or a pipeline step):
ISpecification<FileInfo> policy =
    new AllowedExtensionSpec(options.AllowedFileExtensions)
    .And(new NotExcludedFileSpec(options.ExcludedFiles))
    .And(new NotInExcludedDirSpec(options.ExcludedDirectories));

bool ok = policy.IsSatisfiedBy(fileInfo);
```

**Why:** Each rule is independently unit-testable, serialisable (for a future rules engine), and composable without touching `FileValidator`. The existing tests in `FileValidatorTests` map 1-to-1 onto individual specs.

## 2. Resilience Pipeline (Retry + Circuit Breaker + Timeout Proxy) — Ollama Calls

**Where:** `OllamaChatResponse.GenerateResponse` and `OllamaEmbeddingService.GenerateAsync` make raw HTTP calls. A transient network blip or model reload kills the entire run.

```csharp
// Wrap the client behind a resilience-decorating proxy
public sealed class ResilientOllamaClient
{
    private readonly OllamaApiClient _inner;
    private readonly ResiliencePipeline _pipeline;

    public ResilientOllamaClient(OllamaApiClient inner, ResiliencePipeline pipeline)
    {
        _inner    = inner;
        _pipeline = pipeline;   // built once from config
    }

    public async Task<StreamingChatResponse> SendAsync(
        ChatRole role, string prompt, CancellationToken ct)
        => await _pipeline.ExecuteAsync(
                   async (innerCt) => _inner.SendAsync(role, prompt, innerCt), ct);
}

// Construction (in DI or OllamaClientFactory):
var pipeline = new ResiliencePipelineBuilder()
    .AddRetry(new HttpRetryStrategy
    {
        MaxRetryAttempts = 3,
        Delay            = TimeSpan.FromSeconds(2),
        BackoffType      = DelayBackoffType.Exponential,
        ShouldRetry      = new PredicateHttpMessageRetryStrategy()
    })
    .AddCircuitBreaker(new HttpCircuitBreakerStrategy
    {
        FailureRatio   = 0.5,
        SamplingDuration = TimeSpan.FromSeconds(30),
        MinimumThroughput = 2,
        BreakingDuration = TimeSpan.FromSeconds(10)
    })
    .AddTimeout(TimeSpan.FromSeconds(120))
    .Build();
```

**Why:** `OllamaClientFactory` already centralises client creation — the natural injection point. You eliminate the hand-rolled `CreateTimeoutCts` in `OllamaEmbeddingService` and gain retry/circuit-break for free. The `appsettings.json` already has per-service `Timeout` values; extend with `MaxRetries`, `CircuitBreakerThreshold`, etc.

## 3. Proxy / Decorator — Cross-Cutting Observability

**Where:** `Stopwatch.StartNew()` is sprinkled manually in `ExecuteAsync`. Logging of request/response sizes, model, latency, token counts is ad-hoc.

```csharp
public interface IOllamaGenerationService
{
    Task<string> GenerateResponse(GenerateRequest req, CancellationToken ct);
}

public sealed class ObservabilityDecorator : IOllamaGenerationService
{
    private readonly IOllamaGenerationService _next;
    private readonly ILogger _logger;

    public ObservabilityDecorator(IOllamaGenerationService next, ILogger logger)
    {
        _next   = next;
        _logger = logger;
    }

    public async Task<string> GenerateResponse(GenerateRequest req, CancellationToken ct)
    {
        var sw = Stopwatch.StartNew();
        try
        {
            var result = await _next.GenerateResponse(req, ct);
            _logger.Information(
                "LLM call OK  model={Model}  promptLen={PL}  responseLen={RL}  elapsed={E}",
                req.Model, req.Prompt.Length, result.Length, sw.ElapsedMilliseconds);
            return result;
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            _logger.Error(ex, "LLM call FAILED  model={Model}  elapsed={E}", req.Model, sw.ElapsedMilliseconds);
            throw;
        }
    }
}

// DI registration wraps the concrete implementation:
services.AddScoped<IOllamaGenerationService>(sp =>
{
    var inner  = sp.GetRequiredService<InnerOllamaChatResponse>();
    var logger = sp.GetRequiredService<ILogger>();
    return new ObservabilityDecorator(inner, logger);
});
```

**Why:** Every consumer of `IOllamaGenerationService` (the `Act` stage, `SummaryService`, `ContentSummarizerAgent`) gets timing + structured logs without any code change in the caller.

## 4. Chain of Responsibility / Interpreter — Filter Strategy Generalisation

**Where:** `XmlCommentFilterStrategy` is the only `IFilterStrategy`. The `Condition` / `FieldCondition` / `Range` model in `CreateFilter` hints at a rule engine, but there's no way to *compose* strategies or express multi-field predicates.

```csharp
// Add a composite + interpreter layer
public sealed class CompositeFilterStrategy : IFilterStrategy
{
    private readonly IReadOnlyList<IFilterStrategy> _children;
    public CompositeFilterStrategy(IReadOnlyList<IFilterStrategy> children) => _children = children;

    public Filter CreateFilter(int sizeThreshold)
    {
        var filter = new Filter { Should = [[]] };
        foreach (var child in _children)
            filter.Should.AddRange(child.CreateFilter(sizeThreshold).Should);
        return filter;
    }
}

// An "OR" strategy so you can say: include IF CommentLength >= 40 OR ElementName matches "Foo*"
public sealed class OrFilterStrategy : IFilterStrategy
{
    private readonly IFilterStrategy _a, _b;
    // …
}
```

**Why:** The `QuestionCategory` enum already enumerates `XML`, `Performance`, `Refactor`, `Testing`, etc. Each will need its own filter. A composable strategy tree avoids a `switch`-based factory and lets `appsettings.json` or a CSV drive which strategies are active per category.

## 5. Null Object — Eliminate Null-Checks in Output Pipeline

**Where:** `PathResolver.ResolveResponseDirectory` throws `DirectoryNotFoundException` if the base folder doesn't exist. `SummaryService.SummarizeAllResponsesAsync` does a separate `Directory.Exists` guard. `FileValidator` checks `File.DirectoryName ?? string.Empty`.

```csharp
public sealed class NullDirectory : IDirectory
{
    public static NullDirectory Instance { get; } = new();
    public bool Exists       => false;
    public IReadOnlyList<string> GetFiles(string pattern) => [[]];
    // …
}

// Instead of throwing:
public IDirectory Resolve(string? category) =>
    category is null ? NullDirectory.Instance : new PhysicalDirectory(_basePath, category);
```

**Why:** Callers stop writing `if (dir is null)` / `try-catch DirectoryNotFound` and can iterate uniformly. Pairs well with the Specification pattern: a `NotExcludedDirSpec` simply returns `false` for a `NullDirectory`.

## 6. Memento / Checkpoint — Long-Running Embed Pipeline

**Where:** `EmbedTextPipeline.RunAsync` processes potentially thousands of files (discover → parse → embed → upsert). A crash at file 4,200 of 5,000 restarts from zero.

```csharp
public sealed class EmbedCheckpoint
{
    public string Checksum { get; init; } = "";
    public int    Offset   { get; init; }
    public DateTime Timestamp { get; init; }
}

// In EmbedTextPipeline:
var checkpointPath = Path.Join(sourceDir, ".ragnar_embed_checkpoint.json");
int resumeOffset = 0;
if (File.Exists(checkpointPath))
{
    var cp = JsonSerializer.Deserialize<EmbedCheckpoint>(File.ReadAllText(checkpointPath));
    resumeOffset = cp.Offset;
    logger.Information("Resuming embedding from offset {Off}", resumeOffset);
}

for (int i = resumeOffset; i < documents.Count; i++)
{
    // … upsert …
    if (i % 100 == 0)
        await File.WriteAllTextAsync(checkpointPath,
            JsonSerializer.Serialize(new EmbedCheckpoint { Offset = i + 1, Timestamp = DateTime.UtcNow }));
}
// Clear checkpoint on success
File.Delete(checkpointPath);
```

**Why:** `BATCHSIZE = 1` makes this a long sequential loop. A lightweight checkpoint (no database needed) gives crash-recovery with ~10 lines of code.

## 7. Mediator / Event Bus — Decouple Pipeline Stages

**Where:** `BrandingStage`, `SummarizationStage`, and the `Act` stage all write to `IOutputWriter` and `AnsiConsole` directly. Adding a "progress percentage" stage or a "telemetry" stage requires touching every stage.

```csharp
public enum PipelineEvent
{
    StageStarted,
    StageCompleted,
    ResponseSaved,
    EmbeddingBatchComplete,
    AllDone
}

public sealed class PipelineEventBus
{
    private readonly ConcurrentDictionary<PipelineEvent, List<Delegate>> _subs = new();

    public void Subscribe<TEvent>(Action<TEvent> handler) where TEvent : PipelineEvent { /* … */ }
    public void Publish<TEvent>(TEvent evt) where TEvent : PipelineEvent { /* … */ }
}

// A stage no longer knows about the writer:
public class SummarizationStage(ISummaryService svc, PipelineEventBus bus) : IPipelineStage
{
    public async Task ExecuteAsync(CancellationToken ct)
    {
        bus.Publish<PipelineEvent>(PipelineEvent.StageStarted);
        await svc.SummarizeAllResponsesAsync(ct);
        bus.Publish<PipelineEvent>(PipelineEvent.StageCompleted);
    }
}

// A "console" subscriber renders; a "telemetry" subscriber ships metrics — no coupling.
```

**Why:** The existing `IPipelineStage` interface is the right seam. Adding a bus removes the "every stage needs a writer" coupling and makes it trivial to add a CI/CD status reporter, a Seq dashboard emitter, or a unit-test spy.

## 8. Proxy — Lazy / Virtual Code Document Access

**Where:** `BaseFileParser.ReadFileAsync` reads the *entire* file into memory. For large generated files or multi-thousand-line files, every `CodeDocument` carries the full source string. The `VectorStoreRepository` then concatenates `doc.Code` into the embedding prompt.

```csharp
public sealed class LazyCodeDocument : ICodeDocument
{
    private readonly string _filePath;
    private string? _code;

    public string ElementName { get; init; } = "";
    public string Code => _code ??= File.ReadAllText(_filePath);   // load on first access
    public string FilePath => _filePath;

    // For the embedding prompt, only a snippet is needed:
    public string Snippet(int maxChars = 2000) =>
        Code.Length <= maxChars ? Code : Code[[..maxChars]] + "…";
}
```

**Why:** The embed pipeline currently holds every full file in a `ConcurrentBag<CodeDocument>`. With a lazy proxy, memory stays flat regardless of corpus size, and the embedding prompt uses only what the model needs.

## 9. Strategy + Configuration-Driven Selection — File Parse Dispatch

**Where:** `CodeParserFactory` (referenced in tests) likely does an `if/else` or `switch` on file extension. `FileParseFactoryTests` expects a `NullReferenceException` for `.json`, which signals the dispatch table isn't complete.

```csharp
public sealed record ParseBinding(
    string Extension,
    Func<Serilog.ILogger, IFileParser> Factory);

public sealed class FileParseRegistry
{
    private readonly ConcurrentDictionary<string, Func<Serilog.ILogger, IFileParser>> _map = new();

    public void Register(string ext, Func<Serilog.ILogger, IFileParser> factory)
        => _map[[ext.ToLowerInvariant()]] = factory;

    public IFileParser Resolve(string filePath, Serilog.ILogger logger)
    {
        var ext = Path.GetExtension(filePath);
        return _map.TryGetValue(ext, out var f)
            ? f(logger)
            : throw new NotSupportedException($"No parser registered for '{ext}'.");
    }
}

// In DI:
var registry = new FileParseRegistry();
registry.Register(".cs",  l => new CSharpFileParser(l));
registry.Register(".json", l => new JsonFileParser(l));
registry.Register(".editorconfig", l => new EditorConfigParser(l));
services.AddSingleton(registry);
```

**Why:** Adding a new file type is a one-line registration. The `LoadQuestionPlugins` method already scans for `IQuestionProvider` DLLs — the same mechanism can discover `IFileParser` implementations from plugin assemblies, making the registry truly open/closed.

## 10. CQRS-lite — Separate Query (Read) and Command (Write) Paths

**Where:** `VectorStoreRepository.UpsertBatchAsync` both *reads* document data and *writes* to Qdrant in one method. `SummaryService` reads the response directory and writes summaries. `EmbedTextPipeline` interleaves discovery, parsing, and upserting.

A light CQRS split (not full MediatR) would look like:

```
┌─────────────────────────────────────────────────────────┐
│  READ (Query) side                                       │
│  • DiscoverSourceFiles        (EmbedTextPipeline)        │
│  • ParseDocuments             (BaseFileParser tree)      │
│  • LoadQuestions              (QuestionCombineBuilder)   │
│  • LoadPreviousResponses      (SummaryService)           │
│                                                         │
│  WRITE (Command) side                                    │
│  • UpsertBatchAsync           (VectorStoreRepository)    │
│  • SaveResponse               (ResponseWriter)           │
│  • SaveSummary                (SummaryService)           │
└─────────────────────────────────────────────────────────┘
```

**Why:** It makes the `BATCHSIZE` chunking concern belong to the *write* command only. It lets you swap the vector store (Qdrant → Chroma → Postgres) by replacing one command handler. It clarifies that `EmbedTextPipeline` is an *orchestrator*, not a domain service.
