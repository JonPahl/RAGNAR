### 1. Duplicate `EmbeddingSetupExtension` (copy-paste conflict)

### 3. `NumberedRowDecorator.Render()` duplicates rows

**Problem:** The method reads existing rows into `existing`, then calls `table.AddRow(row)` for each — **without clearing the originals**. The result is every row appearing twice.

```csharp
// ❌ Buggy: adds numbered copies on top of originals
public void Render()
{
    if (_numbered) { inner.Render(); return; }
    _numbered = true;
    var table = inner.Table;
    if (!table.Columns.Contains(columnHeader, StringComparer.OrdinalIgnoreCase))
        table.AddColumns(columnHeader);

    var existing = table.Rows.Select(r => r.ToArray()).ToList();
    for (var i = 0; i < existing.Count; i++)
    {
        // ... builds numbered row ...
        table.AddRow(row);          // ← appends; originals still present!
    }
    inner.Render();
}
```

**Fix:** Snapshot, clear, then re-add:

```csharp
public void Render()
{
    if (_numbered) { inner.Render(); return; }
    _numbered = true;

    var table = inner.Table;
    if (!table.Columns.Contains(columnHeader, StringComparer.OrdinalIgnoreCase))
        table.AddColumns(columnHeader);

    // 1. Snapshot original cells
    var original = table.Rows
        .Select(r => r.Select(c => c.Value).ToList())
        .ToList();

    // 2. Clear and re-add with index column
    table.ClearRows();  // ← or table.Rows.Clear() depending on API
    for (var i = 0; i < original.Count; i++)
    {
        var numbered = new List<TableCell> { new((i + 1).ToString()) };
        numbered.AddRange(original[i].Select(v => new TableCell(v)));
        table.AddRow(numbered);
    }

    inner.Render();
}
```

> If `ConsoleTableBuilder` lacks `ClearRows`, add one, or rebuild the table object before delegating to `inner.Render()`.

### 4. `RagOrchestrator` – duplicated XML doc block + swallowed failure

**Problem A:** The file header has the `<param>`/`<example>` block **twice** (copy-paste).

**Problem B:** On generation failure the exception is caught, a fallback string is stored, and execution continues to `SaveResponseAsync`. The caller has no way to know the generation actually failed.

```csharp
// ❌ Duplicated doc block at top of file (remove the first copy)
// ❌ Swallowed exception:
catch (Exception ex) when (ex is not OperationCanceledException)
{
    logger.Error(ex, "RAG generation failed for {Question}", question.Text);
    response = "⚠️  Generation failed. Check the Ollama service and retry.";
    // ← falls through to SaveResponseAsync as if success
}
```

**Fix:**

```csharp
// ✅ Single doc block + explicit failure path
public async Task ExecuteAsync(
    Core.Models.Question question,
    string contextText,
    CancellationToken cancellationToken)
{
    var sw = Stopwatch.StartNew();
    var finalPrompt = promptBuilder.WithQuestion(question).WithContext(contextText).Build();
    var ollamaClient = ollamaClientFactory.ResolveClient(OllamaServiceType.Ollama);
    logger.Debug("Resolved Ollama client: {ClientType}, Model: {Model}",
        ollamaClient.GetType().Name, ollamaClient.SelectedModel);

    var genOpts = configWrapper.Value.GenerationOptions;
    var request = new GenerateRequest
    {
        Model   = ollamaClient.SelectedModel,
        Prompt  = finalPrompt,
        System  = promptTemplateProvider.System,
        Options = new RequestOptions
        {
            Temperature   = genOpts.Temperature,
            RepeatPenalty = genOpts.RepeatPenalty,
        },
    };

    string response;
    bool   failed = false;

    try
    {
        response = await GenerateAsync(request, cancellationToken).ConfigureAwait(false);
    }
    catch (Exception ex) when (ex is not OperationCanceledException)
    {
        logger.Error(ex, "RAG generation failed for {Question}", question.Text);
        response = "⚠️  Generation failed. Check the Ollama service and retry.";
        failed   = true;
    }

    sw.Stop();
    logger.Information("RAG generation {Result} in {Elapsed}", failed ? "FAILED" : "completed", sw.Elapsed);

    if (configWrapper.Value.ApplicationOptions.IncludeOriginalPrompt)
    {
        response += finalPrompt.ShowPrompt();
        response += Environment.NewLine + request.System;
        logger.Debug("Original prompt appended (IncludeOriginalPrompt = true).");
    }

    // ✅ Record the failure flag so downstream consumers can react
    await SaveResponseAsync(
        new ResponseRecord(question, response, sw.FormatElapsedTime(), failed),
        cancellationToken).ConfigureAwait(false);
}
```

And add a `Failed` property to `ResponseRecord` (or return a small result type) so the caller can decide whether to exit with a non-zero code.

### 5. `QuestionFilterSelector` – fragile built-in registration

**Problem:** The constructor builds a dictionary from injected strategies, then *conditionally* adds a built-in XML strategy. If a custom strategy for `QuestionCategory.XML` is injected, it's silently overridden. There's also no thread-safety on the dictionary if `FindFilter` is called concurrently with construction.

```csharp
// ❌ Fragile:
public QuestionFilterSelector(Serilog.ILogger logger, IEnumerable<IFilterStrategy> strategies)
{
    _logger = logger;
    _strategies = strategies.ToDictionary(s => s.SupportedCategory); // throws on dup
    if (!_strategies.ContainsKey(QuestionCategory.XML))
        _strategies[QuestionCategory.XML] = new XmlCommentFilterStrategy(logger); // mutable dict
}
```

**Fix:** Use an immutable `IReadOnlyDictionary`, and let DI decide which strategies to inject:

```csharp
public sealed class QuestionFilterSelector
{
    private readonly IReadOnlyDictionary<QuestionCategory, IFilterStrategy> _strategies;
    private readonly Serilog.ILogger _logger;

    public QuestionFilterSelector(
        Serilog.ILogger logger,
        IEnumerable<IFilterStrategy> strategies)
    {
        _logger = logger;
        _strategies = strategies
            .ToDictionary(s => s.SupportedCategory)   // throws early on duplicates
            .ToImmutableDictionary();                 // truly immutable
    }

    public Filter FindFilter(QuestionCategory category, int commentLengthThreshold = 0)
    {
        _logger.Debug("Finding filter for {Category}, threshold {Threshold}",
            category, commentLengthThreshold);

        var filter = _strategies.TryGetValue(category, out var strategy)
            ? strategy.CreateFilter(commentLengthThreshold)
            : new Filter();

        _logger.Debug("Filter resolved for {Category}: {Must} must, {MustNot} mustNot",
            category, filter.Must?.Count ?? 0, filter.MustNot?.Count ?? 0);
        return filter;
    }
}
```

Then register the XML strategy explicitly in DI so it's not hidden inside the selector:

```csharp
services.AddSingleton<IFilterStrategy, XmlCommentFilterStrategy>();
// other strategies…
services.AddSingleton<QuestionFilterSelector>();
```

### 6. `OutputPathHelper.GetResponseDirectory` – inconsistent `baseDir` handling

**Problem:** When explicit folders are supplied, `baseDir` is silently ignored. When no folders are supplied, `baseDir` *is* used. The two code paths behave oppositely, which is confusing.

```csharp
// ❌ Inconsistent:
public static string GetResponseDirectory(this IEnumerable<string> folders, string baseDir = "")
{
    var parts = folders as IReadOnlyCollection<string> ?? [..folders];
    if (parts.Count == 0)
        return string.IsNullOrEmpty(baseDir)
            ? DomainDefaults.ResponseDir
            : Path.Join(baseDir, DomainDefaults.ResponseDir);

    // baseDir is intentionally NOT prepended  ← but why?
    return Path.Join(parts.Append(DomainDefaults.ResponseDir).ToArray());
}
```

**Fix:** Always prepend `baseDir` when it's non-empty, and document the contract:

```csharp
/// <summary>
/// Builds a response-directory path by joining <paramref name="folders"/>
/// with the conventional <c>"responses"</c> leaf, optionally rooted at
/// <paramref name="baseDir"/>.
/// </summary>
/// <remarks>
/// If <paramref name="folders"/> is empty, the result is
/// <c>Path.Join(baseDir ?? "", "responses")</c>.
/// </remarks>
public static string GetResponseDirectory(this IEnumerable<string> folders, string? baseDir = null)
{
    Guard.Against.Null(folders);
    var parts = folders as IReadOnlyCollection<string> ?? [..folders];
    var root  = string.IsNullOrWhiteSpace(baseDir) ? "" : baseDir.TrimEnd(Path.DirectorySeparatorChar);

    return Path.Join([.. (root.Length > 0 ? new[] { root } : Array.Empty<string>()),
                      .. parts,
                      DomainDefaults.ResponseDir]);
}
```

### 9. `StageExecutionContext` – mutable property on a `record`

### 10. `CodeParserFactory` – misleading "generic" fallback

**Problem:** The default branch delegates to `_markdownParser` but the local variable and log messages call it "generic parser." A `.java` or `.py` file will be parsed as Markdown.

```csharp
// ❌ Misleading:
".cs" => await GetCodeDocumentsAsync(file, ct).ConfigureAwait(false),
_     => await ParseFile(file, ct).ConfigureAwait(false),   // calls MarkdownFileParser
```

**Fix:** Either add proper parser registrations per extension, or at minimum log a warning for unrecognised types:

```csharp
public async Task<IEnumerable<CodeDocument>> ParseAsync(string file, CancellationToken ct)
{
    ct.ThrowIfCancellationRequested();
    logger.Debug("Dispatching parse for file: {File}", file);
    var ext = Path.GetExtension(file).ToLowerInvariant();

    return ext switch
    {
        ".cs"     => await _csharpParser.ParseAsync(file, ct).ConfigureAwait(false),
        ".md"     => await _markdownParser.ParseAsync(file, ct).ConfigureAwait(false),
        ".json"   => await _jsonParser.ParseAsync(file, ct).ConfigureAwait(false),
        _         => throw new NotSupportedException(
                        $"No parser registered for '{ext}'. " +
                        $"Add a handler in CodeParserFactory."),
    };
}
```

Or use a `Dictionary<string, IFileParser>` keyed by extension so new languages are added without touching the factory (Open/Closed).
