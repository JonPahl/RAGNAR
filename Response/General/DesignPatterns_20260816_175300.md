### 1. Specification Pattern
**Where to apply:** `FileValidator.IsValid`, `QuestionExtensions.WithCategory` / `InActiveOnly`
**Why:** Your current filtering logic is embedded in methods and DTOs (`FileLoadOptions`). Specifications make validation rules composable, testable, and decoupled from domain objects.
```csharp
// Example: Composable file specification
public interface IFileSpecification { bool IsSatisfiedBy(FileInfo file); }
public class AllowedExtensionSpec : IFileSpecification { ... }
public class ExcludedDirSpec : IFileSpecification { ... }

// Composition
var spec = new AllowedExtensionSpec(".cs") 
         & new ExcludedDirSpec("node_modules");
bool isValid = spec.IsSatisfiedBy(file);
```
**Benefit:** Eliminates `if/else` chains, enables unit testing of individual rules, and supports dynamic rule loading.

### 2. Mediator / Pipeline Orchestrator Pattern
**Where to apply:** `RagPipelineRunner.StartAsync`
**Why:** This method currently orchestrates branding, embedding checks, population, question answering, and summarization in a single sequential flow. It violates SRP and is hard to mock/test per step.
```csharp
public interface IPipelineStep { Task ExecuteAsync(CancellationToken ct); }

// Extract steps:
public class EnsureCollectionExistsStep : IPipelineStep { ... }
public class PopulateKnowledgeBaseStep : IPipelineStep { ... }
public class AskQuestionsStep : IPipelineStep { ... }

// Orchestrator (or use MediatR)
public class RagPipelineOrchestrator(IEnumerable<IPipelineStep> steps) 
{
    public async Task RunAsync(CancellationToken ct) => 
        foreach(var step in steps) await step.ExecuteAsync(ct);
}
```
**Benefit:** Each step becomes independently testable, swappable, and configurable. Enables conditional branching or parallel execution later.

### 3. Decorator Pattern
**Where to apply:** `IFileParser`, `IResponseWriter`, `IOllamaClientProvider`
**Why:** You'll likely need cross-cutting concerns (logging, timing, caching, retry) without polluting core implementations. .NET DI supports decorators elegantly.
```csharp
public class LoggingFileParserDecorator : IFileParser
{
    private readonly IFileParser _inner;
    public async ValueTask<CodeDocument[]> ParseFileAsync(string path, CancellationToken ct)
    {
        using var scope = _logger.BeginScope("Parsing {Path}", path);
        return await _inner.ParseFileAsync(path, ct);
    }
}

// DI Registration:
services.AddScoped<IFileParser, LoggingFileParserDecorator>();
services.AddScoped<IFileParser, CsvFileParser>(); // Decorator wraps concrete impl
```
**Benefit:** Keeps core logic clean, enables AOP-like behavior without frameworks, and maintains single responsibility.

### 4. Adapter Pattern
**Where to apply:** `AFileParser` hierarchy
**Why:** You're parsing files into embeddings, but different sources (CSV, JSON, PDF, Markdown) have vastly different structures. Adapters normalize them into a common contract.
```csharp
public interface IChunkAdapter { IEnumerable<CodeDocument> Adapt(string rawContent); }

public class CsvFileParser : AFileParser
{
    private readonly IChunkAdapter _adapter; // Injected per format
    public override async ValueTask<CodeDocument[]> ParseFileAsync(...) 
        => _adapter.Adapt(await ReadFileAsync(...)).ToArray();
}
```
**Benefit:** Isolates format-specific parsing logic, enables hot-swapping parsers, and aligns with Open/Closed Principle.

### 5. Event-Driven / Observer Pattern
**Where to apply:** Pipeline stages & plugin loading
**Why:** `RagPipelineRunner` tightly couples phases. Events allow decoupling, progress tracking, external monitoring, or conditional branching without modifying core flow.
```csharp
public interface IPipelineEventPublisher { void Publish<T>(T @event) where T : IPipelineEvent; }

// Usage in steps:
await _publisher.Publish(new KnowledgeBasePopulatedEvent(collectionName));
await _publisher.Publish(new QuestionAskedEvent(question.Key, duration));

// Subscribers can log, update UI, trigger downstream jobs, etc.
```
**Benefit:** Decouples pipeline consumers, enables async side-effects, and supports plugin-driven extensions safely.
