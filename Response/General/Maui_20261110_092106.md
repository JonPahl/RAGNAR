# Building a Cross-Platform MAUI Blazor Application (Windows, macOS, Linux)

MAUI Blazor lets you embed Blazor components inside a native MAUI shell, giving you a single C#/HTML/CSS codebase that compiles to native executables on all three desktop platforms.

---

## 1. Prerequisites

| Platform | Requirement |
|----------|-------------|
| **All** | .NET 9 SDK (or 8+), Visual Studio 2022 17.10+ (or `dotnet` CLI) |
| **Windows** | .NET MAUI workload + Windows 11 SDK (10.0.22000+) |
| **macOS** | Xcode 15+, .NET MAUI workload, a Mac (or Azure DevOps macOS agent) |
| **Linux** | .NET MAUI workload, Linux desktop runtime, `dotnet` CLI |

Install the workloads:

```bash
dotnet workload install maui
dotnet workload install maui-tvs   # optional
```

---

## 2. Create the Solution

```bash
# Solution
dotnet new sln -n MauiBlazorApp

# 1) MAUI app (the host shell – one project, multi-target)
dotnet new maui -n MauiBlazorApp.App -o App

# 2) Blazor component library (your UI lives here)
dotnet new blazorwasm -n MauiBlazorApp.Components -o Components

# 3) Shared POCO / model library (optional, for clean separation)
dotnet new classlib -n MauiBlazorApp.Shared -o Shared

# Wire them together
dotnet sln add App/MauiBlazorApp.App.csproj Components/MauiBlazorApp.Components.csproj Shared/MauiBlazorApp.Shared.csproj

# References
dotnet add App/MauiBlazorApp.App.csproj reference Components/MauiBlazorApp.Components.csproj Shared/MauiBlazorApp.Shared.csproj
dotnet add Components/MauiBlazorApp.Components.csproj reference Shared/MauiBlazorApp.Shared.csproj
```

## 4. MAUI Host Project (`App/`)

### `MauiBlazorApp.App.csproj`

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFrameworks>net9.0-windows10.0.19041.0;net9.0-maccatalyst18;net9.0</TargetFrameworks>
    <!-- net9.0 = the "Linux / generic" target -->
    <UseMaui>true</UseMaui>
    <SingleProject>true</SingleProject>
    <OutputType>Exe</OutputType>
    <RootNamespace>MauiBlazorApp</RootNamespace>
    <ApplicationTitle>Maui Blazor App</ApplicationTitle>
    <ApplicationId>com.example.maui.blazor</ApplicationId>
    <ApplicationVersion>1</ApplicationVersion>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Microsoft.AspNetCore.Components.WebView.Maui" Version="9.*" />
  </ItemGroup>

  <ItemGroup>
    <ProjectReference Include="..\Components\MauiBlazorApp.Components.csproj" />
    <ProjectReference Include="..\Shared\MauiBlazorApp.Shared.csproj" />
  </ItemGroup>
</Project>
```

> **Key point:** `Microsoft.AspNetCore.Components.WebView.Maui` is the NuGet package that provides the `<BlazorWebView>` MAUI control. It wraps the platform's web engine (WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux).

### `MauiProgram.cs`

```csharp
using Microsoft.AspNetCore.Components.WebView.Maui;

var builder = MauiApp.CreateBuilder();
builder
    .UseMauiApp<App>()
    .ConfigureFonts(fonts =>
    {
        fonts.AddFont("OpenSans-Regular.ttf", "OpenSansRegular");
        fonts.AddFont("OpenSans-Semibold.ttf", "OpenSansSemibold");
    });

// Register Blazor services (services used by .razor components)
builder.Services
    .AddRazorComponents()
    .AddInteractiveServerComponents()   // or AddInteractiveAuto() for hybrid
    .AddSingleton<ITodoService, TodoService>();

return builder.Build();
```

### `Views/MainPage.xaml` — the BlazorWebView host

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             xmlns:web="clr-namespace:Microsoft.AspNetCore.Components.WebView.Maui;assembly=Microsoft.AspNetCore.Components.WebView.Maui"
             x:Class="MauiBlazorApp.Views.MainPage">

    <web:BlazorWebView HostPage="index.html"
                        RootComponentAssembly="{x:Static sys:TypeObject(typeof(MauiBlazorApp.Components.Program))}"
                        Services="{StaticResource Services}">
        <!-- Fallback shown while the web engine loads -->
        <web:BlazorWebView.Fallback>
            <Grid>
                <Label Text="Loading…" HorizontalOptions="Center" VerticalOptions="Center" />
            </Grid>
        </web:BlazorWebView.Fallback>
    </web:BlazorWebView>

</ContentPage>
```

> **Simpler approach** (most common): skip XAML entirely and create a **code-only page**:

```csharp
// Views/MainPage.cs
using Microsoft.AspNetCore.Components.WebView.Maui;

namespace MauiBlazorApp.Views;

public class MainPage : ContentPage
{
    public MainPage(IServiceProvider services)
    {
        // RootComponent points to the Blazor App root
        var rootComponent = new BlazorWebView
        {
            HostPage = null,          // no external index.html; BlazorWebView generates one
            RootComponent = new RootComponent(
                typeof(MauiBlazorApp.Components.App)),
            Services = services,
            Fallback = new ActivityIndicator { IsRunning = true }
        };

        Content = rootComponent;
    }
}
```

And in `App.xaml.cs`:

```csharp
MainPage = new Views.MainPage(new MauiApp().Services);
```

### `Components/Home.razor` — a sample page

```razor
@page "/"
@inject ITodoService TodoService

<PageTitle>Home</PageTitle>

<h1>🖥️ MAUI Blazor – Cross-Platform</h1>
<p>Running on: <b>@PlatformHelper.Current</b></p>

<h3>Todo List</h3>
<ul>
    @foreach (var item in TodoService.Items)
    {
        <li>
            <input type="checkbox" checked="@item.Done"
                   @onchange="e => ToggleItem(item, e)" />
            @if (item.Done)
            {
                <s>@item.Title</s>
            }
            else
            {
                @item.Title
            }
        </li>
    }
</ul>

<EditForm OnValidSubmit="AddItem" Model="_model">
    <InputText @bind-Value="_model.Title" placeholder="New task…" />
    <button type="submit">Add</button>
</EditForm>

@code {
    [[Inject]] private ITodoService TodoService { get; set; } = default!;
    private TodoItem _model = new();

    private void ToggleItem(TodoItem item, ChangeEventArgs e)
    {
        item.Done = (bool)e.Value!;
        TodoService.Save();
    }

    private void AddItem()
    {
        if (!string.IsNullOrWhiteSpace(_model.Title))
        {
            TodoService.Add(new TodoItem { Title = _model.Title });
            _model = new TodoItem();
        }
    }
}
```

### `PlatformHelper.cs` — detect the host OS from inside Blazor

```csharp
using Microsoft.AspNetCore.Components.WebAssembly; // or just System

namespace MauiBlazorApp.Components;

public static class PlatformHelper
{
    public static string Current => OperatingSystem.IsWindows() ? "Windows"
                       : OperatingSystem.IsMacOS()   ? "macOS"
                       : OperatingSystem.IsLinux()   ? "Linux"
                       : OperatingSystem.IsAndroid() ? "Android"
                       : OperatingSystem.IsIOS()     ? "iOS"
                       : "Unknown";
}
```

> Because MAUI Blazor runs **in-process** (not in a browser), `OperatingSystem` reflects the **host OS** directly. No JS interop needed.

## 6. Shared Model (`Shared/`)

```csharp
namespace MauiBlazorApp.Shared.Models;

public record TodoItem
{
    public Guid Id { get; init; } = Guid.NewGuid();
    public string Title { get; init; } = string.Empty;
    public bool Done { get; init; }
}
```

```csharp
public interface ITodoService
{
    IReadOnlyList<TodoItem> Items { get; }
    void Add(TodoItem item);
    void Save();
}
```

```csharp
using System.Text.Json;

public class TodoService : ITodoService
{
    private static readonly string FilePath =
        Path.Combine(AppContext.BaseDirectory, "todos.json");

    public IReadOnlyList<TodoItem> Items { get; private set; } = [[]];

    public TodoService()
    {
        if (File.Exists(FilePath))
            Items = JsonSerializer.Deserialize<List<TodoItem>>(File.ReadAllText(FilePath))!;
    }

    public void Add(TodoItem item)
    {
        Items = [[.. Items, item]];
        Save();
    }

    public void Save()
    {
        File.WriteAllText(FilePath, JsonSerializer.Serialize(Items, new JsonSerializerOptions { WriteIndented = true }));
    }
}
```

## 7. Platform-Specific Configuration

### Windows (`Platforms/Windows/`)

The MAUI Windows workload auto-generates a WinUI 3 + WebView2 host. You typically only need:

- **`Platforms/Windows/Package.appxmanifest`** – app identity, icon, capabilities.
- **`Platforms/Windows/launchSettings.json`** – debug profile.
- No extra code; `<BlazorWebView>` picks up **WebView2** automatically.

```xml
<!-- App.csproj (Windows TFM) -->
<ItemGroup Condition="'$(TargetFramework)' == 'net9.0-windows10.0.19041.0'">
  <PackageReference Include="Microsoft.Windows.SDK.NET.Ref" Version="10.0.26100.*" />
</ItemGroup>
```

### macOS (`Platforms/macOS/`)

- Requires **Xcode 15+** and the **MAUI for Catalyst** target (`net9.0-maccatalyst18`).
- The web engine is **WKWebView** (Safari-based). No extra NuGet needed.
- Optional: enable hardware acceleration, set `WKWebViewConfiguration` via `Platforms/macOS/AppDelegate.swift`.

```swift
// Platforms/macOS/AppDelegate.swift
using Foundation;
using ObjCRuntime;
using UIKit;

namespace MauiBlazorApp
{
    [[Register("AppDelegate")]]
    public class AppDelegate : MauiUIApplicationDelegate
    {
        protected override MauiApp CreateMauiApp() => MauiProgram.CreateMauiApp();
    }
}
```

### Linux (generic `net9.0` target)

> ⚠️ **Important:** As of .NET 9, first-class MAUI Linux desktop is still **community-supported**. The `net9.0` (non-Windows, non-mac) target compiles to a **self-contained .NET 9 app** that uses **WebKitGTK** (or CEF) as the rendering engine.

Steps:

```bash
# On the Linux machine (or a Linux CI agent):
sudo apt-get install -y \
  libgtk-3-dev \
  libwebkit2gtk-4.1-0 \
  libwebkit2gtk-4.1-dev

dotnet workload install maui

# Build
dotnet publish App/MauiBlazorApp.App.csproj \
  -f net9.0 \
  -c Release \
  -r linux-x64 \
  --self-contained true \
  -o publish/linux

# Run
./publish/linux/MauiBlazorApp.App
```

If WebKitGTK is unavailable, you can swap the rendering backend:

```xml
<!-- App.csproj -->
<ItemGroup Condition="'$(TargetFramework)' == 'net9.0' and '$(RuntimeIdentifier)' == 'linux-x64'">
  <!-- Optional: use CEF instead of WebKitGTK -->
  <PackageReference Include="CefSharp.Wpf" Version="129.*" />
</ItemGroup>
```

## 9. Key Differences vs. Pure Blazor WASM

| Concern | MAUI Blazor | Blazor WASM |
|---------|------------|-------------|
| **Runs on** | Native desktop (Win / Mac / Linux) + mobile | Browser only |
| **Web engine** | OS-native (WebView2, WKWebView, WebKitGTK) | Browser |
| **File system** | Full .NET `System.IO` in-process | Sandboxed / no local FS |
| **DI** | `MauiApp` services + Blazor services merged | `WebAssemblyHostBuilder` |
| **Interop** | C# → C# directly (no JS bridge for basic ops) | JS interop (`IJSRuntime`) |
| **Distribution** | Native installer / `.app` / AppImage | Deploy to a web server |
| **Updates** | App store / manual | Instant (browser cache) |

## 10. Common Gotchas

1. **`RootComponentAssembly` vs `RootComponent`** – In code-behind you set `RootComponent = new RootComponent(typeof(App))`. In XAML you set `RootComponentAssembly` to the assembly that contains `App.razor`. Mixing them up causes a blank page.

2. **Service registration** – All services used in `.razor` components via `[[Inject]]` **must** be registered in `MauiProgram.cs` (or `Program.cs` if using the XAML `Services` attribute), *not* in the Components project's `Program.cs`.

3. **Linux + WebKitGTK** – If you see a blank window on Linux, install `libwebkit2gtk-4.1-0` and ensure the `net9.0` (non-Windows) TFM is actually in `TargetFrameworks`.

4. **macOS Catalyst vs macOS (non-Catalyst)** – `net9.0-maccatalyst18` is the **Catalyst** (UIKit-on-Mac) path and is the most mature. A true "macOS native" (AppKit) MAUI target is still experimental.

5. **WebView2 runtime on Windows** – The self-contained publish bundles the Evergreen WebView2 runtime loader, but the **runtime itself** (~200 MB) is downloaded on first launch. For offline scenarios, include a **Fixed** WebView2 runtime installer.

6. **`OperatingSystem` detection** – Works in-process. If you ever need it in a *pure Blazor WASM* fallback, you'd use `IJSRuntime.InvokeAsync<string>("navigator.userAgent")` instead.

---

This gives you a **single C# + Razor codebase** that compiles to native executables on Windows, macOS, and Linux—no separate web server, no browser dependency, full access to the local file system and OS APIs through .NET.
