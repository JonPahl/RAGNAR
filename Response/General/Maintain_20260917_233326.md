## 1. CRITICAL — Duplicated Catch Block (PipelineRunner.cs)

**Problem:** Two identical `catch (OperationCanceledException)` handlers with the same `when` clause. The second is unreachable dead code and signals a copy-paste error. If someone later changes one condition and not the other, it becomes a subtle runtime bug.

```csharp
// ❌ BEFORE – duplicated, unreachable handler
catch (OperationCanceledException) when (ct.IsCancellationRequested)
{
    throw; // propagate
}
catch (OperationCanceledException) when (ct.IsCancellationRequested)
{
    throw;
}
```

**Fix:**

```csharp
// ✅ AFTER – single, clear handler
catch (OperationCanceledException) when (ct.IsCancellationRequested)
{
    logger.Information("Pipeline cancelled during stage [[{Index}]] {Name}", i, stage.Name);
    throw;
}
catch (Exception ex)
{
    logger.Fatal(ex, "Stage [[{Index}]] {Name} failed after {Elapsed}", i, stage.Name, stageSw.Elapsed);
    throw new PipelineStageException(stage.Name, ex);
}
```

## 2. CRITICAL — PathResolver / ResponseWriter Logical Inconsistency

**Problem:** `PathResolver.ResolveResponseDirectory` **throws** if the directory doesn't exist, but `ResponseWriter.WriteResponseAsync` calls `Directory.CreateDirectory` *after* resolving the path. On first run the resolver throws before the writer can create anything. This is a latent runtime failure.

```csharp
// ❌ BEFORE – resolver throws, writer can't create
// PathResolver.cs
public string ResolveResponseDirectory(QuestionCategory? category)
{
    // …
    if (!Directory.Exists(responseDir))
        throw new DirectoryNotFoundException(responseDir);   // ← blows up on first run
    return Path.Join(responseDir, baseDir);
}

// ResponseWriter.cs
public async Task<string> WriteResponseAsync(SaveDetails details, CancellationToken cancellationToken)
{
    var directory = pathResolver.ResolveResponseDirectory(details.Question.Category);
    Directory.CreateDirectory(directory);   // ← never reached on first run
    // …
}
```

**Fix — Option A: Move creation into the resolver (single source of truth)**

```csharp
// ✅ PathResolver.cs – guarantee the directory exists
public string ResolveResponseDirectory(QuestionCategory? category)
{
    var baseDir = category is null || string.IsNullOrWhiteSpace(category.ToString())
        ? nameof(QuestionCategory.Uncategorized)
        : category.ToString();

    var responseDir = Path.Join(_applicationOptions.SourceDirectory, _applicationOptions.OutputFolder);
    var categoryDir = Path.Join(responseDir, baseDir);

    Directory.CreateDirectory(categoryDir);   // idempotent – no throw
    return categoryDir;
}
```

```csharp
// ✅ ResponseWriter.cs – no longer needs CreateDirectory
public async Task<string> WriteResponseAsync(SaveDetails details, CancellationToken cancellationToken)
{
    var directory = pathResolver.ResolveResponseDirectory(details.Question.Category);
    var stamp     = clock.UtcNow.ToString("yyyyMMdd_HHmmss");
    var fileName  = $"{details.Question.Filename}_{stamp}.{formatter.FileExtension}";
    var fullPath  = Path.Join(directory, fileName);
    var content   = formatter.Format(details);

    await fileWriter.WriteAsync(fullPath, content, cancellationToken).ConfigureAwait(false);
    return fullPath;
}
```

**Fix — Option B: Remove the guard entirely (let the writer handle it)**

```csharp
// ✅ PathResolver.cs – pure path computation, no I/O side-effects
public string ResolveResponseDirectory(QuestionCategory? category)
{
    var baseDir = category is null || string.IsNullOrWhiteSpace(category.ToString())
        ? nameof(QuestionCategory.Uncategorized)
        : category.ToString();

    return Path.Join(_applicationOptions.SourceDirectory, _applicationOptions.OutputFolder, baseDir);
}
```

## 3. MODERATE — `NotImplementedException` in Explicit Interface (ConsoleTableBuilder.cs)

**Problem:** Two explicit interface members throw `NotImplementedException`. If any consumer casts to `ITableBuilder` and accesses `Columns` or `Rows`, the app crashes at runtime. This also breaks the Liskov Substitution Principle.

```csharp

List<string> ITableBuilder.Columns => throw new NotImplementedException();
List<List<string>> ITableBuilder.Rows => throw new NotImplementedException();
```

**Fix — Make the interface match what the builder actually provides, or implement the members:**

```csharp
// ✅ Option A: Align the interface with the concrete types
public interface ITableBuilder
{
    List<string> Columns { get; }
    List<string[[]]> Rows { get; }          // string[[]] not List<string>
    int ColumnCount { get; }
    int RowCount { get; }
    bool ShowRowSeparators { get; set; }
    bool Expand { get; set; }

    ITableBuilder AddColumns(params string[[]] columns);
    ITableBuilder AddRow(params string[[]] cells);
    ITableBuilder Clear();
    Table ToTable();
}
```

```csharp
// ✅ Option B: If you must keep the old interface shape, implement the adapters
List<string> ITableBuilder.Columns => Columns.ToList();

List<List<string>> ITableBuilder.Rows => Rows.Select(r => r.ToList()).ToList();
```

Remove the `NotImplementedException` lines entirely.

## 5. MODERATE — Windows-Specific Path in appsettings.Ragnar.json

**Problem:** `%USERPROFILE%\\source\\Ragnar\\` only resolves on Windows. On Linux/macOS the environment variable is `$HOME` and separators are `/`. This breaks cross-platform CI or any contributor on a non-Windows OS.

```json
// ❌ BEFORE
"SourceDirectory": "%USERPROFILE%\\source\\Ragnar\\"
```

**Fix:**

```json
// ✅ AFTER – use a relative or OS-agnostic path; resolve at runtime
"SourceDirectory": ""
```

```csharp
// ✅ In your config-resolution code (e.g., a ConfigInitializer or startup hook)
public static class SourceDirectoryResolver
{
    public static string Resolve(string configured)
    {
        if (!string.IsNullOrWhiteSpace(configured))
            return Environment.ExpandEnvironmentVariables(configured);

        // Fallback: walk up from the assembly base directory to find the repo root
        var base = AppContext.BaseDirectory;
        for (var dir = new DirectoryInfo(base); dir is not null; dir = dir.Parent)
        {
            if (File.Exists(Path.Combine(dir.FullName, ".gitignore")))
                return dir.FullName;
        }

        throw new DirectoryNotFoundException("Could not auto-detect source directory.");
    }
}
```

## 10. MINOR — Inconsistent CancellationToken Guard Style

Some methods use `Guard.Against.Null`, others use `ArgumentNullException.ThrowIfNull`, and some have no guard at all. Pick one convention.

| File | Style used |
|---|---|
| `BaseFileParser` | `Guard.Against.NullOrEmpty` |
| `StopwatchExtensions` | `ArgumentNullException.ThrowIfNull` |
| `CsvFileQuestionProvider` | *(none)* |
| `OllamaEmbeddingService` | `Guard.Against.NullOrWhiteSpace` |
| `FileWriter` | *(none)* |

**Recommended standard:**

```csharp
// Use the built-in .NET 8+ guard for simple null checks (no extra package)
ArgumentNullException.ThrowIfNull(cancellationTokenSource, nameof(cancellationTokenSource));

// Use Guard (Guards library) only when you need compound checks like NullOrWhiteSpace
Guard.Against.NullOrWhiteSpace(input, nameof(input));
```

Add a **style rule / analyzer** (e.g., `CA2225`, custom .editorconfig) so new code follows the same pattern.
