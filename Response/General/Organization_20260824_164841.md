### 🔑 Key Refactoring Guidelines

1. **Separation of Concerns**: 
   - Move all `interface` definitions to `Ragnar.Core.Contracts`.
   - Keep SDK-specific code (`CsvHelper`, `Ollama`, `Qdrant`, `Serilog`) in `Ragnar.Infrastructure`. This prevents your core business logic from leaking external dependencies.
   - Place orchestration logic (`EmbeddingPipeline`, `SummaryAgent` coordination) in `Ragnar.Application`.

2. **Composition Root**: 
   - Create a single `Program.cs` or `DependencyInjectionExtensions.cs` in `Ragnar.Presentation` (or a dedicated `Ragnar.AppHost` project) that wires up DI. This is where `SelfRegisteredExtensions`, `AddSingleton<T>`, and configuration binding happen.

3. **Namespace Convention**: 
   Use `Ragnar.{Layer}.{Feature}` or `Ragnar.Core.Models`. Avoid flat namespaces like `Ragnar.Extensions` unless strictly necessary. Group related utilities under `Ragnar.Core.Extensions`.

4. **Test Isolation**: 
   - Unit tests (`*Tests.cs`) should only reference `Ragnar.Core` and `Ragnar.Application`. Mock infrastructure dependencies using `Moq` or `NSubstitute`.
   - Integration tests go in a separate project that references `Ragnar.Infrastructure` and spins up real/fake Ollama & Qdrant instances.
