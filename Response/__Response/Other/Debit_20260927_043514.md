# Technical Debt Assessment — Ragnar (RAG Console Application)

Below is a structured inventory of the technical debt I identified across the codebase, grouped by severity and category.

---

## 1. Probable Bugs & Correctness Risks

| # | Location | Issue |
|---|----------|-------|
| 1.1 | `ApplicationOptionsValidator` | The regexes `^[[[[\w.-]]]]+$` and `^[[[[a-zA-Z0-9_]]]]+$` contain **nested character classes**. In .NET regex, `[[` inside `[[...]]` is treated as a literal, so these match a literal `[[` or `]]` in addition to the intended characters. They should be `^[[\w.-]]+$` and `^[[a-zA-Z0-9_]]+$`. |
| 1.2 | `FileParser.LineSplit` | Splits on `Environment.NewLine` only. Files authored on Linux/macOS (or with mixed line endings) will produce a single "line", breaking the chunker. Use `Split('\r', '\n')` or a regex split. |
| 1.3 | `FileParser.SplitMarkdown` | Accepts `in ReadOnlyMemory<char>` but immediately calls `.ToString()` on it, allocating a full string copy and defeating the purpose of the zero-copy parameter. |
| 1.4 | `OllamaClientFactory.CreateHttpClient` | Both LLM and Embedding clients call `httpClientFactory.CreateClient(nameof(Ollama))` — the **same named client**. They then override `Timeout` differently, but `IHttpClientFactory` caches by name, so handler-level settings (if any) collide. Use distinct names: `"OllamaLlm"` / `"OllamaEmbedding"`. |
| 1.5 | `OllamaClientFactory` | `EmbeddingOptions.Host` and `EmbeddingOptions.Port` are defined in the config model but **never read**. The factory always uses `OllamaOptions.Host/Port` for both client types. Either the embedding options are dead config, or the factory has a bug. |
| 1.6 | `Question` record | `IsActive` / `IsDisabled` call `question.ValidateQuestion()`, a method that **does not appear anywhere in the provided source**. If it's an extension in an unlisted file, that's a hidden dependency; if it's missing, this is a compile error. |
| 1.7 | `appsettings.json` | `"CategoriesToProcess": [[]]` will **fail validation** because `ApplicationOptionsValidator` has `.NotEmpty()` on that property. The app cannot start with the shipped default config. |
| 1.8 | `appsettings.json` | `"LlmModel": "qwen3.8"` appears to be a typo (no such Ollama model exists). Likely should be `"qwen2.5"` or similar. |
| 1.9 | `ResponseWriter.WriteResponseAsync` | File name is `{Filename}_{yyyyMMdd_HHmmss}.{ext}`. Two questions with the same `Filename` answered in the same second will **overwrite each other**. Add a GUID suffix or use a retry/rename strategy. |
| 1.10 | `appsettings.Ragnar.json` | `"SourceDirectory": "%USERPROFILE%\\source\\Ragnar\\"` uses Windows `%VAR%` syntax and backslashes. This **will not resolve on Linux/macOS** and the backslashes are incorrect for `Path.Join` on non-Windows. |

## 2. Architectural & Design Smells

### 2.1 Inconsistent C# language-feature usage
The codebase mixes **C# 13 `extension` methods** (`CodeDocumentExtensions`, `StringExtensions`, `QuestionExtensions`, `AssemblyExtensions`) with **traditional static extension-method classes** (`StopwatchExtensions`, `FileSystemEntryExtensions`, `FileSystemEntryExtensions`). Pick one idiom and apply it consistently. The `extension` keyword requires C# 13 / .NET 10; if any consumer targets an older runtime, those files will not compile.

### 2.2 `OllamaClientFactory` cache has no lifecycle
```csharp
private readonly ConcurrentDictionary<OllamaServiceType, OllamaApiClient> _cache = new();
```
- `OllamaApiClient` presumably holds an `HttpClient` (or wraps one). The factory never disposes cached entries.
- No `IDisposable` on the factory. If the factory is scoped but the underlying handler is singleton, this is fine; if it's transient, you leak handlers.
- There is no eviction, no maximum size (irrelevant at 2 entries, but the pattern doesn't scale if new `OllamaServiceType` values appear).

### 2.3 `IOutputFormatter.FileExtension` is a mutable interface property
```csharp
string FileExtension { get; set; }
```
A `set` on an interface property is almost always a smell. Make it `get;` only and let each formatter hard-code its extension, or pass it via constructor.

### 2.4 `ConsoleTableBuilder` exposes mutable internals
```csharp
public List<string> Columns { get; set; } = [[]];
public List<string[[]]> Rows  { get; set; } = [[]];
```
The XML docs say *"Read-only snapshot"* but both properties are **publicly settable and the lists are mutable**. Any consumer can add/remove columns mid-build, breaking the invariant that `_expectedCellCount` locks on the first `AddRow`. Use `IReadOnlyList<T>` and a private backing field, or make them `init;`-only.

### 2.5 God-config anti-pattern
`RagnarConfig` bundles four unrelated option groups (`ApplicationOptions`, `EmbeddingOptions`, `OllamaOptions`, `FileLoadOptions`) into one record with `required` on every child. This forces every consumer to accept the entire object even when it only needs one slice. Consider registering each sub-section as a separate `IOptions<T>` instance so consumers depend only on what they use.

### 2.6 `QuestionExecutionStage` retrieves context **once** for all questions
```csharp
var contextText = await questionEmbedding.RetrieveContextAsync(_collectionName, cancellationToken);
foreach (var question in questions)
{
    await ragOrchestrator.ExecuteAsync(question, contextText, cancellationToken);
}
```
Every question gets the **same** retrieved context. A proper RAG pipeline should embed each question independently and retrieve its own top-k passages. This defeats the purpose of vector search.

### 2.7 `FileParser` does chunking, not just parsing
`ParseAsync` reads a file **and** splits it into markdown paragraphs. The chunking logic (`SplitMarkdown`, `LineSplit`) is a separate concern that belongs in a dedicated `ITextChunker` service. This also makes it impossible to reuse the parser for non-markdown files without the chunker coupling.

### 2.8 `Dimension` used as a token limit
```csharp
Convert.ToInt32(EmbeddingOption.Dimension)  // → maxTokensPerParagraph
```
`Dimension` is a **vector-space property** (e.g. 768 for `nomic-embed-text`). Using it as a paragraph token cap is a semantic misuse that will break if someone changes the model to a 1536-dim embedding (the chunker would then allow 1536-token paragraphs).

### 2.9 Tight coupling to Spectre.Console
`QuestionExecutionStage` and `ParsingStage` call `AnsiConsole.Progress()`, `writer.MarkupLine()`, and construct `Text`/`Rule` objects directly. The pipeline stages should depend on an abstraction (e.g. `IPipelineReporter`) so the UI layer is swappable (unit tests, CI, headless mode).

### 2.10 `Question.MarkdownHeader` embeds HTML
```csharp
$"### <span style=\"color:darkblue;\">{Category}</span> {Text}"
```
Inline HTML in Markdown is not portable (GitLab, GitHub, VS Code preview all handle it differently). Prefer a convention that the renderer interprets.

## 3. Security & Robustness Gaps

| # | Issue |
|---|-------|
| 3.1 | `BaseFileParser.ReadFileAsync` has no **path-traversal guard**. A malicious or buggy caller could pass `../../etc/passwd`. Validate that the resolved path stays within the configured `SourceDirectory`. |
| 3.2 | `CsvRecordParser.ParseAsync` opens the file without checking existence or permissions; the `StreamReader` will throw a raw `FileNotFoundException` with no application-level context. |
| 3.3 | `FileWriter.WriteAsync` uses `File.WriteAllTextAsync` with no **concurrency lock**. If two pipeline runs target the same directory simultaneously, writes can interleave (mitigated by the timestamp, but see bug 1.9). |
| 3.4 | `Guard.Against` is used ad-hoc (sometimes for null, sometimes for empty, sometimes missing entirely). There is no unified input-validation policy. The `FluentValidation` validators cover config but not runtime method parameters. |
| 3.5 | No **rate-limiting** or **retry** policy is visible on the Ollama HTTP calls. A transient network blip will surface as an unhandled exception. (Serilog config references `Polly` at `Warning` level, suggesting Polly was considered but I see no Polly usage in the provided code.) |

## 5. Configuration & Portability Issues

| # | Issue |
|---|-------|
| 5.1 | `appsettings.json` ships with an **empty** `CategoriesToProcess` array, which fails the `NotEmpty()` validator. The app is **unrunnable out of the box**. |
| 5.2 | `appsettings.Ragnar.json` hard-codes a Windows user-profile path with `%USERPROFILE%` and backslashes. This breaks on any non-Windows OS. |
| 5.3 | `EmbeddingOptions` has its own `Host`/`Port` (set to `localhost:6334`, which is **Qdrant's** default port, not Ollama's). The Ollama embedding API is on the same Ollama port (11434). This looks like a copy-paste error. |
| 5.4 | `FileLoadOptions.AllowedExtensions` includes `.editorconfig` — an editor configuration file, not source code. It will be parsed, chunked, and embedded, diluting the vector store. |
| 5.5 | Serilog is configured to write to both **Seq** (`http://localhost:5341`) and a **file**. If Seq is not running (CI, production), the file sink still works, but the Seq sink will throw on every flush. No fallback or conditional sink logic is visible. |

## 6. Testing Gaps

Only **one** test class is present (`OllamaClientFactoryTests`). Notable absences:

- **No validator tests** — the regex bugs in §1.1 would be caught immediately by a unit test asserting that `"valid-name"` passes and `"in/valid"` fails.
- **No parser tests** — `FileParser`, `CSharpFileParser` (implied by `BaseFileParser`), and `CsvRecordParser` are untested.
- **No pipeline-stage tests** — `ParsingStage`, `QuestionExecutionStage` have no visible test coverage.
- **No formatter / writer tests** — `IOutputFormatter`, `ResponseWriter`, `PathResolver`, `FileWriter` are untested.
- `OllamaClientFactoryTests.FindClientHttpClientShouldHaveCorrectBaseAddress` asserts on `result.Config.Uri`, but the factory sets `client.BaseAddress`. If `OllamaApiClient` doesn't map `BaseAddress → Config.Uri`, this test passes vacuously or tests the wrong property.
- The cache test (`FindClientSameTypeTwiceShouldReturnCachedInstance`) is good, but there's no test that **different** service types produce **different** clients.

## 7. Minor / Code-Style Inconsistencies

- `#pragma warning disable SKEXP0050` at the top of `FileParser.cs` suppresses a SonarQube rule without explaining why. Add a comment or remove the suppression.
- `Question.MarkdownHeader` is a **computed property** on a `record` that depends on two other properties. If either is `null` (both are `[[NotNull]]` but the record constructor doesn't enforce it at runtime), this will produce `null` in the output.
- `AssemblyExtensions` is defined **twice** in the provided files (once as a static class with a nested `extension`, once as a bare `extension`). If both compile, that's a duplicate-type error; if only one ships, the other is dead.
- `OllamaClientFactory` primary constructor parameter is `IOptions<RagnarConfig> ragnarConfig`, but it immediately dereferences `.Value` into a field. If the `IOptions` instance is a **named** options token or is re-read at runtime, this snapshot will go stale.
- `StopwatchExtensions.FormatElapsedTime` uses `Guard.Against.Null(sw)` — a `Stopwatch` is a struct and **cannot be null** when passed by value. This guard is dead code (unless the parameter is a nullable reference type, which it isn't).
