## 1. Retry-Aware Middleware (fills the `RetryCount = 0` gap)

Your `StageMetric` already has a `RetryCount` property with the comment *"populate via a separate retry middleware if needed"*, but nothing ever writes to it. The Polly `IAsyncPolicy` on `StageEntry` handles the *mechanism*, but there's no middleware that **observes** the attempt count for metrics and logging.

```csharp
public sealed class RetryObservationMiddleware(ILogger logger)
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        var attempt = 0;
        while (true)
        {
            attempt++;
            try
            {
                await next().ConfigureAwait(false);
                if (ctx.Metric is not null)
                    ctx.Metric = ctx.Metric with { RetryCount = attempt - 1, Success = true, Error = null };
                else
                    ctx.Metric = new StageMetric { StageName = ctx.Stage.Name, RetryCount = attempt - 1, Success = true };
                break;
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested) { throw; }
            catch (Exception ex) when (attempt <= 3)
            {
                logger.Warning("Stage {Name} attempt {Attempt} failed: {Error}", ctx.Stage.Name, attempt, ex.Message);
                await Task.Delay(TimeSpan.FromMilliseconds(200 * attempt), ct).ConfigureAwait(false);
            }
        }
    }
}
```

> **Why:** Right now a stage that retries via Polly will still record `RetryCount = 0` in every `StageMetric`, making your telemetry misleading.

## 2. Token-Budget / Quota Middleware

`GenerationOptions` exposes `MaxTokens`, `ContextWindow`, and `ThreadCount`, but nothing in the pipeline *enforces* a cumulative token budget across stages. If you add a stage that counts tokens (e.g., context-length check before generation), a middleware can gate it:

```csharp
public sealed class TokenBudgetMiddleware(ILogger logger, IOptions<RagnarConfig> config)
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        var limit = config.Value.GenerationOptions.MaxTokens;
        if (ctx.PipelineContext is QuestionPipelineContext qpc)
        {
            var used = qpc.Responses.Values.Sum(r => r.Length / 4); // rough tokens
            if (used >= limit)
            {
                logger.Warning("Token budget exhausted ({Used}/{Limit}); skipping stage {Stage}",
                               used, limit, ctx.Stage.Name);
                return;
            }
        }
        await next().ConfigureAwait(false);
    }
}
```

## 3. Correlation-ID / Structured-Event Middleware

Your `RagOrchestrator.ExecuteAsync` generates a `Stopwatch` per call, but the pipeline stages (`BrandingStage`, `QuestionLoadStage`, etc.) have no shared correlation ID. A lightweight middleware can stamp one onto the context and include it in every log line:

```csharp
public sealed class CorrelationIdMiddleware(ILogger logger)
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        var id = Guid.NewGuid().ToString("N")[[..8]];
        logger.Information("[[{Cid}]] Stage {Index}/{Total} {Name} started", id, ctx.StageIndex + 1, ctx.StageTotal, ctx.Stage.Name);
        await next().ConfigureAwait(false);
        logger.Information("[[{Cid}]] Stage {Index}/{Total} {Name} finished", id, ctx.StageIndex + 1, ctx.StageTotal, ctx.Stage.Name);
    }
}
```

This pairs naturally with Serilog's `Enrich.WithProperty` for downstream sinks.

## 4. Circuit-Breaker / Degradation Middleware

`RagOrchestrator` currently catches exceptions and writes a hard-coded `"⚠️ Generation failed…"` string. A middleware that wraps the *call stage* with a Polly `CircuitBreakerPolicy` gives you:

- Automatic open/close transitions when Ollama is down.
- A configurable fallback response (e.g., return cached last-good answer from `QuestionPipelineContext.Responses`).

```csharp
public sealed class CircuitBreakerMiddleware(ILogger logger)
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        var policy = Policy.Handle<HttpRequestException>()
                           .Or<TimeoutException>()
                           .CircuitBreaker(3, TimeSpan.FromSeconds(30));

        try { await policy.ExecuteAsync(async () => await next().ConfigureAwait(false)).ConfigureAwait(false); }
        catch (BrokenCircuitException)
        {
            logger.Error("Circuit OPEN for stage {Name}; using fallback", ctx.Stage.Name);
            // set ctx.PipelineContext to a degraded state
        }
    }
}
```

## 5. Context-Validation / Guard Middleware

Several stages assume preconditions (e.g., `QuestionPipelineContext.Questions` is non-null after `QuestionLoadStage`). A generic guard middleware prevents a `NullReferenceException` deep in a downstream stage:

```csharp
public sealed class ContextGuardMiddleware(ILogger logger)
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        if (ctx.PipelineContext is QuestionPipelineContext qpc && ctx.StageIndex > 0 && qpc.Questions is null)
            throw new InvalidOperationException(
                $"Stage '{ctx.Stage.Name}' requires Questions to be populated, but it is null. " +
                $"Was 'QuestionLoadStage' executed earlier?");
        await next().ConfigureAwait(false);
    }
}
```

## 6. Output-Formatting / Rendering Middleware

`NumberedRowDecorator` and `OutputPathHelper.ShowPrompt` are currently called *imperatively* from specific stages. If you add a middleware that runs **after** every stage, it can uniformly:

- Number console table rows (wrapping `NumberedRowDecorator`).
- Append a visual separator between stages (`writer.MarkupLine("─".Repeat(60))`).
- Emit a progress bar based on `StageIndex / StageTotal`.

This keeps rendering concerns out of `IPipelineStage.ExecuteAsync`.

## 7. Async-Enumeration / Backpressure Middleware (for `FileDiscoveryService`)

`FileDiscoveryService.GetFilesAsync` yields files one-by-one with `await Task.Yield()`, but there's no rate-limiting or concurrency cap. A middleware around the *parse* stage could:

- Limit concurrent `CodeParserFactory.ParseAsync` calls to `GenerationOptions.ThreadCount`.
- Apply a sliding-window throttle so the Ollama embedding endpoint isn't flooded.
