# Packaging Your Pipeline & Stages as a Reusable NuGet Package

Your codebase already has a clean separation between **generic pipeline infrastructure** and **domain-specific stages**. That makes it a natural fit for a package. Below is a step-by-step guide.

---

## 1. Decide What Goes In the Package vs. What Stays

| Belongs in the **package** (generic) | Stays in the **app** (domain-specific) |
|---|---|
| `IPipeline<TContext>` | `QuestionPipelineContext` |
| `IPipelineStage<TContext>` | `EmbeddingContext` |
| `BasePipeline<TContext>` | `BrandingStage`, `DeltaEmbedStage` |
| `PipelineRunner<TContext>` | `QuestionFilterSelector` |
| `StageExecutionContext<TContext>` | `QdrantFilterBuilder` |
| `StageEntry<TContext>` | `XmlCommentFilterStrategy` |
| `StageTimingMiddleware` | `IFileParser`, `IFileParseFactory` |
| `ProgressMiddleware` + `IOutputWriter` | Ollama / Qdrant clients |
| `StageMetric` | `IOllamaClientFactory` |
| `PipelineStageException` | All configuration records |
| `IPipelineMiddleware<TContext>` *(if extracted)* | `RagnarConfig` |

The rule: **anything that doesn't reference your domain types goes in the package.**

## 4. Refactor the Generic Types

### 4a. Extract the middleware interface (makes it extensible)

```csharp
// src/Ragnar.Pipeline/Middleware/IPipelineMiddleware.cs
namespace Ragnar.Pipeline;

public interface IPipelineMiddleware<in TContext> where TContext : class
{
    Task Invoke(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken cancellationToken);
}
```

### 4b. Replace `ILogger` with `ILogger<T>` (avoids the concrete Serilog dependency)

```csharp
// Before (your current code):
public sealed class StageTimingMiddleware(ILogger logger) { … }

// After:
public sealed class StageTimingMiddleware(ILogger<StageTimingMiddleware> logger) { … }
```

Same for `ProgressMiddleware`:

```csharp
public sealed class ProgressMiddleware(IOutputWriter writer) { … }

public interface IOutputWriter
{
    void WriteLine(string message);
}
```

> Ship a default `ConsoleOutputWriter` in the package so consumers who don't override get console output for free.

### 4c. Add DI registration extensions

```csharp
// src/Ragnar.Pipeline/Extensions/ServiceCollectionExtensions.cs
namespace Ragnar.Pipeline;

public static class ServiceCollectionExtensions
{
    /// <summary>
    /// Registers a <see cref="PipelineRunner{TContext}"/> and the
    /// built-in timing + progress middlewares.
    /// </summary>
    public static IServiceCollection AddPipeline<TContext>(this IServiceCollection services)
        where TContext : class
    {
        services.AddSingleton<IOutputWriter, ConsoleOutputWriter>();
        services.AddSingleton<IPipeline<TContext>, PipelineRunner<TContext>>();
        return services;
    }

    /// <summary>
    /// Convenience: build a runner, add middleware, and register stages in one call.
    /// </summary>
    public static PipelineRunner<TContext> BuildPipeline<TContext>(
        this IServiceCollection services,
        Action<PipelineRunner<TContext>>? configure = null)
        where TContext : class
    {
        var runner = new PipelineRunner<TContext>(
            services.BuildServiceProvider().GetRequiredService<ILogger<PipelineRunner<TContext>>>());

        runner.UseTiming(new StageTimingMiddleware(
            services.BuildServiceProvider().GetRequiredService<ILogger<StageTimingMiddleware>>()));
        runner.UseMiddleware((ctx, next, ct) => new ProgressMiddleware(new ConsoleOutputWriter()).Invoke(ctx, next, ct));

        configure?.Invoke(runner);
        return runner;
    }
}
```

### 4d. Make `PipelineRunner` the public surface

Your existing `PipelineRunner<TContext>` is already generic and doesn't touch domain types (except `ILogger`). After the Serilog → `ILogger<T>` swap it's package-ready. Just make sure:

- `public sealed class PipelineRunner<TContext> : IPipeline<TContext>`
- `public sealed record StageExecutionContext<TContext>`
- `public sealed record StageMetric`
- `public sealed class StageEntry<TContext>`

…all live in the `Ragnar.Pipeline` namespace.

Your domain-specific stages (`BrandingStage`, `DeltaEmbedStage`, etc.) **stay in the app project** and simply implement `IPipelineStage<EmbeddingContext>`.

## 7. Build & Publish

### Local (dev)

```bash
dotnet pack src/Ragnar.Pipeline -c Release -o ./artifacts
# → artifacts/Ragnar.Pipeline.0.1.0.nupkg
# → artifacts/Ragnar.Pipeline.0.1.0.snupkg
```

### Feed

```bash
dotnet nuget add source https://api.nuget.org/v3/index.json -n nuget.org
dotnet nuget push artifacts/Ragnar.Pipeline.0.1.0.nupkg --api-key $NUGET_KEY
```

### CI (GitHub Actions example)

```yaml
# .github/workflows/publish-pipeline.yml
name: Publish Ragnar.Pipeline
on:
  push:
    tags: [['pipeline-v*']]

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0'
      - run: dotnet restore src/Ragnar.Pipeline
      - run: dotnet test tests/Ragnar.Pipeline.Tests --no-restore
      - run: |
          VERSION=${GITHUB_REF_NAME#pipeline-v}
          dotnet pack src/Ragnar.Pipeline -c Release -p:PackageVersion=$VERSION -o ./artifacts
      - run: dotnet nuget push artifacts/*.nupkg --source nuget.org --api-key ${{ secrets.NUGET_API_KEY }}
        if: github.event_name == 'push'
```

## 8. `README.md` for the Package

# Ragnar.Pipeline

Generic, middleware-based pipeline runner for .NET 8+.

## Install

```
dotnet add package Ragnar.Pipeline
```

## Quick start

```csharp
using Ragnar.Pipeline;

// 1. Define a context
public class MyContext { public List<string> Items = [[]]; }

// 2. Define stages
public class LoadStage : IPipelineStage<MyContext>
{
    public string Name => "Load";
    public AsyncRetryPolicy? RetryPolicy => null;
    public bool ShouldRun(MyContext ctx) => true;
    public Task ExecuteAsync(MyContext ctx, CancellationToken ct)
    {
        ctx.Items.AddRange([["a", "b", "c"]]);
        return Task.CompletedTask;
    }
}

// 3. Build & run
var runner = new PipelineRunner<MyContext>(logger);
runner
    .UseTiming(new StageTimingMiddleware(logger))
    .AddStage(new LoadStage())
    .AddStage(new TransformStage());

var ctx = new MyContext();
await runner.ExecuteAsync(ctx, cancellationToken);
```

## Middleware

Add your own cross-cutting concern (logging, auth, metrics):

```csharp
public class AuditMiddleware : IPipelineMiddleware<MyContext>
{
    public Task Invoke(StageExecutionContext<MyContext> ctx,
                       Func<Task> next, CancellationToken ct)
    {
        Console.WriteLine($"→ {ctx.Stage.Name}");
        return next();
    }
}

runner.UseMiddleware((c, n, t) => new AuditMiddleware().Invoke(c, n, t));

| # | Change | Why |

| 1 | Create `src/Ragnar.Pipeline/` project with the 7 generic types | Isolation |

| 6 | Move `StageMetric`, `StageExecutionContext`, `StageEntry` into the package | They're already generic |

After these changes, your app project shrinks to just the **domain stages**, **Qdrant/Ollama integration**, and **configuration**, while the pipeline engine is a single `dotnet add package Ragnar.Pipeline` away for any other project you (or your users) build.
