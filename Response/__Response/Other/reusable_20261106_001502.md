# Making the Pipeline & Stages Reusable

Your current design works well for a single, fixed pipeline. The main friction points for reuse are:

1. **Stages are hard-bound to one context type** (`EmbeddingContext`, `QuestionPipelineContext`).
2. **No composition** – you can't nest a pipeline inside a stage or share a sub-sequence.
3. **Stages duplicate boilerplate** (guard, ShouldRun, logging, retry wiring).
4. **Middleware is per-runner** – identical cross-cutting concerns (timing, progress) must be re-registered on every runner.

Below are concrete refactors, ordered from highest-impact to incremental.

---

## 1. Abstract Base Stage (eliminate boilerplate, enable reuse)

Give every stage a shared skeleton so concrete stages only supply *what* they do:

```csharp
/// <summary>
/// Base class providing logging, ShouldRun short-circuit, and retry wiring.
/// Concrete stages override <see cref="ExecuteCoreAsync"/> only.
/// </summary>
public abstract class PipelineStageBase<TContext> : IPipelineStage<TContext>
    where TContext : class
{
    protected PipelineStageBase(ILogger logger) => _logger = logger;
    private readonly ILogger _logger;

    public abstract string Name { get; }
    public virtual AsyncRetryPolicy? RetryPolicy => null;
    public virtual bool ShouldRun(TContext context) => true;

    public async Task ExecuteAsync(TContext context, CancellationToken ct)
    {
        ct.ThrowIfCancellationRequested();
        _logger.Debug("{Stage}: executing", Name);
        await ExecuteCoreAsync(context, ct).ConfigureAwait(false);
        _logger.Debug("{Stage}: completed", Name);
    }

    /// <summary>The stage's actual work. No try/catch – the runner handles that.</summary>
    protected abstract Task ExecuteCoreAsync(TContext context, CancellationToken ct);
}
```

Now `BrandingStage` shrinks to the essential:

```csharp
public sealed class BrandingStage(ILogger logger, IApplicationHeader header)
    : PipelineStageBase<EmbeddingContext>(logger)
{
    public override string Name => "Branding";

    protected override Task ExecuteCoreAsync(EmbeddingContext context, CancellationToken ct)
    {
        header.RenderBranding();
        return Task.CompletedTask;
    }
}
```

**Why this helps reuse:** any team can drop in a new stage by implementing one method. The retry, logging, and cancellation contracts are inherited and consistent.

## 2. Context Segregation (composable context slices)

Instead of one monolithic `EmbeddingContext`, define **context fragments** that stages can *require* and *produce*. This lets the same stage participate in different pipelines:

```csharp
// ── Context fragments ──────────────────────────────────────────────
public record HasDocuments(IEnumerable<CodeDocument> Documents);
public record HasQuestions(IReadOnlyList<Question> Questions);
public record HasFilter(Filter Filter);
public record HasOutputPath(string Path);

// ── Composite context (implements all fragments it carries) ───────
public sealed class EmbeddingContext :
    HasDocuments, HasFilter, HasOutputPath
{
    public IEnumerable<CodeDocument> Documents { get; init; } = [];
    public Filter Filter { get; init; } = default!;
    public string OutputPath { get; init; } = "";
}

public sealed class QuestionPipelineContext :
    HasQuestions, HasFilter
{
    public IReadOnlyList<Question> Questions { get; init; } = [];
    public Filter Filter { get; init; } = default!;

    public ConcurrentDictionary<Guid, string> Responses { get; } = new();
    public ConcurrentDictionary<Guid, TimeSpan> Timings { get; } = new();
}
```

Now a stage can depend on a *capability* rather than a concrete context:

```csharp
/// <summary>
/// A stage that requires the context to carry documents.
/// Reusable in any pipeline whose TContext implements HasDocuments.
/// </summary>
public sealed class DeltaEmbedStage : IPipelineStage<HasDocuments>
{
    // ...same logic, but TContext is HasDocuments, not EmbeddingContext.
    public bool ShouldRun(HasDocuments context) => context.Documents is { Count: > 0 };
    protected override Task ExecuteCoreAsync(HasDocuments context, CancellationToken ct)
    {
        // iterate context.Documents ...
    }
}
```

`EmbeddingContext` *is-a* `HasDocuments`, so `PipelineRunner<EmbeddingContext>` can still execute it via a small adapter (or by making the runner's `TContext` the fragment itself and using a wrapper).

## 3. Pipeline Composition (a pipeline *is* a stage)

This is the single biggest reusability win. Let any pipeline be dropped into a parent pipeline:

```csharp
/// <summary>
/// Wraps a child pipeline so it can be added as a stage to a parent pipeline.
/// </summary>
public sealed class CompositeStage<TContext> : PipelineStageBase<TContext>
    where TContext : class
{
    private readonly IPipeline<TContext> _child;

    public CompositeStage(ILogger logger, IPipeline<TContext> child) : base(logger)
        => _child = child;

    public override string Name { get; init; } = "Sub-pipeline";
    public override bool ShouldRun(TContext context) => true;

    protected override Task ExecuteCoreAsync(TContext context, CancellationToken ct)
        => _child.ExecuteAsync(context, ct).AsTask();
}
```

Usage:

```csharp
// Build a reusable "parse → embed" sub-pipeline once:
var parseEmbed = new PipelineRunner<EmbeddingContext>(logger)
    .AddStage(new FileDiscoveryStage(log, fileSvc, opts))
    .AddStage(new ParseStage(log, parserFactory))
    .AddStage(new DeltaEmbedStage(log, fpStore, writer, opts));

// Compose into the top-level pipeline:
var topPipeline = new PipelineRunner<EmbeddingContext>(logger)
    .UseMiddleware(new StageTimingMiddleware(logger).Invoke)
    .AddStage(new BrandingStage(log, header))
    .AddStage(new CompositeStage<EmbeddingContext>(log, parseEmbed) { Name = "Ingest" });
```

Now the "Ingest" sub-pipeline can be reused verbatim in a different parent, a test harness, or a microservice.

## 4. Stage Decorators (replacing per-stage retry/timing wiring)

Rather than attaching a Polly policy at registration time, decorate the stage itself so the decoration travels *with* the stage wherever it's reused:

```csharp
/// <summary>Wraps a stage with retry-on-exception behavior.</summary>
public sealed class RetryStageDecorator<TContext>(
    IPipelineStage<TContext> inner,
    AsyncRetryPolicy policy,
    ILogger logger)
    : IPipelineStage<TContext> where TContext : class
{
    public string Name => inner.Name;
    public bool ShouldRun(TContext context) => inner.ShouldRun(context);

    public async Task ExecuteAsync(TContext context, CancellationToken ct)
    {
        await policy.ExecuteAsync(async () =>
            await inner.ExecuteAsync(context, ct).ConfigureAwait(false)
        ).ConfigureAwait(false);
    }
}

/// <summary>Wraps a stage with a hard timeout.</summary>
public sealed class TimeoutStageDecorator<TContext>(
    IPipelineStage<TContext> inner,
    TimeSpan timeout,
    ILogger logger)
    : IPipelineStage<TContext> where TContext : class
{
    public string Name => inner.Name;
    public bool ShouldRun(TContext context) => inner.ShouldRun(context);

    public async Task ExecuteAsync(TContext context, CancellationToken ct)
    {
        using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);
        cts.CancelAfter(timeout);
        await inner.ExecuteAsync(context, cts.Token).ConfigureAwait(false);
    }
}
```

Registration becomes declarative and portable:

```csharp
var embed = new DeltaEmbedStage(log, fpStore, writer, opts);
var embedWithRetry  = new RetryStageDecorator<EmbeddingContext>(embed, retryPolicy, log);
var embedWithTimeout = new TimeoutStageDecorator<EmbeddingContext>(embedWithRetry, TimeSpan.FromSeconds(30), log);

runner.AddStage(embedWithTimeout);   // retry + timeout travel with the stage
```

Because decorators are just `IPipelineStage<T>`, they compose: `Timeout(Retry(Inner))` is as natural as `inner` alone.

## 5. Shared Middleware Registry

Extract the "which middlewares apply" decision out of each runner so it's defined once:

```csharp
public sealed record MiddlewareChain(
    IEnumerable<Func<StageExecutionContext<>, Func<Task>, CancellationToken, Task>> Middlewares);

public static class DefaultMiddleware
{
    public static MiddlewareChain Standard(ILogger logger, IOutputWriter writer) => new(
    [
        (ctx, next, ct) => new StageTimingMiddleware(logger).Invoke(ctx, next, ct),
        (ctx, next, ct) => new ProgressMiddleware(writer).Invoke(ctx, next, ct),
    ]);
}
```

Then a runner factory applies them:

```csharp
public static IPipeline<T> CreatePipeline<T>(ILogger logger, IOutputWriter writer)
    where T : class
{
    var runner = new PipelineRunner<T>(logger);
    foreach (var mw in DefaultMiddleware.Standard(logger, writer).Middlewares)
        runner.UseMiddleware(mw);
    return runner;
}
```

Every pipeline created via this factory gets identical cross-cutting behavior.

## 6. DI-Resolvable Stage Registry (for testability & plugin discovery)

Register stages by name so they can be composed at runtime or swapped in tests:

```csharp
public sealed class StageRegistry
{
    private readonly Dictionary<string, Func<IPipelineStage<>>> _factories = new(StringComparer.OrdinalIgnoreCase);

    public void Register<TCtx>(string name, Func<IPipelineStage<TCtx>> factory)
        => _factories[name] = factory;

    public IPipelineStage<T> Resolve<T>(string name)
        => (IPipelineStage<T>)(_factories.TryGetValue(name, out var f) ? f() : throw new KeyNotFoundException(name));
}
```

```csharp
// In DI setup:
services.AddSingleton<StageRegistry>(sp =>
{
    var reg = new StageRegistry();
    reg.Register<EmbeddingContext>("branding",  () => new BrandingStage(log, header));
    reg.Register<EmbeddingContext>("embed",     () => new DeltaEmbedStage(log, fp, writer, opts));
    return reg;
});
```

Tests can then build a pipeline from a *subset* of registered stages without touching production code.

## 7. Summary – What Changed & Why

| Concern | Before | After |
|---|---|---|
| New stage boilerplate | Implement `Name`, `ShouldRun`, `ExecuteAsync`, retry wiring each time | Extend `PipelineStageBase`, implement one method |
| Context coupling | Stage hard-codes `EmbeddingContext` | Stage depends on a capability fragment (`HasDocuments`) |
| Reusing a sequence of stages | Copy-paste registrations | Wrap in `CompositeStage`, add to any parent |
| Cross-cutting (retry, timeout) | Per-registration Polly param | Decorator objects that travel with the stage |
| Middleware re-registration | `UseMiddleware(...)` repeated per runner | `MiddlewareChain` applied by a factory |
| Test / plugin discovery | `new Stage(...)` everywhere | `StageRegistry` resolved from DI |

All seven changes are **additive** – none require altering existing `IPipelineStage<T>` consumers. You can adopt them incrementally: start with the base class (1) and decorators (4), then layer in fragments (2), composition (3), and the registry (6) as the team grows.
