## 1. 🐛 Bug: Double-Bracket Regex in `ApplicationOptionsValidator`

```csharp
// ❌ Current – the outer [[ ]] is a character class containing two [[ and ]] literals
private static readonly Regex _validFolderName = new(@"^[[[[\w.-]]]]+$", RegexOptions.Compiled);
```

This actually matches a literal `[[` or `]]` in addition to word characters, `.`, and `-`. It also makes the pattern harder to reason about.

```csharp
// ✅ Fix
private static readonly Regex _validFolderName = new(@"^[[\w.-]]+$", RegexOptions.Compiled);
```

## 2. 🐛 Bug: Flawed Tag-Stripping Logic in `StringExtensions.CharacterCount`

```csharp
// ❌ Current – breaks on CDATA, self-closing tags, and counts '/' as skipped text
if (c == '<') { insideTag = true; continue; }
if (c == '>') { insideTag = false; continue; }
if (!insideTag && c != '/') count++;   // skips ANY forward slash in prose
```

Problems:
- `<![[CDATA[[...]]]]>` – the second `[[` is counted as content; the `]]]]>` closing is mis-parsed.
- Text like `"Use a/b ratio"` silently drops the `/`.
- No handling of XML declarations `<?xml ... ?>`.

```csharp
// ✅ Fix – use a proper regex or a small state machine that handles CDATA
public int CharacterCount()
{
    // Remove CDATA sections, then strip all tags, then count
    var noCdata = Regex.Replace(xmlComment, @"<!\[[CDATA\[[.*?\]]\]]>", "", RegexOptions.Singleline);
    var noTags  = Regex.Replace(noCdata, @"<[[^>]]*>", "");
    return noTags.Length;
}
```

## 3. 🐛 Design Flaw: Shared Context for All Questions in `QuestionExecutionStage`

```csharp
// ❌ One retrieval feeds every question – defeats the purpose of per-question RAG
var contextText = await questionEmbedding.RetrieveContextAsync(_collectionName, cancellationToken)
                    .ConfigureAwait(false);
foreach (var question in questions)
{
    await ragOrchestrator.ExecuteAsync(question, contextText, cancellationToken);
}
```

Each question should retrieve *its own* most-relevant chunks, otherwise answers degrade as the codebase grows.

```csharp
// ✅ Fix – retrieve per question (or batch-retrieve with per-question vectors)
foreach (var question in questions)
{
    var questionVector = await questionEmbedding.EmbedAsync(question.Text, cancellationToken);
    var contextText    = await vectorSearch.RetrieveContextAsync(
                             _collectionName, questionVector, question.Filter, cancellationToken);
    await ragOrchestrator.ExecuteAsync(question, contextText, cancellationToken);
}
```

## 4. 🐛 Potential Overflow: `Convert.ToInt32` on a `ulong` in `FileParser`

```csharp
// ❌ Dimension is ulong (1–65536 per doc), but max is passed as int
var response = SplitMarkdown(filePath, fileContent.AsMemory(),
                              Convert.ToInt32(EmbeddingOption.Dimension), 50);
```

While 65536 fits in an `int`, the implicit trust is fragile. More importantly, the `in ReadOnlyMemory<char>` is immediately materialised:

```csharp
// ❌ Defeats the purpose of ReadOnlyMemory<char>
private static IList<CodeDocument> SplitMarkdown(string filePath, in ReadOnlyMemory<char> content, ...)
{
    var lines = TextChunker.SplitMarkdownParagraphs(
        lines: LineSplit(content.ToString()), ...);  // allocates a brand-new string
```

```csharp
// ✅ Fix – work with the memory directly, or just accept a string
private static IList<CodeDocument> SplitMarkdown(string filePath, string content,
                                                  int maxTokens, int overlap)
{
    var lines = content.Split(Environment.NewLine);
    var chunks = TextChunker.SplitMarkdownParagraphs(lines, maxTokensPerParagraph: maxTokens,
                                                     overlapTokens: overlap);
    return chunks.Select(chunk => new CodeDocument { ... }).ToList();
}
```

Also, the hard-coded `50` should come from configuration.

## 5. ⚠️ Configuration Will Fail Validation at Startup

```json
// appsettings.json
"ApplicationOptions": {
    "CategoriesToProcess": [[]],          // ← empty array
    ...
}
```

```csharp
// ApplicationOptionsValidator
RuleFor(x => x.CategoriesToProcess).NotEmpty()
    .WithMessage("CategoriesToProcess must contain at least one category.");
```

If the validator is wired into `ValidateOnStart`, the app will crash on launch. Either seed a default or make the rule conditional:

```csharp
// ✅ Allow empty (meaning "process all") OR require at least one
.RuleFor(x => x.CategoriesToProcess)
 .Must(list => list is null || list.Count > 0)
 .WithMessage("CategoriesToProcess must be null (all) or contain at least one entry.");
```

## 13. Minor: `Question` Record Uses `[[NotNull]]` on Positional Parameters

```csharp
// ❌ [[NotNull]] on a record positional parameter is non-standard and confusing
public sealed record class Question(bool IsEnabled,
                                    [[NotNull]] string Text,
                                    [[NotNull]] string Filename, ...)
```

Record positional parameters are already non-nullable when the type is `string` (not `string?`). The attribute adds no value and can confuse readers. Remove it or switch to a validating constructor:

```csharp
// ✅ Rely on the built-in null-check that records generate
public sealed record Question(bool IsEnabled, string Text, string Filename,
                              QuestionCategory Category = QuestionCategory.Other,
                              Filter? Filter = null);
```
