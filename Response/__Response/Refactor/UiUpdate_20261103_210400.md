# Improving / Replacing the Ragnar UI

## Current State (diagnosis)

From the code I can see the UI is **pure console** with a thin abstraction layer:

| Concern | Current implementation |
|---|---|
| Branding | `BrandingStage` → `IApplicationHeader.RenderBranding()` (ASCII art) |
| Progress | `StageTimingMiddleware` writes via Serilog → console sink |
| Tables | `NumberedRowDecorator` wrapping a `ConsoleTableBuilder` |
| Response output | `IOutputWriter.WriteLine()` / `.MarkupLine("[[red underline]]…[[/]]")` (Spectre-style markup) |
| Prompt display | `prompt.ShowPrompt()` wraps text in markdown fences |

The good news: **`IOutputWriter` already decouples the pipeline from the rendering surface**, so you can swap or layer UIs without touching `RagOrchestrator`, `PipelineRunner`, or the stages.

// StageProgressWriter — new class
public sealed class StageProgressWriter(AnsiConsole console, ILogger log) : IPipelineStage<QuestionPipelineContext>
{
    public string Name => "Progress";
    public bool ShouldRun(QuestionPipelineContext _) => true;

    public Task ExecuteAsync(QuestionPipelineContext ctx, CancellationToken ct)
    {
        var stages = new[[]] { "Branding", "Load", "Parse", "Embed", "Retrieve", "Generate" };
        using var progress = console.CreateProgress(new ProgressColumn[[]]
        {
            new TaskDescriptionColumn(),
            new ProgressBarColumn(),
            new PercentageColumn(),
            new SpinnerColumn(),
            new ElapsedTimeColumn()
        });

        var tasks = stages.Select(s => progress.AddTask(s, maxValue: 100)).ToList();
        // stages update their task via a shared IStageProgress channel
        return Task.CompletedTask;
    }
}

### Key pieces

```csharp
// 1. Expose stage progress as IAsyncEnumerable (reuses StageExecutionContext)
public sealed class PipelineProgressHub
{
    private readonly Channel<StageMetric> _channel = Channel.CreateBounded<StageMetric>(16);

    public async IAsyncEnumerable<StageMetric> WatchAsync(CancellationToken ct)
    {
        await foreach (var m in _channel.Reader.ReadAllAsync(ct))
            yield return m;
    }

    public void Publish(StageMetric m) => _channel.Writer.TryWrite(m);
}

// 2. Blazor component
@inject PipelineProgressHub Hub
@inject IRagOrchestrator Orchestrator

<div class="stages">
@foreach (var s in _stages)
{
    <div class="stage @(s.Success ? "done" : s.Error != null ? "error" : "running")">
        @s.StageName — @s.Duration.TotalSeconds.ToString("F1")s
    </div>
}
</div>

<div class="answer markdown">@_response</div>

@code {
    protected override async Task OnInitializedAsync()
    {
        var ct = CancellationToken.None;
        _ = Task.Run(async () =>
        {
            foreach (var m in Hub.WatchAsync(ct))
                await InvokeAsync(() => { _stages.Add(m); StateHasChanged(); });
        });
        await Orchestrator.ExecuteAsync(_question, _context, ct);
    }
}
```

## Option C — Avalonia / WPF desktop app (highest effort)

Only worth it if Ragnar becomes a product with a non-technical audience.

- Use **Avalonia 11** for cross-platform (Windows / macOS / Linux).
- Bind the same `IRagOrchestrator` and `PipelineRunner<TContext>` — the pipeline is already UI-agnostic.
- Use **Avalonia.MarkdownView** for the answer, **Avalonia.Controls.DataGrid** for history.
- Ship as a single-file `ragnar.exe` / `ragnar` binary.

**Effort:** 3–4 weeks. **Impact:** native feel, offline, no browser needed.

## Concrete refactoring steps (regardless of option)

| # | Change | Why |
|---|--------|-----|
| 1 | Extract an **`IUiService`** (or keep `IOutputWriter`) with methods: `RenderBanner()`, `RenderProgress(StageMetric)`, `RenderAnswer(ResponseRecord)`, `RenderTable(IReadOnlyList<Row>)` | One seam to swap CLI ↔ Web ↔ Desktop |
| 2 | Make `BrandingStage` resolve `IUiService` instead of `IApplicationHeader` | Decouple banner from a single implementation |
| 3 | Publish `StageMetric` via an `IEventBus` / `Channel<T>` so *any* UI can subscribe | No tight coupling between pipeline and display |
| 4 | Add a **`/api`** ASP.NET Core endpoint (even if Blazor isn't ready) | Lets you prototype the web UI in 2 hours |
| 5 | Move `ShowPrompt()` and `NumberedRowDecorator` behind `IUiService.RenderPrompt()` / `RenderTable()` | Remove Spectre markup strings from domain code |
| 6 | Add **Serilog → `IUiService` sink** so log lines flow through the same surface | One place to style everything |
