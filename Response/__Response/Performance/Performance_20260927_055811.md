## 1. **Critical: `OllamaClientFactory` Mutates a Shared `HttpClient`** (Correctness + Performance)

**File:** `OllamaClientFactory.cs`

```csharp
private HttpClient CreateHttpClient(OllamaServiceType type)
{
    var host = NormalizeHost(_config.OllamaOptions.Host);   // ← always OllamaOptions
    var port = ValidatePort(_config.OllamaOptions.Port);    // ← always OllamaOptions
    var client = httpClientFactory.CreateClient(nameof(Ollama)); // ← same name both times
    client.BaseAddress = new Uri($"{host}:{port}");          // ← mutates shared instance
    client.Timeout = type switch { ... };                    // ← mutates shared instance
    return client;
}
```

**Problems:**
- `IHttpClientFactory.CreateClient("Ollama")` returns a **cached/shared** `HttpClient`. Mutating `BaseAddress` and `Timeout` on it affects **all** callers. The second `ResolveClient` call overwrites the first.
- Both LLM and Embedding clients read from `OllamaOptions` (same host/port) instead of each using their own options (`EmbeddingOptions.Host`/`Port` from the config shows they're different: port 11434 vs 6334).
- The test `FindClientHttpClientShouldHaveCorrectBaseAddress` passes only because it resolves a single type, masking the issue.

**Fix:**
```csharp
private HttpClient CreateHttpClient(OllamaServiceType type)
{
    var (host, port, timeout) = type switch
    {
        OllamaServiceType.Ollama => (
            NormalizeHost(_config.OllamaOptions.Host),
            ValidatePort(_config.OllamaOptions.Port),
            _config.OllamaOptions.Timeout),
        OllamaServiceType.Embedding => (
            NormalizeHost(_config.EmbeddingOptions.Host),
            ValidatePort(_config.EmbeddingOptions.Port),
            _config.EmbeddingOptions.Timeout),
        _ => throw new ArgumentOutOfRangeException(nameof(type))
    };

    // Use distinct named clients so the factory tracks them independently
    var clientName = type switch
    {
        OllamaServiceType.Ollama => "OllamaLlm",
        OllamaServiceType.Embedding => "OllamaEmbedding",
        _ => throw new ArgumentOutOfRangeException(nameof(type))
    };

    var client = httpClientFactory.CreateClient(clientName);
    client.BaseAddress = new Uri($"{host}:{port}");
    client.Timeout = timeout;
    return client;
}
```

And register them in DI:
```csharp
builder.Services.AddHttpClient("OllamaLlm")
    .ConfigurePrimaryHttpMessageHandler(() => new SocketsHttpHandler
    {
        PooledConnectionLifetime = TimeSpan.FromMinutes(5)
    });
builder.Services.AddHttpClient("OllamaEmbedding")
    .ConfigurePrimaryHttpMessageHandler(() => new SocketsHttpHandler
    {
        PooledConnectionLifetime = TimeSpan.FromMinutes(5)
    });
```

## 2. **High: Unnecessary Collection Copies in `FileParser`**

**File:** `Ragnar.Embedding/Parsers/FileParser.cs`

```csharp
public override async Task<IEnumerable<CodeDocument>> ParseAsync(...)
{
    var fileContent = await ReadFileAsync(filePath, cancellationToken).ConfigureAwait(false);
    var response = SplitMarkdown(filePath, fileContent.AsMemory(), ...);
    return[[..response]];  // ← allocates a brand-new collection copying every element
}

private static IList<CodeDocument> SplitMarkdown(...)
{
    var lines = TextChunker.SplitMarkdownParagraphs(
        lines: LineSplit(content.ToString()),  // ← extra string allocation
        ...);
    return[[..lines.Select(chunk => new CodeDocument { ... })]];  // ← another copy into List
}

private static List<string> LineSplit(in string content)
{
    var lines = new List<string>();
    lines.AddRange(content.Split(Environment.NewLine));  // ← array → List copy
    return lines;
}
```

**Problems:**
- `content.ToString()` on a `ReadOnlyMemory<char>` that was already backed by a string (from `ReadFileAsync`) creates a **redundant string allocation**.
- `LineSplit` splits into an array, then copies into a `List<string>` — two allocations for what could be one.
- `SplitMarkdown` returns `IList<CodeDocument>` (a `List`), then `ParseAsync` does `[[..response]]` creating **yet another** list.

**Fix:**
```csharp
public override async Task<IEnumerable<CodeDocument>> ParseAsync(
    string filePath, CancellationToken cancellationToken)
{
    var fileContent = await ReadFileAsync(filePath, cancellationToken).ConfigureAwait(false);
    return SplitMarkdown(filePath, fileContent, Convert.ToInt32(EmbeddingOption.Dimension), 50);
}

private static IEnumerable<CodeDocument> SplitMarkdown(
    string filePath, string content, int maxTokens, int overlap)
{
    var lines = content.Split('\n', StringSplitOptions.RemoveEmptyEntries);
    var paragraphs = TextChunker.SplitMarkdownParagraphs(
        lines: lines, maxTokensPerParagraph: maxTokens, overlapTokens: overlap);

    return paragraphs.Select(chunk => new CodeDocument
    {
        FileName = filePath,
        Comment = string.Empty,
        CommentLength = 0,
        ElementType = "Summary",
        ElementName = string.Empty,
        Code = chunk,
    });
}
```

This eliminates two intermediate allocations and returns a deferred LINQ sequence.

## 3. **High: `CodeDocumentExtensions.Dictionary` Allocates on Every Access**

**File:** `Ragnar.Core/models/CodeDocumentExtensions.cs`

```csharp
public IDictionary<string, Value> Dictionary => new Dictionary<string, Value>
{
    { nameof(CodeDocument.FileName), doc.FileName.Replace("//", "/") },
    { nameof(CodeDocument.ElementType), doc.ElementType ?? string.Empty },
    // ... 7 entries
};
```

**Problem:** Every property access allocates a new `Dictionary` + 7 `Value` boxing operations. In `PointStructFactory`, this is called once per document, but in logging/debugging it could be called repeatedly.

**Fix:** Cache the dictionary or make it a method with explicit ownership:

```csharp
extension(CodeDocument doc)
{
    public IDictionary<string, Value> BuildPayload() => new Dictionary<string, Value>(8)
    {
        [[nameof(CodeDocument.FileName)]]    = doc.FileName.Replace('\\', '/'),
        [[nameof(CodeDocument.ElementType)]] = doc.ElementType ?? string.Empty,
        [[nameof(CodeDocument.ElementName)]] = doc.ElementName ?? string.Empty,
        [[nameof(CodeDocument.Comment)]]     = doc.Comment ?? string.Empty,
        [[nameof(CodeDocument.CommentLength)]] = doc.CommentLength,
        [[nameof(CodeDocument.Code)]]        = doc.Code ?? string.Empty,
        [[nameof(CodeDocument.Category)]]    = doc.Category ?? "General",
    };
}
```

> Note: `.Replace("//", "/")` should be `.Replace('\\', '/')` — you're replacing a two-character string with a single character, not normalizing Windows path separators.

## 4. **Medium: Unbounded Memory Growth in `ParsingStage`**

**File:** `Ragnar/Stages/ParsingStage.cs`

```csharp
var documents = new ConcurrentBag<CodeDocument>();
// ... Parallel.ForEachAsync adds all parsed elements
context.Documents = [[..documents]];  // final copy into a List
```

**Problem:** For a large repository with thousands of files and hundreds of thousands of parsed elements, all documents accumulate in memory simultaneously. The final `[[..documents]]` also creates a full copy.

**Fix:** If downstream consumers process documents in batches (e.g., embedding in `BatchSize` groups), consider a streaming/bounded approach:

```csharp
public async Task ExecuteAsync(EmbeddingContext context, CancellationToken cancellationToken)
{
    var files = context.DiscoveredFiles;
    if (files.Count == 0) return;

    var maxParallelism = Math.Min(Environment.ProcessorCount, 8);
    var batch = new List<CodeDocument>(4096);

    await AnsiConsole.Progress().AutoClear(true).StartAsync(async ctx =>
    {
        var task = ctx.AddTask(Name, maxValue: files.Count);

        await Parallel.ForEachAsync(files,
            new ParallelOptions
            {
                CancellationToken = cancellationToken,
                MaxDegreeOfParallelism = maxParallelism
            },
            async (filePath, token) =>
            {
                var elements = await parseFactory.ParseAsync(filePath, token).ConfigureAwait(false);
                lock (batch)
                {
                    batch.AddRange(elements);
                    if (batch.Count >= 100_000)
                        await FlushBatchAsync(batch, context, token);
                }
                task.Increment(1);
            }).ConfigureAwait(false);

        lock (batch)
            await FlushBatchAsync(batch, context, cancellationToken);
    }).ConfigureAwait(false);
}
```

If the full collection is truly needed, at minimum avoid the double-copy by using a pre-allocated `List<CodeDocument>` with `Lock` instead of `ConcurrentBag` (avoids the internal per-producer segment overhead when parallelism is capped at 8).

## 5. **Medium: `ConsoleTableBuilder.AddColumns` — O(n²) Duplicate Detection**

**File:** `Ragnar.Core/Rendering/ConsoleTableBuilder.cs`

```csharp
public ConsoleTableBuilder AddColumns(params string[[]] columns)
{
    foreach (var col in columns)
    {
        if (Columns.Contains(col, StringComparer.OrdinalIgnoreCase))  // O(n) scan
            throw new ArgumentException(...);
    }
    Columns.AddRange(columns);
    return this;
}
```

**Fix:** Use a `HashSet<string>(StringComparer.OrdinalIgnoreCase)` for O(1) lookups:

```csharp
private readonly HashSet<string> _columnSet = new(StringComparer.OrdinalIgnoreCase);

public ConsoleTableBuilder AddColumns(params string[[]] columns)
{
    if (Columns.Count > 0)
        throw new InvalidOperationException("Columns already defined.");

    foreach (var col in columns)
    {
        if (!_columnSet.Add(col))
            throw new ArgumentException($"Duplicate column '{col}'.", nameof(columns));
    }
    Columns.AddRange(columns);
    return this;
}
```

## 6. **Medium: `QuestionExtensions` Properties Allocate on Every Access**

**File:** `Ragnar.Core/models/QuestionExtensions.cs`

```csharp
public IReadOnlyList<Question> ActiveOnly   => [[..questions.Where(q => q.IsEnabled)]];
```

Each access to `.ActiveOnly` or `.InActiveOnly` re-iterates the list and allocates a new collection. If called in a loop or multiple times, this multiplies allocations.

**Fix:** If the list is small (< a few hundred questions), this is acceptable. If it's used repeatedly, cache or compute once:

```csharp
// At the call site, compute once:
var active = questions.Where(q => q.IsEnabled).ToArray();
```

## 7. **Low: `StringExtensions.CharacterCount` — Per-Character Branching**

**File:** `Ragnar.Core/Text/StringExtensions.cs`

The character-by-character loop with a boolean state machine is O(n) but has poor branch prediction on mixed content. For large XML comments (thousands of characters), a `Regex`-based or `Span`-based approach may be faster:

```csharp
public int CharacterCount()
{
    // Remove XML tags and count remaining non-whitespace
    var stripped = Regex.Replace(xmlComment, @"<[[^>]]*>", "");
    return stripped.Count(c => !char.IsWhiteSpace(c));
}
```

> This is a micro-optimization; only relevant if called on thousands of documents in a hot loop.

## 8. **Low: Sequential Question Processing in `QuestionExecutionStage`**

**File:** `Ragnar/Stages/Questions/QuestionExecutionStage.cs`

```csharp
foreach (var question in questions)
{
    await ragOrchestrator.ExecuteAsync(question, contextText, cancellationToken).ConfigureAwait(false);
}
```

Questions are processed strictly sequentially. If they're independent (no shared mutable state), parallelizing with a throttle would reduce wall-clock time:

```csharp
var semaphore = new SemaphoreSlim(3); // limit concurrency to protect LLM
await Task.WhenAll(questions.Select(async q =>
{
    await semaphore.WaitAsync(cancellationToken);
    try
    {
        writer.MarkupLine($"Question: {Markup.Escape(q.Text)}");
        await ragOrchestrator.ExecuteAsync(q, contextText, cancellationToken).ConfigureAwait(false);
    }
    finally
    {
        semaphore.Release();
        Interlocked.Increment(ref processedCount);
    }
}));
```

> Only safe if `ragOrchestrator` and `writer` are thread-safe or if output ordering doesn't matter.

## 10. **Low: `appsettings.json` — `CategoriesToProcess` is Empty**

```json

```

Combined with the validator:
```csharp

    .WithMessage("CategoriesToProcess must contain at least one category.");
```

This will **fail validation at startup**. While not a performance issue, it means the app either crashes or skips validation, potentially causing runtime surprises. Populate it with at least one category or relax the validator to allow "process all."
