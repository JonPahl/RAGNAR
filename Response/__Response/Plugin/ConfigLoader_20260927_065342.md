# Extending Question Loading: Embedded Resources & Remote Configuration

Yes — the existing `IQuestionSource` strategy pattern already provides a natural seam for this. The main impedance mismatch is the `fileName` parameter, which presumes a file-system path. Below is a concrete breakdown of how to extend the pipeline for both scenarios, along with the design trade-offs.

---

## 1. What You Have Today (Extension Surface)

```
IQuestionSource
  ├── ProviderName : string
  └── LoadQuestionsAsync(string fileName, CancellationToken) → Task<IEnumerable<Question>>

CsvQuestionSource  (implements IQuestionSource)
  └── depends on IRecordParser<QuestionRecord>  (CsvHelper-based)
```

The pipeline stage (`QuestionExecutionStage`) consumes the already-materialised `context.Questions` list, so it is **source-agnostic**. Any new source just needs to satisfy `IQuestionSource` and be registered in DI.

---

## 2. Embedded Resource Source

The `fileName` parameter can be reinterpreted as a **manifest resource name** (e.g. `"Ragnar.Questions.Defaults.csv"`).

### New class

```csharp
using System.Reflection;
using Ragnar.Abstractions;
using Ragnar.Core.Models;
using Ragnar.Questions.Questions;

namespace Ragnar.Questions.Sources;

/// <summary>Loads questions from assembly-embedded CSV resources.</summary>
/// <param name="parser">CSV record parser for deserialising embedded content.</param>
/// <example><![[CDATA[[var src = new EmbeddedResourceQuestionSource(parser); ]]]]></example>
public sealed class EmbeddedResourceQuestionSource(IRecordParser<QuestionRecord> parser)
    : IQuestionSource
{
    public string ProviderName => "Embedded Resource";

    /// <summary>
    /// Reads an embedded CSV resource and maps it to Question objects.
    /// </summary>
    /// <param name="resourceName">
    /// Fully-qualified manifest resource name, e.g.
    /// <c>"Ragnar.Questions.Defaults.csv"</c>.
    /// </param>
    /// <param name="cancellationToken">Cancellation token.</param>
    /// <returns>Deserialised questions.</returns>
    public async Task<IEnumerable<Question>> LoadQuestionsAsync(
        string resourceName,
        CancellationToken cancellationToken)
    {
        Guard.Against.NullOrEmpty(resourceName);

        var assembly = Assembly.GetExecutingAssembly();
        using var stream = assembly.GetManifestResourceStream(resourceName)
            ?? throw new FileNotFoundException($"Embedded resource '{resourceName}' not found.", resourceName);

        // Reuse the existing CSV pipeline by wrapping the stream.
        using var reader = new StreamReader(stream);
        var config = new CsvConfiguration(CultureInfo.InvariantCulture)
        {
            HasHeaderRecord = true,
            TrimOptions = TrimOptions.Trim,
        };
        using var csv = new CsvReader(reader, config);
        csv.Context.RegisterClassMap<QuestionMap>();

        var records = await csv.GetRecordsAsync<QuestionRecord>(cancellationToken)
            .ToListAsync(cancellationToken)
            .ConfigureAwait(false);

        return records.Select(r => new Question(
            IsEnabled:  r.IsEnabled,
            Text:       r.Text,
            Filename:   r.FileName,
            Category:   r.Category));
    }
}
```

### Project-file inclusion (`.csproj`)

```xml
<ItemGroup>
  <EmbeddedResource Include="Questions\Defaults.csv" />
</ItemGroup>
```

### DI registration

```csharp
builder.Services.AddSingleton<IQuestionSource, EmbeddedResourceQuestionSource>();
```

> **Tip:** If you want to avoid duplicating the CsvHelper boilerplate, extract the parsing loop into a small `IQuestionCsvReader` (or generic `StreamCsvParser`) shared by both `CsvRecordParser` and `EmbeddedResourceQuestionSource`.

## 3. Azure App Configuration Source

Here the `fileName` parameter naturally becomes a **key prefix** (Azure App Configuration groups keys by prefix, e.g. `Ragnar/Questions/`).

### New class (skeleton)

```csharp
using Azure;
using Azure.AppConfiguration;
using Ragnar.Abstractions;
using Ragnar.Core.Models;
using System.Text.Json;

namespace Ragnar.Questions.Sources;

/// <summary>Loads questions from Azure App Configuration key-value pairs.</summary>
/// <remarks>
/// Expected schema – each key under <paramref name="keyPrefix"/> holds a JSON payload:
/// <code>{"IsEnabled":true,"Text":"…","Filename":"…","Category":"XML"}</code>
/// </remarks>
public sealed class AppConfigurationQuestionSource(
    ConfigurationClient client,          // injected
    ILogger<AppConfigurationQuestionSource> logger)
    : IQuestionSource
{
    public string ProviderName => "Azure App Configuration";

    /// <summary>
    /// Retrieves all question records whose key starts with <paramref name="keyPrefix"/>.
    /// </summary>
    /// <param name="keyPrefix">
    /// Configuration key prefix, e.g. <c>"Ragnar/Questions/"</c>.
    /// Acts as the "file name" equivalent.
    /// </param>
    /// <param name="cancellationToken">Cancellation token.</param>
    /// <returns>Parsed Question objects.</returns>
    public async Task<IEnumerable<Question>> LoadQuestionsAsync(
        string keyPrefix,
        CancellationToken cancellationToken)
    {
        Guard.Against.NullOrEmpty(keyPrefix);
        if (!keyPrefix.EndsWith('/'))
            keyPrefix += '/';

        var questions = new List<Question>();

        // Paginated enumeration of matching keys
        await foreach (var kv in client
            .GetConfigurationSettingValuesAsync(
                keyFilter: new KeyFilter(keyPrefix),
                cancellationToken: cancellationToken)
            .AsAsyncEnumerable(cancellationToken))
        {
            try
            {
                var dto = JsonSerializer.Deserialize<QuestionDto>(kv.Value,
                    AppJsonContext.Default.QuestionDto);
                if (dto is null) continue;

                questions.Add(new Question(
                    IsEnabled:  dto.IsEnabled,
                    Text:       dto.Text,
                    Filename:   dto.Filename,
                    Category:   Enum.Parse<QuestionCategory>(dto.Category, ignoreCase: true)));
            }
            catch (JsonException ex)
            {
                logger.LogWarning(ex, "Skipping malformed config key '{Key}'", kv.Key);
            }
        }

        return questions;
    }
}

// ── DTO + source-gen context ──────────────────────────────────────────────
internal sealed record QuestionDto(
    bool   IsEnabled,
    string Text,
    string Filename,
    string Category);

[[JsonSourceGenerationOptions(PropertyNameCaseInsensitive = true)]]
[[JsonSerializable(typeof(QuestionDto))]]
internal partial class AppJsonContext : JsonSerializerContext;
```

## 4. Making the Pipeline Source-Agnostic

Today the caller passes a hard-coded file name. To support **multiple sources simultaneously** (or to let the user pick one), introduce a small resolver:

```csharp
public interface IQuestionSourceResolver
{
    /// <summary>Resolves the active IQuestionSource based on application config.</summary>
    IQuestionSource Resolve();
}

public sealed class QuestionSourceResolver(
    IEnumerable<IQuestionSource> sources,
    IOptions<RagnarConfig> config) : IQuestionSourceResolver
{
    public IQuestionSource Resolve()
    {
        var preferred = config.Value.ApplicationOptions.QuestionSource
                        ?? "Csv";   // default

        return sources.FirstOrDefault(s =>
               string.Equals(s.ProviderName, preferred, StringComparison.OrdinalIgnoreCase))
            ?? throw new InvalidOperationException(
                $"No IQuestionSource registered with name '{preferred}'. " +
                $"Available: {string.Join(", ", sources.Select(s => s.ProviderName))}");
    }
}
```

Add to `ApplicationOptions`:

```csharp
/// <summary>Preferred question source name (e.g. "CSV File", "Embedded Resource", "Azure App Configuration").</summary>
public string? QuestionSource { get; init; }
```

And in `appsettings.json`:

```json
"ApplicationOptions": {
  "QuestionSource": "CSV File"
}
```

## 5. Design Trade-offs & Recommendations

| Concern | Guidance |
|---|---|
| **`fileName` parameter** | The name is misleading for remote sources. If you control the interface, consider renaming to `sourceKey` / `identifier` in the next major version. For now, document the semantic in XML-docs. |
| **Caching** | Embedded resources are immutable per-assembly – cache the parsed `List<Question>` keyed by resource name. Azure App Configuration supports ETag-based conditional GETs; wrap the client in a `Microsoft.Extensions.Caching`-friendly decorator. |
| **Validation** | Reuse `FluentValidation` (`QuestionValidator` on the `Question` record) after parsing, regardless of source. The existing `ApplicationOptionsValidator` pattern is a good template. |
| **Filtering** | `QuestionExtensions.WithCategory` / `ActiveOnly` already operate on `IReadOnlyList<Question>`, so they work identically no matter where the data came from. |
| **Testing** | `AppConfigurationQuestionSource` is trivially testable: `ConfigurationClient` can be replaced with an in-memory `ConfigurationClient` mock, or you can introduce an `IConfigurationKeyValueReader` abstraction. |
| **Secrets / model names** | Keep LLM model names and endpoints in `appsettings.json` / user-secrets (as they already are). Only the *question definitions* move to the remote store; the Ollama connection string stays local. |

---

## 6. TL;DR

The `IQuestionSource` → `IRecordParser<T>` → `Question` chain is a clean strategy pattern. Adding an embedded-resource source is a ~50-line class plus one `<EmbeddedResource>` project item. Adding an Azure App Configuration source is a ~80-line class plus one NuGet package. Neither requires touching `QuestionExecutionStage`, `Question`, or the RAG orchestrator—only DI registration and (optionally) a new `IQuestionSourceResolver` for runtime selection.
