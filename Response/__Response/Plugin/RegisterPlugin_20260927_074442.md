# Registering a Custom `IQuestionSource` Plugin

The existing architecture already exposes the `IQuestionSource` abstraction (implemented today only by `CsvQuestionSource`). The natural extension point is to add another implementation that returns **static, hard-coded** domain questions, then register it alongside the CSV source in the DI container.

## 1. Create the Built-In Question Source

```csharp
// Ragnar.Questions/Questions/BuiltInQuestionSource.cs
namespace Ragnar.Questions.Questions;

/// <summary>
/// Provides hard-coded, domain-specific questions that ship with the application.
/// These questions do not require an external CSV file.
/// </summary>
/// <remarks>
/// Register this as an additional <see cref="IQuestionSource"/> so the pipeline
/// merges its questions with those loaded from CSV.
/// </remarks>
/// <example>
/// <code>
/// var provider = new BuiltInQuestionSource();
/// var qs = await provider.LoadQuestionsAsync(fileName: string.Empty, ct);
/// </code>
/// </example>
public sealed class BuiltInQuestionSource : IQuestionSource
{
    /// <inheritdoc />
    public string ProviderName => "Built-In";

    /// <inheritdoc />
    /// <remarks>
    /// The <paramref name="fileName"/> parameter is intentionally ignored because
    /// these questions are static.  The signature is kept for interface compatibility.
    /// </remarks>
    public Task<IEnumerable<Question>> LoadQuestionsAsync(
        string fileName,
        CancellationToken cancellationToken)
    {
        var questions = new[[]]
        {
            Question.IsActive(
                text:     "Are we using Microsoft.Extensions.Hosting correctly?",
                key:      "hosting-verify",
                category: QuestionCategory.Hosting),          // ← new enum value

            Question.IsActive(
                text:     "Do all pipeline stages implement IDisposable or use async streams properly?",
                key:      "resource-leaks",
                category: QuestionCategory.Hosting),

            Question.IsActive(
                text:     "Are cancellation tokens propagated end-to-end through the RAG pipeline?",
                key:      "cancellation-flow",
                category: QuestionCategory.Hosting),

            // A question that is intentionally disabled by default
            Question.IsDisabled(
                text:     "Is the vector store index strategy optimal for the current corpus size?",
                key:      "index-strategy",
                category: QuestionCategory.Performance),
        };

        return Task.FromResult<IEnumerable<Question>>(questions);
    }
}
```

> **Note on `QuestionCategory`** – if `Hosting` / `Performance` don't already exist, add them to the enum:
>
> ```csharp
> public enum QuestionCategory
> {
>     XML,
>     Hosting,        // ← new
>     Performance,    // ← new
>     Other,
>     Uncategorized
> }
> ```

## 2. Register Both Sources in the DI Container

The pipeline resolves questions by injecting **all** `IQuestionSource` instances (open-generic / multi-registration pattern). Update your service-collection setup:

```csharp
// Program.cs  (or a dedicated DependencyInjection extension)
using Ragnar.Questions.Questions;

// ── Existing CSV-based source ──────────────────────────────────
builder.Services.AddSingleton<IQuestionSource, CsvQuestionSource>();

// ── NEW: built-in domain questions ─────────────────────────────
builder.Services.AddSingleton<IQuestionSource, BuiltInQuestionSource>();
```

Because both are registered as **separate singletons of the same open interface**, any consumer that injects `IEnumerable<IQuestionSource>` will receive *both* instances automatically.

## 3. Merge All Sources in the Pipeline

The existing `QuestionExecutionStage` (or an earlier "load" stage) should resolve every registered source and concatenate the results. If you haven't done that yet, here's a small orchestrator that does it:

```csharp
// Ragnar.Questions/QuestionAggregator.cs
namespace Ragnar.Questions;

/// <summary>
/// Aggregates questions from every registered <see cref="IQuestionSource"/>.
/// </summary>
/// <param name="sources">All registered question sources (CSV + built-in + …).</param>
/// <param name="logger">Serilog logger.</param>
public sealed class QuestionAggregator(IEnumerable<IQuestionSource> sources, ILogger logger)
{
    /// <summary>
    /// Loads and merges questions from every source, de-duplicating by key.
    /// </summary>
    /// <param name="csvFilePath">Path to the optional CSV file (passed to CSV source).</param>
    /// <param name="categories">Optional category filter; <c>null</c> means "all".</param>
    /// <param name="cancellationToken">Cancellation token.</param>
    /// <returns>A merged, deduplicated list of enabled questions.</returns>
    public async Task<IReadOnlyList<Question>> LoadAllAsync(
        string csvFilePath,
        HashSet<QuestionCategory>? categories,
        CancellationToken cancellationToken)
    {
        var all = new List<Question>();

        foreach (var source in sources)
        {
            try
            {
                // BuiltInQuestionSource ignores the file name;
                // CsvQuestionSource uses it.
                var fromSource = await source
                    .LoadQuestionsAsync(csvFilePath, cancellationToken)
                    .ConfigureAwait(false);

                all.AddRange(fromSource);
                logger.Information("Loaded {Count} question(s) from [[{Source}]].",
                    fromSource.Count(), source.ProviderName);
            }
            catch (Exception ex)
            {
                logger.Warning(ex,
                    "Source [[{Source}]] failed to load questions; skipping.",
                    source.ProviderName);
            }
        }

        // De-duplicate by Filename (the "key"), keep first occurrence.
        var unique = all
            .Where(q => q.IsEnabled)
            .GroupBy(q => q.Filename, StringComparer.OrdinalIgnoreCase)
            .Select(g => g.First())
            .ToList();

        // Apply optional category filter.
        return categories is null
            ? unique.AsReadOnly()
            : unique.WithCategory(categories).ActiveOnly;
    }
}
```

Register it:

```csharp
builder.Services.AddSingleton<QuestionAggregator>();
```

## 4. Consume the Aggregated Questions in the Stage

`QuestionExecutionStage` currently reads `context.Questions`. Upstream of it, a **Load Questions** stage (or the composition root) would look like this:

```csharp
// In the pipeline composition root or a preceding stage
var questions = await questionAggregator.LoadAllAsync(
    csvFilePath: "questions.csv",          // path from config / CLI arg
    categories:  config.Value.ApplicationOptions.CategoriesToProcess
                 .Select(c => (QuestionCategory)Enum.Parse<QuestionCategory>(c))
                 .ToHashSet(),
    cancellationToken);

context.Questions = questions;            // QuestionPipelineContext.Questions
```

From that point on, `QuestionExecutionStage.ExecuteAsync` iterates `context.Questions` exactly as it already does, running each one through the RAG orchestrator.

## 5. (Optional) Configuration-Driven Toggle

If you want the built-in questions to be switchable via `appsettings.json` without a code change, add a small flag:

```jsonc
// appsettings.Ragnar.json
{
  "RagnarConfig": {
    "ApplicationOptions": {
      "SourceDirectory": "%USERPROFILE%\\source\\Ragnar\\",
      "VectorStoreName": "Ragnar",
      "EnableBuiltInQuestions": true      // ← new
    }
  }
}
```

Then guard inside `BuiltInQuestionSource.LoadQuestionsAsync`:

```csharp
public sealed class BuiltInQuestionSource(IOptions<RagnarConfig> config) : IQuestionSource
{
    public string ProviderName => "Built-In";

    public Task<IEnumerable<Question>> LoadQuestionsAsync(
        string fileName, CancellationToken cancellationToken)
    {
        if (!config.Value.ApplicationOptions.EnableBuiltInQuestions)
            return Task.FromResult<IEnumerable<Question>>([[]]);

        // … same list as before …
    }
}
```

## How It All Fits Together

```
┌─────────────────────────────────────────────────────────────────┐
│                        DI Container                              │
│                                                                 │
│   IQuestionSource  ──►  CsvQuestionSource                       │
│                 ──►  BuiltInQuestionSource   ←  NEW             │
│                                                                 │
│   QuestionAggregator (IEnumerable<IQuestionSource>)             │
└──────────────────────────────┬──────────────────────────────────┘
                               │  LoadAllAsync()
                               ▼
                   ┌───────────────────────┐
                   │ QuestionPipelineContext│
                   │   .Questions          │
                   └───────────┬───────────┘
                               │
                               ▼
                  ┌────────────────────────┐
                  │ QuestionExecutionStage │
                  │  foreach question:     │
                  │   RAG → format → write │
                  └────────────────────────┘
```

**Key points**

| Concern | How it's handled |
|---|---|
| **No new interface needed** | `BuiltInQuestionSource` implements the existing `IQuestionSource`. |
| **Multi-registration** | Both sources are registered as `IQuestionSource`; the aggregator injects `IEnumerable<IQuestionSource>`. |
| **De-duplication** | Aggregator groups by `Filename` (the stable key) and keeps the first match. |
| **Filtering** | Re-uses the existing `QuestionExtensions.WithCategory` / `ActiveOnly` extensions. |
| **Zero changes to the execution stage** | `QuestionExecutionStage` only reads `context.Questions` – it doesn't care *where* the questions came from. |
| **Config toggle** | Optional `EnableBuiltInQuestions` flag in `ApplicationOptions`. |

This keeps the plugin surface area minimal (one new class + one DI line) while remaining fully testable: you can unit-test `BuiltInQuestionSource` in isolation, or swap it for another implementation (e.g., one that reads questions from a database) by simply adding another `AddSingleton<IQuestionSource, …>` call.
