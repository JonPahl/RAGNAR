## 1. TimeoutMiddleware (per-stage hard deadline)

Your Polly policies handle *retry*, but nothing enforces a **wall-clock ceiling per stage**. A hanging Ollama call or a stuck Qdrant upsert will block the whole pipeline indefinitely.

```csharp
public sealed class TimeoutMiddleware(ILogger logger, TimeSpan defaultTimeout = TimeSpan.FromMinutes(5))
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken cancellationToken) where TContext : class
    {
        using var cts = CancellationTokenSource.CreateLinkedTokenSource(cancellationToken);
        cts.CancelAfter(defaultTimeout);

        try
        {
            await next().ConfigureAwait(false);
        }
        catch (OperationCanceledException) when (!cancellationToken.IsCancellationRequested)
        {
            logger.Warning("Stage {Name} exceeded {Timeout} and was cancelled.",
                context.Stage.Name, defaultTimeout);
            throw new TimeoutException(
                $"Stage '{context.Stage.Name}' timed out after {defaultTimeout}.",
                new OperationCanceledException("TimeoutMiddleware", cts.Token))
            {
                HResult = -2146233044
            };
        }
    }
}
```

## 2. PreconditionMiddleware (context invariant guard)

Prevents a stage from running when its **upstream dependency is missing** (e.g., `LLMStage` firing before `Questions` are loaded). Cheaper than letting the stage throw a cryptic NRE.

```csharp
public sealed class PreconditionMiddleware(ILogger logger)
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken cancellationToken) where TContext : class
    {
        if (context is QuestionPipelineContext qpc
            && string.Equals(context.Stage.Name, "LLM Stage", StringComparison.OrdinalIgnoreCase)
            && qpc.Questions is null)
        {
            throw new PipelineStageException(context.Stage.Name,
                new InvalidOperationException("Questions have not been loaded. Run QuestionLoadStage first."));
        }

        await next().ConfigureAwait(false);
    }
}
```

Generalise it with a `Func<TContext, bool>` predicate if you want it composable:

```csharp
public sealed record PreconditionRule<TContext>(string StageName, Func<TContext, bool> IsSatisfied, string FailureMessage)
    where TContext : class;

public sealed class PreconditionMiddleware<TContext>(ILogger logger, params PreconditionRule<TContext>[[]] rules)
    where TContext : class
{
    public async Task Invoke(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken ct)
    {
        foreach (var rule in rules.Where(r => r.StageName == context.Stage.Name))
        {
            if (!rule.IsSatisfied(context.Context))
                throw new PipelineStageException(context.Stage.Name,
                    new PreconditionException(rule.FailureMessage));
        }

        await next().ConfigureAwait(false);
    }
}
```

## 3. CircuitBreakerMiddleware (pipeline-level abort)

Polly's `CircuitBreakerPolicy` is per-stage. What's missing is a **pipeline-level** breaker: if *N out of the last M* stages fail, short-circuit the remaining stages so you don't burn API credits on a broken embedding model.

```csharp
public sealed class CircuitBreakerMiddleware(
    ILogger logger,
    int failureThreshold = 3,
    TimeSpan resetInterval = TimeSpan.FromMinutes(1))
{
    private int _consecutiveFailures;
    private DateTime _lastFailureUtc;
    private readonly object _lock = new();

    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        EnsureNotOpen();

        try
        {
            await next().ConfigureAwait(false);
            lock (_lock) _consecutiveFailures = 0;
        }
        catch (PipelineStageException)
        {
            lock (_lock)
            {
                _consecutiveFailures++;
                _lastFailureUtc = DateTime.UtcNow;
                if (_consecutiveFailures >= failureThreshold)
                    logger.Error("Circuit OPEN after {N} consecutive stage failures.", _consecutiveFailures);
            }
            throw;
        }
    }

    private void EnsureNotOpen()
    {
        lock (_lock)
        {
            if (_consecutiveFailures < failureThreshold) return;
            if (DateTime.UtcNow - _lastFailureUtc >= resetInterval)
            {
                _consecutiveFailures = 0; // half-open
                return;
            }

            throw new PipelineStageException("<pipeline>",
                new CircuitBreakerOpenException($"Pipeline aborted: {failureThreshold} consecutive failures."));
        }
    }
}
```

## 4. SingleFlightMiddleware (concurrency guard)

Prevents two `dotnet ragnar embed` invocations from racing on the same Qdrant collection.

```csharp
public sealed class SingleFlightMiddleware(ILogger logger)
{
    private static readonly SemaphoreSlim _gate = new(1, 1);

    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        if (!await _gate.WaitAsync(0, ct).ConfigureAwait(false))
        {
            logger.Warning("Another pipeline run is in progress; skipping stage {Name}.", context.Stage.Name);
            return;
        }

        try { await next().ConfigureAwait(false); }
        finally { _gate.Release(); }
    }
}
```

> For a true app-wide guard, inject a `SemaphoreSlim` via DI instead of `static`.

## 5. Idempotency / ResumeMiddleware (skip already-completed stages)

If the pipeline crashes mid-run, you don't want to re-embed 50 000 vectors on the next start. Track stage completion in a small JSON sidecar.

```csharp
public sealed class ResumeMiddleware(
    ILogger logger,
    string stateFile = Path.Combine(AppContext.BaseDirectory, ".ragnar-state.json"))
{
    private readonly Dictionary<string, DateTime> _completed
        = System.Text.Json.JsonSerializer.Deserialize<Dictionary<string, DateTime>>(
            File.Exists(stateFile) ? File.ReadAllText(stateFile) : "{}") ?? new();

    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        if (_completed.TryGetValue(context.Stage.Name, out var ts))
        {
            logger.Information("Stage {Name} already completed at {Ts:u}; skipping.", context.Stage.Name, ts);
            return;
        }

        await next().ConfigureAwait(false);

        lock (_completed)
        {
            _completed[[context.Stage.Name]] = DateTime.UtcNow;
            File.WriteAllText(stateFile,
                System.Text.Json.JsonSerializer.Serialize(_completed));
        }
    }

    /// <summary>Call at the start of a new run to wipe stale checkpoints.</summary>
    public void Reset() => File.Delete(stateFile);
}
```

## 6. StructuredLoggingMiddleware (before/after context snapshot)

`ProgressMiddleware` prints a one-liner; `StageTimingMiddleware` captures a `StageMetric`. A **structured logging** middleware that serialises the context *before* and *after* each stage gives you a free audit trail (great for debugging "why did this question get this answer?").

```csharp
public sealed class StructuredLoggingMiddleware(ILogger logger)
{
    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> context,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        logger.Debug("→ [[{Idx}/{Total}]] {Name} BEGIN", context.StageIndex, context.StageTotal, context.Stage.Name);

        await next().ConfigureAwait(false);

        logger.Debug("← [[{Idx}/{Total}]] {Name} END", context.StageIndex, context.StageTotal, context.Stage.Name);
    }
}
```

Pair it with Serilog's `ForContext` / `Enrich` to tag the `StageName` property so your log sink can group by stage.

## Recommended middleware onion order

```csharp
runner
    .UseTiming(stageTiming)            // outermost – captures total wall-clock
    .UseMiddleware((c, n, ct) => timeoutMw.Invoke(c, n, ct))
    .UseMiddleware((c, n, ct) => circuitMw.Invoke(c, n, ct))
    .UseMiddleware((c, n, ct) => preconditionMw.Invoke(c, n, ct))
    .UseMiddleware((c, n, ct) => resumeMw.Invoke(c, n, ct))
    .UseMiddleware((c, n, ct) => singleFlightMw.Invoke(c, n, ct))
    .UseMiddleware((c, n, ct) => logMw.Invoke(c, n, ct))
    .UseMiddleware((c, n, ct) => progressMw.Invoke(c, n, ct))  // innermost – user-facing
```

Each middleware wraps the next, so the outermost sees the **full** elapsed time (including all inner retries) and the innermost runs closest to the actual stage logic.
