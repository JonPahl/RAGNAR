### Rationale for the groupings

| Namespace | Why it's its own folder |
|-----------|------------------------|
| **Core/Pipeline** | The runner, middleware, stage-entry, and context form a single cohesion unit. Stages live under a sub-folder so adding `QuestionLoadStage`, `ParseStage`, etc. is obvious. |
| **RAG** | Everything that talks to Ollama for *generation* (not embedding). Keeps the "ask the LLM" concern isolated. |
| **Embedding** | Everything that produces/consumes vectors – options, strategies, filter builder, point factory. |
| **Files** | The file-IO pipeline (discover → validate → parse). All interfaces + implementations co-locate. |
| **Questions** | Question-specific filtering, category enums, CSV converters. |
| **Validation** | Every `FluentValidation` class in one place; easy to find and extend. |
| **Infrastructure** | Extensions, rendering decorators, DI wiring – things that don't belong to a single domain. |

## 2. PowerShell Reorganisation Script

Save as `reorganise.ps1` in the project root (next to `Ragnar.csproj`).

```powershell
#!/usr/bin/env pwsh
<#
.SYNOPSIS
    Reorganises Ragnar source files into a layered folder structure
    and rewrites `namespace` / `using` directives accordingly.

.DESCRIPTION
    Run from the SOLUTION root (the folder that contains Ragnar.csproj).
    Creates the target tree, moves each file, and patches the C# namespace.
    All changes are dry-run printed first; add -Force to apply.

.EXAMPLE
    pwsh ./reorganise.ps1          # dry-run (prints planned moves)
    pwsh ./reorganise.ps1 -Force   # actually moves files & rewrites namespaces
#>

[[CmdletBinding()]]
param(
    [[switch]]$Force
)

$ErrorActionPreference = 'Stop'
$root = $PSScriptRoot
$src  = Join-Path $root 'Src\Ragnar'   # adjust if your .cs files live elsewhere

if (-not (Test-Path $src)) {
    # Fall back to looking for .cs files anywhere under root
    $csFiles = Get-ChildItem -Path $root -Filter '*.cs' -Recurse |
               Where-Object { $_.FullName -notmatch '\\(obj|bin|Properties)\\' }
    $src = $csFiles | Select-Object -First 1 -ExpandProperty DirectoryName
    Write-Warning "Src\Ragnar not found; using $src as source root."
}

# ─── 1. Map every known file → target relative path ──────────────────────────
$map = [[ordered]]@{
    # Core / Pipeline
    'PipelineRunner.cs'           = 'Core\Pipeline\PipelineRunner.cs'
    'PipelineMiddleware.cs'       = 'Core\Pipeline\PipelineMiddleware.cs'
    'StageTimingMiddleware.cs'    = 'Core\Pipeline\StageTimingMiddleware.cs'
    'StageEntry.cs'               = 'Core\Pipeline\StageEntry.cs'
    'StageMetric.cs'              = 'Core\Pipeline\StageMetric.cs'
    'QuestionPipelineContext.cs'  = 'Core\Pipeline\QuestionPipelineContext.cs'
    'BrandingStage.cs'            = 'Core\Pipeline\Stages\BrandingStage.cs'

    # Core / Models
    'CollectionInfo.cs'           = 'Core\Models\CollectionInfo.cs'

    # RAG
    'RagOrchestrator.cs'          = 'RAG\RagOrchestrator.cs'
    'GenerationOptions.cs'        = 'RAG\GenerationOptions.cs'
    'IOllamaClientFactory.cs'     = 'RAG\IOllamaClientFactory.cs'
    'OllamaChatClientBuilder.cs'  = 'RAG\OllamaChatClientBuilder.cs'

    # Embedding
    'EmbeddingOptions.cs'         = 'Embedding\EmbeddingOptions.cs'
    'QdrantFilterBuilder.cs'      = 'Embedding\QdrantFilterBuilder.cs'
    'QuestionFilterSelector.cs'   = 'Embedding\QuestionFilterSelector.cs'
    'XmlCommentFilterStrategy.cs' = 'Embedding\Strategies\XmlCommentFilterStrategy.cs'

    # Files
    'FileLoadOptions.cs'             = 'Files\FileLoadOptions.cs'
    'IFileEligibilityValidator.cs'   = 'Files\IFileEligibilityValidator.cs'
    'IFileDiscoveryService.cs'       = 'Files\IFileDiscoveryService.cs'
    'FileDiscoveryService.cs'        = 'Files\FileDiscoveryService.cs'
    'IFileParser.cs'                 = 'Files\IFileParser.cs'
    'CodeParserFactory.cs'           = 'Files\CodeParserFactory.cs'
    'FileSystemEntryExtensions.cs'   = 'Files\Extensions\FileSystemEntryExtensions.cs'

    # Questions
    'QuestionsExtensions.cs'  = 'Questions\QuestionsExtensions.cs'
    'EnumConverter.cs'        = 'Questions\Converters\EnumConverter.cs'

    # Validation
    'RagnarConfigValidator.cs'     = 'Validation\RagnarConfigValidator.cs'
    'FileLoadOptionsValidator.cs'  = 'Validation\FileLoadOptionsValidator.cs'

    # Infrastructure / Extensions
    'AssemblyExtensions.cs'   = 'Infrastructure\Extensions\AssemblyExtensions.cs'
    'GeneratorExtensions.cs'  = 'Infrastructure\Extensions\GeneratorExtensions.cs'
    'OutputPathHelper.cs'     = 'Infrastructure\Extensions\OutputPathHelper.cs'
    'NumberedRowDecorator.cs' = 'Infrastructure\Rendering\NumberedRowDecorator.cs'

    # DI (consolidated – both EmbeddingSetupExtension copies)
    'EmbeddingSetupExtension.cs' = 'Infrastructure\DI\EmbeddingSetupExtension.cs'
}

# ─── 2. Derive the new namespace from the target folder path ─────────────────
function Get-NewNamespace([[string]]$targetRelPath) {
    # Strip file extension, keep folder path, replace '\' with '.'
    $dir = Split-Path $targetRelPath -Parent          # e.g. "Core\Pipeline"
    if ($dir -eq '' -or $dir -eq '.') { return 'Ragnar' }
    return 'Ragnar.' + ($dir -replace '\\', '.')
}

# ─── 3. Helper: rewrite namespace line in a .cs file ─────────────────────────
function Set-Namespace([[string]]$filePath, [[string]]$newNs) {
    $content = Get-Content $filePath -Raw
    # Replace the first occurrence of "namespace X { " (or file-scoped "namespace X;")
    $content = $content -replace 'namespace\s+[[\w.]]+\s*\{?', "namespace $newNs {"
    $content = $content -replace 'namespace\s+[[\w.]]+;',  "namespace $newNs;"
    Set-Content -Path $filePath -Value $content -NoNewline
}

# ─── 4. Execute ──────────────────────────────────────────────────────────────
$moved = 0
$skipped = 0

foreach ($key in $map.Keys) {
    $targetRel = $map[[$key]]
    $sourceFile = Join-Path $src $key
    $targetFile = Join-Path $src $targetRel

    # Skip if source doesn't exist (already moved, or not in this repo)
    if (-not (Test-Path $sourceFile)) {
        Write-Verbose "SKIP  $key  (not found)"
        $skipped++
        continue
    }

    # Skip if source and target are the same
    if ((Resolve-Path $sourceFile).Path -eq (Resolve-Path $targetFile).Path) {
        Write-Verbose "SKIP  $key  (already in place)"
        $skipped++
        continue
    }

    $newNs = Get-NewNamespace $targetRel

    if (-not $Force) {
        Write-Host "  MOVE  $key  →  $targetRel" -ForegroundColor Cyan
        Write-Host "        namespace → $newNs" -ForegroundColor DarkGray
    }
    else {
        # Create target directory
        $targetDir = Split-Path $targetFile -Parent
        if (-not (Test-Path $targetDir)) {
            New-Item -Path $targetDir -ItemType Directory -Force | Out-Null
        }

        # Move (overwrite if a duplicate DI extension exists)
        Move-Item -Path $sourceFile -Destination $targetFile -Force

        # Rewrite namespace
        Set-Namespace $targetFile $newNs

        Write-Host "  ✔  $key  →  $targetRel  ($newNs)" -ForegroundColor Green
    }

    $moved++
}

# ─── 5. Summary ──────────────────────────────────────────────────────────────
Write-Host ""
Write-Host "Files planned: $moved   Skipped: $skipped" -ForegroundColor Yellow

if (-not $Force) {
    Write-Host "Dry-run complete. Re-run with -Force to apply changes." -ForegroundColor Yellow
}
else {
    Write-Host "Reorganisation complete. Run `dotnet build` to verify." -ForegroundColor Green
}
```

## 3. Step-by-Step Guide

### Step 0 – Back up

```powershell
git add -A && git commit -m "chore: snapshot before reorganisation"
```

### Step 1 – Run the script in dry-run mode

```powershell
cd C:\Users\jp325\source\Ragnar\Src\Ragnar
pwsh .\reorganise.ps1
```

Review the output. Every `MOVE` line shows the source → target and the new namespace. If a file isn't listed (e.g. `IRagOrchestrator.cs`, `IEmbeddingService.cs`, `Question.cs`), add it to the `$map` hashtable at the top of the script.

### Step 2 – Apply the move

```powershell
pwsh .\reorganise.ps1 -Force
```

The script will:
1. Create every target folder (`Core\Pipeline\Stages`, `Embedding\Strategies`, …).
2. `Move-Item` each `.cs` file.
3. Rewrite the single `namespace` declaration to the new dotted path (e.g. `Ragnar.Core.Pipeline`).

### Step 3 – Fix `using` directives across the project

The script only changes the *namespace declaration* in the moved file. Every other file that referenced the old namespace needs a `using` update. The fastest way is to let the compiler tell you:

```powershell
dotnet build Ragnar.sln
```

You'll see `CS0246` / `CS0234` errors. For each, add the new `using`:

| Old namespace (typical) | New `using` to add |
|---|---|
| `Ragnar` (everything was flat) | `Ragnar.Core.Pipeline` |
| | `Ragnar.RAG` |
| | `Ragnar.Embedding` |
| | `Ragnar.Files` |
| | `Ragnar.Questions` |
| | `Ragnar.Validation` |
| | `Ragnar.Infrastructure.Extensions` |
| | `Ragnar.Infrastructure.Rendering` |
| | `Ragnar.Infrastructure.DI` |

> **Tip:** In Visual Studio, select all error lines → *Fix All* (Ctrl+Shift+R) → *Add missing usings*. Or in the CLI:
> ```powershell
> dotnet build --no-incremental | Select-String 'error CS'
> ```

### Step 4 – Consolidate the duplicate DI extension

You had **two** `EmbeddingSetupExtension.cs` files (one as a C# 13 `extension` block, one as a static class). Keep the **static-class** version in `Infrastructure\DI\EmbeddingSetupExtension.cs` and delete the other. Make sure the static class exposes:

```csharp
public static IServiceCollection AddRagnarEmbedding(this IServiceCollection services)
```

…and call it from your `Program.cs`:

```csharp
builder.Services.AddRagnarEmbedding();
```

```csharp

    sp.GetRequiredService<IOptions<RagnarConfig>>().Value.ApplicationOptions
```

### Step 6 – Update `.csproj` (if it uses explicit `<Compile>` items)

If your `Ragnar.csproj` has `<Compile Include="...">` entries, update the paths or simply remove them and let the SDK glob pick up the new tree:

```xml
<!-- Remove any explicit <Compile> items; the SDK includes **\*.cs by default. -->
<!-- Keep only exclusions you need: -->
<ItemGroup>
  <Compile Remove="bin\**\*.*" />
  <Compile Remove="obj\**\*.*" />
</ItemGroup>
```

### Step 7 – Add `.editorconfig` / namespace style (optional but recommended)

```ini
[[*.cs]]
csharp_style_namespace_declarations = file_scoped
dotnet_style_qualification_for_type = false
```

This enforces `namespace Ragnar.Core.Pipeline;` (file-scoped) going forward.

### Step 8 – Build, test, commit

```powershell
dotnet build Ragnar.sln --no-incremental
dotnet test
git add -A
git commit -m "refactor: reorganise into layered namespaces (Core, RAG, Embedding, Files, Questions, Validation, Infrastructure)"
```

## 5. Tips for Keeping It Clean Going Forward

1. **One namespace per folder.** Don't let a file's namespace differ from its folder path.
2. **`global using` for cross-cutting types.** Add to a `GlobalUsings.cs` at the project root:
   ```csharp
   global using Serilog;
   global using Ragnar.Core.Pipeline;
   global using Ragnar.Core.Models;
   ```
3. **New stage?** Drop it in `Core/Pipeline/Stages/` – the runner discovers by interface, not by folder.
4. **New filter strategy?** Drop it in `Embedding/Strategies/` and register it in DI; `QuestionFilterSelector` picks it up by `SupportedCategory`.
5. **Run the script with `-DryRun`** before any future big move to preview impact.

This layout keeps the ~500-line `RagOrchestrator` in `RAG/` where it belongs, separates the 6 pipeline engine files from the 6 file-IO files, and puts every validator in one predictable folder – so a new developer can find anything in **≤ 3 folder clicks**.
