# Reworking & Improving the Existing Builders

Your codebase has three builder patterns in play: **`QdrantFilterBuilder`**, **`OllamaChatClientBuilder`**, and the **`IRagPromptBuilder`** (referenced in `RagOrchestrator` but not shown). Below is a structured analysis of concrete issues and how to rework each one.

---

## 1. `QdrantFilterBuilder` — the biggest candidate for rework

### Current problems

| # | Issue | Why it matters |
|---|-------|---------------|
| 1 | `Build()` throws when the builder is empty | Callers like `QuestionFilterSelector.FindFilter` fall back to `new Filter()` when no strategy matches, but a *valid* "match-everything" query is impossible to express. |
| 2 | `AddRange` / `AddExclusionRange` duplicate the `Range`-construction logic | DRY violation; two methods that should share one private helper. |
| 3 | No `Should` condition support | Qdrant's filter model supports `must`, `must_not`, **and** `should`; the builder only models the first two. |
| 4 | No `Clone()` / `With…` method | Every strategy must start from scratch; you can't derive one filter from another. |
| 5 | No `Clear()` method | Can't reuse a builder instance across pipeline runs without GC pressure. |
| 6 | `AddExceptKeywords` builds a deeply-nested object inline | Hard to read, hard to unit-test the shape. |
| 7 | No field-name validation or normalisation | Typos in field names silently produce broken Qdrant queries at runtime. |

### Reworked version

```csharp
/// <summary>
/// Fluent builder for constructing Qdrant <see cref="Filter"/> expressions.
/// Supports must / must_not / should condition sets and is safe to reuse.
/// </summary>
/// <example>
/// <![[CDATA[[
/// var filter = new QdrantFilterBuilder()
///     .Must(m => m.MatchKeyword("Category", "XML"))
///     .Must(m => m.Range("CommentLength", gte: 50))
///     .Should(s => s.MatchKeyword("Tag", "api"))
///     .MustNot(m => m.MatchKeyword("Category", "Test"))
///     .Build();
/// ]]]]>
/// </example>
public sealed class QdrantFilterBuilder
{
    private readonly List<Condition> _must     = [[]];
    private readonly List<Condition> _mustNot  = [[]];
    private readonly List<Condition> _should   = [[]];   // ← NEW

    // ─── Fluent entry points (unchanged surface) ───────────────────────
    public QdrantFilterBuilder AddMatch(string field, string value)
        => Must(c => c.MatchKeyword(field, value));

    public QdrantFilterBuilder AddExclusion(string field, string value)
        => MustNot(c => c.MatchKeyword(field, value));

    public QdrantFilterBuilder AddRange(string field, double? gte = null, double? lte = null)
        => Must(c => c.Range(field, gte, lte));

    public QdrantFilterBuilder AddExclusionRange(string field, double? gte = null, double? lte = null)
        => MustNot(c => c.Range(field, gte, lte));

    public QdrantFilterBuilder AddExceptKeywords(string field, params string[[]] keywords)
        => Must(c => c.ExceptKeywords(field, keywords));

    // ─── NEW: should-conditions ────────────────────────────────────────
    public QdrantFilterBuilder AddShould(string field, string value)
        => Should(c => c.MatchKeyword(field, value));

    // ─── NEW: predicate-based overloads (single API surface) ──────────
    public QdrantFilterBuilder Must(Action<Condition> configure)
    { _must.Add(configure()); return this; }

    public QdrantFilterBuilder MustNot(Action<Condition> configure)
    { _mustNot.Add(configure()); return this; }

    public QdrantFilterBuilder Should(Action<Condition> configure)
    { _should.Add(configure()); return this; }

    // ─── NEW: reusability ──────────────────────────────────────────────
    public QdrantFilterBuilder Clear()
    { _must.Clear(); _mustNot.Clear(); _should.Clear(); return this; }

    public QdrantFilterBuilder Clone() => new()
    {
        _must    = [[.._must.Select(CloneCondition)]],
        _mustNot = [[.._mustNot.Select(CloneCondition)]],
        _should  = [[.._should.Select(CloneCondition)]],
    };

    public bool IsEmpty => _must.Count == 0 && _mustNot.Count == 0 && _should.Count == 0;

    // ─── Build (relaxed: empty filter is now legal) ────────────────────
    public Filter Build()
    {
        return new Filter
        {
            Must     = [[.._must]],
            MustNot  = [[.._mustNot]],
            Should   = [[.._should]],   // ← NEW
        };
    }

    // ─── Private helpers (deduplicated) ────────────────────────────────
    private static Condition CloneCondition(Condition c) => c.DeepClone(); // use System.Text.Json or MemberwiseClone

    private static Range BuildRange(double? gte, double? lte)
    {
        ArgumentNullException.ThrowIfNull(gte is null && lte is null);
        var r = new Range();
        if (gte is not null) r.Gte = gte.Value;
        if (lte is not null) r.Lte = lte.Value;
        return r;
    }
}

/// <summary>Small DSL helper so callers write natural-language-style chains.</summary>
public static class QdrantConditionExtensions
{
    public static Condition MatchKeyword(this Condition _, string field, string value) =>
        Conditions.MatchKeyword(field, value);

    public static Condition Range(this Condition _, string field, double? gte = null, double? lte = null) =>
        new() { Field = new FieldCondition { Key = field, Range = BuildRange(gte, lte) } };

    public static Condition ExceptKeywords(this Condition _, string field, string[[]] keywords) =>
        new() { Field = new FieldCondition
        {
            Key   = field,
            Match = new Match { ExceptKeywords = new RepeatedStrings { Strings = { keywords } } }
        } };
}
```

### How existing call-sites adapt

```csharp
// Before (XmlCommentFilterStrategy):
var filter = new QdrantFilterBuilder()
    .AddRange("CommentLength", sizeThreshold)
    .AddExceptKeywords("Category", "Test", "Tests", "Testing")
    .Build();

// After — identical call-site, zero breaking change.
// You *can* now also do:
var filter = new QdrantFilterBuilder()
    .AddRange("CommentLength", sizeThreshold)
    .AddExceptKeywords("Category", "Test", "Tests", "Testing")
    .AddShould("Tag", "api")          // ← new capability
    .Build();
```

## 2. `OllamaChatClientBuilder` — rename & tighten

### Current problems

* The class **doesn't build a client**; it returns a *configured options wrapper*. The name is misleading.
* The constructor is empty (`OllamaChatClientBuilder()`) yet the doc-comment and usage examples show a `factory` parameter — the interface and the class are out of sync.
* No validation that `options` is non-null or that `ServiceType` is a valid enum member.
* No way to layer options (e.g. start from defaults, then override `Timeout`).

### Reworked version

```csharp
/// <summary>
/// Fluent factory for producing configured <see cref="IOllamaApiClient"/> instances.
/// </summary>
/// <example>
/// <![[CDATA[[
/// var client = new OllamaClientFactoryBuilder(ollamaClientFactory)
///     .For(OllamaServiceType.Embedding)
///     .WithTimeout(TimeSpan.FromSeconds(120))
///     .Build();
/// ]]]]>
/// </example>
public sealed class OllamaClientFactoryBuilder(IOllamaClientFactory factory)
{
    private OllamaServiceType _serviceType = OllamaServiceType.Ollama;
    private TimeSpan?         _timeout;
    private string?           _model;

    public OllamaClientFactoryBuilder For(OllamaServiceType type)
    {
        _serviceType = type;
        return this;
    }

    public OllamaClientFactoryBuilder WithTimeout(TimeSpan timeout)
    {
        Guard.Against.Null(timeout);
        _timeout = timeout;
        return this;
    }

    public OllamaClientFactoryBuilder WithModel(string model)
    {
        Guard.Against.NullOrEmpty(model);
        _model = model;
        return this;
    }

    /// <summary>
    /// Resolves the client from the underlying factory and applies
    /// any additional options captured by this builder.
    /// </summary>
    public IOllamaApiClient Build()
    {
        var client = factory.ResolveClient(_serviceType);
        // Apply post-resolution tweaks if the client exposes a mutable Options bag:
        // if (_timeout is not null) ((IOllamaApiClientEx)client).Options.Timeout = _timeout;
        return client;
    }
}
```

> **Key rename:** `OllamaChatClientBuilder` → `OllamaClientFactoryBuilder` so the name matches what it actually does (wraps a *factory*, not a *chat client*).

## 3. `IRagPromptBuilder` (the one used in `RagOrchestrator`)

You only see its call-site:

```csharp
var finalPrompt = promptBuilder.WithQuestion(question).WithContext(contextText).Build();
```

### Recommended improvements

1. **Return a value-type `RagPrompt` record instead of a raw `string`**, so callers can inspect `.System`, `.User`, `.Model` independently without string-parsing.

```csharp
public sealed record RagPrompt
{
    public required string System { get; init; }
    public required string User   { get; init; }
    public string?         Model  { get; init; }
    public override string ToString() => $"\n{System}\n{User}\n";
}

public interface IRagPromptBuilder
{
    IRagPromptBuilder WithQuestion(Question q);
    IRagPromptBuilder WithContext(string context);
    IRagPromptBuilder WithSystemPrompt(string system);   // ← explicit, not hidden
    RagPrompt Build();
}
```

2. **Validate in `Build()`** — throw `InvalidOperationException` if `Question` or `Context` were never set, instead of silently producing `"Context:\n\nQuestion:\n\nAnswer:"`.

3. **Add a `WithConstraints(...)` method** that accepts a `GenerationOptions` and embeds temperature / max-tokens hints into the system prompt (useful for Ollama which sometimes honours prompt-level guidance).

## 4. Cross-cutting improvements that apply to *all* builders

### a. Implement a tiny `IBuilder<T>` contract

```csharp
public interface IBuilder<TResult>
{
    TResult Build();
    IBuilder<TResult> Clear();
    IBuilder<TResult> Clone();
}
```

Making `QdrantFilterBuilder`, `OllamaClientFactoryBuilder`, and `IRagPromptBuilder` all implement this gives you:

* A uniform `Clear()` / `Clone()` / `Build()` surface.
* A place to hang a generic `Validate()` extension that runs before `Build()`.
* Easier DI: register `IBuilder<Filter>, QdrantFilterBuilder` and swap implementations in tests.

### b. Add a `BuilderValidation` layer

```csharp
public static class BuilderValidation
{
    public static void EnsureNonEmpty(this IBuilder<> builder, string name)
    {
        if (builder is QdrantFilterBuilder fb && fb.IsEmpty)
            throw new InvalidOperationException($"{name}: call at least one Add* before Build().");
        // extend per builder type…
    }
}
```

This lets you keep `Build()` permissive (return an empty filter) while still giving strict callers a one-liner guard.

### c. Unit-test the builders in isolation

```csharp
[[Fact]]
public void Build_WithNoConditions_ReturnsEmptyFilter()
{
    var f = new QdrantFilterBuilder().Build();
    Assert.Empty(f.Must);
    Assert.Empty(f.MustNot);
    Assert.Empty(f.Should);
}

[[Fact]]
public void Clone_IsDeepCopy()
{
    var a = new QdrantFilterBuilder().AddMatch("K","V");
    var b = a.Clone();
    b.AddMatch("K2","V2");
    Assert.Single(a.Build().Must);   // a unchanged
    Assert.Equal(2, b.Build().Must.Count);
}
```

### d. Add a `ToString()` / `Describe()` for diagnostics

```csharp
public override string ToString() =>
    $"QdrantFilter(must:{_must.Count}, mustNot:{_mustNot.Count}, should:{_should.Count})";
```

Wire it into the existing Serilog calls in `QuestionFilterSelector` so a single log line shows the full filter shape during debugging.

## 5. Suggested migration order

| Step | What | Risk |
|------|------|------|
| 1 | Add `Should` list + `Clear()` + `Clone()` to `QdrantFilterBuilder`; relax `Build()` empty-throw | **Low** – purely additive |
| 2 | Extract `BuildRange` private helper; deduplicate `AddRange` / `AddExclusionRange` | **Low** – internal refactor |
| 3 | Rename `OllamaChatClientBuilder` → `OllamaClientFactoryBuilder`; fix the constructor/factory mismatch | **Medium** – touches DI registrations in `EmbeddingSetupExtension` and any `Program.cs` wiring |
| 4 | Introduce `RagPrompt` record; update `IRagPromptBuilder.Build()` return type; update the single call-site in `RagOrchestrator.ExecuteAsync` | **Medium** – one production call-site |
| 5 | Introduce `IBuilder<T>` + `BuilderValidation` extension; have all three builders opt in | **Low** – additive interface |
| 6 | Add unit tests for every `Add*` / `Build` / `Clone` / `Clear` path | **Low** |

This sequence keeps each step independently shippable and testable, so you never have a PR where the builder API and its call-sites change in the same commit.
