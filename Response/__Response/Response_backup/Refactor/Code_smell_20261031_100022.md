# Code Smells Identified in the Ragnar Project

## 1. Critical: Dead Code / Broken Middleware Pipeline (`PipelineRunner.cs`)

The most serious issue is that the middleware system is **never actually invoked**. In `ExecuteAsync`, a `core` delegate is defined but never used, and `ExecuteStageWithMiddlewareAsync` is never called:

```csharp
// This delegate is defined...
Func<Task> core = async () =>
{
    if (entry.AsyncPolicy is null)
    {
        await stage.ExecuteAsync(context, ct).ConfigureAwait(false);
    }
    else
    {
        await entry.AsyncPolicy.ExecuteAsync(async () => await stage.ExecuteAsync(context, ct).ConfigureAwait(false)).ConfigureAwait(false);
    }
};

// ...but then the logic is duplicated in the try block instead of calling `core`
// or going through the middleware chain:
try
{
    if (snapshot[[i]].AsyncPolicy is null)
    {
        await stage.ExecuteAsync(context, ct).ConfigureAwait(false); // ← duplicate of `core`
    }
    else { ... } // ← duplicate of `core`
}
```

**Fix:** Wire the middleware chain into the execution path and remove the duplication:

```csharp
public override async Task<TContext> ExecuteAsync(TContext context, CancellationToken ct)
{
    var totalSw = Stopwatch.StartNew();
    List<StageEntry<TContext>> snapshot;
    lock (_gate) snapshot = [[.._stages]];

    for (var i = 0; i < snapshot.Count; i++)
    {
        var entry = snapshot[[i]];
        if (!entry.PipelineStage.ShouldRun(context))
        {
            logger.Information("Skipping stage [[{Index}]]: {Name}", i, entry.PipelineStage.Name);
            continue;
        }

        logger.Information("Starting stage [[{Index}/{Total}]]: {Name}", i + 1, snapshot.Count, entry.PipelineStage.Name);
        var execCtx = new StageExecutionContext<TContext>(entry.PipelineStage, context, i, snapshot.Count);

        Func<Task> core = async () =>
        {
            if (entry.AsyncPolicy is null)
                await entry.PipelineStage.ExecuteAsync(context, ct).ConfigureAwait(false);
            else
                await entry.AsyncPolicy.ExecuteAsync(
                    async () => await entry.PipelineStage.ExecuteAsync(context, ct).ConfigureAwait(false)
                ).ConfigureAwait(false);
        };

        try
        {
            await ExecuteStageWithMiddlewareAsync(execCtx, core, ct).ConfigureAwait(false);
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested) { throw; }
        catch (Exception ex)
        {
            logger.Fatal(ex, "Stage [[{Index}]] {Name} failed", i, entry.PipelineStage.Name);
            throw new PipelineStageException(entry.PipelineStage.Name, ex);
        }
    }

    logger.Information("Pipeline finished in {Total}", totalSw.Elapsed);
    return context;
}
```

## 2. Mutation in a Query Method (`QuestionFilterSelector.FindFilter`)

`FindFilter` is a read/query operation, but it **mutates internal state** as a side effect:

```csharp
public Filter FindFilter(QuestionCategory category, int commentLengthThreshold = 0)
{
    _strategies.TryAdd(QuestionCategory.XML, new XmlCommentFilterStrategy(logger)); // ← MUTATION
    // ...
}
```

This violates the principle of least surprise and makes the method non-idempotent in its effects. It also means the first call and subsequent calls behave differently with respect to state.

**Fix:** Register the XML strategy in the constructor (where the DI container already resolves `IEnumerable<IFilterStrategy>`), or guard it explicitly:

```csharp
public sealed class QuestionFilterSelector(Serilog.ILogger logger, IEnumerable<IFilterStrategy> strategies)
{
    private readonly Dictionary<QuestionCategory, IFilterStrategy> _strategies;

    public QuestionFilterSelector(Serilog.ILogger logger, IEnumerable<IFilterStrategy> strategies)
    {
        _strategies = strategies.ToDictionary(s => s.SupportedCategory);
        // Register any built-in strategies that aren't supplied via DI:
        if (!_strategies.ContainsKey(QuestionCategory.XML))
            _strategies[[QuestionCategory.XML]] = new XmlCommentFilterStrategy(logger);
    }

    public Filter FindFilter(QuestionCategory category, int commentLengthThreshold = 0)
    {
        // Pure read — no mutation
        return _strategies.TryGetValue(category, out var strategy)
            ? strategy.CreateFilter(commentLengthThreshold)
            : new Filter();
    }
}
```

## 3. String Mutation via `+=` (`RagOrchestrator.ExecuteAsync`)

```csharp
if (configWrapper.Value.ApplicationOptions.IncludeOriginalPrompt)
{
    response += finalPrompt.ShowPrompt();   // new allocation
    response += Environment.NewLine;        // new allocation
    response += request.System;             // new allocation
}
```

Each `+=` on a `string` allocates a new array. With potentially large prompts this is wasteful.

**Fix:** Use a `StringBuilder` or compose once:

```csharp
if (configWrapper.Value.ApplicationOptions.IncludeOriginalPrompt)
{
    var sb = new StringBuilder(response);
    sb.Append(finalPrompt.ShowPrompt());
    sb.AppendLine();
    sb.Append(request.System);
    response = sb.ToString();
}
```

## 4. Inconsistent Path Logic (`OutputPathHelper.GetResponseDirectory`)

```csharp
public static string GetResponseDirectory(this IEnumerable<string> folders, string baseDir = "")
{
    var parts = folders as IReadOnlyCollection<string> ?? [[..folders]];
    if (parts.Count == 0)
        return string.IsNullOrEmpty(baseDir) ? DomainDefaults.ResponseDir : Path.Join(baseDir, DomainDefaults.ResponseDir);
    return Path.Join(parts.Append(DomainDefaults.ResponseDir).ToArray()); // ← baseDir is IGNORED
}
```

When `folders` is empty, `baseDir` is honoured. When it's non-empty, `baseDir` is silently dropped. This is a surprising, undocumented behavioural branch.

**Fix:** Make the behaviour explicit and consistent:

```csharp
public static string GetResponseDirectory(this IEnumerable<string> folders, string baseDir = "")
{
    var parts = folders as IReadOnlyCollection<string> ?? [[..folders]];
    var segments = parts.Append(DomainDefaults.ResponseDir);
    var joined = Path.Join(segments.ToArray());

    return string.IsNullOrEmpty(baseDir) ? joined : Path.Join(baseDir, joined);
}
```

## 5. Non-Injectable Dependencies (`CodeParserFactory`)

```csharp
private readonly ParseCSharpFile _codeParser = new(logger, cSharpFile);
private readonly MarkdownFileParser _markdownParser = new(options, logger);
```

These are constructed inline, making them impossible to replace with mocks in unit tests or swap via DI.

**Fix:** Inject them through the constructor:

```csharp
public class CodeParserFactory(
    Serilog.ILogger logger,
    IOptions<RagnarConfig> options,
    IFileParser cSharpParser,       // ← inject
    IFileParser markdownParser)    // ← inject
    : IFileParseFactory
{
    // use cSharpParser / markdownParser directly
}
```

Then register the concrete parsers in DI alongside the embedding setup extensions.

## 7. Inconsistent Extension-Method Style

Some files use the C# 14 `extension` keyword (e.g., `EmbeddingSetupExtension`, `QuestionsExtensions`, `AssemblyExtensions`) while others use the traditional `public static class` pattern (`GeneratorExtensions`, `FileSystemEntryExtensions`, `OutputPathHelper`). Pick one convention across the codebase. If targeting .NET 9+, prefer `extension` everywhere; otherwise use `static class` consistently.
