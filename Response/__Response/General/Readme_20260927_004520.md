## What is Ragnar?

Ragnar is a **local-first, RAG-powered code intelligence engine** that indexes your source code, answers natural-language questions about it, and writes structured Markdown reports — all without sending a single token to a cloud provider.

It works by:

1. **Discovering** source files across a directory tree (with extension and path filters).
2. **Parsing** each file into semantic `CodeDocument` segments (types, methods, XML comments, free-form text).
3. **Embedding** every segment with a local Ollama model and persisting vectors in Qdrant.
4. **Retrieving** the most relevant context for each question in a CSV-driven question set.
5. **Generating** grounded answers via a local Ollama LLM.
6. **Writing** timestamped, category-organised Markdown reports to disk.

The entire pipeline runs on your machine. No API keys. No data exfiltration.

## Features

| Area | Detail |
|------|--------|
| **File Discovery** | Recursive scan with configurable allowed extensions (`.cs`, `.json`, `.editorconfig`, …) and excluded directories (`bin`, `obj`, `.git`, …). |
| **Code Parsing** | C# files are decomposed into per-element documents (class, method, property) with XML-comment extraction. Non-C# files are chunked by paragraph with token-aware overlap. |
| **Embedding** | Batched vector generation via Ollama (`nomic-embed-text` or any compatible model). Configurable dimension and batch size. |
| **Vector Store** | Qdrant collections with rich payload (`FileName`, `ElementType`, `ElementName`, `Comment`, `Category`, …) for filtered retrieval. |
| **Question Engine** | CSV-based question sets with per-row enable/disable, category grouping, and pluggable filter strategies (e.g. exclude test files, min comment length). |
| **RAG Pipeline** | Stage-based architecture: *Discover → Parse → Embed → Retrieve → Generate → Write*. Each stage is independently testable. |
| **Output** | Timestamped Markdown files under per-category sub-folders. Optional inclusion of the original prompt. |
| **Console UI** | Spectre.Console progress bars, styled tables, rules, and colour-coded status lines. |
| **Logging** | Serilog with structured JSON file sinks and optional Seq forwarding. |
| **Validation** | FluentValidation rulesets for every configuration section; fail-fast at startup. |
| **Caching** | `ConcurrentDictionary`-based Ollama client cache keyed by service type (LLM vs. Embedding). |

  -v qdrant_storage:/qdrant/storage \

## Configuration

All settings live in **`appsettings.json`** (defaults) and **`appsettings.Ragnar.json`** (local overrides). The two files are merged at startup.

### `appsettings.json` (reference)

```jsonc
{
  "RagnarConfig": {

    // ── Application ──────────────────────────────────────────────
    "ApplicationOptions": {
      "OutputFolder": "Response",          // sub-folder for .md reports
      "CategoriesToProcess": [],           // empty = all categories
      "IncludeOriginalPrompt": false       // prepend the question to output?
    },

    // ── Embedding (Ollama) ───────────────────────────────────────
    "EmbeddingOptions": {
      "BatchSize": 16,                     // vectors per /api/embed request
      "Dimension": 768,                    // must match the model
      "EmbeddingModel": "nomic-embed-text",
      "Host": "localhost",
      "Port": 6334,                        // ← Qdrant port (see note below)
      "Timeout": "00:05:00"
    },

    // ── File loading ─────────────────────────────────────────────
    "FileLoadOptions": {
      "AllowedExtensions": [".editorconfig", ".cs", ".json"],
      "ExcludedFiles":   ["docker-compose.yml"]
    },

    // ── Ollama LLM ───────────────────────────────────────────────
    "OllamaOptions": {
      "LlmModel": "qwen3.8",
      "Host": "localhost",
      "Port": 11434,
      "Timeout": "00:30:00"
    }
  },

  // ── Serilog ────────────────────────────────────────────────────
  "Serilog": {
    "MinimumLevel": { "Default": "Information" },
    "WriteTo": [
      { "Name": "File", "Args": { "path": "logs/log-.txt", "rollingInterval": "Day" } }
    ]
  }
}
```

### `appsettings.Ragnar.json` (local overrides)

```jsonc
{
  "RagnarConfig": {
    "ApplicationOptions": {
      "SourceDirectory": "%USERPROFILE%\\source\\Ragnar\\",
      "VectorStoreName": "Ragnar"
    },
    "FileLoadOptions": {
      "ExcludedDirectories": [
        "qdrant_storage", "Response", "obj", "bin",
        ".sonarqube", ".git", ".github", ".vs", ".config", "Logs"
      ]
    }
  }
}
```

> **Note:** `EmbeddingOptions.Port` in the sample points at **Qdrant** (6334). Adjust to your environment. The Ollama embedding endpoint is typically on **11434** alongside the LLM.

### Validation

Every configuration section is validated at startup via **FluentValidation**:

- `Host` must be non-empty.
- `Port` must be in range **1 – 65 535**.
- `Timeout` must be > 0.
- `LlmModel` / `EmbeddingModel` must be non-empty.
- `AllowedExtensions` entries must start with `.`.
- `ExcludedDirectories` must be folder names (no path separators).

Invalid values produce a clear, aggregated error message before the pipeline starts.

## Usage

### 1. Define your questions

Create a CSV file (e.g. `questions.csv`):

```csv
IsEnabled,Text,Filename,Category
True,What design patterns are used in the output pipeline?,design-patterns,Architecture
True,Summarise all XML comments longer than 200 chars,xml-audit,XML
False,List every external HTTP endpoint referenced,http-endpoints,Network
```

| Column | Type | Description |
|--------|------|-------------|
| `IsEnabled` | `bool` | `true` to include the question in the run. |
| `Text` | `string` | Natural-language prompt sent to the LLM. |
| `Filename` | `string` | Base name for the output Markdown file. |
| `Category` | `enum` | `Architecture`, `XML`, `Network`, `Other`, … (maps to a sub-folder). |

## Filter Strategies

Ragnar ships with pluggable **filter strategies** that shape *which* code documents are eligible for a given question category.

| Strategy | Category | Rule |
|----------|----------|------|
| `XmlCommentFilterStrategy` | `XML` | Include comments **shorter** than the size threshold; exclude any whose `Category` payload contains *Test / Tests / Testing*. |

Custom strategies implement `IFilterStrategy` and are resolved via DI.

## Extending

### Adding a new file parser

1. Create a class in `Ragnar.Embedding/Parsers/` that inherits `BaseFileParser`.
2. Override `ParseAsync` to return `IEnumerable<CodeDocument>`.
3. Register it in `IFileParseFactory` for the target extension.

### Adding a new pipeline stage

1. Implement `IPipelineStage<TContext>`.
2. Set `Name` (display string) and `ShouldRun` (predicate).
3. Inject into the pipeline builder in `Program.cs`.

### Adding a new question source

Implement `IQuestionSource`:

```csharp
public sealed class MyQuestionSource : IQuestionSource
{
    public string ProviderName => "My Source";
    public async Task<IEnumerable<Question>> LoadQuestionsAsync(
        string fileName, CancellationToken ct) { /* … */ }
}
```
