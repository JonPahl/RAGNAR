# Reworking & Improving the Existing Builders

After reviewing the codebase, I've identified four builder-pattern components with specific weaknesses. Below is a concrete improvement plan for each.

---

## 1. `QdrantFilterBuilder` — Most Impactful Rework

### Problems Found

| Issue | Location |
|-------|----------|
| `_should` list is **dead code** — no public method ever populates it | `_should` field + `Build()` |
| `CloneCondition` is private and **never called** | bottom of class |
| No `AddShould` / `AddMatchAny` / `IsNull` / `IsNotNull` methods | missing API surface |
| No nested/grouped filter support (Qdrant supports `Should` inside `Must`) | `Build()` only returns flat lists |
| No field-name validation (empty string silently accepted) | `AddRange`, `AddMatch`, etc. |
| `AddExceptKeywords` accepts `params string[]` but callers may want `IEnumerable<string>` | `AddExceptKeywords` |
| `Build()` throws `InvalidOperationException` with no `TryBuild` alternative | `Build()` |

### Proposed Rework

```csharp
public sealed class QdrantFilterBuilder
{
    private readonly List<Condition> _must = [];
    private readonly List<Condition> _mustNot = [];
    private readonly List<Condition> _should = [];
    private readonly List<Condition> _shouldMust = [];   // nested: should-conditions inside a must-group

    // ── Guards (centralised) ──────────────────────────────────────────
    private static void GuardField(string field) =>
        Guard.Against.NullOrWhiteSpace(field, nameof(field));

    // ── Existing methods (now with validation) ───────────────────────
    public QdrantFilterBuilder AddMatch(string field, string value)
    {
        GuardField(field);
        Guard.Against.Null(value, nameof(value));
        _must.Add(Conditions.MatchKeyword(field, value));
        return this;
    }

    public QdrantFilterBuilder AddExclusion(string field, string value)
    {
        GuardField(field);
        Guard.Against.Null(value, nameof(value));
        _mustNot.Add(Conditions.MatchKeyword(field, value));
        return this;
    }

    public QdrantFilterBuilder AddRange(string field, double? gte = null, double? lte = null)
    {
        GuardField(field);
        if (gte is null && lte is null)
            throw new ArgumentException("At least one of gte or lte must be provided.", nameof(gte));
        var range = new Range { Gte = gte, Lte = lte };
        _must.Add(new Condition { Field = new FieldCondition { Key = field, Range = range } });
        return this;
    }

    public QdrantFilterBuilder AddExclusionRange(string field, double? gte = null, double? lte = null)
    {
        GuardField(field);
        if (gte is null && lte is null)
            throw new ArgumentException("At least one of gte or lte must be provided.", nameof(gte));
        var range = new Range { Gte = gte, Lte = lte };
        _mustNot.Add(new Condition { Field = new FieldCondition { Key = field, Range = range } });
        return this;
    }

    // ── NEW: Should conditions (previously dead) ─────────────────────
    /// <summary>Adds a keyword match to the positive "should" set.</summary>
    public QdrantFilterBuilder AddShouldMatch(string field, string value)
    {
        GuardField(field);
        _should.Add(Conditions.MatchKeyword(field, value));
        return this;
    }

    /// <summary>Adds a "should" group: match ANY of the given keywords on the same field.</summary>
    public QdrantFilterBuilder AddShouldAny(string field, params string[] values)
    {
        GuardField(field);
        Guard.Against.Empty(values, nameof(values));
        _should.Add(new Condition
        {
            Should = [.. values.Select(v => (Condition)Conditions.MatchKeyword(field, v))]
        });
        return this;
    }

    // ── NEW: Null / Not-Null ─────────────────────────────────────────
    public QdrantFilterBuilder AddIsNull(string field)
    {
        GuardField(field);
        _must.Add(new Condition { IsNull = new IsNullCondition { IsNull = true } });
        return this;
    }

    public QdrantFilterBuilder AddIsNotNull(string field)
    {
        GuardField(field);
        _must.Add(new Condition { IsNull = new IsNullCondition { IsNull = false } });
        return this;
    }

    // ── NEW: Accept IEnumerable for keyword lists ────────────────────
    public QdrantFilterBuilder AddExceptKeywords(string field, IEnumerable<string> keywords)
    {
        GuardField(field);
        var list = keywords as IReadOnlyCollection<string> ?? keywords.ToList();
        if (list.Count == 0) return this;
        _must.Add(new Condition
        {
            Field = new FieldCondition
            {
                Key = field,
                Match = new Match { ExceptKeywords = new RepeatedStrings { Strings = { list } } }
            }
        });
        return this;
    }

    // ── NEW: Nested grouped filter (Qdrant "must inside should") ─────
    public QdrantFilterBuilder AddGroupedMust(params string[] fields)
    {
        Guard.Against.Empty(fields, nameof(fields));
        _must.Add(new Condition
        {
            Must = [.. fields.Select(f => (Condition)new Condition { Has = new HasCondition { Key = f } })]
        });
        return this;
    }

    // ── State / lifecycle ─────────────────────────────────────────────
    public QdrantFilterBuilder Clear()
    {
        _must.Clear(); _mustNot.Clear(); _should.Clear(); _shouldMust.Clear();
        return this;
    }

    public bool IsEmpty =>
        _must.Count == 0 && _mustNot.Count == 0 && _should.Count == 0 && _shouldMust.Count == 0;

    // ── Build ─────────────────────────────────────────────────────────
    public Filter Build()
    {
        if (IsEmpty)
            throw new InvalidOperationException(
                "QdrantFilterBuilder is empty. Add at least one condition before calling Build().");

        return new Filter
        {
            Must    = { _must },
            MustNot = { _mustNot },
            Should  = { _should },
        };
    }

    /// <summary>Non-throwing variant; returns <c>false</c> if the builder is empty.</summary>
    public bool TryBuild(out Filter filter)
    {
        if (IsEmpty) { filter = null!; return false; }
        filter = Build();
        return true;
    }

    // ── Diagnostics ───────────────────────────────────────────────────
    public override string ToString() =>
        $"QdrantFilterBuilder[must:{_must.Count} mustNot:{_mustNot.Count} should:{_should.Count}]";
}
```

### Key changes summarised

1. **Killed dead code** — removed `CloneCondition`; added the missing `AddShould*` methods so `_should` is actually usable.
2. **Centralised guards** — every public method validates its `field` parameter up front.
3. **`TryBuild`** — lets callers avoid try/catch in non-critical paths.
4. **`IEnumerable<string>` overloads** — callers can pass `List<string>`, `HashSet<string>`, LINQ results without boxing into `params`.
5. **`ToString()`** — one-liner for logging/debugging instead of reaching into private lists.
6. **Nested group support** — Qdrant's filter model allows arbitrary nesting; the old flat-only API was a ceiling.

## 2. `OllamaChatClientBuilder` — Thin Wrapper → Real Builder

### Problems

* It's a single-method façade that just wraps an `OllamaClientOptions` object; there's no actual *building*.
* No chainable configuration (base URL, model, timeout, headers).
* No separation of "builder" from "client factory" (SRP).

### Proposed Rework

```csharp
// ── Builder interface (for DI / testing) ─────────────────────────────
public interface IOllamaChatClientBuilder
{
    OllamaChatClientBuilderConfigured WithChatClient(OllamaServiceType type);
    OllamaChatClientBuilderConfigured WithOptions(OllamaClientOptions options);
}

// ── Configured intermediate (fluent) ─────────────────────────────────
public sealed class OllamaChatClientBuilderConfigured
{
    private readonly OllamaClientOptions _options;
    internal OllamaChatClientBuilderConfigured(OllamaClientOptions options) => _options = options;

    public OllamaChatClientBuilderConfigured WithModel(string model)
    {
        Guard.Against.NullOrWhiteSpace(model, nameof(model));
        _options.Model = model;
        return this;
    }

    public OllamaChatClientBuilderConfigured WithBaseUrl(Uri baseUrl)
    {
        Guard.Against.Null(baseUrl, nameof(baseUrl));
        _options.BaseUrl = baseUrl;
        return this;
    }

    public OllamaChatClientBuilderConfigured WithTimeout(TimeSpan timeout)
    {
        if (timeout < TimeSpan.Zero)
            throw new ArgumentOutOfRangeException(nameof(timeout));
        _options.Timeout = timeout;
        return this;
    }

    /// <summary>Resolves the concrete API client.</summary>
    public IOllamaApiClient Build(IOllamaClientFactory factory)
    {
        Guard.Against.Null(factory, nameof(factory));
        return factory.ResolveClient(_options.ServiceType);
    }
}

// ── Builder (unchanged public surface, now delegates to configured) ──
public sealed class OllamaChatClientBuilder : IOllamaChatClientBuilder
{
    public OllamaChatClientBuilderConfigured WithChatClient(OllamaServiceType type)
        => new(new OllamaClientOptions { ServiceType = type });

    public OllamaChatClientBuilderConfigured WithOptions(OllamaClientOptions options)
        => new(options ?? throw new ArgumentNullException(nameof(options)));
}
```

**What changed:**
* `WithModel`, `WithBaseUrl`, `WithTimeout` give a real fluent chain instead of a single-step "configured" object.
* `Build(factory)` is the terminal call, making the builder→product boundary explicit.
* Null / range guards on every input.

## 3. `PipelineRunner` — Builder-Registration Improvements

The runner already uses a builder-like registration API (`AddStage`, `ReplaceStage`, `UseMiddleware`). Targeted tweaks:

### a) Add a `UseRetry` sugar method

```csharp
/// <summary>Convenience: wrap the next registered stage with a Polly retry policy.</summary>
public IPipeline<TContext> UseRetry(
    int maxAttempts = 3,
    TimeSpan baseDelay = default,
    IEnumerable<Type>? exceptions = null)
{
    baseDelay = baseDelay == default ? TimeSpan.FromSeconds(2) : baseDelay;
    exceptions ??= [typeof(HttpRequestException), typeof(TimeoutException)];

    var policy = Polly.Policy
        .Handle(exceptions)
        .WaitAndRetryAsync(
            Enumerable.Range(1, maxAttempts)
                .Select(i => baseDelay * i),
            (attempt, delay, ex, ctx) =>
                logger.Warning(ex, "Retry {Attempt}/{Max} after {Delay}", attempt, maxAttempts, delay));

    // Attach to the *last* registered stage (or next one to be added)
    // — store as "pending policy" consumed by the next AddStage call
    _pendingPolicy = policy;
    return this;
}
```

Then `AddStage` picks up `_pendingPolicy` if set, so callers can write:

```csharp
runner.UseRetry(5)
      .AddStage(embedStage)          // gets the retry policy
      .AddStage(writeStage);         // no retry
```

### b) `ReplaceStage` — non-throwing overload

```csharp
public bool TryReplaceStage(string oldName, IPipelineStage<TContext> newStage, IAsyncPolicy? policy = null)
{
    if (_stages.FindIndex(s => s.PipelineStage.Name == oldName) == -1)
        return false;
    RemoveStage(oldName);
    AddStage(newStage, policy);
    return true;
}
```

### c) Consistent logging via a single logger type

Right now the codebase mixes `Serilog.ILogger` (in `CodeParserFactory`, `FileDiscoveryService`, etc.) with `Microsoft.Extensions.Logging.ILogger` (in `PipelineRunner`, `DeltaEmbedStage`). Pick one:

```csharp
// In .csproj or Directory.Build.props:
<PropertyGroup>
  <LoggerAbstraction>Microsoft.Extensions.Logging.ILogger</LoggerAbstraction>
</PropertyGroup>
```

Then convert all `Serilog.ILogger` constructor parameters to `ILogger`. Serilog can still be the *provider*; the *abstraction* stays ME.L.

## 4. `EmbeddingSetupExtension` — DI Builder Hygiene

### Problems
* Registers `QuestionFilterSelector` as a singleton but injects `Serilog.ILogger` directly (tightly coupled).
* No way to override a single service without re-registering the whole group.
* No `ValidateOnBuild` hook.

### Proposed Rework

```csharp
public static class EmbeddingSetupExtension
{
    public static IServiceCollection EmbeddingSetup(
        this IServiceCollection services,
        Action<EmbeddingSetupBuilder>? configure = null)
    {
        var builder = new EmbeddingSetupBuilder(services);

        // defaults
        builder.AddEmbeddingService<OllamaEmbeddingGenerator>()
               .AddPointFactory<PointStructFactory>()
               .AddVectorSetup<VectorSetup>()
               .AddVectorStoreWriter<VectorStoreWriter>()
               .AddFilterSelector<QuestionFilterSelector>();

        configure?.Invoke(builder);

        services.AddOptions<EmbeddingOptions>().ValidateOnBuild();
        return services;
    }
}

/// <summary>Fluent DI registration scoped to the embedding pipeline.</summary>
public sealed class EmbeddingSetupBuilder(IServiceCollection services)
{
    public EmbeddingSetupBuilder AddEmbeddingService<TImpl>() where TImpl : class, IEmbeddingService
    { services.Replace(ServiceDescriptor.Singleton<IEmbeddingService, TImpl>()); return this; }

    public EmbeddingSetupBuilder AddPointFactory<TImpl>() where TImpl : class, IQdrantPointFactory
    { services.Replace(ServiceDescriptor.Singleton<IQdrantPointFactory, TImpl>()); return this; }

    public EmbeddingSetupBuilder AddVectorSetup<TImpl>() where TImpl : class, IVectorSetup
    { services.Replace(ServiceDescriptor.Singleton<IVectorSetup, TImpl>()); return this; }

    public EmbeddingSetupBuilder AddVectorStoreWriter<TImpl>() where TImpl : class, IVectorStoreWriter
    { services.Replace(ServiceDescriptor.Singleton<IVectorStoreWriter, TImpl>()); return this; }

    public EmbeddingSetupBuilder AddFilterSelector<TImpl>() where TImpl : class, QuestionFilterSelector
    { services.Replace(ServiceDescriptor.Singleton<TImpl>()); return this; }
}
```

**What changed:**
* Callers can now **swap a single implementation** without re-registering everything:
  ```csharp
  services.EmbeddingSetup(b => b.AddVectorStoreWriter<MockWriter>());
  ```
* `services.Replace(...)` means re-calling `EmbeddingSetup()` is idempotent.
* `ValidateOnBuild()` catches misconfigured `EmbeddingOptions` at startup.

## 5. Cross-Cutting Improvements (All Builders)

| Area | Action |
|------|--------|
| **Logger abstraction** | Standardise on `ILogger` (Microsoft) everywhere; keep Serilog as the *sink*. Replace every `Serilog.ILogger` parameter. |
| **Guard consistency** | All builders should use `Guard.Against.Null` / `NullOrWhiteSpace` / `Empty` before touching the value. Currently `QdrantFilterBuilder` does none; `OllamaChatClientBuilder` does none; `PipelineRunner` does some. |
| **`ToString()` / diagnostics** | Add `ToString()` to `QdrantFilterBuilder`, `OllamaChatClientBuilderConfigured`, and `PipelineRunner` so a single log line dumps the builder state. |
| **XML-doc consistency** | Every public member currently has a `<summary>` and `<example>`. Ensure `<param>` tags are present on *every* parameter (a few are missing in `AddExceptKeywords`, `AddRange`). |
| **`IFormattable`** | `GenerationOptions` and `EmbeddingOptions` could implement `IFormattable` for one-line config dumps in logs. |
| **Nullability annotations** | `QuestionFilterSelector.FindFilter` can return an *empty* `Filter`; document that explicitly with `<returns>` and a `<remarks>` note. |
| **Thread-safety doc** | `QdrantFilterBuilder` is *not* thread-safe. Add a `<remarks>` note: *"This class is not thread-safe. Create one instance per filter."* |
| **Remove dead code** | `CloneCondition` in `QdrantFilterBuilder`, the commented-out `Render()` block in `NumberedRowDecorator`, the unused `INotificationService` (empty interface). |

## Suggested Order of Work

1. **`QdrantFilterBuilder`** — highest impact; it's used by `XmlCommentFilterStrategy` and any future `IFilterStrategy`. The dead `_should` and missing `AddShould` are the most visible gap.
2. **Logger unification** — mechanical but touches ~15 files; do it in one PR with a project-wide search-and-replace + compile-fix.
3. **`EmbeddingSetupExtension`** — small change, big DX win (swappable implementations, idempotent registration).
4. **`OllamaChatClientBuilder`** — add the fluent chain; low risk.
5. **`PipelineRunner` sugar** — `UseRetry`, `TryReplaceStage`; polish, not refactor.
6. **Dead-code sweep** — delete `CloneCondition`, commented blocks, empty interfaces in a cleanup PR.

Each item is independently shippable and testable, so you can parallelise across two or three branches.
