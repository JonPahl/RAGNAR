# Code Smells & Recommendations for the Ragnar Project

Below is a structured audit of the codebase, grouped by smell category, with concrete fixes.

---

## 1. Long Parameter List / God Object

**`RagOrchestrator`** — 8 constructor parameters:

```csharp
public sealed class RagOrchestrator(
    Serilog.ILogger logger,
    IOutputWriter writer,
    IOptions<RagnarConfig> configWrapper,
    [FromKeyedServices("Common")] IChatPromptProvider promptTemplateProvider,
    IRagPromptBuilder promptBuilder,
    IResponseWriter saveService,
    IOllamaClientFactory ollamaClientFactory,
    IOllamaGenerationService ollamaProvider)
```

**Fix:** Introduce a small *mediator* or *request-context* object that groups related dependencies:

```csharp
public sealed record GenerationContext(
    IChatPromptProvider Prompt,
    IRagPromptBuilder Builder,
    IResponseWriter Writer,
    IOllamaClientFactory Factory,
    IOllamaGenerationService Provider,
    IOptions<RagnarConfig> Config);

// Constructor becomes:
public sealed class RagOrchestrator(
    Serilog.ILogger logger,
    IOutputWriter writer,
    GenerationContext ctx) : IRagOrchestrator
```

This also removes the `[FromKeyedServices("Common")]` annotation from the consuming class, making it easier to unit-test.

## 3. Duplicate / Conflicting Definitions

`EmbeddingSetupExtension` is defined **twice**:

```csharp
// First occurrence – top-level extension block
extension(IServiceCollection services) { public IServiceCollection EmbeddingSetup() { … } }

// Second occurrence – static class wrapping the same extension block
public static class EmbeddingSetupExtension
{
    extension(IServiceCollection services) { public IServiceCollection EmbeddingSetup() { … } }
}
```

This will cause a compile error (ambiguous extension method) or, if the compiler resolves one, the other is dead. **Fix:** keep only the `static class` form (it's the conventional pattern and plays nicely with namespace imports).

## 4. Mixed Responsibilities (SRP Violations)

### `RagOrchestrator.ExecuteAsync`
Does **four** things in one method:
1. Builds the prompt
2. Calls the LLM
3. Conditionally appends the original prompt to the response
4. Persists the response

**Fix:** Extract steps 3 and 4:

```csharp
public async Task ExecuteAsync(Question q, string ctx, CancellationToken ct)
{
    var sw = Stopwatch.StartNew();
    var prompt  = promptBuilder.WithQuestion(q).WithContext(ctx).Build();
    var response = await GenerateAsync(prompt, ct).ConfigureAwait(false);

    if (configWrapper.Value.ApplicationOptions.IncludeOriginalPrompt)
        response = PromptDecorator.AppendOriginal(response, prompt);

    await SaveResponseAsync(new ResponseRecord(q, response, sw.Elapsed), ct)
        .ConfigureAwait(false);
}
```

### `FileDiscoveryService.GetFilesAsync`
Accepts `IOptions<RagnarConfig>` but only reads `FileLoadOptions`. This couples the discovery service to the entire application config.

**Fix:** Accept `IOptions<FileLoadOptions>` (or just `FileLoadOptions`) directly.

### `NumberedRowDecorator`
Is simultaneously a *renderer*, a *row mutator*, and a *one-shot guard* (`_numbered` flag).

**Fix:** Make it a pure transformation: return a new `ITableRenderer` rather than mutating internal state.

```csharp
public ITableRenderer Decorate()
{
    // Build a new table with the # column, return a new renderer
    return new NumberedTableRenderer(inner.Table, columnHeader);
}
```

## 5. Fragile / Hardcoded Logic

| Location | Smell | Fix |
|---|---|---|
| `CodeParserFactory.ParseAsync` | `fileInfo.Extension switch { ".cs" => …, _ => … }` – only one extension is special-cased; adding a second language requires editing the switch. | Use a `Dictionary<string, IFileParser>` keyed by extension, resolved via DI. New parsers register themselves. |
| `GeneratorExtensions.AsEmbeddingGenerator` | Manual `is not` check + `InvalidCastException` – the method name suggests it *converts*, but it really just *casts*. | Rename to `AsEmbeddingGenerator` → `ToEmbeddingGenerator` (implies no conversion, just a cast) or use `as` + null-check for a clearer message. |

## 6. Concurrency / Thread-Safety Gaps

**`PipelineRunner.ReplaceStage`** does **not** acquire `_gate`:

```csharp
public IPipeline<TContext> ReplaceStage(string oldName, IPipelineStage<TContext> newStage, IAsyncPolicy? policy = null)
{
    var oldIdx = _stages.IndexOf(_stages.Find(x => x.PipelineStage.Name == oldName)); // ← no lock
    if (oldIdx == -1) throw new KeyNotFoundException();
    RemoveStage(oldName);   // acquires lock
    AddStage(newStage, policy); // acquires lock
    return Reorder(newStage.Name, oldIdx); // acquires lock
}
```

Three separate lock acquisitions are not atomic. Another thread can insert a stage between `RemoveStage` and `Reorder`.

**Fix:**

```csharp
public IPipeline<TContext> ReplaceStage(string oldName, IPipelineStage<TContext> newStage, IAsyncPolicy? policy = null)
{
    lock (_gate)
    {
        var oldIdx = _stages.FindIndex(s => s.PipelineStage.Name == oldName);
        if (oldIdx == -1) throw new KeyNotFoundException(oldName);
        _stages.RemoveAt(oldIdx);
        _stages.Insert(oldIdx, new StageEntry<TContext>(newStage, policy));
    }
    return this;
}
```

## 7. Synchronous I/O Inside Async Methods

**`FileDiscoveryService.GetFilesAsync`:**

```csharp
foreach (var path in Directory.EnumerateFiles(directory, "*.*", SearchOption.AllDirectories))
{
    …
    yield return path;
    await Task.Yield();   // ← cooperative yield, not true async I/O
}
```

`Directory.EnumerateFiles` is a synchronous, blocking call. On a large tree it will block the calling thread.

**Fix:** Use `IAsyncEnumerable`-based enumeration (available in .NET 8 via `Directory.EnumerateFilesAsync` if targeting a platform that supports it) or offload to a thread-pool task:

```csharp
public async IAsyncEnumerable<string> GetFilesAsync(
    string directory, FileLoadOptions filter,
    [EnumeratorCancellation] CancellationToken ct)
{
    var all = await Task.Run(
        () => Directory.EnumerateFiles(directory, "*.*", SearchOption.AllDirectories).ToList(), ct);

    foreach (var path in all)
    {
        ct.ThrowIfCancellationRequested();
        if (validator.IsValid(new FileInfo(path), filter))
            yield return path;
    }
}
```

## 8. Inconsistent `ConfigureAwait` Usage

Some `await` calls use `.ConfigureAwait(false)` and others don't:

```csharp
// In RagOrchestrator:
response = await GenerateAsync(request, cancellationToken).ConfigureAwait(false);  // ✅
await SaveResponseAsync(new ResponseRecord(…), cancellationToken).ConfigureAwait(false); // ✅

// In PipelineRunner:
await next().ConfigureAwait(false);  // ✅
// but StageTimingMiddleware:
await next().ConfigureAwait(false);  // ✅
// yet BrandingStage:
return Task.CompletedTask;          // no await, fine

// In FileDiscoveryService:
await Task.Yield();                 // no ConfigureAwait (irrelevant for Task.Yield, but inconsistent style)
```

This is a minor but real consistency smell. **Fix:** Add a project-level analyser rule (e.g. `ConfigureAwait` always-true) or a `.editorconfig` entry:

```
dotnet_diagnostic.CA2007.severity = warning
```

## 9. Over-Engineered Abstractions / YAGNI

| Item | Why it's a smell |
|---|---|
| `IFileParser` interface with two methods, but only one concrete implementation (`ParseCSharpFile`) is used in production. `MarkdownFileParser` is the "generic" fallback. | Two interfaces (`IFileParser`, `IFileParseFactory`) + a factory class for what is effectively a two-branch `if/else`. |
| `IOllamaChatClientBuilder` + `OllamaChatClientBuilderConfigured` | A two-step builder for what is a single object construction. |
| `QuestionFilterSelector` with a `Dictionary<QuestionCategory, IFilterStrategy>` | Only **one** strategy (`XmlCommentFilterStrategy`) is ever registered. The strategy pattern + selector adds indirection without benefit. |

**Fix:** Collapse until a second use-case appears:

```csharp
// Instead of factory + interface + strategy:
public static class QuestionFilters
{
    public static Filter For(QuestionCategory cat, int threshold = 0) => cat switch
    {
        QuestionCategory.XML => new QdrantFilterBuilder()
            .AddRange("CommentLength", threshold)
            .AddExceptKeywords("Category", "Test", "Tests", "Testing")
            .Build(),
        _ => new Filter()
    };
}
```

Re-introduce the strategy/factory pattern when a **second** category strategy is needed.

## 11. Validation Gaps

- **`RagnarConfigValidator`** validates that nested option objects are non-null and delegates to sub-validators, but **`GenerationOptions`** (Temperature, MaxTokens, etc.) is **not** validated at all. A typo'd `Temperature = -5` would flow silently to the LLM call.

  **Fix:** Add a `GenerationOptionsValidator` and wire it in:

  ```csharp
  RuleFor(x => x.GenerationOptions).SetValidator(new GenerationOptionsValidator());
  ```

- **`FileLoadOptionsValidator.ExcludedFiles`** only checks `!string.IsNullOrWhiteSpace(f)`. A path separator or `*` wildcard would slip through.

  **Fix:** Add a check that the value contains no path separators and is a valid file name.

## 12. Error-Handling Anti-Patterns

**`RagOrchestrator.ExecuteAsync`:**

```csharp
catch (Exception ex) when (ex is not OperationCanceledException)
{
    logger.Error(ex, "RAG generation failed for {Question}", question.Text);
    response = "⚠️  Generation failed. Check the Ollama service and retry.";
}
```

The method *swallows* the exception and returns a user-facing string. The caller (`PipelineRunner`) has no way to distinguish a successful answer from a failure message, which breaks the `StageMetric.Success` flag.

**Fix:** Let the exception propagate (the pipeline already wraps stages in try/catch and records `StageMetric.Success = false`). If a graceful fallback is truly needed, log and re-throw a domain-specific `RagGenerationException`.

## 13. Minor / Cosmetic

- **`QuestionsExtensions`** uses C# 13 `extension` blocks *inside* a `static class`, which is redundant nesting. Flatten to a single `static class` with regular `static` methods, or a single top-level `extension` block.
- **`CollectionInfo`** example XML doc is malformed: `<![[CDATA[[var info = …` — missing closing bracket and extra `[`.
- **`PipelineRunner._gate`** is named `_gate` but is a plain `Lock`/`object`. Name it `_syncRoot` for clarity.
- **`StageExecutionContext<TContext>`** is a `record` but has a mutable `Metric` property — defeats the immutability contract of `record`. Either make it a `class` or make `Metric` a `required` init-only property set by the middleware.
