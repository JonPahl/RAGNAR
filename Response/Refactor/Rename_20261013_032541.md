## Structural / File-Level Suggestions

1. **Eliminate the duplicate `EmbeddingSetupExtension.cs`.** Merge into one file with the static class *and* the extension block, or move the extension block into the consuming class. Two files with identical names will confuse IDE navigation.

2. **Rename `QuestionCombineBuilderExtensions.cs`** (the file containing `SetActive`) to `QuestionBuilderExtensions.cs`. Its current name suggests DI registration (matching the XML doc), but the content is a fluent-builder convenience method.

3. **Split `OutputPathHelper`.** Extract `ShowPrompt` into `PromptDisplayExtensions` (or fold it into `IOutputWriter`). A class whose methods are `GetResponseDirectory` and `ShowPrompt` violates the Single Responsibility Principle and the name can't cover both.

4. **Consolidate the two `IQuestionSource`-related builder interfaces.** `IQuestionSourceBuilder` (the aggregator) and `IQuestionBuilder` (the single-question fluent builder) differ by one word. Consider:
   - `IQuestionAggregator` (multi-source, accumulates)
   - `IQuestionFluentBuilder` (single question, returns one `Question`)

5. **Rename the `RagnarConfig` record to `RagnarAppConfig`** or keep as-is but ensure the XML doc explicitly states it is the *root* configuration that composes the four child option records.

## Naming Conventions to Enforce (`.editorconfig` / style)

```ini
# Prefer noun-phrase type names (no leading verb)
dotnet_diagnostic.CS0001.severity = warning   # type names shouldn't read as sentences

# Prefer "I<Domain><Concern>" for interfaces
# e.g. IQdrantPointFactory, not IPointStructFactory

# Prefer <Domain><Role> for classes
# e.g. QdrantCollectionInitializer, not VectorSetup
```

These changes keep the public API surface small while making each name *self-documenting*—a reader should be able to infer the type's role from its name alone, without opening the file.
