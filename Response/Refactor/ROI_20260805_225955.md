### **1. Hardcoded `https: false` in QdrantClient initialization**  
**Location**: `Program.cs`, line in `CreateDefaultBuilder`:  
```csharp
Services.AddSingleton<IQdrantClient, QdrantClient>(ServiceProvider =>
{
    var Options = ServiceProvider.GetRequiredService<IOptions<EmbeddingOptions>>().Value;
    return new QdrantClient(Options.Host, Options.Port, https: false); // ❗
});
```

#### **Why Critical?**
- **Security Risk**: Forces insecure HTTP communication with Qdrant (no TLS), exposing embeddings and code context to MITM attacks—especially dangerous if deployed in production or shared networks.
- **Compliance Violation**: Likely violates security policies (e.g., PCI-DSS, HIPAA, internal standards) that mandate TLS for all data-in-transit.
- **Brittleness**: Hardcoded flag bypasses configuration-driven security; cannot be toggled per environment (dev/staging/prod).
- **Hidden Failure Point**: If Qdrant enforces HTTPS (as newer versions do), the app will fail silently or with cryptic errors.

#### **Remediation Effort**: **Low**  
- Replace `https: false` with `Options.UseHttps` (or similar) from config.
- Add validation in `RegisterOptions` to require `UseHttps = true` in non-dev environments.
- Add integration test verifying TLS handshake.

#### **Impact Score**: **High** (security + reliability)
