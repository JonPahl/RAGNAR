## Quick-Win: Inconsistency Sweep

These are mechanical renames that eliminate the most frequent "which one is which?" confusion:

1. **`*Validation` → `*Validator`** – `ApplicationOptionsValidation` → `ApplicationOptionsValidator`. Every other validator in the codebase already uses `Validator`.
2. **`IWriter` → `IFileWriter`** – Disambiguates from `IOutputWriter` (console) in every `using` statement and DI registration.
3. **`StringExtensions` → `SpanExtensions`** – The `extension(ReadOnlySpan<char>)` block makes it obvious this is *not* a `string` extension. A reader who sees `stringExtensions.cs` will hunt for `string` methods and not find them.
4. **`OllamaChatResponse` → `OllamaGenerationService`** – The class already implements `IOllamaGenerationService`. Having the *class* name and the *interface* name describe the same responsibility (without the `I` prefix) is the conventional C# pattern (`Foo` / `IFoo`).

These changes are all mechanical (search-and-replace + rename), carry no behavioural risk, and can be landed in a single refactoring PR before any further feature work.
