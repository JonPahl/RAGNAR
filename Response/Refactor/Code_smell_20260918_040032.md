## 1. Unreachable / Duplicate Code (Critical)

**File:** `PipelineRunner.cs`

```csharp

{
```

The second catch block is **unreachable** — the first one already handles the identical condition. This is almost certainly a copy-paste accident.

## 2. God Method / Too Many Responsibilities

**File:** `QuestionExecutionStage.cs` → `LoadQuestionsAsync`

```csharp
private async Task<IReadOnlyList<Core.Model.Question>> LoadQuestionsAsync(CancellationToken cancellationToken)
{
    //TODO Make loading questions be its own stage.
    builder.GetCategories().GetFileConfig();
    var pluginDir = Path.Join(AppContext.BaseDirectory, "Plugins");
    await builder.GetCsvFilesAsync(pluginDir, cancellationToken).ConfigureAwait(false);
    builder.WithCategoryFilter();
    var sorted = builder.Build();
    ShowTable(sorted);
    return [[..sorted]];
}
```

This method simultaneously: resolves a path, loads categories, loads config, discovers CSV files, applies filters, builds the final list, **and** renders a console table. The `TODO` comment even acknowledges the problem.

**Fix:** Extract each concern into its own stage or service:

```csharp
// 1. A dedicated QuestionLoadingStage that only discovers + filters
// 2. Move ShowTable into an ITableRenderer or IOutputWriter concern
// 3. LoadQuestionsAsync should only return the list
private async Task<IReadOnlyList<Question>> LoadQuestionsAsync(CancellationToken ct)
{
    builder.GetCategories().GetFileConfig();
    var pluginDir = Path.Join(AppContext.BaseDirectory, "Plugins");
    await builder.GetCsvFilesAsync(pluginDir, ct).ConfigureAwait(false);
    builder.WithCategoryFilter();
    return builder.Build();
}
```

## 4. `NotImplementedException` in Production Code

**File:** `ConsoleTableBuilder.cs`

```csharp
List<string> ITableBuilder.Columns => throw new NotImplementedException();
List<List<string>> ITableBuilder.Rows => throw new NotImplementedException();
```

Throwing `NotImplementedException` in shipped code is a maintenance hazard. If a consumer resolves `ITableBuilder` and accesses these members, the application crashes at runtime with no graceful degradation.

**Fix:** Either implement them (returning the existing data in the expected shape) or remove the explicit implementations and drop the members from `ITableBuilder`:

```csharp
List<string> ITableBuilder.Columns => [[..Columns.Select(c => c)]];
List<List<string>> ITableBuilder.Rows => [[..Rows.Select(r => r.ToList())]];
```

## 5. Tight Coupling to `AnsiConsole` (Testability Smell)

**Files:** `QuestionExecutionStage.ShowTable`, `ParsingStage.ExecuteAsync`

Both call `AnsiConsole.Progress()` / `AnsiConsole.Live()` directly, making it impossible to unit-test the rendering or progress paths without a real console.

**Fix:** Inject an `IProgressReporter` or `IConsoleOutput` abstraction:

```csharp
public interface IProgressReporter
{
    void Start(string title, int maxValue, Action<int> onIncrement);
    void Stop();
}
```

Then `ParsingStage` and `ShowTable` depend on the abstraction, and tests supply a no-op or in-memory implementation.

## 6. Contradictory Directory Handling

**Files:** `PathResolver.cs` vs `ResponseWriter.cs`

`PathResolver.ResolveResponseDirectory` **throws** `DirectoryNotFoundException` when the path doesn't exist:

```csharp
if (!Directory.Exists(responseDir))
    throw new DirectoryNotFoundException(responseDir);
```

But `ResponseWriter.WriteResponseAsync` immediately calls `Directory.CreateDirectory(directory)`:

```csharp
var directory = pathResolver.ResolveResponseDirectory(details.Question.Category);
Directory.CreateDirectory(directory);
```

This is a design contradiction — one component says "fail if missing," the other says "create it."

**Fix:** Pick one policy. If auto-creation is intended, remove the `throw` from `PathResolver` and let `ResponseWriter` (or a dedicated `IDirectoryEnsurer`) handle creation:

```csharp
// PathResolver – just resolve, don't enforce existence
public string ResolveResponseDirectory(QuestionCategory? category)
{
    var baseDir = category?.ToString() ?? nameof(QuestionCategory.Uncategorized);
    return Path.Join(_applicationOptions.SourceDirectory, _applicationOptions.OutputFolder, baseDir);
}
```

## 7. Redundant / Wasted Work in `AssemblyExtensions`

**File:** `AssemblyExtensions.cs`

```csharp
public string? InformationalVersion =>
    asm.GetCustomAttribute<AssemblyInformationalVersionAttribute>()?.InformationalVersion ?? "1.0.0";
```

`GetCustomAttribute` performs reflection on every access. In `ApplicationHeader` this is called once at construction (fine), but the pattern invites repeated calls elsewhere.

**Fix:** Cache it once:

```csharp
public static class AssemblyExtensions
{
    private static readonly Lazy<string> _cachedVersion = new(() =>
        typeof(AssemblyExtensions).Assembly
            .GetCustomAttribute<AssemblyInformationalVersionAttribute>()?.InformationalVersion
            ?? "1.0.0");

    public static string InformationalVersion => _cachedVersion.Value;
}
```

## 8. Overly Broad Exception Swallowing

**File:** `BaseFileParser.ReadFileAsync`

```csharp
catch (Exception ex)
{
    logger.Error(ex, "Failed to read file: {FilePath}", filePath);
    throw new InvalidOperationException($"Could not read file '{filePath}'.", ex);
}
```

Catching `Exception` (beyond the explicit `OperationCanceledException` re-throw) can mask bugs like `OutOfMemoryException` or `StackOverflowException` by wrapping them in a less descriptive `InvalidOperationException`.

**Fix:** Narrow the catch to expected I/O failures:

```csharp
catch (OperationCanceledException) when (cancellationToken.IsCancellationRequested)
{
    throw;
}
catch (IOException ex) when (ex.HResult == 0x20 || ex.HResult == 0x12) // sharing violation / not found
{
    logger.Error(ex, "Failed to read file: {FilePath}", filePath);
    throw new InvalidOperationException($"Could not read file '{filePath}'.", ex);
}
```

## 10. Static Method with Hidden Dependencies

**File:** `QuestionExecutionStage.ShowTable`

```csharp
private static void ShowTable(IReadOnlyList<Core.Model.Question> questions)
{
    var table = new Spectre.Console.Table()...;
    AnsiConsole.Live(table).Start(ctx => { ... });
}
```

It is `static` (so it can't be mocked), yet it depends on the ambient `AnsiConsole`. Combined with smell #5, this is the hardest method in the class to test.

**Fix:** Make it an instance method that calls an injected `ITableRenderer` (which already exists as `ConsoleTableRenderer`). The `ConsoleTableRenderer.Render()` method writes to `AnsiConsole`, so tests can substitute a fake:

```csharp
private void ShowTable(IReadOnlyList<Question> questions)
{
    var builder = tableRenderer.Table
        .AddColumns("#", "Category", "Text")
        .ShowRowSeparators()
        .Expand;
    var i = 0;
    foreach (var q in questions)
    {
        builder.AddRow(i.ToString(), q.Category.ToString(), q.Text);
        i++;
    }
    tableRenderer.Render();
}
```

## 11. Magic Numbers / Hardcoded Paths

**File:** `QuestionExecutionStage.LoadQuestionsAsync`

```csharp
var pluginDir = Path.Join(AppContext.BaseDirectory, "Plugins");
```

The `"Plugins"` segment is a magic string. If the plugin directory name changes, it must be found manually.

**Fix:** Move it into `ApplicationOptions` / `RagnarConfig`:

```json
"ApplicationOptions": { "PluginsDirectory": "Plugins" }
```

## 12. Inconsistent Null-Guard Strategy

Some methods use `Guard.Against.NullOrEmpty`, others use `ArgumentNullException.ThrowIfNull`, and `PathResolver` uses a ternary + `throw new ArgumentNullException`. There is no single idiom.

**Fix:** Standardise on one approach (e.g., `Guard.Against`) across the project and enforce it with a custom analyzer or an `.editorconfig` rule.
