# Top 3 Critical Technical Debt Items

## 1. Plugin Loading Into the Default `AssemblyLoadContext`

**File:** `ApplicationConfigurationExtensions.cs` → `LoadQuestionPlugins()`

```csharp
var assembly = AssemblyLoadContext.Default.LoadFromAssemblyPath(dll);
```

**Impact: Critical / Production-breaking**

Loading plugin DLLs into the **default** ALC is a well-documented .NET anti-pattern with several concrete consequences:

- **Memory leaks:** Plugins can never be unloaded; every restart of the "plugin subsystem" accumulates garbage.
- **Type-identity conflicts:** If two plugins reference `Newtonsoft.Json` at different versions, the CLR resolves one and the other silently fails at runtime (`InvalidCastException`, `MissingMethodException`).
- **Host-process instability:** A single bad plugin can corrupt the default context for the entire process, including the Qdrant client and Ollama HTTP stack.
- **No isolation boundary:** The plugin API surface (`IQuestionSource`) is only as safe as the default ALC's global type cache.

**Remediation effort: Medium (~2–3 days)**

| Step | Detail |
|------|--------|
| 1 | Create a `sealed class PluginLoadContext : AssemblyLoadContext, IDisposable` with `IsCollectible = true`. |
| 2 | Implement `IAssemblyResolver` / `ILibraryResolver` so each plugin resolves its own dependency graph. |
| 3 | Load the plugin, discover types, and **extract only the `IQuestionSource` delegates** before disposing the context handle (or keep a weak ref). |
| 4 | Add an integration test that loads two plugins with a conflicting transitive dependency and asserts both resolve. |

## 2. Shared Mutable `IQuestionBuilder` Corrupted in Loops

**File:** `QuestionCombineBuilder.cs` → `GetCsvFilesAsync`, `GetCsvFileAsync`, `GetFileConfig`

```csharp
foreach (var csv in csvConfigs)
{
    questionBuilder.WithText(csv.Text)
                   .WithFileName(csv.Filename)
                   .SetCategory(csv.Category)
                   .SetActive(csv.IsEnabled);
    Questions.Add(questionBuilder.Build());   // ← builder still holds last item's state
}
```

**Impact: High / Silent data corruption**

`IQuestionBuilder` is injected via DI (scoped or singleton). Each iteration **mutates the same instance**, so:

- If the builder has internal buffers (e.g., a `StringBuilder` for text, a cached `QuestionCategory`), leftover state from iteration *N* can bleed into iteration *N+1*.
- Under concurrent pipeline execution (the `PipelineRunner` supports per-stage retry, and `QuestionPipelineContext` uses `ConcurrentDictionary`), two threads calling `Build()` on the same builder will interleave and return **nondeterministic** questions.
- `GetFileConfig()` has the identical pattern with `new FileConfigLoader()`—bypassing DI and making the loader un-mockable in tests.

**Remediation effort: Low–Medium (~½–1 day)**

1. Obtain a **fresh builder per item**: inject `IQuestionBuilderFactory` (or use `ActivatorUtilities.CreateInstance`) instead of a shared instance.
2. Register `FileConfigLoader` in DI so it can be replaced with a stub in unit tests.
3. Add a unit test that feeds 3 CSV rows with distinct text/category and asserts each `Question` in the output list matches its source row exactly (guards against cross-contamination).

## 3. `NumberedRowDecorator` Duplicates Every Row on Render

**File:** `NumberedRowDecorator.cs` → `Render()`

```csharp
var existing = table.Rows.Select(r => r.ToArray()).ToList();
for (var i = 0; i < existing.Count; i++)
{
    // …builds "indexed" row…
    table.AddRow(row);          // ← ADDS a new row
}
inner.Render();                 // ← renders ALL rows (originals + new)
```

**Impact: Medium / Visible UI defect**

The method **reads** the existing rows into `existing`, then **appends** a numbered copy of each one. It never clears or replaces the originals. The console table therefore shows **2 N rows** (the original unnumbered set followed by the numbered set) on every render. This is user-facing and will be immediately visible in `QuestionShowStage` and `ShowFileStage` output.

**Remediation effort: Low (~1–2 hours)**

```csharp
public void Render()
{
    var table = inner.Table;
    if (!table.Columns.Contains(columnHeader, StringComparer.OrdinalIgnoreCase))
        table.AddColumns(columnHeader);

    var existing = table.Rows.Select(r => r.ToArray()).ToList();
    table.Rows.Clear();                          // ← remove originals first

    for (var i = 0; i < existing.Count; i++)
    {
        var indexed = new string[[table.Columns.Count]];
        indexed[[0]] = (i + 1).ToString();
        for (var c = 0; c < existing[[i]].Length; c++)
            indexed[[c + 1]] = existing[[i]][[c]];

        table.AddRow(indexed.Select(cell => new TableCell(cell)).ToList());
    }
    inner.Render();
}
```

Add a snapshot/arrange-act-assert test that asserts `table.Rows.Count == originalCount` after `Render()`.
