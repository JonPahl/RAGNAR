### ✅ 1. **Per-File Collections / Scoped Indexes for Targeted QA**

#### 🔧 Solution: **Dynamic Collection Switching**
- **Create a per-file sub-collection** (or use *payload filtering*) when a user specifies a file context:

#### 📈 Benefit:

### ✅ 2. **Hybrid Search: Semantic + Keyword + Metadata**
You currently rely *only* on semantic search. Qdrant supports hybrid search via:
- **Dense vectors** (your current approach)
- **Sparse vectors** (BM25 via `HnswQuantization` + `ScalarQuantization`)
- **Payload filters** (e.g., `ElementType == "ClassDeclaration"`)

#### 🔧 Solution: Hybrid Search Pipeline
```csharp
// 1. Embed query → dense vector
var denseVec = await generator.GenerateAsync(query, ct);

// 2. Parse query for keywords → sparse vector (using Qdrant's `Sparse` index)
var sparseVec = SparseVector.FromTerms(query.Tokenize());

// 3. Fuse scores (reciprocal rank fusion or weighted sum)
var results = await qdrantClient.SearchPointsAsync(new SearchPointsRequest
{
    CollectionName = Options.VectorStoreName,
    Vector = new VectorStruct(denseVec),
    SparseVector = sparseVec,
    Filter = new Filter { /* optional: file_name = "Point.cs" */ },
    ScoreThreshold = 0.7f,
    Limit = 10
});
```
> 💡 **Setup**: Enable sparse vectors in Qdrant via `CreateCollection` with `SparseVectors` field.

#### 📈 Benefit:
- Captures *exact term matches* (e.g., "FromFilePathAndIndex") even if semantics are weak.
- Improves recall for technical terms.

### ✅ 3. **Hierarchical Chunking + Parent-Child Retrieval**
You chunk at the *class level* (via `ChunkBySyntaxTree`). But questions often target:
- A single method inside a class
- A property or comment block

#### 🔧 Solution: **Multi-Level Chunking**
1. **Parent chunks**: Full class (current behavior).
2. **Child chunks**: Methods/properties/comments (new).
3. Store parent-child IDs in payload:
   ```csharp
   new PointStruct
   {
       Id = childPointId,
       Vectors = childEmbedding,
       Payload = {
           ["Code"] = methodCode,
           ["ParentId"] = classPointId,
           ["ElementType"] = "MethodDeclaration",
           ["ElementName"] = "FromFilePathAndIndex"
       }
   }
   ```

#### 🔍 Retrieval Strategy:
- **Step 1**: Retrieve top-k parent chunks (classes).
- **Step 2**: For each parent, retrieve top-*m* child chunks (methods) using `ParentId` filter.
- **Step 3**: Rerank combined results.

#### 📈 Benefit:
- Answers *granular* questions like *"What does the `Guard.Against.NullOrWhiteSpace` check do?"* without returning the entire class.

### ✅ 6. **Real-Time Indexing & Incremental Updates**
You currently re-embed *all* files on every run (`CodeEmbeddingPipeline.RunAsync`). Qdrant supports **upserting partial updates**.

#### 🔧 Solution: Incremental Embedding Pipeline
1. On startup, fetch existing point IDs + file hashes from Qdrant.
2. Compare with local file hashes (e.g., `SHA256` of source).
3. Only re-embed changed files:
   ```csharp
   var existing = await qdrantClient.GetPointsAsync(collectionName, pointIds: [fileHash]);
   if (!existing.Any() || !FileMatchesHash(file, existing[0].Payload["hash"]))
   {
       await upsertAsync(file);
   }
   ```

#### 📈 Benefit:
- **100x faster** for large repos (avoids full re-embedding).
- Enables real-time indexing (e.g., VS Code extension triggers updates).
