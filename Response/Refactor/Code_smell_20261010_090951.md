# Code Smells & Remediation for the Ragnar Project

Below is a structured audit of the codebase, grouped by smell type, with concrete fixes.

## 1. Duplicated Code

### 1a. Two `EmbeddingSetupExtension` files
You have **two files** with the same name registering the same services—one as a `static class`, one using the `extension()` keyword. Only one can win at runtime, and the other is dead weight.

**Fix:** Delete the duplicate. Keep a single `static class` (the more discoverable pattern) and register the concrete implementation that you actually want (`OllamaEmbeddingGenerator` vs. `EmbeddingGeneratorService`—pick one).

```csharp
// Keep ONE file
public static class EmbeddingSetupExtension
{
    public static IServiceCollection EmbeddingSetup(this IServiceCollection services)
    {
        services.AddSingleton<IEmbeddingService, OllamaEmbeddingGenerator>();
        services.AddSingleton<IQdrantPointFactory, PointStructFactory>();
        services.AddSingleton<IVectorSetup, VectorSetup>();
        services.AddSingleton<IVectorStoreWriter, VectorStoreWriter>();
        return services;
    }
}
```

### 1b. `CodeParserFactory` – two identical private methods
```csharp
private async Task<IEnumerable<CodeDocument>> ParseFile(...)      => await _codeParser.ParseAsync(...);
private async Task<IEnumerable<CodeDocument>> GetCodeDocumentsAsync(...) => await _codeParser.ParseAsync(...);
```
Both delegate to the exact same call.

**Fix:** Remove one. The `switch` in `ParseAsync` can just call `_codeParser.ParseAsync` directly:

```csharp
public async Task<IEnumerable<CodeDocument>> ParseAsync(string file, CancellationToken ct)
{
    return fileInfo.Extension switch
    {
        ".cs"  => await _codeParser.ParseAsync(file, ct).ConfigureAwait(false),
        _      => await _codeParser.ParseAsync(file, ct).ConfigureAwait(false),
    };
}
```
If the `_` case is truly different in the future, add a second parser then (YAGNI).

### 1c. `QuestionCombineBuilder.GetCsvFileAsync` vs `GetCsvFilesAsync`
The singular method is a one-file special case of the plural method.

**Fix:** Delete `GetCsvFileAsync` and have callers pass a single-element enumeration, or make `GetCsvFilesAsync` accept an optional single-file parameter.

## 3. Inconsistent Extension-Method Patterns

Some files use the C# 13 `extension()` syntax, others use `static class` + `this`:

```
extension(Assembly asm)            ← AssemblyExtensions
extension(IServiceCollection)     ← ApplicationConfigurationExtensions, EmbeddingSetupExtension
static class OutputPathHelper      ← this string ...
static class GeneratorExtensions   ← this IOllamaApiClient ...
static class FileSystemEntryExtensions
static class QuestionCombineBuilderExtensions  ← uses extension(QuestionBuilder)
```

**Fix:** Pick **one** convention project-wide. For a .NET 9+ project, standardise on `extension(T)`:

```csharp
extension(string prompt)
{
    public string ShowPrompt() => $"\n\n***\n[[Original Prompt]]\n{prompt}\n[[/Original Prompt]]***";
}
```

Update `.editorconfig` to enforce it and remove the static classes.

## 6. Misleading / No-Op Class

`NumberedRowDecorator` claims to prepend a row-number column, but its `Render()` method only checks whether the column header exists and then delegates to `inner.Render()`—**it never actually adds row numbers**.

**Fix:** Either implement the row-numbering logic (mutate `Table.Rows` to prepend an index cell before calling `inner.Render()`) or delete the class and let callers add a `#` column explicitly.

## 7. Null-Safety Inconsistency

`QuestionPipelineContext.Questions` is nullable (`IReadOnlyList<Question>?`), yet:

```csharp
// QuestionExecutionStage
public bool ShouldRun(QuestionPipelineContext context) => context.Questions.Any();  // NRE if null
```

Meanwhile `SummarizeSaveResponse` defensively uses `details?.Question?.Filename` everywhere.

**Fix:**
- Make `Questions` **non-nullable** and default to `Empty<IReadOnlyList<Question>>` (or `Array.Empty`). Stages that haven't populated it yet get an empty list, and `Any()` / `Count` work naturally.
- Make `ResponseRecord` a **record with `required` properties** so the compiler enforces non-null:

```csharp
public sealed record ResponseRecord(
    required Question Question,
    required string Answer,
    required string ElapsedTime);
```

Then `SummarizeSaveResponse` can use `details.Question.Filename` without `?.`.

## 8. Pointless Indirection

```csharp
// RagOrchestrator
private async Task<string> GenerateAsync(GenerateRequest req, CancellationToken ct)
    => await ollamaProvider.GenerateResponse(req, ct).ConfigureAwait(false);
```

This is a one-line pass-through. It adds a stack frame and a method to document/maintain for no value.

**Fix:** Inline the call in `ExecuteAsync`:

```csharp
var response = await ollamaProvider.GenerateResponse(request, cancellationToken).ConfigureAwait(false);
```

If the wrapper exists to allow swapping providers, extract an `IResponseGenerator` interface instead—don't hide the dependency behind a private method.

## 9. Hardcoded Retry Policy in `PipelineRunner`

```csharp
CachedPolicy = Policy.Handle<HttpRequestException>()
    .Or<TimeoutException>()
    .WaitAndRetryAsync(3, a => TimeSpan.FromSeconds(Math.Pow(2, a)))
```

Every stage gets the **same** policy with **same** parameters. A file-parse stage and an Ollama HTTP call have very different failure profiles.

**Fix:** Make the policy injectable per-stage:

```csharp
public sealed record PipelineStageEntry<T>(IPipelineStage<T> Stage)
{
    public IPolicyExecutionEngine? CachedPolicy { get; set; } // null = no retry
}

// Registration site
runner.AddStage(ollamaStage, RetryPolicy.Exponential(3, TimeSpan.FromSeconds(1)));
runner.AddStage(parseStage,  null);  // no retry for local file parsing
```

## 10. `QuestionCombineBuilder.Clear()` Returns `bool`

```csharp
public bool Clear()
{
    Questions.Clear();
    return Questions.Count != 0;   // always false after Clear()
}
```

A `Clear` that returns a `bool` is semantically wrong, and the return value is always `false` (you just cleared the list).

**Fix:** Make it `void`, or if you need a "reset to defaults" semantic, call it `Reset()` and return `this` for the builder chain:

```csharp
public IQuestionSourceBuilder Reset()
{
    Questions.Clear();
    return this;
}
```

## 11. Inconsistent DI Registration for the Same Service

- `ApplicationConfigurationExtensions.RegisterEmbeddingServices()` → registers `OllamaEmbeddingGenerator` via a **lambda** (to inject logger + config).
- `EmbeddingSetupExtension.EmbeddingSetup()` → registers `IEmbeddingService, OllamaEmbeddingGenerator` **directly**.

Whichever is called last wins. The first one also pulls in a `Serilog.ILogger` and `IOptions<RagnarConfig>` that the second doesn't.

**Fix:** Register `IEmbeddingService` exactly once. Use the lambda form if you need constructor injection of non-standard services; delete the other.

var content = string.Format(_template, details?.Answer, DateTime.UtcNow.ToString("O"));

var content = $$"""

## 15. Inconsistent `ConfigureAwait(false)` Usage

Some methods consistently use `.ConfigureAwait(false)` (good for library code), others omit it (e.g., `QuestionExecutionStage.ExecuteAsync` has it, but `ShowFileStage.EnumerateStoredFiles` mixes it with `await` without it in the `do/while`).

**Fix:** Pick a policy. For a console app that's not a NuGet library, you can **drop** `ConfigureAwait(false)` entirely for readability, or use a `.editorconfig` / analyser rule (`ConfigureAwait` = `true`) to enforce it uniformly.

## 18. Coupling to Concrete Types in `RagOrchestrator`

The constructor takes `IOllamaClientFactory` and `IOllamaGenerationService`—two Ollama-specific abstractions. If you ever swap to a different LLM backend, you'd have to rewrite `RagOrchestrator`.

**Fix:** Introduce a higher-level abstraction:

```csharp
public interface ITextGenerationService
{
    Task<string> GenerateAsync(string prompt, string system, CancellationToken ct);
}
```

`RagOrchestrator` depends on this; the Ollama implementation is an adapter. This also eliminates the need for `IOllamaClientFactory` in the orchestrator.
