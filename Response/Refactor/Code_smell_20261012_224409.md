# Code Smells in the Ragnar Project

Below is a structured catalogue of the smells I found, grouped by category, each with a concrete remediation.

---

## 1. Duplicated / Redundant Definitions

### 1.1 `EmbeddingSetupExtension` defined twice

One file defines it as a top-level `extension(IServiceCollection services)`, another wraps the same method inside a `static class EmbeddingSetupExtension`. At runtime the compiler will either reject the duplicate or the two will drift apart.

```csharp
// File A – top-level extension
extension(IServiceCollection services)
{
    public IServiceCollection EmbeddingSetup() { … }
}

// File B – static-class extension (duplicate)
public static class EmbeddingSetupExtension
{
    public static IServiceCollection EmbeddingSetup(this IServiceCollection services) { … }
}
```

**Fix:** Keep a single definition. Prefer the C# 14 top-level `extension` form (or the classic static-class form) and delete the other.

---

### 1.2 `CodeParserFactory` – both branches call the same method

```csharp
return fileInfo.Extension switch
{
    ".cs"  => await GetCodeDocumentsAsync(file, ct),
    _      => await ParseFile(file, ct),
};
// GetCodeDocumentsAsync → _codeParser.ParseAsync(file, ct)
// ParseFile             → _codeParser.ParseAsync(file, ct)   ← identical
```

The factory provides **no** dispatch. It's a pass-through that misleads the reader into expecting different parsers per extension.

**Fix:** Either (a) register a `Dictionary<string, IFileParser>` keyed by extension and truly delegate, or (b) collapse to a single `ParseAsync` call and drop the factory indirection:

```csharp
public async Task<IEnumerable<CodeDocument>> ParseAsync(string file, CancellationToken ct)
    => await _codeParser.ParseAsync(file, ct).ConfigureAwait(false);
```

## 2. Single-Responsibility Violations

### 2.1 `PipelineRunner<TContext>` does registration **and** execution **and** reordering **and** metrics

```csharp
public sealed class PipelineRunner<TContext>(Serilog.ILogger logger) : BasePipeline<TContext>
{
    // stage registry  (_stages, AddStage, RemoveStage, Reorder, ReplaceStage, ClearStages)
    // execution engine (ExecuteAsync with retry, logging, timing)
    // thread-safety gate (_gate)
}
```

**Fix:** Split into:

| Class | Responsibility |
|-------|---------------|
| `StageRegistry<TContext>` | Add / Remove / Reorder / Replace / snapshot |
| `PipelineExecutor<TContext>` | Iterate a snapshot, apply Polly policy, log |
| `PipelineRunner<TContext>` | Thin façade composing the two above |

---

### 2.2 `QuestionCombineBuilder` mixes **loading** (I/O, CSV, plugin discovery) with **building** (fluent configuration + `Build()`)

It instantiates `new FileConfigLoader()` internally, reads directories, calls `questionProvider.LoadQuestionsAsync`, *and* maintains a mutable `List<Question>` that callers mutate via `AddQuestion`.

**Fix:**

```csharp
// Loader side (I/O)
public sealed class QuestionLoader(
    IQuestionSource provider,
    IQuestionCatalogLoader catalog,
    IQuestionBuilder builder,
    IOptions<RagnarConfig> opts)
{
    public async Task<IReadOnlyList<Question>> LoadAllAsync(
        string? csvDir, CancellationToken ct) { … }
}

// Builder side (pure in-memory composition)
public sealed class QuestionBuilder2
{
    private readonly List<Question> _qs = [[]];
    public QuestionBuilder2 WithCategories(IEnumerable<QuestionCategory> cats) { … }
    public IReadOnlyList<Question> Build() { … }
}
```

## 3. Tight Coupling / Missing Abstraction

### 3.1 Concrete types registered in DI

```csharp
services.AddSingleton<IEmbeddingService, OllamaEmbeddingGenerator>();
services.AddSingleton<IQdrantPointFactory, PointStructFactory>();
services.AddSingleton<IVectorSetup, VectorSetup>().AddSingleton<IVectorStoreWriter, VectorStoreWriter>();
```

If the project ever supports a non-Ollama embedding backend, every call-site that resolves `IEmbeddingService` is fine, but the *registration* hard-codes the provider. Worse, `GeneratorExtensions.AsEmbeddingGenerator` does a runtime `is` check and throws `InvalidCastException`—a design that fights the abstraction.

**Fix:**

```csharp
// config-driven provider selection
services.AddSingleton<IEmbeddingService>(sp =>
{
    var opts = sp.GetRequiredService<IOptions<RagnarConfig>>();
    return opts.Value.EmbeddingOptions.Provider switch
    {
        "ollama" => new OllamaEmbeddingGenerator(sp),
        "openai" => new OpenAiEmbeddingGenerator(sp),
        _ => throw new NotSupportedException()
    };
});
```

Remove `GeneratorExtensions.AsEmbeddingGenerator` entirely; let DI do the casting.

public IQuestionSourceBuilder GetFileConfig()

## 4. Inconsistent Patterns

### 4.1 Two extension-method styles coexist

| Style | Example |
|-------|---------|
| C# 14 `extension(T)` | `extension(IServiceCollection services) { … }` |
| Classic `static class` + `this` | `public static class OutputPathHelper { public static string …(this …) }` |

Both appear in the same codebase. Pick one convention (I'd recommend C# 14 `extension` blocks if you target .NET 10+) and convert the rest.

---

### 4.2 Inconsistent `ConfigureAwait(false)` usage

`QuestionCombineBuilder.GetCsvFilesAsync` and `PipelineRunner.ExecuteAsync` consistently call `.ConfigureAwait(false)`, but `BrandIngStage.ExecuteAsync`, `QuestionShowStage.ExecuteAsync`, and `NumberedRowDecorator.Render` do not (where async methods exist).

**Fix:** Adopt a project-wide rule (typically: **always** in class libraries, **never** in UI / top-level-await code) and enforce it with an analyser (`ConfigureAwaitChecker` or `StyleCop SA1201`).

---

### 4.3 Inconsistent async return for "synchronous" work

```csharp
// BrandingStage – purely synchronous, but returns Task
public Task ExecuteAsync(EmbeddingContext context, CancellationToken ct)
{
    header.RenderBranding();
    return Task.CompletedTask;
}
```

**Fix:** If `IPipelineStage<T>.ExecuteAsync` must return `Task`, that's fine as an interface contract. But document it, and consider a `TryExecuteSync` fast-path to avoid the allocation.

## 6. Thread-Safety / Concurrency Issues

### 6.1 `PipelineRunner._gate` protects `_stages`, but `ExecuteAsync` takes a snapshot and then **releases the lock** before iterating. Any concurrent `AddStage` during execution is silently ignored (or the snapshot is stale).

```csharp
lock (_gate)
    snapshot = [[.._stages]];
// lock released here
for (var i = 0; i < snapshot.Count; i++) { … }
```

This is *acceptable* if documented ("stages are frozen at the moment of execution"), but it's not stated.

**Fix:** Add a clear `[[ThreadStatic]]` or `volatile bool _isRunning` flag, or document the "frozen snapshot" semantics in the XML doc and add a unit test that verifies `AddStage` during `ExecuteAsync` does not corrupt the running pipeline.

### 6.2 `NumberedRowDecorator.Render()` **mutates** the table it decorates

```csharp
public void Render()
{
    var table = inner.Table;
    if (!table.Columns.Contains(columnHeader, …))
        table.AddColumns(columnHeader);          // mutation
    for (var i = 0; i < existing.Count; i++)
    {
        …
        table.AddRow(row);                        // mutation (adds duplicate rows!)
    }
    inner.Render();
}
```

If `Render()` is called **twice**, the index column is added again and rows are duplicated. Decorators should be side-effect-free (or at minimum idempotent).

**Fix:**

```csharp
public void Render()
{
    var table = inner.Table;
    var existingRows = table.Rows.Select(r => r.ToArray()).ToList();

    // Build a *new* table or clone, rather than mutating
    var decorated = table.Clone();              // or construct fresh
    if (!decorated.Columns.Contains(columnHeader, OrdinalIgnoreCase))
        decorated.AddColumns(columnHeader);

    for (var i = 0; i < existingRows.Count; i++)
        decorated.AddRow(new[[]] { (i + 1).ToString() }
            .Concat(existingRows[[i]]).ToArray());

    AnsiConsole.Write(decorated);
}
```

## 7. Validation / Guard Clauses

### 7.1 Inconsistent null-guarding

- `GeneratorExtensions.AsEmbeddingGenerator` → `Guard.Against.Null(api)`
- `IFileValidator.IsValid` → documented `<exception cref="ArgumentNullException">` but no guard in the interface
- `FileDiscoveryService.GetFilesAsync` → `Guard.Against.Null(filter); Guard.Against.NullOrEmpty(directory);`
- `QuestionCombineBuilder.GetCsvFileAsync` → no guard on `csvFile`

**Fix:** Enforce a single convention. Use `Guard.Against.*` at every public entry point (or `[[NotNull]]` attributes + a runtime analyser), and add `<exception>` docs consistently.

---

### 7.2 `[[Required]]` on record properties that are also validated by FluentValidation

```csharp
public record FileLoadOptions
{
    [[Required]]
    public HashSet<string> AllowedExtensions { get; init; } = …;
    …
}
```

`[[Required]]` is an **MVC / binding** attribute. In a CLI tool there's no model-binding pipeline, so it's dead metadata. The real validation lives in `FileLoadOptionsValidator`.

**Fix:** Remove `[[Required]]` and rely solely on the FluentValidation validator (or a `RequiredMember` C# 13 `required` modifier if you want compile-time enforcement).

## 8. Dead / Misleading Code

### 8.1 `QuestionFilterSelector` registry has exactly one entry

```csharp
private static readonly ImmutableDictionary<QuestionCategory, IFilterStrategy> _strategies
    = ImmutableDictionary<QuestionCategory, IFilterStrategy>.Empty
        .Add(QuestionCategory.XML, new XmlCommentFilterStrategy());
```

The "strategy + registry" pattern is over-engineered for a single known strategy. It also hard-codes the strategy instance (not injectable, not testable).

**Fix:** If you expect multiple strategies, register them via DI:

```csharp
public sealed class QuestionFilterSelector(
    IEnumerable<IFilterStrategy> strategies)
{
    private readonly Dictionary<QuestionCategory, IFilterStrategy> _map
        = strategies.ToDictionary(s => s.SupportedCategory);

    public Filter FindFilter(QuestionCategory cat, int threshold = 0)
        => _map.TryGetValue(cat, out var s) ? s.CreateFilter(threshold) : new();
}
```

If you don't, inline the one strategy and drop the indirection.

## 9. Naming & Cohesion

### 9.1 `ApplicationConfigurationExtensions` only loads question plugins

The class name implies broad configuration, but it contains one method: `LoadQuestionPlugins()`.

**Fix:** Rename to `QuestionPluginExtensions` or fold the method into an existing DI extension class.

### 9.2 `QuestionCombineBuilder` vs `QuestionBuilder` vs `FilterBuilder` – three "builder" concepts

- `QuestionBuilder` – fluent setter for a **single** question
- `QuestionCombineBuilder` – aggregates many questions from many sources
- `FilterBuilder` – builds a Qdrant `Filter`

They are unrelated but share the `*Builder` suffix, creating cognitive load.

**Fix:** Rename to make the distinction explicit:

| Current | Suggested |
|---------|-----------|
| `QuestionBuilder` | `QuestionSpec` (it builds a spec, not an action) |
| `QuestionCombineBuilder` | `QuestionAggregator` / `QuestionCollector` |
| `FilterBuilder` | `FilterExpressionBuilder` (fine, but group under a `Qdrant/` namespace) |

## 10. Exception Handling

### 10.1 Plugin loading swallows all exceptions

```csharp
catch (Exception ex)
{
    AnsiConsole.MarkupLine($"[[red]]Failed to load plugin: {dll}[[/]]");
    AnsiConsole.MarkupLine($"[[dim]]{ex.Message}[[/]]");
}
```

A `SecurityException` or `BadImageFormatException` gets the same cosmetic treatment as a missing constructor. Also, `ex.StackTrace` is lost.

**Fix:**

```csharp
catch (Exception ex) when (ex is not OperationCanceledException)
{
    AnsiConsole.MarkupLine($"[[red]]✗ {Path.GetFileName(dll)}: {ex.GetType().Name}[[/]]");
    AnsiConsole.MarkupLine($"[[dim]]{ex.Message}[[/]]");
    AnsiConsole.MarkupLine($"[[grey50]]{ex.StackTrace?.Split('\n')[[0]]}[[/]]");
    logger.Warning(ex, "Plugin load failed: {Dll}", dll);
}
```

### 10.2 `QuestionCombineBuilder.Build()` throws `InvalidOperationException` with a compound message

```csharp
0 => throw new InvalidOperationException(
    "QuestionCombineBuilder produced zero questions. " +
    "Check categories, file paths, and CSV sources."),
```

This is a **business-rule failure**, not an "invalid operation". A custom exception (`EmptyQuestionSetException`) is more precise and lets callers differentiate.

## 11. Missing Cancellation

### 11.1 `QuestionShowStage.ExecuteAsync` checks cancellation once, then renders synchronously

```csharp
public async Task ExecuteAsync(QuestionPipelineContext context, CancellationToken cancellationToken)
{
    cancellationToken.ThrowIfCancellationRequested();
    TableRendererFactory.Create()
        .WithColumns("#", "Category", "Text")
        .WithRows(context.Questions.Select((f, i) => …))
        …
        .Render();          // ← synchronous, potentially large table
}
```

If the table has 10 000 rows the render blocks the thread and the user cannot cancel.

**Fix:** If `TableRenderer` supports async, use it. Otherwise, chunk the rendering and check the token between chunks.

## 12. Inconsistent Record vs Class

| Type | Kind | Why it matters |
|------|------|----------------|
| `RagnarConfig` | record | value equality, `with`-expression support |
| `EmbeddingOptions` | record | ✓ |
| `FileLoadOptions` | record | ✓ |
| `GenerationOptions` | record | ✓ |
| `QuestionPipelineContext` | **class** | mutable bag – acceptable, but inconsistent with the options records |

`QuestionPipelineContext` is a mutable context object, so a class is justified. But the project should **document** the convention: *"Option DTOs are records; mutable runtime contexts are classes."* Add this to the `.editorconfig` or a `CONTRIBUTING.md`.
