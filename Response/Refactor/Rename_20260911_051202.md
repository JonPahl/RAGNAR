## 2. Method Names

| Current | Proposed | Why |
|---|---|---|
| `VectorStoreBuilder.BuildAsync()` | `EnsureCollectionExistsAsync()` | "Build" is overloaded. The method checks existence and creates the collection – a self-documenting name removes the need to read the body. |
| `VectorStoreBuilder.MakeIndexAsync()` | `CreatePayloadIndexAsync()` | "Make" is informal; "Create" matches the Qdrant client verb and is more precise. |
| `OllamaClientFactory.FindClient()` | `GetClient()` | "Find" implies a search or lookup that may fail. `GetOrAdd` in `ConcurrentDictionary` is a *creation* path. `GetClient` is idiomatic in .NET. |
| `IQuestionAggregator.GetCategories()` | `AddFromCategories()` | Builder-pattern convention: mutating methods start with `Add`/`With`. `Get` implies a pure retrieval that returns a new object. |
| `IQuestionAggregator.GetCsvFilesAsync()` | `AddCsvFilesAsync()` | Same reasoning. |
| `IQuestionAggregator.GetCsvFileAsync()` | `AddCsvFileAsync()` | Same. |
| `IQuestionAggregator.GetFileConfig()` | `AddFromFileConfig()` | Same. |
| `ApplicationConfigurationExtensions.LoadQuestionPlugins()` | `RegisterQuestionPlugins()` | The method calls `services.AddTransient(...)`. "Register" is the DI idiom; "Load" is misleading. |
| `EmbedTextPipeline.ShowTable()` | *(move to a decorator or separate `IProgressReporter`)* | A side-effecting UI method inside a pipeline orchestrator violates SRP. If it must stay, rename to `ReportDiscoveredFiles()` to make the intent clear. |
| `StringExtensions.LastFolder` (property) | `GetLastFolder()` (method) | It performs work (`Path.GetFileName` + `TrimEnd`). A property should be a cheap field access. (If C# 14 extension blocks make it feel like a method, that's fine – just keep the verb.) |
| `OllamaChatResponse.GenerateResponse()` | `CompleteAsync()` or `GenerateCompletionAsync()` | "Response" appears twice (class + method). `Complete` is the industry-standard verb for LLM chat completion. |
| `IResponseWriter.WriteResponseAsync()` | `WriteAsync()` | The interface is already `IResponseWriter`; repeating "Response" is redundant. |
| `IOutputFormatter.Format()` | `Render()` or `FormatMarkdown()` | "Format" is ambiguous (culture formatting? layout?). `Render` makes it clear you're producing a display string. |

## 4. Structural / Naming-Smell Recommendations

### 4a. Split `OllamaChatResponse` (God-class smell)

The class mixes three concerns:
1. Building `RequestOptions` (temperature, tokens, context window)
2. Streaming tokens into a `StringBuilder`
3. Rendering a live `Spectre.Console` panel

Consider:
```
IChatCompletionService          // abstraction
  └─ OllamaChatCompletionService  // builds request, streams tokens
       uses IStreamRenderer       // Spectre panel, progress, etc.
```
This lets you swap the console renderer for a test double without pulling in `AnsiConsole`.

### 4b. `EmbedTextPipeline` has a TODO to adopt `IPipelineStage`

When you do that rename, the stage classes already follow a good pattern:

```
IPipelineStage
  ├─ BrandingStage
  ├─ IngestionStage        ← was EmbedTextPipeline
  ├─ QuestionProcessingStage
  └─ SummarizationStage
```

Make `IngestionStage` the name so every stage is a noun describing *what happens*, not *what it uses* (Ollama, text, etc.).

### 4c. `IKnowledgeBaseInitialize` → `IKnowledgeBaseOrchestrator`

The three methods (`InitializeVectorStoreAsync`, `RunEmbeddingPipelineAsync`, `AskQuestionsAsync`) are a *sequence*, not an "initialization." An orchestrator name sets the expectation that it coordinates other services.

### 4d. Config hierarchy

```
RagnarConfig                  // root
  ├─ ApplicationOptions      // paths, store name, categories
  ├─ EmbeddingOptions        // model, dim, timeout, host, port
  ├─ OllamaOptions           // model, timeout, host, port
  └─ FileLoadOptions         // extensions, exclusions
```

`EmbeddingOptions` and `OllamaOptions` both carry `Host`, `Port`, `Timeout`. Consider a shared `EndpointOptions` base so the duplication is visible and the naming is consistent:

```
EndpointOptions               // Host, Port, Timeout
  ├─ OllamaEndpointOptions   // + LlmModel
  └─ EmbeddingEndpointOptions // + EmbeddingModel, Dimension
```

### 4e. `IQuestionEmbedding` split

This is the single most confusing name in the codebase. Split into:

```csharp
// "What do I need to ask the vector store?"
public interface IVectoretrievalService
{
    Task<string> RetrieveContextAsync(string collection, ReadOnlyMemory<float> queryVector, Filter? filter, CancellationToken ct);
    Task<ReadOnlyMemory<float>> EmbedQueryAsync(string text, CancellationToken ct);
}

// "What do I need to ask the LLM?"
public interface IChatCompletionService
{
    Task<string> CompleteAsync(GenerateRequest request, CancellationToken ct);
}
```

Then a higher-level `IQuestionAnswerService` orchestrates both. The names now describe *what the caller cares about* (retrieve context, complete a prompt, answer a question) rather than the implementation detail (Ollama, embedding).
