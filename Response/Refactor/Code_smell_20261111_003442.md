## 2. **Inconsistent Validation / Null-Handling**

### `FileLoadOptionsValidator.cs`
```csharp
RuleFor(x => x.ExcludedFiles)
    .Must(files => files.All(f => !string.IsNullOrWhiteSpace(f)))
```
If `ExcludedFiles` is `null`, `.All()` will throw a `NullReferenceException` instead of producing a validation error.

**Fix:**
```csharp
RuleFor(x => x.ExcludedFiles)
    .Must(files => files is null || files.All(f => !string.IsNullOrWhiteSpace(f)))
    .WithMessage("ExcludedFiles entries must be non-empty file names.");
```

### `QdrantFilterBuilder.cs`
```csharp
public QdrantFilterBuilder AddShouldMatch(string field, string value)
{
    GuardField(field);          // field is validated
    // value is NOT validated — inconsistent with AddMatch/AddExclusion
    _should.Add(Conditions.MatchKeyword(field, value));
    return this;
}
```
**Fix:** Add `Guard.Against.Null(value, nameof(value));` to match the sibling methods.

### `AddExceptKeywords(IEnumerable<string>)` overload
Individual keywords are never checked for null/whitespace, unlike the `params` overload path which also doesn't check them. A null keyword will propagate into Qdrant and produce an opaque server error.

**Fix:**
```csharp
public QdrantFilterBuilder AddExceptKeywords(string field, IEnumerable<string> keywords)
{
    GuardField(field);
    Guard.Against.Null(keywords, nameof(keywords));
    var list = keywords as IReadOnlyCollection<string> ?? keywords.ToList();
    Guard.Against.NullOrEmpty(list, nameof(keywords));
    if (list.Count == 0) return this;
    list.ForEach(k => Guard.Against.NullOrWhiteSpace(k, nameof(keywords)));
    // ...
}
```

## 3. **Thread-Safety / Concurrency Bugs**

### `PipelineRunner.ReplaceStage` — missing lock
```csharp
public IPipeline<TContext> ReplaceStage(string oldName, IPipelineStage<TContext> newStage, IAsyncPolicy? policy = null)
{
    var oldIdx = _stages.IndexOf(_stages.Find(x => x.PipelineStage.Name == oldName)); // ← no lock
    if (oldIdx == -1) throw new KeyNotFoundException();
    RemoveStage(oldName);   // acquires lock
    AddStage(newStage, policy); // acquires lock
    return Reorder(newStage.Name, oldIdx); // acquires lock
}
```
The `IndexOf`/`Find` call reads `_stages` **without** `_gate`, so a concurrent `AddStage` or `Reorder` can mutate the list mid-read → `InvalidOperationException` or stale index.

**Fix:**
```csharp
public IPipeline<TContext> ReplaceStage(string oldName, IPipelineStage<TContext> newStage, IAsyncPolicy? policy = null)
{
    int oldIdx;
    lock (_gate)
    {
        oldIdx = _stages.FindIndex(x => x.PipelineStage.Name == oldName);
        if (oldIdx == -1)
            throw new KeyNotFoundException($"Stage '{oldName}' not found.");
        _stages.RemoveAt(oldIdx);
    }

    AddStage(newStage, policy);
    return Reorder(newStage.Name, oldIdx);
}
```

### `JsonFileFingerprintStore` — lock + `Task.Yield` anti-pattern
```csharp
public async Task<bool> IsUnchangedAsync(string filePath, string sha256, CancellationToken ct)
{
    bool result;
    lock (_gate)
        result = _fingerprints.TryGetValue(filePath, out var stored) && stored == sha256;
    await Task.Yield();   // ← pointless: no I/O, just forces a context switch
    return result;
}
```
`Task.Yield()` here adds an async state-machine hop with zero benefit (the dictionary lookup is a single lock-protected read). It also makes the method look "expensive" in profilers.

**Fix:** Make it a synchronous helper or remove the `async`/`await`:
```csharp
public Task<bool> IsUnchangedAsync(string filePath, string sha256, CancellationToken ct)
{
    ct.ThrowIfCancellationRequested();
    lock (_gate)
    {
        return Task.FromResult(_fingerprints.TryGetValue(filePath, out var stored) && stored == sha256);
    }
}
```

## 5. **Misleading / Inconsistent Naming & API Design**

### `IFileEligibilityValidator.IsValid` — `in` on a reference type
```csharp
bool IsValid(FileInfo file, in FileLoadOptions fileLoadOptions);
```
`FileLoadOptions` is a `record` (reference type). The `in` modifier only makes sense for value types (prevents copies). On a reference type it's a no-op that misleads readers into thinking the argument is a struct.

**Fix:** Drop `in`:
```csharp
bool IsValid(FileInfo file, FileLoadOptions fileLoadOptions);
```

### `FileDiscoveryService` — ignores `ExcludedDirectories`
```csharp
foreach (var path in Directory.EnumerateFiles(directory, "*.*", SearchOption.AllDirectories))
```
The `FileLoadOptions.ExcludedDirectories` field is documented as "directories to skip", but `GetFilesAsync` never consults it — it relies entirely on the injected `IFileEligibilityValidator`. If the validator only checks extension + filename, excluded directories will still be traversed (wasted I/O).

**Fix:** Either filter at enumeration time (skip sub-trees) or document clearly that the validator is the sole gate. A more efficient approach:
```csharp
foreach (var dir in Directory.EnumerateDirectories(directory))
{
    if (filter.ExcludedDirectories.Contains(Path.GetFileName(dir), StringComparer.OrdinalIgnoreCase))
        continue;
    // recurse
}
```

### `CodeParserFactory` — only first extension used as key
```csharp
_byExt = parsers.ToDictionary(p => p.SupportedExtensions[[0]], StringComparer.OrdinalIgnoreCase);
```
If a parser declares `[[".cs", ".csx"]]`, only `.cs` is indexed. `.csx` files fall through to the `MarkdownFileParser` default.

**Fix:**
```csharp
_byExt = parsers
    .SelectMany(p => p.SupportedExtensions.Select(e => (Ext: e, Parser: p)))
    .ToDictionary(x => x.Ext, x => x.Parser, StringComparer.OrdinalIgnoreCase);
```

## 6. **Magic Defaults / Hidden Fallback**

### `CodeParserFactory`
```csharp
if (!_byExt.TryGetValue(ext, out var parser))
{
    parser = new MarkdownFileParser(options, logger);  // silent fallback
}
```
An unknown extension silently becomes Markdown. This can mask misconfigured `AllowedExtensions` (e.g., a typo `".c#"` never matches, falls back to Markdown parser, produces garbage embeddings).

**Fix:** Log a `Warning` or `Error`, or make the fallback configurable via `RagnarConfig`:
```csharp
if (!_byExt.TryGetValue(ext, out var parser))
{
    if (options.Value.ParserFallback == ParserFallbackPolicy.Markdown)
        parser = new MarkdownFileParser(options, logger);
    else
        throw new NotSupportedException($"No parser registered for extension '{ext}'.");
}
```

### `EnumConverter` — silent fallback
```csharp
return Enum.TryParse<QuestionCategory>(value, out var match)
    ? match
    : QuestionCategory.Uncategorized;   // silently swallows bad data
```
**Fix:** Log a warning at minimum:
```csharp
if (!Enum.TryParse<QuestionCategory>(value, out var match))
{
    logger?.LogWarning("Unrecognized category '{Raw}'; defaulting to Uncategorized", value);
    return QuestionCategory.Uncategorized;
}
```

## 7. **Unnecessarily Generic / Over-Engineered Signatures**

### `StageTimingMiddleware.Invoke<TContext>`
```csharp

    where TContext : class
```
The method only touches `context.Stage.Name`, `context.StageIndex`, `context.StageTotal`, and `context.Metric`. The generic parameter adds a constraint and a type parameter that carry zero information.

public async Task Invoke(StageExecutionContextBase context, Func<Task> next, CancellationToken ct)

(Requires extracting a small `IStageMetadata` interface from `StageExecutionContext`.)

## 9. **Retry Policy Allocated Per Access**

### `DeltaEmbedStage.RetryPolicy`
```csharp
public AsyncRetryPolicy? RetryPolicy =>
    Polly.Policy.Handle<HttpRequestException>()
                .Or<TimeoutException>()
                .WaitAndRetryAsync([[...]], (attempt, ts, ex, _) => ...);
```
Every property **get** constructs a new policy object. `PipelineRunner` accesses it via `entry.AsyncPolicy` (cached at `StageEntry` construction), but if any code reads `stage.RetryPolicy` directly multiple times, it allocates redundantly.

**Fix:** Cache in a field:
```csharp
private readonly AsyncRetryPolicy _retryPolicy =
    Polly.Policy.Handle<HttpRequestException>()
                .Or<TimeoutException>()
                .WaitAndRetryAsync([[...]], (a, ts, ex, _) => ...);

public AsyncRetryPolicy? RetryPolicy => _retryPolicy;
```

## 10. **`TryBuild` uses null-forgiving operator**

```csharp
public bool TryBuild(out Filter filter)
{
    if (IsEmpty)
    {
        filter = null!;   // suppresses nullable warning; caller can't distinguish "empty" from "real null"
        return false;
    }
    filter = Build();
    return true;
}
```
**Fix:** Use a nullable out parameter properly:
```csharp
public bool TryBuild([[NotNullWhen(true)]] out Filter? filter)
{
    if (IsEmpty) { filter = null; return false; }
    filter = Build();
    return true;
}
```

## 11. **`FileLoadOptionsValidator` — Overly Restrictive Extension Rule**

```csharp
.Must(exts => exts.All(e => !string.IsNullOrWhiteSpace(e) && e.Length > 1 && e[[0]] == '.'))
```
This rejects valid single-letter extensions (unlikely but possible) and — more practically — rejects `".CS"` if the validator runs before the `OrdinalIgnoreCase` comparer in `FileLoadOptions` normalises casing. The rule is also duplicated at the data layer (`FileLoadOptions` already constrains via the `HashSet` comparer).

**Fix:** Keep validation to the non-empty + starts-with-dot check, and let the `OrdinalIgnoreCase` comparer handle casing. Avoid double-enforcing format in two places.
