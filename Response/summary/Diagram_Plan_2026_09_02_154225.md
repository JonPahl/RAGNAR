## 4. Step-by-Step Implementation

### Step 1 — Add Polly (P0)
- `dotnet add package Microsoft.Extensions.Http.Resilience`
- Create `Resilience/RetryPolicy.cs` + `CircuitBreakerPolicy.cs` with a single `ResiliencePipeline` configured from `RagnarConfig.Resilience`.
- Register in `ApplicationConfigurationExtensions` via `AddStandardResilienceHandler()` on the `HttpClient` used by `OllamaApiClient`, and wrap every `IQdrantClient` call in `VectorStoreRepository` with `pipeline.ExecuteAsync`.

### Step 2 — Raise `BATCHSIZE` + parallel upserts (P0)
- Move `BATCHSIZE` to `EmbeddingOptions` (`{ "BatchSize": 16, "MaxParallelism": 4 }`) read from `appsettings.json`.
- Replace the sequential `foreach` in `UpsertInBatchesAsync` with:
  ```csharp
  await Parallel.ForEachAsync(batches,
      new ParallelOptions { MaxDegreeOfParallelism = options.MaxParallelism, CancellationToken = ct },
      async (batch, c) => await client.UpsertAsync(batch, c));
  ```
- Guard with a semaphore if you need to cap Ollama concurrent embedding requests.

### Step 3 — Parallel summarization (P1)
- In `SummaryService`, materialize `IReadOnlyList<(string folder, Question q)>` up front.
- Replace the nested `foreach` with `Parallel.ForEachAsync(pairs, new ParallelOptions { MaxDegreeOfParallelism = 4 }, ...)`.
- Collect `OllamaChatResponse` results into a thread-safe `ConcurrentDictionary<string, string>` keyed by `folder|question`.

### Step 4 — Plugin isolation (P1)
- Add `RagnarPluginContext : AssemblyLoadContext(isCollectible: true)` in `PluginLoader.cs`.
- `LoadQuestionPlugins` creates **one context per DLL**, `LoadFromAssemblyPath`s the plugin, discovers `IQuestionProvider` types, instantiates them, and registers via DI.
- Expose `Release(Assembly asm)` → `RagnarPluginContext.Unload()` + `GC.GetMemoryLoad()` for diagnostics.
- This enables hot-reload on config reload or `/reload` command.

### Step 5 — `PipelineOrchestrator` (P2)
```csharp
public sealed class PipelineOrchestrator
{
    private readonly IReadOnlyList<IPipelineStage> _stages;
    public PipelineOrchestrator(IReadOnlyList<IPipelineStage> stages) => _stages = stages;

    public async Task RunAsync(IProgress<PipelineProgress>? progress = null, CancellationToken ct = default)
    {
        using var activity = ActivitySource.Create("ragnar.pipeline").StartActivity();
        for (int i = 0; i < _stages.Count; i++)
        {
            using var span = Activity.Current?.StartActivity($"stage:{_stages[i].Name}");
            progress?.Report(new PipelineProgress(i, _stages.Count, _stages[i].Name, "running"));
            await _stages[i].ExecuteAsync(ct);
            progress?.Report(new PipelineProgress(i, _stages.Count, _stages[i].Name, "done"));
        }
    }
}
```
- Wire `IProgress<PipelineProgress>` into each stage for per-stage %, elapsed time, current file.

### Step 6 — Ollama health check (P2)
- Add to `OllamaClientFactory`:
  ```csharp
  private static readonly ConcurrentDictionary<OllamaServiceType, bool> _verified = new();
  public async Task<bool> VerifyReachableAsync(OllamaServiceType type, CancellationToken ct = default)
  {
      return await _verified.GetOrAdd(type,
          async t => (await _http.GetAsync($"http://{host}/api/version", ct)).IsSuccessStatusCode);
  }
  ```
- Call from `EmbeddingStage.ExecuteAsync` before the first batch; throw a descriptive `InvalidOperationException` on failure.

### Step 7 — `IQdrantClient : IAsyncDisposable` (P3)
- Add `ValueTask DisposeAsync()` to the interface; implement by closing the gRPC `Channel`.
- Propagate `await using` through `VectorStoreRepository` and `VectorStoreBuilder` so channels don't leak on error paths.

### Step 8 — Observability (P2)
- Define `ActivitySource RagnarSource = new("ragnar")`.
- Every `IPipelineStage.ExecuteAsync` starts a child `Activity`.
- For long loops (embedding batches, summarization), emit `Activity.AddEvent` per unit of work.
- CLI can opt into `ConsoleExportActivityListener` for verbose runs.

## 7. Risk & Mitigation Notes

- **Ollama rate-limit under parallelism** → cap embedding concurrency with a `SemaphoreSlim` shared by `EmbeddingStage`; surface `429` through the retry policy with exponential backoff.
- **Collectible ALC + DI** → ensure plugin types are **not** captured in the host service provider. Register them in a *scoped* provider that's disposed on `Release()`.
- **gRPC channel churn** → keep a single channel per `VectorStoreRepository` lifetime; only close on `DisposeAsync`.
- **Backward compatibility** → keep `BATCHSIZE = 1` as a valid config value for environments with constrained GPUs; all new APIs are *additive* (no existing signatures change).

This plan keeps the existing interfaces intact, attacks the two biggest wall-clock costs first (sequential embedding + serial summarization), and lays a clean foundation for observability and hot-reload without any breaking API changes.
