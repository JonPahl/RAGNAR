### 🔥 1. `SummaryAgent.LoadFolderContentsAsync()` (String Concatenation & Memory Pressure)
**Current Code:**
```csharp
var contents = await Task.WhenAll(files.Select(async file => { ... }));
return $"{AppDefaults.CODE_BLOCK_START} " + string.Concat(contents) + AppDefaults.CODE_BLOCK_END;
```
**Why it's a hot path:** 
- `string.Concat(string[])` allocates one massive string in the Large Object Heap (LOH) if the total size exceeds ~85KB. This causes GC pressure and potential fragmentation.
- `File.OpenText()` + `ReadToEndAsync()` loads entire files into memory without buffering control.
- Already parallelized (`Task.WhenAll`), but lacks degree-of-parallelism control and streaming capabilities.

**Optimization Strategy:**
Use `IAsyncEnumerable<string>` for streaming, `ArrayPool<byte>`/`Memory<T>` for buffered I/O, and avoid intermediate string allocations.

```csharp
// .NET 10 optimized version
public async IAsyncEnumerable<string> StreamFolderContentsAsync(string folder, [EnumeratorCancellation] CancellationToken ct)
{
    var files = Directory.EnumerateFiles(folder);
    var pool = ArrayPool<byte>.Shared;
    
    await foreach (var filePath in files.WithCancellation(ct))
    {
        using var fs = new FileStream(filePath, FileMode.Open, FileAccess.Read, FileShare.Read, 
                                        bufferSize: 81920, useAsync: true); // Larger buffer reduces allocations
        var buffer = pool.Rent(65536);
        try
        {
            var span = buffer.AsSpan();
            int bytesRead;
            while ((bytesRead = await fs.ReadAsync(span.Slice(0, Math.Min(fs.Length - fs.Position, buffer.Length)), ct)) > 0)
            {
                // Process with Span<char> if needed (e.g., encoding conversion)
                yield return $"---\n{Path.GetFileName(filePath)}\n";
                yield return Encoding.UTF8.GetString(span[..bytesRead]);
            }
        }
        finally => pool.Return(buffer);
    }
}
```
**Parallelization Note:** If you must load everything at once, cap concurrency to avoid disk thrashing:
```csharp
var semaphore = new SemaphoreSlim(Environment.ProcessorCount * 2);
var tasks = files.Select(async file => { await semaphore.WaitAsync(ct); try { return await ReadFileAsync(file, ct); } finally => semaphore.Release(); });
return string.Concat(await Task.WhenAll(tasks));
```

### 🔥 2. `ResponseWriter.FormatFile()` (StringBuilder & String Formatting)
**Current Code:**
```csharp
var response = new StringBuilder();
response.AppendLine($"{Detail.Question.MarkdownHeader}");
// ... multiple Appends/AppendLine calls
return response.ToString();
```
**Why it's a hot path:** 
- `StringBuilder` internally uses char arrays that resize dynamically. If called frequently in a tight loop, reallocations cause GC churn.
- String interpolation inside `AppendLine` creates temporary strings before appending.

**Optimization Strategy:**
Use `Memory<char>` with pre-sized buffers or `Span<T>` formatting to eliminate intermediate allocations:

```csharp
public string FormatFile(SaveDetails Detail)
{
    // Pre-calculate exact size to avoid resizing
    int estimatedSize = Detail.Question.MarkdownHeader.Length + 
                        30 + // "> **Date Generated**: " + date
                        12 + // "> ## Question: \n> "
                        Detail.Question.Text.Length + 
                        28 + // "> **Method Call Duration**: " + duration
                        16 + // " ## Response: \n"
                        Detail.Response.Length;

    var buffer = new char[estimatedSize];
    var span = buffer.AsSpan();
    int offset = 0;

    offset += Detail.Question.MarkdownHeader.CopyTo(span.Slice(offset));
    offset += $"> **Date Generated**: {DateTime.Now:G}".CopyTo(span.Slice(offset));
    // ... continue with Span<T> CopyTo or Utf8Formatter for UTF-8 output
    return new string(buffer);
}
```
*Note:* If markdown generation is not in a microsecond-critical path, stick with `StringBuilder` but call `EnsureCapacity()` once upfront.
