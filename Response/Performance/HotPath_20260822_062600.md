### 🔥 1. `SummaryAgent.LoadFolderContentsAsync` (Critical: Race Condition + Allocation Heavy)
**Current Issue:**
- **Race Condition:** `ArrayPool<char>.Shared.Rent(8192)` is rented *outside* the parallel loop. Multiple threads will concurrently read/write to the same buffer, causing data corruption or `IndexOutOfRangeException`.
- **Dynamic List Growth:** `List<string>` grows dynamically, causing hidden allocations and cache misses.
- **String Chaining:** `$"---\n[RESPONSE_FILE]{...}\n{text}\n"` creates multiple intermediate strings per file.

**Optimized Approach:**
Rent buffers per-task, pre-allocate the result array, and use `string.Create` with a span-based factory for zero-allocation assembly until the final string is materialized.

```csharp
private static async Task<string> LoadFolderContentsAsync(string folder, CancellationToken ct)
{
    var files = Directory.GetFiles(folder);
    if (files.Length == 0) return "No items to summary. Please ignore.";

    // Pre-allocate exact-sized array for thread-safe parallel writes
    var results = new string[files.Length];
    
    await Parallel.ForEachAsync(files, new ParallelOptions { CancellationToken = ct }, async (file, token) =>
    {
        // Rent buffer INSIDE the loop to avoid race conditions
        var buffer = ArrayPool<char>.Shared.Rent(8192);
        try
        {
            using var reader = File.OpenText(file);
            var sb = new StringBuilder();
            int bytesRead;
            while ((bytesRead = await reader.ReadAsync(buffer.AsMemory(), token)) > 0)
                sb.Append(buffer.AsSpan(0, bytesRead));

            // Format with span to avoid intermediate allocations
            results[Array.IndexOf(files, file)] = string.Create(sb.Length + 45, (sb, name) =>
            {
                var span = new Span<char>(new char[sb.Length + 45]);
                $"---\n[RESPONSE_FILE]{name}[/RESPONSE_FILE]\n".AsSpan().CopyTo(span);
                sb.ToString().AsSpan().CopyTo(span["---\n[RESPONSE_FILE]".Length..]);
            }, Path.GetFileName(file));
        }
        finally { ArrayPool<char>.Shared.Return(buffer); }
    });

    // Single allocation for final concatenation
    return string.Create(results.Sum(s => s.Length) + 16, results, (span, arr) =>
    {
        var written = 0;
        "[RESPONSE_CODE] ".AsSpan().CopyTo(span);
        foreach (var s in arr)
        {
            s.AsSpan().CopyTo(span[written..]);
            written += s.Length;
        }
        "[/RESPONSE_CODE]".AsSpan().CopyTo(span[written..]);
    });
}
```

### 🔥 2. `QdrantSearchService.FormatContext` (Medium: Iterator Allocation + Span Overhead)
**Current Issue:**
- `.Select(p => p.Payload.ToObject())` creates an iterator allocation per call.
- Manual char array management is good, but if the estimate is wrong, it either wastes memory or truncates data.
- `new string(span.AsSpan(0, written))` forces a full copy at the end.

**Optimized Approach:**
Remove `.Select()`, use direct iteration, and leverage `Memory<T>` for async-safe boundaries. If you know the approximate payload size, pre-calculate exactly to avoid resizing logic.

```csharp
private static string FormatContext(IReadOnlyList<ScoredPoint> results)
{
    // Avoid .Select() allocation; iterate directly
    var estimatedSize = results.Count * 256;
    var memory = new Memory<char>(new char[estimatedSize]);
    var span = memory.Span;
    int written = 0;

    foreach (var point in results)
    {
        var payload = point.Payload.ToObject(); // Direct access, no iterator
        
        var remaining = span.Slice(written);
        if (!remaining.TryWrite($"File Name: {payload.FileName} | Type: {payload.Type} | Element: {payload.ElementName}\n{payload.Code}\n", out var charsWritten))
            break; // Or handle resize gracefully
            
        written += charsWritten;
    }

    // Return as ReadOnlyMemory<T> if passing to async methods, or string if final output
    return memory.Slice(0, written).ToString();
}
```
💡 *Note:* If `results.Count` is highly variable, consider using a `PooledBuffer<char>` (from `System.Buffers`) which handles dynamic resizing with zero allocations until the final slice.

### 🔥 3. `ResponseWriter.FormatFile` (Low/Medium: StringBuilder Overhead)
**Current Issue:**
`StringBuilder` is excellent for unknown-length appends, but here you know the exact structure. It still incurs internal buffer management and thread-safety checks.

**Optimized Approach:**
Use `string.Create` with a span-based factory. This pushes all formatting to the stack/heap in one pass with zero intermediate allocations.

```csharp
private static string FormatFile(SaveDetails detail)
{
    // Pre-calculate exact length for zero-allocation formatting
    int totalLength = 
        detail.Question.MarkdownHeader.Length + 1 +
        $"> **Date Generated**: {DateTime.Now:G}".Length + 2 +
        "> ## Question: \n> ".Length + detail.Question.Text.Length + 2 +
        $"**Method Call Duration**: {detail.Duration}".Length + 3 +
        " ## Response: \n".Length + detail.Response.Length;

    return string.Create(totalLength, (detail, now) =>
    {
        var span = new Span<char>(new char[totalLength]);
        int offset = 0;

        // Fast span-based writes
        detail.Question.MarkdownHeader.AsSpan().CopyTo(span[offset..]); offset += detail.Question.MarkdownHeader.Length;
        $"\n> **Date Generated**: {now:G}\n".AsSpan().CopyTo(span[offset..]); offset += $"\\n> **Date Generated**: {now:G}\\n".Length;
        "> ## Question: \n> ".AsSpan().CopyTo(span[offset..]); offset += 17;
        detail.Question.Text.AsSpan().CopyTo(span[offset..]); offset += detail.Question.Text.Length;
        $"\n> **Method Call Duration**: {detail.Duration}\n".AsSpan().CopyTo(span[offset..]); offset += $"\\n> **Method Call Duration**: {detail.Duration}\\n".Length;
        " ## Response: \n".AsSpan().CopyTo(span[offset..]); offset += 15;
        detail.Response.AsSpan().CopyTo(span[offset..]);
    }, DateTime.Now);
}
```

### 📊 Parallelization & Span/Memory Guidelines for .NET 10
| Technique | Best For | Your Codebase Application |
|-----------|----------|---------------------------|
| `Parallel.ForEachAsync` | I/O-bound or CPU-bound loops with independent iterations | ✅ Already used in `SummaryAgent`. Fix the buffer race condition first. |
| `Span<T>` | Stack-only, short-lived data, zero-allocation parsing/formatting | ✅ Use for string formatting, XML comment filtering, and path slicing. |
| `Memory<T>` | Heap-allocated, async-safe boundaries, passing data across `await` | ✅ Use when returning formatted context from async methods or caching embeddings. |
| `ArrayPool<T>` | High-frequency allocation of fixed-size buffers | ✅ Rent *inside* parallel loops or use `ThreadLocal<T>`. Never share across tasks. |
