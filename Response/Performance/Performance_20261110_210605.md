## 1. **FileDiscoveryService** – Full-Tree Enumeration + Per-File `FileInfo` Syscall

```csharp
// PROBLEM: Enumerates EVERY file in the entire tree, then checks each one.
// For a monorepo with 50k+ files, this is O(N) syscalls for FileInfo
// even though you may only need .cs files.
foreach (var path in Directory.EnumerateFiles(directory, "*.*", SearchOption.AllDirectories))
{
    var fi = new FileInfo(path);          // ← syscall per file
    if (!validator.IsValid(fi, filter))   // ← extension check happens AFTER enumeration
```

**Fix:** Prune excluded directories *during* the walk and filter by extension from the path string (avoids the `FileInfo` allocation and syscall for every ineligible file):

```csharp
public async IAsyncEnumerable<string> GetFilesAsync(
    string directory, IOptions<RagnarConfig> options,
    [[EnumeratorCancellation]] CancellationToken ct)
{
    var filter = options.Value.FileLoadOptions;
    var allowed = filter.AllowedExtensions;          // HashSet – O(1) Contains
    var excludedDirs = filter.ExcludedDirectories;   // HashSet – O(1) Contains
    var excludedFiles = filter.ExcludedFiles;        // HashSet – O(1) Contains

    async IAsyncEnumerable<string> Walk(string dir)
    {
        foreach (var sub in Directory.EnumerateDirectories(dir))
        {
            var folderName = Path.GetFileName(sub);
            if (!excludedDirs.Contains(folderName)) // prune early
            {
                await foreach (var f in Walk(sub).WithCancellation(ct))
                    yield return f;
            }
        }

        foreach (var path in Directory.EnumerateFiles(dir))
        {
            var ext = Path.GetExtension(path);
            if (!allowed.Contains(ext)) continue;    // string compare, no syscall
            var name = Path.GetFileName(path);
            if (excludedFiles.Contains(name)) continue;
            yield return path;
            await Task.Yield();
        }
    }

    await foreach (var f in Walk(directory).WithCancellation(ct))
        yield return f;
}
```

> **Impact:** Eliminates `FileInfo` construction (each one is a kernel call) for every file that doesn't match, and stops descending into `bin/`, `obj/`, `node_modules/`, etc. before enumerating their contents.

## 3. **JsonFileFingerprintStore** – Full-Dictionary Serialization on Every Flush & `RemoveAsync`

```csharp
// PROBLEM A: RemoveAsync persists the ENTIRE dictionary to disk on every call.
// In a batch-delete scenario (e.g. 2 000 files removed) this means 2 000 full
// JSON serializations + disk writes.
public async Task RemoveAsync(string filePath, CancellationToken ct)
{
    lock (_gate)
        _fingerprints.Remove(filePath);
    await PersistAsync(ct);   // ← full serialize + write every single call
}

// PROBLEM B: PersistAsync serializes the whole dict under no lock,
// but a concurrent RecordAsync could mutate _fingerprints mid-serialize.
private async Task PersistAsync(CancellationToken ct)
{
    string snapshot;
    lock (_gate)
        snapshot = JsonSerializer.Serialize(_fingerprints, _jsonOption); // CPU-bound inside lock
    await File.WriteAllTextAsync(_filePath, snapshot, ct);
}
```

**Fix:** Batch removals like `RecordAsync` does, and move serialization outside the critical section:

```csharp
private int _dirtyCount;
private const int FlushThreshold = 256;

public async Task RemoveAsync(string filePath, CancellationToken ct)
{
    bool shouldFlush;
    lock (_gate)
    {
        _fingerprints.Remove(filePath);
        shouldFlush = ++_dirtyCount >= FlushThreshold;
        if (shouldFlush) _dirtyCount = 0;
    }
    if (shouldFlush)
        await PersistAsync(ct);
}

private async Task PersistAsync(CancellationToken ct)
{
    string snapshot;
    lock (_gate)
        snapshot = JsonSerializer.SerializeToUtf8Bytes(_fingerprints, _jsonOption);

    // Write asynchronously without holding the lock
    await File.WriteAllBytesAsync(_filePath, snapshot, ct).ConfigureAwait(false);
}
```

> Additionally, consider an **append-only WAL** (write-ahead log) for the hot path and a periodic full-compaction, which avoids rewriting the entire JSON on every threshold hit.

## 4. **PipelineRunner.ReplaceStage** – Three Separate Lock Acquisitions (Non-Atomic)

```csharp
// PROBLEM: RemoveStage, AddStage, Reorder each acquire _gate independently.
// Between the three calls, another thread could observe an inconsistent
// stage list (stage removed but not yet re-added).
public IPipeline<TContext> ReplaceStage(string oldName, IPipelineStage<TContext> newStage, IAsyncPolicy? policy = null)
{
    var oldIdx = _stages.IndexOf(_stages.Find(x => x.PipelineStage.Name == oldName)); // ← no lock
    // …
    RemoveStage(oldName);   // lock #1
    AddStage(newStage, policy); // lock #2
    return Reorder(newStage.Name, oldIdx); // lock #3
}
```

**Fix:** Perform the swap in a single critical section:

```csharp
public IPipeline<TContext> ReplaceStage(string oldName, IPipelineStage<TContext> newStage, IAsyncPolicy? policy = null)
{
    lock (_gate)
    {
        var oldIdx = _stages.FindIndex(s => s.PipelineStage.Name == oldName);
        if (oldIdx == -1)
            throw new KeyNotFoundException(oldName);
        if (_stages.Any(x => x.PipelineStage.Name == newStage.Name) && oldIdx /* not self */)
            throw new ArgumentException($"Stage '{newStage.Name}' is already registered.");
        _stages[[oldIdx]] = new StageEntry<TContext>(newStage, policy);
    }
    return this;
}
```

## 5. **QdrantFilterBuilder** – Dead Code & Redundant Allocation

```csharp

// PROBLEM B: CloneCondition is declared but never called.
private static Condition CloneCondition(Condition c) => c.Clone();

// PROBLEM C: TryBuild checks IsEmpty, then calls Build() which checks IsEmpty AGAIN.
public bool TryBuild(out Filter filter)
{
    if (IsEmpty) { filter = null!; return false; }
```

**Fix:** Remove `_shouldMust` and `CloneCondition`. Make `Build` an internal `BuildCore` that skips the guard, and have `Build` call it:

```csharp
public Filter Build()

        throw new InvalidOperationException("…");
    return BuildCore();
}

public bool TryBuild(out Filter filter)
{
    if (IsEmpty) { filter = null!; return false; }
    filter = BuildCore();
    return true;
}

private Filter BuildCore() => new()
{
    Must = { _must }, MustNot = { _mustNot }, Should = { _should }
```

## 6. **PipelineRunner.ExecuteStageWithMiddlewareAsync** – Closure Allocation Per Stage

```csharp
// PROBLEM: For every stage, a new List snapshot is copied AND a new
// closure is allocated for each middleware in the chain.
// With 5 stages × 3 middlewares = 15 closure allocations per pipeline run.
for (var i = snapshot.Count - 1; i >= 0; i--)
{
    var mw = snapshot[[i]];
    var nextRef = pipeline;
    pipeline = () => mw(ctx, nextRef, ct);   // ← new delegate per stage
}
```

For a CLI tool this is negligible, but if the pipeline runs in a loop (e.g. processing many directories), pre-allocate the chain:

```csharp
// Pre-build the onion ONCE at construction / middleware-registration time
// and reuse the delegate for every stage (ctx changes, but the closure
// shape is identical).  This is a micro-optimization; the main win is
// avoiding the per-stage List copy via a ref struct or pinned array.
```
