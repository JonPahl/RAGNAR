### The Issue: Synchronous I/O and Memory Pressure

In `SummaryAgent.cs`, the method `LoadFolderContentsAsync` contains two major bottlenecks:

1.  **Synchronous Directory Scanning:**
    ```csharp
    var files = Directory.GetFiles(Folder);
    ```
    `Directory.GetFiles` is a synchronous call that blocks the calling thread while it scans the file system. If the folder contains thousands of files, this will block the thread pool and spike memory usage by loading all paths into an array simultaneously.

2.  **Memory Explosion (String Concatenation):**
    ```csharp
    var contents = await Task.WhenAll(files.Select(async file => { ... }));
    return $"{AppDefaults.CODE_BLOCK_START} " + string.Concat(contents) + AppDefaults.CODE_BLOCK_END;
    ```
    This code reads the content of *every* file in the directory into memory, stores them in a `string[]` array, and then concatenates them. If you point this at a large project folder (e.g., 50MB+ of source code), this will cause:
    *   High Memory Usage (Raw bytes + String objects + Concatenated result).
    *   Garbage Collection pauses.
    *   Potential `OutOfMemoryException`.

### The Fix

You should use **`Directory.EnumerateFiles`** to avoid blocking the thread and loading all paths into memory at once. Additionally, using a **`StringBuilder`** is more efficient than concatenating an array of strings.

Here is the optimized code for `LoadFolderContentsAsync`:

```csharp
private async Task<string> LoadFolderContentsAsync(string Folder, CancellationToken Ct)
{
    // 1. Use EnumerateFiles to avoid blocking the thread and loading all paths into memory immediately.
    // We convert to List here only because we need to check for existence (Any) before processing.
    var files = Directory.EnumerateFiles(Folder).ToList();

    if (!files.Any())
        return "No items to summarize. Please ignore.";

    // 2. Use StringBuilder to accumulate content efficiently without creating intermediate string arrays.
    var builder = new StringBuilder();

    // Note: If you strictly need parallelism for speed, you would need a thread-safe collection 
    // or process in batches. For most "summarize" use cases, sequential processing with async I/O 
    // is sufficient and safer for memory management.
    
    foreach (var file in files)
    {
        using var reader = File.OpenText(file);
        var text = await reader.ReadToEndAsync(Ct);
        
        builder.AppendLine($"---\n{AppDefaults.FILE_MARKER_START}{Path.GetFileName(file)}{AppDefaults.FILEMARKEREND}\n{text}\n");
    }

    return $"{AppDefaults.CODE_BLOCK_START} {builder.ToString()} {AppDefaults.CODE_BLOCK_END}";
}
```
