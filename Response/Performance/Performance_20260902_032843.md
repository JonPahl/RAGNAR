# Performance Issues and Fixes

## Critical: `VectorStoreRepository.UpsertBatchAsync` — Premature Return

This is the most severe issue. The `return` statement sits **inside** the `foreach` loop, so only the **first** document is ever processed.

```csharp
// ❌ PROBLEM: return exits after the first iteration
public async Task<UpdateResult> UpsertBatchAsync(CodeDocument[[]] codeDocuments, CancellationToken cancellationToken)
{
    foreach (var doc in codeDocuments)
    {
        // ... work ...
        return points.Count > 0
            ? await qdrantClient.UpsertAsync(...)
            : new UpdateResult { Status = UpdateStatus.UnknownUpdateStatus };  // ← exits loop
    }
    return new UpdateResult { Status = UpdateStatus.Completed };
}
```

**Fix:** Generate all embeddings in parallel, then upsert in a true batch:

```csharp
public async Task<UpdateResult> UpsertBatchAsync(CodeDocument[[]] codeDocuments, CancellationToken cancellationToken)
{
    cancellationToken.ThrowIfCancellationRequested();

    // Parallelize embedding generation
    var tasks = codeDocuments.Select(async doc =>
    {
        var text = $"Context: {doc.ElementName}\nCode:\n{doc.Code}";
        var vector = await embeddingService.GenerateAsync(text, cancellationToken);
        return generatorService.BuildPointStructs(doc.AsPoint(), vector.ToArray(), doc);
    });

    var allPoints = (await Task.WhenAll(tasks)).SelectMany(p => p).ToList();

    if (allPoints.Count == 0)
        return new UpdateResult { Status = UpdateStatus.UnknownUpdateStatus };

    try
    {
        return await qdrantClient.UpsertAsync(_appOptions.VectorStoreName, allPoints, cancellationToken);
    }
    catch (Exception ex) when (ex is not OperationCanceledException)
    {
        logger.Fatal(ex, "Failed to upsert embeddings to Qdrant.");
        return new UpdateResult { Status = UpdateStatus.UnknownUpdateStatus };
    }
}
```

## High: `EmbedTextPipeline` — `BATCHSIZE = 1` Defeats Batching

```csharp

```

Each "batch" triggers a separate `UpsertBatchAsync` call, a progress refresh, and a cancellation check. With hundreds of documents this is hundreds of round-trips to Qdrant.

**Fix:**

```csharp
private const int BATCHSIZE = 32; // or derive from embedding model limits
```

## High: `OllamaChatResponse` — Per-Token UI Refresh

Every streamed token triggers two `ctx.UpdateTarget` calls and a `ctx.Refresh()`, which re-renders the entire Spectre panel. At 50–100 tokens/sec this is hundreds of full panel re-renders per second.

```csharp
// ❌ PROBLEM: refresh on every single token
await foreach (var token in client.SendAsAsync(...))
{
    completeText.Append(Markup.Escape(token));
    panelText = new Markup(completeText.ToString(), Styles.Yellow);  // allocates every token
    ctx.UpdateTarget(panel);
    ctx.UpdateTarget(panelText);
    ctx.Refresh();                                                    // full re-render
}
```

**Fix — throttle refreshes and avoid per-token string allocation:**

```csharp
const int REFRESH_EVERY = 10; // tokens
int sinceRefresh = 0;

await foreach (var token in client.SendAsAsync(...))
{
    if (token is null) throw new ArgumentException("null response is null");
    completeText.Append(Markup.Escape(token));
    sinceRefresh++;

    if (sinceRefresh >= REFRESH_EVERY)
    {
        panelText = new Markup(completeText.ToString(), Styles.Yellow);
        ctx.UpdateTarget(panel);
        ctx.UpdateTarget(panelText);
        ctx.Refresh();
        sinceRefresh = 0;
    }
}
// final render after the loop
panelText = new Markup(completeText.ToString(), Styles.Yellow);
ctx.UpdateTarget(panel);
ctx.UpdateTarget(panelText);
ctx.Refresh();
```

The same throttling should be applied to the `OnThink` handler.

## Medium: `SummaryService` — N×M Sequential API Calls

```csharp
foreach (var folder in folders)            // N folders
{
    foreach (var question in summaryQuestions)  // M questions
    {
        var agent = new ContentSummarizerAgent(...);  // new agent each time
        var response = await AskAgentAsync(folder, question, ct);  // sequential
        await SaveResponseAsync(...);
    }
}
```

For 5 folders × 2 questions that's 10 **sequential** LLM calls, each taking 5–30 s. Total wall-time ≈ 50–300 s.

**Fix — run folder-question pairs in parallel (bounded):**

```csharp
var pairs = folders.SelectMany(f => summaryQuestions, (f, q) => (f, q)).ToList();

await Parallel.ForEachAsync(pairs,
    new ParallelOptions { MaxDegreeOfParallelism = 3, CancellationToken = cancellationToken },
    async ((folder, question), token) =>
    {
        var agent = new ContentSummarizerAgent(_ollamaAIClient, _ollamaClientProvider, _summaryPrompt);
        var response = await agent.AskAgent(folder, question.Text, token);
        var fileName = $"{folder.LastFolder}_{question.Filename}";
        await SaveResponseAsync(response, responseDir, "summary", fileName, token);
    });
```

Also consider caching the `ContentSummarizerAgent` instead of constructing one per call if it holds shared HTTP clients.

## Medium: `FileValidator.IsValid` — O(N) `StartsWith` per Excluded Dir

```csharp
var isNotExcludedByDir = !FileLoadOptions.ExcludedDirectories.Any(
    exclDir => dir.Equals(exclDir, ...) ||
               dir.StartsWith($"{exclDir}{Path.DirectorySeparatorChar}", ...));
```

For each file, this scans the entire exclusion list with a string allocation (`$"{exclDir}{sep}"`). With deep directory trees and many exclusions this adds up.

**Fix — precompute normalised exclusion paths and use `OrdinalIgnoreCase` span-based comparison:**

```csharp
// In FileLoadOptions or a cache:
private static readonly HashSet<string> _normalisedExcludedDirs = new(StringComparer.OrdinalIgnoreCase);

static void Normalise(ref HashSet<string> dirs)
{
    var copy = new HashSet<string>(dirs, StringComparer.OrdinalIgnoreCase);
    foreach (var d in copy)
        _normalisedExcludedDirs.Add(d.TrimEnd(Path.DirectorySeparatorChar, Path.AltDirectorySeparatorChar).ToLowerInvariant());
}

public bool IsValid(FileInfo file, in FileLoadOptions opts)
{
    var dir = (file.DirectoryName ?? "").Replace('\\', '/').ToLowerInvariant();
    // ...
    var isNotExcludedByDir = !_normalisedExcludedDirs.Any(
        exclDir => dir == exclDir || dir.StartsWith(exclDir + '/', StringComparison.Ordinal));
    // ...
}
```

## Low: `StringExtensions.LastFolder` — Unnecessary `ToString()` on a Span

```csharp
public string LastFolder => Path.GetFileName(value.ToString().TrimEnd('/', '\\'));
```

`value` is already a `ReadOnlySpan<char>`. Calling `.ToString()` allocates a new string just to call `TrimEnd` and then `Path.GetFileName` which scans the whole thing.

**Fix:**

```csharp
public string LastFolder
{
    var span = value.TrimEnd('/', '\\');
    var lastSep = Math.Max(span.LastIndexOf('/'), span.LastIndexOf('\\'));
    var name = (lastSep == -1) ? span : span.Slice(lastSep + 1);
    return name.ToString();
}
```

## Low: `OllamaEmbeddingService` — Per-Call `CancellationTokenSource` Allocation

```csharp
private CancellationTokenSource CreateTimeoutCts(CancellationToken parent)
{
    var cts = CancellationTokenSource.CreateLinkedTokenSource(parent);
    cts.CancelAfter(config.Value.EmbeddingOptions.Timeout);
    return cts;
}
```

Every `GenerateAsync` / `GenerateBatchAsync` call allocates a linked CTS and its registration. Under heavy batch workloads (thousands of documents) this is a measurable GC pressure.

**Fix — use `HttpClient.Timeout` (already set in the factory) and drop the per-call CTS:**

```csharp
public async Task<ReadOnlyMemory<float>> GenerateAsync(string input, CancellationToken ct)
{
    Guard.Against.NullOrWhiteSpace(input);
    var result = await _generator.GenerateAsync(input, cancellationToken: ct);
    return result.Vector;
}
```

The `HttpClient.Timeout` configured in `OllamaClientFactory.CreateHttpClient` already enforces the timeout.
