### 🔍 1. String & Character Processing (Allocation & Bounds Check Elimination)
#### `StringExtensions.CharacterCount()`
Iterating by index over a `string` forces bounds checking on every access and prevents some JIT optimizations. Converting to `ReadOnlySpan<char>` eliminates bounds checks, improves cache locality, and enables faster SIMD/vectorization in modern .NET runtimes.

**Before:**
```csharp
public int CharacterCount()
{
    var count = 0;
    var insideTag = false;
    for (var i = 0; i < xmlComment.Length; i++)
    {
        var c = xmlComment[i]; // Bounds check per iteration
        // ...
    }
    return count;
}
```

**After (`Span<T>`):**
```csharp
public static int CharacterCount(this ReadOnlySpan<char> xmlComment)
{
    int count = 0;
    bool insideTag = false;
    foreach (ref readonly char c in xmlComment) // Zero bounds checks, JIT-friendly
    {
        if (c == '<') { insideTag = true; continue; }
        if (c == '>') { insideTag = false; continue; }
        if (!insideTag && c != '/' && !char.IsWhiteSpace(c)) count++;
    }
    return count;
}
```

#### `FileSystemEntryExtensions.HasAllowedExtension()`
`Path.GetExtension()` allocates a new string. When scanning thousands of files, this creates significant GC pressure.

**Before:**
```csharp
public static bool HasAllowedExtension(this FileSystemEntry entry, IReadOnlyCollection<string> allowedExtensions) => 
    !entry.IsDirectory && allowedExtensions.Contains(Path.GetExtension(entry.FileName.ToString()), StringComparer.OrdinalIgnoreCase);
```

**After (`Span<T>` + Allocation-Free Comparison):**
```csharp
public static bool HasAllowedExtension(this FileSystemEntry entry, IReadOnlyCollection<string> allowedExtensions)
{
    if (entry.IsDirectory) return false;
    
    ReadOnlySpan<char> fileName = entry.FileName.ToString().AsSpan();
    int lastDot = fileName.LastIndexOf('.');
    if (lastDot < 0 || lastDot == fileName.Length - 1) return false; // No extension
    
    ReadOnlySpan<char> ext = fileName.Slice(lastDot);
    
    foreach (var allowed in allowedExtensions)
    {
        if (ext.Equals(allowed.AsSpan(), StringComparison.OrdinalIgnoreCase)) return true;
    }
    return false;
}
```

### ⚡ 2. Parallelization Opportunities

### ✅ Recommendations & Caveats
1. **Profile First**: Use `dotnet-counters`, `PerfView`, or BenchmarkDotNet to confirm these are actual bottlenecks before refactoring.
2. `Span<T>` vs `Memory<T>`: 
   - Use `Span<T>` for stack-only, short-lived operations (parsing, formatting, validation).
   - Use `Memory<T>` if you need to pass buffers across async boundaries or store them in fields.
3. **Parallelization Overhead**: Parallelizing small workloads can hurt performance due to thread pool contention. Stick to `AsParallel()` for >10k items or CPU-bound loops, and use `async`/`await` with batching for I/O/GPU paths.
4. **Console Output**: `AnsiConsoleOutputWriter` is inherently sequential and sync-heavy. Do not parallelize it; keep it on the main thread to avoid garbled output.
