### 🔴 1. Critical: `ArrayPool` Leak & Inefficient String Building in `SummaryAgent`
**Location:** `LoadFolderContentsAsync` method  
**Issue:** 
- `ArrayPool<char>.Shared.Rent(8192)` is **never returned**, causing pool starvation and memory leaks under load.
- Collecting strings into a `List<string>` and then using `string.Concat()` creates multiple intermediate allocations.
- Unbounded parallel file reads can cause I/O thrashing on mechanical drives.

**Fix:**
```csharp
private static async Task<string> LoadFolderContentsAsync(string Folder, CancellationToken Ct)
{
    var files = Directory.GetFiles(Folder);
    if (files.Length == 0) return "No items to summary. Please ignore.";

    // Use a single StringBuilder with estimated capacity to avoid reallocations
    var sb = new StringBuilder(files.Length * 512); 
    await Parallel.ForEachAsync(files, new ParallelOptions { CancellationToken = Ct }, async (file, token) =>
    {
        using var reader = File.OpenText(file);
        // Rent buffer properly scoped to this iteration or reuse a shared one with lock/sync if needed
        char[] poolBuffer = ArrayPool<char>.Shared.Rent(8192);
        try
        {
            int bytesRead;
            while ((bytesRead = await reader.ReadAsync(poolBuffer.AsMemory(), token)) > 0)
            {
                sb.Append(poolBuffer.AsSpan(0, bytesRead));
            }
            sb.AppendLine($"---\n[RESPONSE_FILE]{Path.GetFileName(file)}[/RESPONSE_FILE]");
        }
        finally
        {
            // ✅ CRITICAL: Always return rented buffers to avoid pool starvation
            ArrayPool<char>.Shared.Return(poolBuffer);
        }
    });

    // ✅ Use string.Create for zero-allocation final assembly (or just sb.ToString() is fine here)
    return $"[RESPONSE_CODE] {sb} [/RESPONSE_CODE]";
}
```

### 🔴 2. High Impact: Fragile Span Allocation in `QdrantSearchService.FormatContext`
**Location:** `FormatContext` method  
**Issue:** 
- Pre-calculating `Results.Count * 256` is a guess. Overestimation wastes memory; underestimation silently truncates output.
- `.Select(p => p.Payload.ToObject())` creates an iterator and closure allocations per call.
- Span `TryWrite` with interpolated strings still triggers internal allocations in .NET.

**Fix:** Use `string.Create`, which is allocation-free for the final string and handles sizing dynamically:

```csharp
private static string FormatContext(IReadOnlyList<ScoredPoint> Results)
{
    return string.Create(Results.Count * 128, Results, (span, results) =>
    {
        int written = 0;
        foreach (var point in results) // ✅ Avoids LINQ iterator allocation
        {
            var payload = point.Payload.ToObject(); // Cache or optimize if this is JSON-heavy
            string line = $"File Name: {payload.FileName} | Type: {payload.Type} | Element: {payload.ElementName}\n{payload.Code}\n";
            
            if (!span[written..].TryWrite(line, out var charsWritten))
                break; // Or handle resize/fallback
                
            written += charsWritten;
        }
    });
}
```
