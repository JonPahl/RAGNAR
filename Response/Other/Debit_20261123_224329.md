### 🔴 Critical: Resource Leaks & Lifetime Violations
**1. Raw `HttpClient` Allocation in Fluent Builder**
- **Location:** `OllamaChatClientBuilderConfigured.cs` → `Build()`
- **Debt:** Creates a new `HttpClient` per build call. Bypasses the HTTP connection pool, leading to socket exhaustion under concurrent RAG queries or high-frequency plugin loading.
- **Fix:** Inject `IHttpClientFactory` into the builder and use `factory.CreateClient("Ollama")`. Cache clients keyed by service/model if pooling overhead is a concern, but never instantiate raw clients in DI-registrable services.

**2. Constructor Parameter Bloat & SRP Violation**
- **Location:** `RagPipelineRunner.cs`, `ContentSummarizerAgent.cs`
- **Debt:** Both classes have 10+ constructor parameters. This forces tight coupling, breaks Open/Closed Principle (OCP), and makes unit testing/mocking cumbersome. It also violates the principle that a class should have ≤5 direct dependencies.
- **Fix:** Introduce a facade or builder per pipeline phase (`IEmbeddingPipelineConfigurator`, `IRagQuestionConfigurator`). Group related services into typed configuration records or use the **Mediator** pattern (via `MediatR`) to decouple orchestration from stage implementations.

### 🟠 High: Concurrency, Closures & State Management
**3. Deferred Iterator Capturing Loop Variable (`i`)**

```csharp

```
If `UpsertAsync` yields or runs concurrently later, `i` will point to the final batch count. This corrupts error logs.

**4. Mutable State in "Immutable" Contexts**

- **Fix:** Use `ConcurrentDictionary<string, object>` for diagnostics, or switch to `IReadOnlyCollection<StageMetric>` + append via a thread-safe aggregator middleware.

### 🔵 C# 14 / .NET 10 Specific Considerations
**8. Extension Member Scoping & Ambiguity**
- You're correctly using the new `extension(Type) { public prop ... }` syntax across multiple files (`StringExtensions.cs`, `CodeDocumentExtensions.cs`, `StylesExtensions.cs`, etc.).
- **Debt Risk:** Without strict namespace organization, compiler `CS0121` (ambiguous call) will surface when multiple files expose overlapping members on the same type. Additionally, extension properties cannot be virtual or override base implementations, which may conflict with your `IClock.Now/UtcNow` or `IOutputWriter` abstractions if they later need polymorphic behavior.
- **Fix:** Group extensions into tightly scoped namespaces (e.g., `Ragnar.Extensions.Collections`, `Ragnar.Extensions.Diagnostics`). Prefer extension methods over properties for cross-cutting concerns to maintain interface contract purity.

**9. Missing `ConfigureAwait(false)` Consistency in Async Flows**
- While most code correctly uses `.ConfigureAwait(false)`, pipeline middlewares and stage orchestrators occasionally drop it or use `await Task.Yield()` as a poor-man's cancellation check. In .NET 10, the synchronization context is less prevalent, but explicit config is still critical for library code and Spectre.Console live rendering loops to prevent thread starvation on UI/console threads.

**10. Regex & Validation Logic Drift**
- **Location:** `ApplicationOptionsValidator.cs`
```csharp

// But comment says: "must not contain path separators or invalid characters"
```

- Windows/Unix paths legitimately use dots. The regex is over-restrictive and will block valid output folders like `v1.2-final`. Use `Path.GetInvalidFileNameChars()` for validation instead of custom regex.
