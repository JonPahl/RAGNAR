# Technical Debt Assessment – Ragnar (Repository Augmented Generator & Resolver)

Below is a structured inventory of the technical debt I can identify across the codebase, grouped by severity and category.

---

## 1. Bugs / Correctness Issues (High Priority)

### 1.1 Contradictory unit tests in `SystemPromptProviderTests`
```csharp
// Test A asserts System is NOT empty
provider.System.Should().NotBeNull();
Assert.NotEmpty(provider.System);
provider.System.Should().Contain(".NET 10");

// Test B (same class) asserts System IS empty
provider.System.Should().Be(string.Empty);
```
Both tests cannot pass simultaneously. One of them is dead or the other is a bug. This signals the test suite may be silently skipping or one test is masking a failure.

### 1.2 `VectorStoreRepository.UpsertBatchAsync` returns inside the `foreach`
```csharp
foreach (var doc in codeDocuments)
{
    // ... generate embedding, build points ...
    return await qdrantClient.UpsertAsync(...); // ← returns on FIRST doc
}
return new UpdateResult { Status = UpdateStatus.Completed };
```
Only the **first** document in the batch is ever upserted. The loop body should collect results and the `return` should move outside the loop (or the loop should be replaced with `Task.WhenAll` / sequential awaits that don't early-return).

### 1.3 Swallowed exception in `OllamaChatResponse.GenerateResponse`
```csharp
catch (Exception ex)
{
    var y = ex.Message;   // ← discarded, no log, no rethrow
}
```
Any failure in the "Think" event wiring is silently lost. This will make production incidents nearly impossible to diagnose.

### 1.4 `PathResolver` vs `ResponseWriter` inconsistency
`PathResolver.ResolveResponseDirectory` **throws** `DirectoryNotFoundException` if the folder doesn't exist, while `ResponseWriter.WriteResponseAsync` **creates** the directory. Depending on call order, one will throw where the other would have succeeded. The contract should be "ensure exists" in one place only.

## 2. Architecture / Layering Violations

### 2.1 UI rendering inside a service (`OllamaChatResponse`)
`AnsiConsole.Live(...)`, `Panel`, `Markup`, and `Style` objects live inside what is supposed to be a generation service. This couples the LLM client to Spectre.Console, making the service untestable headlessly and violating separation of concerns. Rendering belongs in a presentation/pipeline-stage layer.

### 2.2 `EmbedTextPipeline` – large commented-out block + TODO
```csharp
//TODO: Rewrite this class to use IPipelineStage logic.
// (40+ lines of commented-out implementation)
```
The class is a hybrid of two designs (old monolithic vs. new pipeline). The dead code should be deleted and the migration completed.

### 2.3 Plugin loading inside DI extension method
`ApplicationConfigurationExtensions.LoadQuestionPlugins()` calls `AssemblyLoadContext.Default.LoadFromAssemblyPath` and scans the filesystem during service registration. This is an infrastructure concern that belongs in a dedicated `IPluginLoader` registered earlier in the pipeline.

### 2.4 `SummaryService` hard-codes questions
```csharp
//todo: move these questions to csv file. Call load csv builder.
return new(...)
```
This bypasses the entire `IQuestionProvider` / `QuestionCombineBuilder` / CSV infrastructure that exists for a reason. Until it's migrated, the summary flow is unconfigurable.

## 3. Design & Maintainability Debt

### 3.1 Mutable service properties in `VectorStoreBuilder`
```csharp
public string VectorStoreName { get; set; }
public ulong Dimension { get; set; }
public Serilog.ILogger Logger { get; set; }
public IQdrantClient QdrantClient { get; set; }
```
These are settable after construction, defeating the purpose of the constructor-injected values and inviting accidental reassignment. They should be `private readonly` (or removed if truly part of the builder chain).

### 3.2 `BATCHSIZE = 1` in `EmbedTextPipeline`
A batch size of 1 negates any benefit of `UpsertBatchAsync`. Either this is a placeholder that was never updated, or the batching abstraction is premature.

### 3.3 Magic numbers in `OllamaChatResponse`
```csharp
NumPredict = 8192, NumCtx = 16384, NumThread = 4,
Temperature = 0.2f, RepeatPenalty = 1.02f
```
None of these are in `RagnarConfig`. They should be configurable via `OllamaOptions` so different models or environments can tune them.

### 3.4 `StringExtensions.LastFolder` defeats span semantics
```csharp
public string LastFolder => Path.GetFileName(value.ToString().TrimEnd('/', '\\'));
```
Calling `.ToString()` on a `ReadOnlySpan<char>` allocates a full string copy just to extract a folder name. A `Span`-aware implementation would avoid the allocation.

### 3.5 `FileValidator` – parameter shadows type
```csharp
public bool IsValid(FileInfo File, in FileLoadOptions FileLoadOptions)
```
Parameter names `File` and `FileLoadOptions` shadow their type names, reducing readability. The TODO to "replace with fluentvalidation" also means there's no centralized validation rule for file policies.

### 3.6 `AppDefaults` is a grab-bag
Mixes directory names, prompt labels, and code-block markers in one static class. These have different lifetimes and concerns; splitting them (or moving them to their consuming types) would reduce coupling.

## 5. Configuration & Operational Debt

- **Multiple `appsettings`-style JSON blobs** with different source directories, vector store names, and excluded-folder lists are present in the codebase. There is no visible environment-specific config layer (`appsettings.Development.json`, `appsettings.Production.json`, or user-secrets). This makes local vs. CI vs. prod configuration error-prone.
- **`%USERPROFILE%` hardcoded paths** in at least two config files. These won't resolve on Linux CI runners.
- **Serilog → Seq** sink points to `http://localhost:5341`. If Seq isn't running, log writes will silently fail (no visible fallback to console).
- **No visible health-check or readiness probe** for the Ollama or Qdrant endpoints before the pipeline starts. Failures will surface mid-run.

## 7. Security / Robustness Gaps

- **`FileValidator`** only checks extension, file name, and immediate directory. It does **not** verify that the resolved path is actually inside the source directory (no `Path.GetFullPath` containment check), leaving the door open to `..` traversal if a crafted CSV or config injects a path.
- **`OllamaClientFactory.CreateHttpClient`** sets `client.BaseAddress` but does not configure `HttpClientHandler` for certificate validation, proxy, or SSL settings. If the Ollama endpoint is ever moved to HTTPS, the default handler behaviour may be surprising.
- **No input sanitisation** on the `question.Text` or `contextText` before they are interpolated into the prompt string. A prompt-injection via a malicious source file could alter the LLM's behaviour.

---

## 8. Suggested Remediation Order

1. **Fix the `VectorStoreRepository` early-return bug** – data is being silently lost.
2. **Resolve the contradictory tests** and the swallowed exception in `OllamaChatResponse`.
3. **Extract UI rendering** out of `OllamaChatResponse` into a dedicated pipeline stage.
4. **Delete all commented-out code** and resolve every `TODO`.
5. **Make `VectorStoreBuilder` properties read-only**; introduce constants/config for `BATCHSIZE` and LLM sampling parameters.
6. **Consolidate configuration** into proper environment-specific layers; eliminate hardcoded user paths.
7. **De-duplicate and re-locate tests** so each class is tested in its own file.
8. **Add path-containment validation** in `FileValidator` / `PathResolver`.
9. **Add integration tests** that exercise the full pipeline (discover → parse → embed → upsert → query → summarise) against a seeded Qdrant + Ollama stub, to catch layering regressions early.

Addressing items 1–4 will remove the highest-risk debt; items 5–9 progressively reduce the long-term maintenance cost.
