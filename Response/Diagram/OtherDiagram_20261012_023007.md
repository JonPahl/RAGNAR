## 2. Pipeline Execution Sequence Diagram

```mermaid
sequenceDiagram
    participant App as Application
    participant Runner as PipelineRunner<T>
    participant Stage as IPipelineStage
    participant Policy as RetryPolicy (Polly)
    participant Ctx as PipelineContext
    participant Logger as Serilog.ILogger

    App->>Runner: AddStage(stage, policy)
    Note over Runner: Lock _gate, validate unique name

    App->>Runner: ExecuteAsync(context, ct)
    Runner->>Runner: Snapshot stages (lock)
    Runner->>Logger: "Pipeline starting..."

    loop For each stage in snapshot
        Runner->>Stage: ShouldRun(context)
        alt Should skip
            Runner->>Logger: "Skipping stage [i]: Name"
        else Should execute
            Runner->>Logger: "Starting stage [i/total]: Name"
            Runner->>Runner: Start Stopwatch

            alt Has retry policy
                Runner->>Policy: ExecuteAsync(...)
                Policy->>Stage: ExecuteAsync(context, ct)
                Note over Policy: Retry with exponential backoff
            else No retry policy
                Runner->>Stage: ExecuteAsync(context, ct)
            end

            alt Success
                Stage-->>Runner: Complete
                Runner->>Logger: "Completed stage [i] in {time}"
            else OperationCanceledException
                Stage--xRunner: Cancellation
                Runner--xApp: Re-throw
            else Other Exception
                Stage--xRunner: Exception
                Runner->>Logger: FATAL: Stage failed
                Runner--xApp: PipelineStageException
            end
        end
    end

    Runner->>Logger: "Pipeline finished in {total}"
    Runner-->>App: Return enriched context
```

## Summary of Key Architectural Patterns

| Pattern | Implementation |
|---------|---------------|
| **Pipeline / Chain of Responsibility** | `PipelineRunner<T>` orchestrates `IPipelineStage<T>` instances sequentially |
| **Fluent Builder** | `QuestionCombineBuilder`, `FilterBuilder`, `QuestionBuilder` |
| **Strategy** | `IFilterStrategy` / `XmlCommentFilterStrategy` for category-specific filtering |
| **Factory** | `CodeParserFactory`, `IOllamaClientFactory`, `TableRendererFactory` |
| **Decorator** | `NumberedRowDecorator` wrapping `ITableRenderer` |
| **Options Pattern** | `IOptions<RagnarConfig>` with cascading FluentValidation |
| **Retry / Resilience** | Polly `AsyncRetryPolicy` with exponential backoff per stage |
| **CQRS-like Separation** | Embedding (write) vs. Retrieval/RAG (read) as distinct services |
| **CancellationToken Propagation** | End-to-end async cancellation through all stages and I/O |
