You already have the full middleware infrastructure in place — the onion-pattern loop in `ExecuteStageWithMiddlewareAsync`, the thread-safe `_middlewares` list, and the `UseMiddleware` / `UseTiming` registration surface. `StageTimingMiddleware` is your one concrete middleware. Whether you need more depends on cross-cutting concerns you want applied *uniformly across every stage* without touching each stage's `ExecuteAsync`.

Here are the practical candidates, ranked by how much they fill a real gap in the current design:

---

### 1. Telemetry / Tracing Middleware (highest value if you adopt OpenTelemetry)

The runner logs to a `Microsoft.Extensions.Logging.ILogger`, but there's no span-based tracing. A middleware can create a parent `Activity` (or OTel span) per stage, attach the stage name and index, and propagate the `Activity.Current` into the downstream context so downstream HTTP calls (Qdrant, Ollama) automatically join the same trace.

```csharp
public sealed class TracingMiddleware
{
    private readonly Tracer _tracer;

    public TracingMiddleware(Tracer tracer) => _tracer = tracer;

    public Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct)
        where TContext : class
    {
        Guard.Against.Null(ctx);
        Guard.Against.Null(next);
        ct.ThrowIfCancellationRequested();

        using var activity = _tracer.StartActivity(
            $"pipeline.{ctx.Stage.Name}",
            ActivityKind.Internal,
            new ActivityTagsCollection
            {
                ["pipeline.index"] = ctx.Index,
                ["pipeline.total"] = ctx.Total
            });

        return next();
    }
}
```

Register with: `runner.UseMiddleware((ctx, next, ct) => tracingMiddleware.Invoke(ctx, next, ct));`

### 2. Context-Invariant Validation Middleware

`DeltaEmbedStage` does `Guard.Against.Null(context.Documents)` internally. If you have multiple stages that depend on a prior stage's output, a single middleware can enforce the contract *before* the stage body runs, giving you a uniform error message and avoiding scattered null-checks:

```csharp
public sealed class ValidationMiddleware
{
    private readonly ILogger _logger;
    private readonly Dictionary<string, Func<EmbeddingContext, string?>> _preChecks;

    public ValidationMiddleware(ILogger logger)
    {
        _logger = logger;
        _preChecks = new()
        {
            ["Delta Embed"]  = ctx => ctx.Documents is null ? "Documents is null" : null,
            ["Upsert"]       = ctx => ctx.Documents is null ? "Documents is null" : null,
        };
    }

    public Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        Guard.Against.Null(ctx);
        Guard.Against.Null(next);
        ct.ThrowIfCancellationRequested();

        if (ctx.PipelineContext is EmbeddingContext ectx
            && _preChecks.TryGetValue(ctx.Stage.Name, out var check))
        {
            var violation = check(ectx);
            if (violation is not null)
                throw new PipelineStageException(ctx.Stage.Name,
                    new InvalidOperationException($"Pre-condition failed: {violation}"));
        }

        return next();
    }
}
```

### 3. Metrics-Export Middleware

`StageTimingMiddleware` writes into `context.Metric` (a `StageMetric` record), but nothing *consumes* it externally. A thin middleware that fires after the timing middleware can push the captured metric to a `Counter` / `Histogram` (e.g., `Metrics.CreateHistogram` in .NET 9+, or a `MetricSet` in OpenTelemetry):

```csharp
public sealed class MetricsExportMiddleware
{
    private readonly Histogram _duration;
    private readonly Counter _failures;

    public MetricsExportMiddleware(Histogram duration, Counter failures)
    {
        _duration  = duration;
        _failures  = failures;
    }

    public async Task Invoke<TContext>(
        StageExecutionContext<TContext> ctx,
        Func<Task> next,
        CancellationToken ct) where TContext : class
    {
        Guard.Against.Null(ctx);
        Guard.Against.Null(next);

        try
        {
            await next().ConfigureAwait(false);
        }
        finally
        {
            if (ctx.Metric is { } m)
            {
                _duration.Record(m.Duration.TotalSeconds,
                    new KeyValuePair<string, object?>("stage", m.StageName));
                if (!m.Success)
                    _failures.Add(1,
                        new KeyValuePair<string, object?>("stage", m.StageName));
            }
        }
    }
}
```

Because middlewares execute in registration order (onion: first-registered = outermost), register **timing first, then export** so the export middleware can read the already-populated `ctx.Metric`.

### What you probably do **not** need as middleware

| Concern | Already covered by |
|---|---|
| Retry with back-off | Per-stage `IAsyncPolicy` in `StageEntry<TContext>` |
| Cancellation propagation | `CancellationToken` threaded through every `ExecuteAsync` + `ThrowIfCancellationRequested` guards |
| Basic start/finish logging | `PipelineRunner.ExecuteAsync` itself |
| Structured metrics *capture* | `StageTimingMiddleware` → `StageMetric` |

Adding a retry-as-middleware would collide with the existing `IAsyncPolicy` path and create two competing retry mechanisms. The current split (policy = retry, middleware = cross-cutting observability) is clean; keep it that way.

---

### TL;DR

You have exactly **one** middleware (`StageTimingMiddleware`) on a fully functional onion pipeline. The three most useful additions are:

1. **Tracing** – gives you end-to-end distributed traces across Qdrant + Ollama calls.
2. **Validation** – centralises pre-condition checks so stages stay focused.
3. **Metrics export** – gets the `StageMetric` data you're already capturing *out* of the process.

None of them are required for correctness; they're the standard observability trio (traces, validation, metrics) that the pipeline infrastructure is already shaped to accept.
