# Reworking Ragnar with MassTransit

Your current architecture is a well-designed **in-process sequential pipeline** (`PipelineRunner<TContext>`) with custom middleware, Polly retry, and a shared mutable context. Moving to MassTransit means shifting from *imperative orchestration* to *message-driven coordination*. Below is a pragmatic, staged migration plan.

---

## 1. Decide the Transport & Topology

| Concern | Current | MassTransit Equivalent |
|---|---|---|
| Execution order | `PipelineRunner` sequential loop | Message handler → publish next → next handler consumes |
| Shared state | `EmbeddingContext` / `QuestionPipelineContext` (mutable POCO) | **Saga state** (persisted) or **message payload** (ephemeral) |
| Retry | Polly `IAsyncPolicy` per stage | MassTransit `Retry.Sent` / `Retry` configuration on the consumer |
| Middleware | `StageTimingMiddleware` (Stopwatch + log) | `IConsumerFilter` / `IMessageSentObserver` / `IConsumerObserver` |
| Cancellation | `CancellationToken` threaded manually | `Timeout` on the consumer + `PoisonMessage` policy |
| Stage reorder/remove | `Reorder()` / `RemoveStage()` | Republish to a different endpoint, or conditionally skip (guard clause in handler) |

**Transport choice:**
- **Local dev / single-node:** `RabbitMqTransport` (most feature-complete) or `InMemoryTransport` (zero infra, good for unit tests).
- **Production / multi-node:** RabbitMQ or Azure Service Bus.

```csharp
// Program.cs
services.AddMassTransit(x =>
{
    x.UsingRabbitMq((ctx, cfg) =>
    {
        cfg.Host("localhost", v => { v.Username("guest"); v.Password("guest"); });

        cfg.ConfigureEndpoints(ctx);

        // Global retry (replaces Polly per-stage policies)
        cfg.UseRetry(r => r.Interval(3, TimeSpan.FromMilliseconds(500)));

        // Global timeout (replaces CancellationToken plumbing)
        cfg.UseTimeout(t => t.Interval(TimeSpan.FromMinutes(5)));

        // Observers (replaces StageTimingMiddleware)
        cfg.UseMessageObserver(new StageTimingObserver(ctx.GetRequiredService<ILogger<MassTransitHost>>()));
    });
});
```

## 2. Define Messages (Replace the Mutable Context)

Your two contexts (`EmbeddingContext`, `QuestionPipelineContext`) are mutable bags of data passed stage-to-stage. In MassTransit, each message is **immutable** and **self-describing**.

```csharp
// ── Embedding pipeline ──

public record EmbeddingStarted
{
    public required string SourceDirectory { get; init; }
    public required string CollectionName  { get; init; }
    public required Guid PipelineRunId     { get; init; }   // correlates all messages
}

public record FilesDiscovered
{
    public required Guid PipelineRunId          { get; init; }
    public required IReadOnlyList<string> Paths { get; init; }
}

public record FilesParsed
{
    public required Guid PipelineRunId  { get; init; }
    public required IReadOnlyList<CodeDocument> Documents { get; init; }
}

public record VectorsUpserted
{
    public required Guid PipelineRunId { get; init; }
    public required int  VectorCount   { get; init; }
}

// ── Question pipeline ──

public record QuestionRunStarted
{
    public required Guid RunId        { get; init; }
    public required string SourceDir  { get; init; }
}

public record QuestionAsked
{
    public required Guid RunId       { get; init; }
    public required Guid QuestionId  { get; init; }
    public required string Prompt    { get; init; }
}

public record QuestionAnswered
{
    public required Guid RunId      { get; init; }
    public required Guid QuestionId { get; init; }
    public required string Answer   { get; init; }
    public required TimeSpan Elapsed { get; init; }
}
```

> **Key rule:** a message carries only what the *next* handler needs. No more `ctx.Responses[[guid]] = answer` side-effects.

## 3. Convert Each Stage to a Consumer

### 3a. File Discovery → `FilesDiscovered` consumer

```csharp
public class FileDiscoveryConsumer(
    IFileDiscoveryService discovery,
    IFileEligibilityValidator validator,
    Serilog.ILogger logger) : IConsumer<EmbeddingStarted>
{
    public async Task Consume(ConsumeContext<EmbeddingStarted> ctx)
    {
        logger.Information("Discovery started for {Dir}", ctx.Message.SourceDirectory);
        var options = ctx.GetRequiredService<IOptions<RagnarConfig>>();

        var files = new List<string>();
        await foreach (var path in discovery.GetFilesAsync(
                           ctx.Message.SourceDirectory, options, ctx.CancellationToken))
        {
            files.Add(path);
        }

        await ctx.Publish(new FilesDiscovered
        {
            PipelineRunId = ctx.Message.PipelineRunId,
            Paths         = files
        }, ctx.CancellationToken);
    }
}
```

### 3b. Parsing → `FilesParsed` consumer (replaces `CodeParserFactory`)

```csharp
public class FileParsingConsumer(
    IFileParseFactory parser,
    Serilog.ILogger logger) : IConsumer<FilesDiscovered>
{
    public async Task Consume(ConsumeContext<FilesDiscovered> ctx)
    {
        var docs = new List<CodeDocument>();
        foreach (var path in ctx.Message.Paths)
        {
            docs.AddRange(await parser.ParseAsync(path, ctx.CancellationToken));
        }

        await ctx.Publish(new FilesParsed
        {
            PipelineRunId = ctx.Message.PipelineRunId,
            Documents     = docs
        }, ctx.CancellationToken);
    }
}
```

### 3c. Upsert → `VectorsUpserted` consumer (replaces `VectorStoreWriter`)

```csharp
public class VectorUpsertConsumer(
    VectorStoreWriter writer,
    Serilog.ILogger logger) : IConsumer<FilesParsed>
{
    public async Task Consume(ConsumeContext<FilesParsed> ctx)
    {
        var result = await writer.UpsertBatchAsync(ctx.Message.Documents, ctx.CancellationToken);
        await ctx.Publish(new VectorsUpserted
        {
            PipelineRunId = ctx.Message.PipelineRunId,
            VectorCount   = result.UpsertedCount
        }, ctx.CancellationToken);
    }
}
```

### 3d. Register the chain

```csharp
x.UsingRabbitMq((ctx, cfg) =>
{
    cfg.ReceiveFrom(RabbitQueue.Embedding, q =>
    {
        q.Consumer<FileDiscoveryConsumer>();
    });

    cfg.ReceiveFrom(RabbitQueue.Parsing, q =>
    {
        q.Consumer<FileParsingConsumer>();
        q.UseRetry(r => r.Interval(3, TimeSpan.FromSeconds(2)));   // per-queue override
    });

    cfg.ReceiveFrom(RabbitQueue.Upsert, q =>
    {
        q.Consumer<VectorUpsertConsumer>();
    });
});
```

The **ordering guarantee** (RabbitMQ single-partition queues) replaces your `PipelineRunner` loop.

## 4. Question Pipeline → Saga (replaces `QuestionPipelineContext`)

Your question pipeline **accumulates** `Responses` and `Timings` across stages. That is exactly what a MassTransit **saga** models:

```csharp
public interface QuestionRunStateMachine
{
    string RunId { get; set; }
    int    TotalQuestions { get; set; }
    int    AnsweredCount  { get; set; }
    bool   IsComplete     { get; set; }
    // …per-question results
    IDictionary<string, string> Responses { get; set; }
    IDictionary<string, TimeSpan> Timings { get; set; }
}

public class QuestionRunSagaState : QuestionRunStateMachine
{
    public string RunId { get; set; } = Guid.NewGuid().ToString();
    public int TotalQuestions { get; set; }
    public int AnsweredCount  { get; set; }
    public bool IsComplete    { get; set; }
    public IDictionary<string, string> Responses { get; set; } = new Dictionary<string, string>();
    public IDictionary<string, TimeSpan> Timings { get; set; } = new Dictionary<string, TimeSpan>();
}

public class QuestionRunStateMachine(QuestionRunSagaState state) : StateMachine<QuestionRunStateMachine, QuestionRunSagaState>
{
    // Event: QuestionAsked
    this.When<QuestionAsked>((ctx, evt) => new
    {
        evt.RunId == ctx.RunId
    })
    .Then(ctx =>
    {
        // fire off the LLM call, publish QuestionAnswered
    });

    // Event: QuestionAnswered
    this.When<QuestionAnswered>((ctx, evt) => new
    {
        evt.RunId == ctx.RunId
    })
    .Then(ctx =>
    {
        ctx.Responses[[evt.QuestionId.ToString()]] = evt.Answer;
        ctx.Timings[[evt.QuestionId.ToString()]]   = evt.Elapsed;
        ctx.AnsweredCount++;
    })
    .TransitionTo(IsComplete)
    .When(ctx => ctx.AnsweredCount == ctx.TotalQuestions);
}
```

> This gives you **automatic state persistence** (via the saga repository), **resumability** after a crash, and **event-driven completion** — none of which the mutable `QuestionPipelineContext` can provide.

## 5. Replace Custom Middleware with MassTransit Observers

Your `StageTimingMiddleware` becomes a global `IConsumerObserver`:

```csharp
public class StageTimingObserver(Serilog.ILogger logger) : IConsumerObserver
{
    public void ConsumeStart<T>(ReceiveEndpoint endpoint, ConsumeContext<T> context)
    {
        endpoint.Stopwatch = Stopwatch.StartNew();  // stash on a concurrent dict keyed by message Id
    }

    public void ConsumeStop<T>(ReceiveEndpoint endpoint, ConsumeContext<T> context)
    {
        var elapsed = /* retrieve stopwatch */;
        logger.Information(
            "Stage {Consumer} completed in {Elapsed} ({Success})",
            context.ConsumerType.Name, elapsed, !context.IsFaulted);
    }

    public void ConsumeFault<T, TException>(ReceiveEndpoint endpoint,
        ConsumeContext<T> context, TException exception) where TException : Exception
    {
        logger.Error(exception, "Stage {Consumer} failed: {Msg}",
            context.ConsumerType.Name, exception.Message);
    }
}
```

This **eliminates** `StageTimingMiddleware.cs`, `StageExecutionContext`, and the `Metric` property entirely — the same data is now captured globally with zero per-stage boilerplate.

## 6. Replace Polly Retry with MassTransit Retry

Delete the `IAsyncPolicy` / `StageEntry.AsyncPolicy` plumbing:

```csharp
// Global default
cfg.UseRetry(r => r.Interval(3, TimeSpan.FromSeconds(1)));

// Per-consumer override (e.g. Ollama calls are flaky)
cfg.ReceiveFrom(RabbitQueue.Llm, q =>
{
    q.Consumer<LlmCallConsumer>();
    q.UseRetry(r =>
    {
        r.Interval(5, TimeSpan.FromSeconds(2));
        r.OnMessageExpired(p => /* publish DeadLetter / alert */);
    });
});
```

The `StageMetric.RetryCount` you were tracking manually is now available via `context.Attempts`.

## 7. Cancellation & Timeouts

Instead of threading `CancellationToken` through every method:

| Mechanism | MassTransit feature |
|---|---|
| "User pressed Ctrl+C" | `IHostedService.StopAsync()` → broker gracefully drains; or publish a `PipelineCancelled` message that guards check |
| "This stage took too long" | `cfg.UseTimeout(t => t.Interval(...))` → message goes to a poison queue |
| "Per-request cancellation token" | `ctx.CancellationToken` is provided automatically by the transport (RabbitMQ uses `amqp.cancel`; InMemory uses `CancellationToken`) |

You can still **pass** a `CancellationToken` in your messages if you need correlated cancellation:

```csharp
public record LlmRequest
{
    public required Guid CorrelationId { get; init; }
    // …
}

// In consumer:
public async Task Consume(ConsumeContext<LlmRequest> ctx)
{
    using var cts = CancellationTokenSource.CreateLinkedTokenSource(ctx.CancellationToken);
    cts.CancelAfter(TimeSpan.FromSeconds(30));  // per-request timeout
    // …
}
```

## 10. Suggested Migration Order (Lowest Risk First)

1. **Add MassTransit alongside** the existing pipeline (dual-run). Wire the embedding chain first (4 consumers, no saga).
2. **Replace Polly** with MassTransit retry on the new consumers; keep the old `PipelineRunner` for the question pipeline.
3. **Extract `StageTimingMiddleware`** into the observer and remove the middleware class.
4. **Migrate the question pipeline** to a saga (highest risk — most state).
5. **Delete** `PipelineRunner`, `StageEntry`, `StageExecutionContext`, `BasePipeline`, and the Polly references.
6. **Add a management endpoint** (e.g. publish `PipelineStatusRequested`) so your CLI can still show progress — subscribe to a `PipelineProgress` message per stage completion.

This keeps every stage's **domain logic** (`ParseCSharpFile`, `VectorStoreWriter`, `OllamaChatClient`) intact and only replaces the **orchestration shell** — the part you built by hand that MassTransit provides out of the box.
