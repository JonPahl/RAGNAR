Based on your codebase, you're already using `DefaultQuestionFactory` to create questions with a `key`/`Filename` property that serves as the unique identifier. The most efficient and maintainable way to simplify lookup by name is to **cache questions in a dictionary at startup** and expose it via DI.

Here’s how to implement it cleanly within your existing architecture:

### 1. Implement a Dictionary-Backed Catalog
Replace linear searches or repeated config reads with an O(1) lookup cache:

```csharp
public class QuestionCatalog : IQuestionCatalogLoader
{
    private readonly ConcurrentDictionary<string, Question> _questions = new();

    public void LoadQuestions(IEnumerable<Question> questions)
    {
        foreach (var q in questions.Where(q => !string.IsNullOrWhiteSpace(q.Filename)))
        {
            _questions.TryAdd(q.Filename.ToLowerInvariant(), q);
        }
    }

    public Question? GetByName(string name) 
        => _questions.TryGetValue(name?.ToLowerInvariant() ?? string.Empty, out var question) ? question : null;
}
```

### 2. Register & Populate via DI (Startup)
Hook this into your existing `RagPipelineHostBuilder` so questions are loaded exactly once:

```csharp
// In RagPipelineHostBuilder.CreateDefaultBuilder()
services.AddSingleton<IQuestionCatalogLoader>(sp =>
{
    var loader = sp.GetRequiredService<ConfigurationBasedQuestionLoader>();
    var catalog = new QuestionCatalog();
    
    // Load from config, database, or embedded resources

    catalog.LoadQuestions(questions);
    
    return catalog;

```
