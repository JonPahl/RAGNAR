### 🔴 Critical Logical & Concurrency Issues

#### 1. Unsafe Indexing in Parallel Loop (`SummaryAgent.cs`)
**Smell:** Using `Array.IndexOf(files, file)` inside a parallel loop to index into an array is both inefficient (`O(n)` per iteration) and unsafe in concurrent contexts. It can lead to race conditions or incorrect indexing if files are processed out of order.
```csharp
// Problematic Code
await Parallel.ForEachAsync(files, new ParallelOptions { CancellationToken = Ct }, async (file, token) =>
{
    int index = Array.IndexOf(files, file); // ❌ O(n) lookup + unsafe in parallel
    var text = await File.ReadAllTextAsync(file, token);
    contents[index] = $"---\n[RESPONSE_FILE]{Path.GetFileName(file)}[/RESPONSE_FILE]\n{text}\n";
});
```
**Fix:** Use the built-in index parameter provided by `Parallel.ForEachAsync`. It guarantees thread-safe indexing without lookup overhead.
```csharp
await Parallel.ForEachAsync(files, new ParallelOptions { CancellationToken = Ct }, async (file, state, index) =>
{
    var text = await File.ReadAllTextAsync(file, state);
    contents[index] = $"---\n[RESPONSE_FILE]{Path.GetFileName(file)}[/RESPONSE_FILE]\n{text}\n";
});
```

#### 2. Redundant & Flawed Directory Existence Check (`ResponseWriter.cs`)
**Smell:** `BuildDirectory` explicitly calls `Directory.CreateDirectory(targetDir)`, then `WriteResponseAsync` checks if the directory exists and throws if it doesn't. Since you just created it, this check will almost never trigger unless there's a permission issue or race condition elsewhere. It creates false confidence and dead code paths.
```csharp
// Problematic Code
var targetDir = Path.Join(responseDir, baseDir);
Directory.CreateDirectory(targetDir); // ✅ Always succeeds (or throws on permission)
return targetDir;

// Later in WriteResponseAsync:
if (!Directory.Exists(path)) throw new ArgumentException($"Save path: {path} does not exist"); // ❌ Redundant
```
**Fix:** Remove the existence check. If directory creation fails, `CreateDirectory` will throw a meaningful `UnauthorizedAccessException` or `IOException`. Trust the framework's exception handling.

### 🟡 Performance & Async Anti-patterns

#### 3. Synchronous I/O in Async Context (`SummaryAgent.cs`)
**Smell:** `Directory.GetFiles(Folder)` is a synchronous, blocking call inside an async method. This blocks a thread pool thread and defeats the purpose of async/await for I/O-bound operations.
```csharp
var files = Directory.GetFiles(Folder); // ❌ Blocks thread pool
```
**Fix:** Use asynchronous enumeration available in .NET 10:
```csharp
var files = await Directory.EnumerateFilesAsync(Folder, "*", SearchOption.TopDirectoryOnly).ToArrayAsync();
```

#### 4. Confusing `Aggregate` Logic (`SavePathExtensions.cs`)
**Smell:** The ternary logic around `Folders.Aggregate(BaseDir, Path.Join)` is hard to read and masks intent. If `Folders` is empty, it returns the seed, but if it has items, it ignores them entirely in favor of `FullPath`. This likely indicates a logic bug or leftover refactoring.
```csharp
return !Folders.Any() ? Folders.Aggregate(BaseDir, Path.Join) : FullPath; // ❌ Confusing & potentially dead code
```
**Fix:** Simplify to explicit path joining with clear fallbacks:
```csharp
public static string GetResponseDirectory(this IEnumerable<string> folders, string baseDir = "")
{
    var responseBase = string.IsNullOrEmpty(baseDir) ? "Response" : Path.Join(baseDir, "Response");
    return folders.Any() 
        ? folders.Aggregate(responseBase, Path.Join) 
        : responseBase;
}
```

### 🟠 Design & Maintainability Smells

#### 5. Dynamic Payload Parsing (`QdrantSearchService.cs`)
**Smell:** `Point.Payload.ToObject()` returns a dynamic/expando object. Accessing `.FileName`, `.Type`, etc., bypasses compile-time type safety. If the Qdrant payload schema changes, this will fail silently or throw at runtime.
```csharp
foreach (var Point in Results.Select(P => P.Payload.ToObject()))
{
    sb.AppendLine($"File Name: {Point.FileName} | Type: {Point.Type} ..."); // ❌ Dynamic access
}
```
**Fix:** Define a strongly-typed DTO and deserialize explicitly, or use explicit property extraction with fallbacks:
```csharp
public record QdrantPayload(string FileName, string Type, string ElementName, string Code);

// In FormatContext:
var payload = Point.Payload.ToObject<QdrantPayload>();
sb.AppendLine($"File Name: {payload.FileName} | Type: {payload.Type} ...");
```

#### 6. Hardcoded System Prompt (`SystemPromptProvider.cs`)
**Smell:** The AI system prompt is hardcoded in C# code. LLM prompts are configuration artifacts that change frequently based on model updates, testing, and iteration. Hardcoding them reduces maintainability and makes A/B testing difficult.
```csharp

""";
```
**Fix:** Externalize to `appsettings.json` or a `.prompt` file, and load via `IOptions<T>` or configuration binding. This allows prompt versioning without code deployments.
