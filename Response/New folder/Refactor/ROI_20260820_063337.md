- **Impact:** 🔴 High  
- **Remediation Effort:** 🟡 Medium  
- **Evidence from Codebase:** 
  ```csharp
  // SummaryAgent.cs
  await Parallel.ForEachAsync(files, new ParallelOptions { CancellationToken = Ct }, async (file, token) =>
  {
      int index = Array.IndexOf(files, file); // ❌ O(n) inside parallel loop = O(n²) total
      var text = await File.ReadAllTextAsync(file, token);
      contents[index] = $"---\n[RESPONSE_FILE]{Path.GetFileName(file)}[/RESPONSE_FILE]\n{text}\n";
  });
  ```
- **Why It's Critical:** `Array.IndexOf` performs a linear scan on every iteration. For directories with hundreds or thousands of files, this negates the benefits of parallelism, causes CPU thrashing, and severely degrades throughput in a RAG pipeline where file ingestion is a core bottleneck.
- **Remediation Strategy:** 
  Replace with index tracking using `Interlocked.Increment` or a concurrent dictionary:
  ```csharp
  var contents = new string[files.Length];
  int nextIndex = 0;
  await Parallel.ForEachAsync(files, new ParallelOptions { CancellationToken = Ct }, async (file, token) =>
  {
      int index = Interlocked.Increment(ref nextIndex) - 1;
      contents[index] = $"---\n[RESPONSE_FILE]{Path.GetFileName(file)}[/RESPONSE_FILE]\n{await File.ReadAllTextAsync(file, token)}";
  });
  ```
