### 2. **Path Traversal Vulnerability**
- **Issue**: In `SavePathExtension.GetResponseDirectory`, user-provided folder paths could be used to traverse outside intended directories:
  ```csharp
  public string GetResponseDirectory(IList<string> Folders, string BaseDir = "")
  {
      var Root = string.IsNullOrEmpty(BaseDir) ? Options.SaveDirectory : Path.Combine(BaseDir, Options.SaveDirectory);
      return Folders.Count == 0 ? Root : Folders.Aggregate(Root, Path.Combine);
  }
  ```
  If `Folders` contains malicious entries like `..\\..\\`, it could escape the base directory.
- **Fix**:
  - Validate and sanitize input paths.
  - Use `Path.GetFullPath` and verify the result is within the intended base directory:
    ```csharp
    var fullPath = Path.GetFullPath(Path.Combine(Root, folder));
    if (!fullPath.StartsWith(expectedBasePath, StringComparison.OrdinalIgnoreCase))
        throw new SecurityException("Invalid path traversal attempt.");
    ```

### 3. **Dynamic Code Loading (Plugin System)**
- **Issue**: The `RegisterQuestionPlugins` method dynamically loads assemblies from a directory:
  ```csharp

  ```
  If the `Questions/Plugins` directory is writable by an attacker, malicious DLLs could be injected.
- **Fix**:
  - **Sign plugins** with strong names and verify signatures before loading.
  - Restrict write access to the plugin directory (e.g., only deploy via CI/CD).
  - Use **IsolatedAppDomain** or **AssemblyLoadContext.CreateDefaultLoadContext** with restricted permissions.
  - Implement a plugin manifest with checksums/hashes for verification.
