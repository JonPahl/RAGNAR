### **Project Overview**
This is a **C# CLI application** designed to automate code documentation and resolve AI-assisted queries. It ingests source code files, generates semantic embeddings using Ollama, stores them in Qdrant, and retrieves relevant context via vector similarity to generate LLM-driven responses. The system emphasizes testability, configuration safety, and clear separation of AI/vector concerns from core orchestration.

### **Key Architectural Patterns**
*   **Pipeline Architecture:** Strictly decoupled ingestion (`EmbeddingPipeline`) and query phases (`QdrantSearchService` → `SummaryAgent`).
*   **Dependency Injection & Interface Segregation:** Heavy reliance on constructor injection and granular interfaces (e.g., `IQdrantClient`, `OllamaEmbeddingService`) to enable mocking and modular testing.
*   **Layered Design:** Five distinct layers: Client/CLI, Core Services, AI Integration, Data Storage, and Configuration/Validation.
*   **Strongly-Typed Configuration:** Uses `ApplicationConfiguration` and `OllamaOptions` with runtime validation (`FluentValidation`) to prevent misconfiguration at startup.
*   **Abstracted I/O:** File path resolution and markdown formatting are encapsulated in extension methods to isolate side effects and improve unit testability.

### **Core Workflow**
1.  **Initialization:** Validates configuration → Instantiates services → Ensures Qdrant collection exists (`programming_docs`, 768-dim).
2.  **Ingestion Phase:** Scans source directory → Filters by extension → Parses files → Generates embeddings via `nomic-embed-text` → Upserts vectors + metadata to Qdrant.
3.  **Query Phase:** User submits question → Agent loads target context → Vector search (limit: 200) → Formats scored payloads into markdown → Injects into LLM prompt → Generates response → Writes `.md` output file.

### **Qdrant Integration Insights**
*   **Collection Schema:** `programming_docs` with Cosine/InnerProduct metric and 768-dimensional float vectors.
*   **Payload Structure:** Each point stores `FileName`, `Type`, `ElementName`, and `Code` for precise context reconstruction.
*   **Runtime Validation:** Vector dimension is explicitly checked against config at query time to prevent mismatched embeddings.
*   **Extensibility:** The `Filter? Filter` parameter in `RetrieveContextAsync` supports dynamic payload filtering (e.g., by file type or category).
