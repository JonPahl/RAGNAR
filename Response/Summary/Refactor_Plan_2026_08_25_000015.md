#### **Key Insights**

*   **Memory Safety**: The current codebase attempts to load all files into memory simultaneously. This is a critical flaw for production environments handling large datasets; streaming or chunking is mandatory.
*   **Syntax Compatibility**: Current references to "extension properties" (C# 14 feature) are not yet supported in the current runtime context and must be reverted to standard `this` extension methods.
*   **Configuration Rigidity**: Hardcoded strings for prompts prevent runtime flexibility. Configuration should be managed via `IOptions<T>` or a dedicated repository.

#### **Patterns & Recommendations**

1.  **Concurrency Control Pattern**:
    *   Implement an `IAsyncEnumerable` with a semaphore to control parallelism during file reading (`maxConcurrency = 4` recommended).

2.  **Dependency Injection Consolidation**:
    *   Move all registration logic into a single, typed extension method:
        ```csharp
        services.AddRagnar(IConfiguration config);
        ```
    *   Ensure `IValidateOptions<T>` is used to fail fast on misconfiguration during application startup.

3.  **Strategy & Factory Patterns**:
    *   Use the **Strategy Pattern** for file filtering and formatting logic to allow switching implementations without modifying core business logic.
    *   Use a **Factory Pattern** or MediatR for question handling to replace reflection-heavy, type-unsafe routers.

4.  **Configuration Management**:
    *   Implement `IOptions<PromptConfig>` or `IOptionsMonitor` for dynamic prompt updates.
    *   Externalize prompts to embedded resources or the filesystem rather than inlining them in C# classes.
