## Ragnar – What It Is
A **.NET 8+ RAG (Retrieval-Augmented Generation) CLI tool**. It walks a directory tree for source files, chunks them with Roslyn-based parsers, embeds the chunks into **Qdrant**, and answers questions by feeding retrieved context to a local **Ollama** LLM. Results render as styled console tables.

## High-Level Architecture
```
Program.cs (host, DI, FluentValidation config)
   ├── Discovery & Parse   → FileDiscoveryService + Roslyn/Markdown chunkers
   ├── RAG Orchestrator    → RagOrchestrator (prompt → Ollama → persist)
   ├── Ollama / LLM        → OllamaApiClient (HttpClient) + MS.AI bridge
   ├── Embedding / Qdrant  → EmbeddingSetupExtension, IVectorStoreWriter, QdrantFilterBuilder
   ├── Pipeline Runner<T>  → generic StageEntry<T> + Polly middleware
   └── Questions / Output  → filters, categories, CSV I/O, console tables
```

## Key Subsystems
- **Pipeline** – generic `PipelineRunner<TContext>`: ordered stages, middleware onion (timing + Polly `IAsyncPolicy` retry), per-stage `ShouldRun` gating.
- **RAG** – `RagOrchestrator` composes prompt-building → generation → persistence via `QuestionPipelineContext`.
- **Ollama** – `OllamaApiClient` over REST; `IOllamaClientFactory` + `GeneratorExtensions` bridge to Microsoft.Extensions.AI.
- **VectorStore** – fluent `QdrantFilterBuilder` (`Must`/`MustNot`/`Should`) over the Qdrant gRPC client.
- **Discovery** – `FileDiscoveryService` (include/exclude) + `CodeParserFactory` dispatching to Roslyn C# or Markdown parsers.
- **Questions/Output** – pluggable `IFilterStrategy` (e.g. `XmlCommentFilterStrategy`), CSV round-tripping, `IResponseWriter`/`ITableRenderer`.
- **Configuration** – POCO option records (`RagnarConfig`, `EmbeddingOptions`, `GenerationOptions`, `FileLoadOptions`) validated at startup via FluentValidation.

## Notable Design Choices
- **Framework-generic pipeline** – `PipelineRunner<T>` is reusable for any sequential/middleware workflow; knows nothing about RAG/Ollama/Qdrant.
- **Layered dependencies** – RAG sits *above* Ollama & VectorStore; no circular references.
- **Discovery decoupled from Questions** – source can be swapped without touching question logic.
- **C# 14 `extension()` blocks** (assembly, `IServiceCollection`, `IReadOnlyList<Question>`) – requires preview/C# 14.
- **Polly v7** retry; **Serilog** structured logging.

## Gaps / Refactor Targets
1. `NumberedRowDecorator` likely duplicates rows (appends indexed copies without removing originals).
2. `QdrantFilterBuilder._should` never populated – no public `AddShould`.
3. `PipelineRunner` still has a commented-out legacy execution loop to delete.
4. `RagOrchestrator` is monolithic – primary refactor target (split into pipeline stages).
5. Resilience is basic (retry only) – migrate to `Microsoft.Extensions.Resilience` (circuit-breaker/timeout/fallback).
6. No OpenTelemetry `ActivitySource` spans per stage.
7. `CodeParserFactory` uses a `switch` on extension – should be a strategy dictionary.
8. Incomplete Docker profile in `launchSettings.json`; malformed CDATA in `CollectionInfo.cs`; `StageMetric.RetryCount` hardcoded to `0`.

## Build / Run
```bash
dotnet build -c Release
dotnet run -- <directory> --category XML --size 50
```
Config via `appsettings.json`/env vars → `RagnarConfig`. CI should target **C# 14 / .NET 8+** with `dotnet test`.

**Bottom line:** A clean, well-layered RAG CLI whose biggest wins would be decomposing `RagOrchestrator` into pipeline stages and upgrading from Polly retry to full `Microsoft.Extensions.Resilience` with tracing.
