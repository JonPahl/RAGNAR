The codebase exhibits **critical security gaps** caused by an implicit trust in unvalidated user inputs (filenames, paths, prompts). The primary risks are:
*   **Path Traversal:** Unrestricted file writes and reads allow attackers to overwrite system files or access sensitive data outside the sandbox.
*   **LLM Prompt Injection:** Raw user data injected directly into AI prompts blurs the line between data and instructions, risking unauthorized actions or data leakage.
*   **Configuration Blind Spots:** Unvalidated environment variables and config identifiers can lead to path manipulation or operational instability.

### Observed Patterns
1.  **Lack of Containment:** File paths are constructed but never verified against a secure root directory (`baseDir`).

**Priority 2: Neutralize LLM Prompt Injection (Critical)**
*   **Input Cleaning:** Implement strict sanitization to strip control characters (`\r`, `\n`, `\t`) and escape special tokens in user data.
*   **Structural Change:** Replace string concatenation with structured prompt templates or parameterized placeholders to ensure user input is treated strictly as data, not executable code.
*   **Guardrails:** Update system prompts to explicitly forbid instructions that override safety rules (e.g., "Never access files").

**Priority 3: Harden Configuration & Environment (High)**
*   **Validation:** Apply strict regex patterns (e.g., `^[a-zA-Z0-9_-]+$`) to validate configuration identifiers.
*   **Safe Expansion:** Eliminate direct use of `Environment.ExpandEnvironmentVariables` on user-influenced paths; implement validation logic post-expansion to ensure paths remain within allowed bounds.

**Priority 4: Architectural Hardening (Long-Term)**
*   **Centralization:** Move all validation and sanitization logic into reusable middleware or utility classes to prevent code duplication.
*   **Monitoring:** Implement structured logging for rejected inputs to detect probing patterns.
