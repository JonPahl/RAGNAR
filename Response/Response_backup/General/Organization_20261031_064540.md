### Step 3 — Run the reorganization script

Save the following as `reorganize.ps1` in the project root:

```powershell
#requires -Version 7.3
<#
.SYNOPSIS
    Moves .cs files into the target folder structure defined by reorg-map.csv
    and rewrites their `namespace` declarations to match.
.DESCRIPTION
    1. Reads reorg-map.csv (CurrentPath → TargetFolder).
    2. Creates target directories if they don't exist.
    3. Moves each file.
    4. Rewrites the namespace line to Ragnar.<FolderWithSlashes→Dots>.
    5. Updates the .csproj to remove explicit <Compile> items (SDK-style auto-globs).
#>

[[CmdletBinding()]]
param(
    [[string]]$ProjectRoot = (Get-Location).Path,
    [[string]]$MapFile     = Join-Path (Get-Location).Path "reorg-map.csv"
)

$ErrorActionPreference = "Stop"
$root = Resolve-Path $ProjectRoot

# --- Validate map file ---
if (-not (Test-Path $MapFile)) {
    throw "Map file not found: $MapFile"
}

# --- Read map ---
$entries = Import-Csv $MapFile
$moved = 0; $skipped = 0

foreach ($entry in $entries) {
    $src = Join-Path $root $entry.CurrentPath
    $destFolder = Join-Path $root $entry.TargetFolder
    $dest = Join-Path $destFolder (Split-Path $entry.CurrentPath -Leaf)

    if (-not (Test-Path $src)) {
        Write-Warning "  SKIP (not found): $($entry.CurrentPath)"
        $skipped++
        continue
    }

    # Create target directory
    New-Item -ItemType Directory -Force -Path $destFolder | Out-Null

    # Move file
    Move-Item -Path $src -Destination $dest -Force
    Write-Host "  ✓ $($entry.CurrentPath)  →  $($entry.TargetFolder)/" -ForegroundColor Cyan
    $moved++

    # --- Rewrite namespace ---
    # Derive namespace from folder: Pipeline/Stages → Ragnar.Pipeline.Stages
    $nsParts = $entry.TargetFolder.Split("/") | Where-Object { $_ -ne "" }
    $newNs = "Ragnar." + ($nsParts -join ".")

    $content = Get-Content $dest -Raw
    # Replace the first occurrence of "namespace Ragnar..." or "namespace <old>"
    $content = [[regex]]::Replace($content, '^\s*namespace\s+[[\w.]]+\s*\{', "namespace $newNs {", [[System.Text.RegularExpressions.RegexOptions]]::Multiline)

    # Handle C# 10+ file-scoped namespaces: "namespace Ragnar.Core;"
    $content = [[regex]]::Replace($content, '^\s*namespace\s+[[\w.]]+;?$', "namespace $newNs;", [[System.Text.RegularExpressions.RegexOptions]]::Multiline)

    Set-Content -Path $dest -Value $content -NoNewline
}

# --- Clean up now-empty top-level .cs files' old namespace usages in other files ---
# (Optional: run a project-wide "dotnet build" to catch broken usings.)

Write-Host "`nDone. Moved $moved file(s), skipped $skipped." -ForegroundColor Green
Write-Host "Next: run 'dotnet build' and fix any missing usings." -ForegroundColor Yellow
```

## Summary of Design Rationale

| Decision | Why |
|----------|-----|
| **`Core/Models` vs `Config`** | Models are *data*; validators are *behavior*. Keeping them separate lets you unit-test validation without pulling in the full domain. |
| **`Pipeline/Stages` as sub-folder** | Stages are pluggable; separating them makes it obvious where to add a new stage without scrolling through runner/middleware code. |
| **`Embedding/Filters` as sub-folder** | Filter strategies (XML, future JSON, etc.) grow independently; the selector is the only entry point. |
| **`Llm` instead of `Ollama`** | Keeps the door open for swapping providers; the factory pattern already abstracts this. |
| **`Extensions` is flat** | These are static helper methods with no shared state—no need for sub-folders. |
| **`Shared` for Guard/Defaults** | Used by *every* other folder; putting them in a leaf folder avoids circular-looking references. |

This layout keeps **dependency flow** strictly inward (Orchestration → Pipeline → Embedding/Parsing → Llm → Core) and makes it straightforward to extract any layer into its own NuGet package later if the project grows.
