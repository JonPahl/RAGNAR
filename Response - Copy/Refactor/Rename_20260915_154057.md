## 1. Classes & Interfaces with Misleading or Overloaded Names

| Current Name | Proposed Name | Rationale |
|---|---|---|
| `DataTableBuilder` | `ConsoleTableBuilder` | "DataTable" strongly evokes ADO.NET's `System.Data.DataTable`. This class builds a Spectre.Console `Table` for terminal display. |
| `IQuestionEmbedding` | `IQuestionContextResolver` | The interface does **two** things: generates an embedding **and** retrieves context. The name only hints at the first. A caller seeing `IQuestionEmbedding` would expect only `GenerateEmbeddingAsync`. |
| `IQuestionSourceAggregator` | `IQuestionSourceBuilder` | "Aggregator" implies merging/combining sources. The interface actually *builds* a filtered collection of questions. The test already calls the mock `_builderMock`, which is closer to the truth. |
| `VectorStoreRepository` / `IVectorStoreRepository` | `VectorStoreWriter` / `IVectorStoreWriter` | A repository implies query + mutation. This type only upserts embeddings into Qdrant. "Writer" scopes the contract accurately. |
| `IPointStructFactory` | `IQdrantPointFactory` | "PointStruct" is internal jargon. Prefixing with "Qdrant" tells the reader *which* point structure is being built. |
| `IChatPromptProvider` | `ILlmPromptProvider` | "Chat" is informal and doesn't distinguish this from a chat *session* or *channel*. The purpose is supplying system + user prompt templates to an LLM. |
| `IApplicationHeader` / `ApplicationHeader` | `IBrandingRenderer` / `BrandingRenderer` | The class renders a full branding block (title, tagline, version, rule). "Header" undersells what it does and overlaps with HTML/XML "header" terminology. |
| `IOutputWriter` | `IConsoleWriter` | There are two `I*Writer` interfaces: one for console (`IOutputWriter`) and one for file (`IWriter`). The "Output" suffix is ambiguous—output where? "Console" removes the ambiguity. |
| `IWriter` | `IFileWriter` | Bare `IWriter` is the most generic name possible. Pairing it with `IFileWriter` makes the console/file split obvious at the call site. |
| `IOutputFormatter` | `IResponseFormatter` | It formats a `SaveDetails` object into Markdown for a *response* file. "Output" is too broad; "Response" matches the domain language used everywhere else (`ResponseWriter`, `Response` folder). |
| `ISummaryService` | `IResponseSummarizer` | "All responses" is vague. Tying it to the `Response` noun the rest of the app uses makes the scope clear. |
| `EmbeddingContext` | `RagPipelineContext` | This is the shared state passed through the entire pipeline (discovery → parse → embed → ask). Calling it "Embedding" makes it look like it only carries vectors. |
| `UnknownUpdateStatus` | `CompletedWithErrors` | An "unknown" status conveys that the system doesn't know what happened. In reality it *does* know: some batches succeeded, some failed. The name should state that. |
| `SaveDetails` | `ResponseRecord` | "Save" is a verb; this is a data record. "Response" ties it to the domain noun used in `ResponseWriter`, `ResolveResponseDirectory`, etc. |

## 6. Principles Applied

1. **Name the *domain noun*, not the mechanism.** `ResponseWriter` (domain) beats `OutputWriter` (mechanism). `VectorStoreWriter` beats `VectorStoreRepository` (over-promising).
2. **One responsibility → one name.** `IQuestionEmbedding` did two jobs; splitting the name (or the interface) removes the ambiguity.
3. **Match the suffix to the abstraction.** `…Factory` creates, `…Builder` accumulates, `…Writer` persists, `…Renderer` displays, `…Resolver` looks up. Use the right verb-noun pairing.
4. **Make the pair distinguishable.** Two interfaces that both end in `Writer` force the reader to check which one is in scope. `IFileWriter` / `IConsoleWriter` are self-distinguishing.
5. **Keep test names in lock-step with the SUT.** `AskQuestionsStageTests` testing `QuestionExecutionStage` is a small cognitive tax on every code review.
