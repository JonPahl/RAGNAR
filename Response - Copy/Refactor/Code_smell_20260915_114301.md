# Code Smells & Suggested Fixes in the Ragnar Project

## 1. Mutable State Leakage — `DataTableBuilder`

**Smell:** `Rows` exposes `IReadOnlyList<List<string>>`, but the inner `List<string>` objects remain mutable. A caller can do `builder.Rows[[0]][[0]] = "hacked"` and silently corrupt table state.

```csharp
// Current – inner lists are still writable
public IReadOnlyList<List<string>> Rows => _rows;
```

**Fix:** Return immutable snapshots or switch the internal storage to `IReadOnlyList<string>` per row.

```csharp
private readonly List<IReadOnlyList<string>> _rows = [[]];

public DataTableBuilder AddRow(params string[[]] cells)
{
    _rows.Add(cells);
    return this;
}

public IReadOnlyList<IReadOnlyList<string>> Rows => _rows;
```

## 3. Dead / Redundant Guard — `PathResolver`

**Smell:** `QuestionCategory` is a value-type enum. When non-null, `category.ToString()` can *never* be null or whitespace. The `IsNullOrWhiteSpace` check is dead code that misleads readers into thinking the category could be an empty string.

```csharp
// Current – IsNullOrWhiteSpace is unreachable for a non-null enum
var baseDir = category is null || string.IsNullOrWhiteSpace(category.ToString())
    ? nameof(QuestionCategory.Uncategorized)
    : category.ToString();
```

**Fix:** Simplify to a null check only, or better, map to a well-known string via a helper.

```csharp
var folderName = category?.ToString() ?? nameof(QuestionCategory.Uncategorized);
return Path.Join(responseDir, folderName);

## 4. Lost Failure Details — `VectorStoreRepository`

```

**Fix:** Include the failure list in the result (or log it at `Error` level with structured fields) so operators can see *which* documents failed and *why*.

    FailedCount = failed.Count,
    Errors = failed.Select(f => f.Ex.Message).ToList()

## 7. Broad Exception Swallowing — `PipelineRunner`

**Smell:** Catching `Exception` (after re-throwing `OperationCanceledException`) wraps *every* fault—including `NullReferenceException`, `InvalidOperationException`, `StackOverflowException`—in a single `PipelineStageException`. This obscures the root cause and makes it harder for global exception handlers to react appropriately.

```csharp
catch (Exception ex)
{
    logger.Fatal(ex, "Stage [[{Index}]] {Name} failed after {Elapsed}", i, stage.Name, stageSw.Elapsed);
    throw new PipelineStageException(stage.Name, ex);
}
```

**Fix:** Catch the expected domain exceptions explicitly and let truly unexpected ones propagate (or at minimum log the full type before wrapping):

```csharp
catch (OperationCanceledException) when (ct.IsCancellationRequested)
{
    throw;
}
catch (Exception ex) when (ex is not PipelineStageException)
{
    logger.Fatal(ex, "Stage [[{Index}]] {Name} ({ExType}) failed after {Elapsed}",
        i, stage.Name, ex.GetType().Name, stageSw.Elapsed);
    throw new PipelineStageException(stage.Name, ex) from ex;
}
```

## 10. Constructor-Time Side Effects — `OllamaEmbeddingService`

**Smell:** The primary-constructor expression `clientFactory.ResolveClient(OllamaServiceType.Embedding).AsEmbeddingGenerator()` runs **at object construction**. If the factory throws (e.g., invalid config), the entire DI graph fails *before* the object can be inspected, logged, or retried. It also prevents lazy re-resolution if the underlying HTTP client is recycled.

```csharp
public class OllamaEmbeddingService(…, IOllamaClientFactory clientFactory, …) : IEmbeddingService
{
    private readonly IEmbeddingGenerator<string, Embedding<float>> _generator
        = clientFactory.ResolveClient(OllamaServiceType.Embedding).AsEmbeddingGenerator();
    // ^ resolved eagerly in ctor
}
```

**Fix:** Resolve lazily on first use, or accept the `OllamaApiClient` directly and defer `AsEmbeddingGenerator()` to a cached property:

```csharp
private IEmbeddingGenerator<string, Embedding<float>>? _generator;

private IEmbeddingGenerator<string, Embedding<float>> Generator
    => _generator ??= clientFactory.ResolveClient(OllamaServiceType.Embedding).AsEmbeddingGenerator();
```

## 12. C# 13 `extension` Keyword — `AssemblyExtensions`

**Smell:** The file uses the C# 13 preview `extension` modifier for file-scoped extensions. This is a **preview feature** that may change or require a specific SDK channel. It also means the class is no longer a traditional static class, which can surprise tooling (ILSpy, analyzers) that expect `static class` for extension methods.

```csharp
public static class AssemblyExtensions
{
    extension(Assembly asm)
    {
        public string? InformationalVersion => …;
    }
}
```

**Fix:** Unless you specifically need C# 13 features, prefer the conventional pattern:

```csharp
public static class AssemblyExtensions
{
    public static string? InformationalVersion(this Assembly asm)
        => asm.GetCustomAttribute<AssemblyInformationalVersionAttribute>()?.InformationalVersion ?? "1.0.0";
}
```
