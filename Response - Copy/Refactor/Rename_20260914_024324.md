# Naming Recommendations

Below is a structured set of renaming suggestions grouped by concern. Each entry shows the **current name**, the **proposed name**, and a short rationale. I've focused on the changes that most improve clarity for someone reading the codebase for the first time.

## 1. Class & Interface Names

| Current | Proposed | Why |
|---|---|---|
| `QuestionExecutionStage` | `RagQueryStage` | The stage doesn't "execute questions"; it loads them and runs RAG retrieval + generation. *RagQuery* captures both halves. |
| `IQuestionEmbedding` | `IQuestionContextService` | The interface exposes `GenerateEmbeddingAsync` **and** `GetContext` (a vector-store search). "Embedding" undersells the retrieval half and collides with the separate `IEmbeddingService`. |
| `IQuestionSourceAggregator` | `IQuestionSourceBuilder` | The class uses fluent `Get…/With…/Build()` calls. *Aggregator* suggests it merges data sources; *Builder* matches the actual API shape. |
| `VectorStoreRepository` | `VectorStorePersister` | "Repository" implies full CRUD on an entity. This class has exactly one operation: batch-embedding + upsert. *Persister* is more honest. |
| `DataTableBuilder` | `SpectreTableBuilder` | "DataTable" is the first thing developers associate with `System.Data.DataTable`. Tying the name to Spectre removes the ambiguity. |
| `BaseFileParser` | `FileParserBase` | "Base" as a *prefix* is less conventional in .NET; the suffix reads more naturally (`CSharpFileParser : FileParserBase`). |
| `XmlCommentFilterStrategy` | `XmlCommentFilterRule` | *Strategy* is a GoF pattern label that adds cognitive load without adding information. *Rule* is simpler and equally accurate. |
| `FileWriter` (class) | `AsyncFileWriter` | The only method is `WriteAsync`. Naming the async contract in the type avoids confusion with a synchronous writer. |
| `PipelineRunner` | `EmbeddingPipeline` | "Runner" is generic. The pipeline it drives is specifically the *embedding* pipeline (discover → parse → embed → ask questions). |
| `ISummaryService` | `IRagResponseSummarizer` | The name doesn't say *what* is summarized. This service summarises RAG Q&A responses specifically. |
| `IWriter` | `IAsyncFileWriter` | Same rationale as `FileWriter` → `AsyncFileWriter`; the interface should carry the same specificity. |
| `IOutputWriter` | `IConsoleWriter` | It writes Spectre.Console markup, rules, and styled text — it is a *console* writer, not a generic output writer. |
| `IOllamaClientFactory` | `IOllamaClientProvider` | "Factory" is a design-pattern label. The actual behaviour is *resolve-or-create and cache* — a provider. |
| `OllamaOptionsValidator` | `OllamaOptionsValidator` ✓ | (No change needed; it is a FluentValidation validator by convention.) |
| `ApplicationHeader` | `AppBanner` | "Header" is ambiguous (HTTP header? form header?). *Banner* is the common term for a console splash screen. |
| `IApplicationHeader` | `IAppBanner` | Match the renamed implementation. |
| `ConsoleTableRenderer` | `ConsoleTableDisplay` | "Renderer" is overloaded in .NET (WinForms `IRenderer`, WPF, Blazor). *Display* is plainer and matches the single `Render()` → `Write()` behaviour. |

## 2. Method Names

| Current | Proposed | Why |
|---|---|---|

| `IQuestionEmbedding.GenerateEmbeddingAsync(…)` | `EmbedQuestionAsync(…)` | Shorter, and the *Question* noun makes it clear this embeds a user question, not an arbitrary document. |
| `IVectorSearchService.RetrieveContextAsync(…)` | `SearchAsync(…)` | The service already says *VectorSearch*; repeating "RetrieveContext" is redundant. A simple `SearchAsync` on `IVectorSearchService` reads cleanly. |

| `FileSystemEntryExtensions.HasAllowedExtension(…)` | `HasAllowedFileExtension(…)` | Adding *File* disambiguates from a generic extension (e.g. a MIME type or a string suffix). |

## 9. Summary of the Biggest Wins

If you only have time for a few renames, these four will have the highest clarity-per-keystroke ratio:

1. **`IQuestionEmbedding` → `IQuestionContextService`** – eliminates the #1 source of confusion (embedding vs. retrieval vs. the separate `IEmbeddingService`).
2. **`QuestionExecutionStage` → `RagQueryStage`** – the name now matches what the stage actually does.
3. **`builder` → `questionSourceBuilder`** – removes the most cryptic local variable in the codebase.
4. **`RagnarConfig` → `RagnarOptions`** + **`ApplicationOptions` → `PipelineOptions`** – aligns with the `IOptions<>` idiom and makes the config hierarchy self-explanatory.
