## Identified Issues & Concrete Fixes

### 1. `FileReader` — Overly-broad exception swallowing

**Problem:** Every I/O exception (`UnauthorizedAccessException`, `FileNotFoundException`, `IOException`) gets wrapped in `InvalidOperationException`, losing semantic meaning and making caller-side handling impossible.

```csharp
// ❌ BEFORE
catch (Exception ex)
{
    logger.Error(ex, "Failed to read file: {FilePath}", filePath);
    throw new InvalidOperationException($"Could not read file '{filePath}'.", ex);
}
```

```csharp
// ✅ AFTER — let domain-meaningful exceptions propagate; wrap only truly unexpected ones
catch (OperationCanceledException) when (cancellationToken.IsCancellationRequested)
{
    throw;
}
catch (UnauthorizedAccessException ex)
{
    logger.Error(ex, "Access denied reading file: {FilePath}", filePath);
    throw new FileAccessDeniedException(filePath, ex);
}
catch (FileNotFoundException ex)
{
    logger.Warning("File not found: {FilePath}", filePath);
    throw new FileMissingException(filePath, ex);
}
catch (Exception ex) when (ex is IOException or OutOfMemoryException)
{
    logger.Fatal(ex, "Unexpected I/O failure reading: {FilePath}", filePath);
    throw new FileReadFailureException(filePath, ex);
}
```

### 2. `PathResolver` vs `ResponseWriter` — Contradictory directory contract

**Problem:** `PathResolver.ResolveResponseDirectory` **throws** if the directory doesn't exist, but `ResponseWriter` calls `Directory.CreateDirectory` *after* the resolver. The resolver's guard is therefore dead code in the normal path and misleading in tests.

```csharp
// ❌ BEFORE (PathResolver)
public string ResolveResponseDirectory(QuestionCategory? category)
{
    var baseDir = category is null || string.IsNullOrWhiteSpace(category.ToString())
        ? nameof(QuestionCategory.Uncategorized)
        : category.ToString();
    var responseDir = Path.Join(_applicationOptions.SourceDirectory, _applicationOptions.OutputFolder);
    if (!Directory.Exists(responseDir))          // ← throws, but caller creates it next
        throw new DirectoryNotFoundException(responseDir);
    return Path.Join(responseDir, baseDir);
}
```

```csharp
// ✅ AFTER — Resolver only *resolves*; the writer is responsible for *ensuring existence*
public string ResolveResponseDirectory(QuestionCategory? category)
{
    Guard.NotNull(_applicationOptions, nameof(_applicationOptions));
    var baseDir = category is null || string.IsNullOrWhiteSpace(category.ToString())
        ? nameof(QuestionCategory.Uncategorized)
        : category.ToString();
    return Path.Join(_applicationOptions.SourceDirectory!, _applicationOptions.OutputFolder!, baseDir);
}
```

```csharp
// ✅ AFTER (ResponseWriter) — single ownership of directory creation
public async Task<string> WriteResponseAsync(SaveDetails details, CancellationToken cancellationToken)
{
    var directory = pathResolver.ResolveResponseDirectory(details.Question.Category);
    Directory.CreateDirectory(directory);          // ← sole place that ensures existence

    var fileName = $"{details.Question.Filename}_{_clock.UtcNow:yyyyMMdd_HHmmss}.{formatter.FileExtension}";
    var fullPath = Path.Join(directory, fileName);
    var content  = formatter.Format(details);

    await fileWriter.WriteAsync(fullPath, content, cancellationToken).ConfigureAwait(false);
    return fullPath;
}
```

### 4. `OllamaEmbeddingService` — Eager client resolution hurts testability

**Problem:** `_generator` is resolved in the field initializer, so the client must be available at *construction* time. Unit tests must mock `IOllamaClientFactory` before the object is even created.

```csharp
// ❌ BEFORE
public class OllamaEmbeddingService(
    ILogger logger,
    IOllamaClientFactory clientFactory,
    IOptions<RagnarConfig> config) : IEmbeddingService
{
    // Resolved immediately — hard to test, fails fast if factory misbehaves
    private readonly IEmbeddingGenerator<string, Embedding<float>> _generator =
        clientFactory.ResolveClient(OllamaServiceType.Embedding).AsEmbeddingGenerator();
    // …
}
```

```csharp
// ✅ AFTER — lazy resolution via a cached property
public sealed class OllamaEmbeddingService(
    ILogger logger,
    IOllamaClientFactory clientFactory,
    IOptions<RagnarConfig> config) : IEmbeddingService
{
    private IEmbeddingGenerator<string, Embedding<float>>? _generator;

    private IEmbeddingGenerator<string, Embedding<float>> Generator =>
        _generator ??= clientFactory.ResolveClient(OllamaServiceType.Embedding).AsEmbeddingGenerator();

    public async Task<ReadOnlyMemory<float>> GenerateAsync(string input, CancellationToken ct)
    {
        Guard.Against.NullOrWhiteSpace(input);
        using var cts = CreateTimeoutCts(ct);
        var result = await Generator.GenerateAsync(input, cancellationToken: cts.Token).ConfigureAwait(false);
        return result.Vector;
    }

    public async Task<GeneratedEmbeddings<Embedding<float>>> GenerateBatchAsync(
        IReadOnlyCollection<string> inputs, CancellationToken ct)
    {
        Guard.Against.Null(inputs);
        using var cts = CreateTimeoutCts(ct);
        return await Generator.GenerateAsync([[.. inputs]], cancellationToken: cts.Token).ConfigureAwait(false);
    }

    private CancellationTokenSource CreateTimeoutCts(CancellationToken parent)
    {
        var cts = CancellationTokenSource.CreateLinkedTokenSource(parent);
        cts.CancelAfter(config.Value.EmbeddingOptions.Timeout);
        return cts;
    }
}
```

### 9. `AskQuestionsStageTests` — Fragile fluent-builder mocking

**Problem:** Every method on `IQuestionSourceAggregator` must be set up to return the mock itself. Adding a new method to the interface silently breaks *every* test.

```csharp
// ❌ BEFORE (repeated 5× per test)
_builderMock.Setup(b => b.GetCategories()).Returns(_builderMock.Object);
_builderMock.Setup(b => b.GetFileConfig()).Returns(_builderMock.Object);
_builderMock.Setup(b => b.GetCsvFilesAsync(It.IsAny<string>(), It.IsAny<CancellationToken>())).ReturnsAsync(_builderMock.Object);
_builderMock.Setup(b => b.WithCategoryFilter()).Returns(_builderMock.Object);
_builderMock.Setup(b => b.Build()).Returns(questions);
```

```csharp
// ✅ AFTER — centralise the fluent setup in a helper
private void SetupBuilderToReturn(IReadOnlyList<Core.Model.Question> questions)
{
    _builderMock
        .Setup(b => b.GetCategories())
        .Setup(b => b.GetFileConfig())
        .Setup(b => b.WithCategoryFilter())
        .Returns(_builderMock.Object);

    _builderMock
        .Setup(b => b.GetCsvFilesAsync(It.IsAny<string>(), It.IsAny<CancellationToken>()))
        .ReturnsAsync(_builderMock.Object);

    _builderMock
        .Setup(b => b.Build())
        .Returns(questions);
}

// In each test:
SetupBuilderToReturn(questions);   // one line instead of five
```

> **Root-cause suggestion:** If the fluent chain grows beyond ~4 calls, split `IQuestionSourceAggregator` into `IQuestionQueryBuilder` (stateful) and `IQuestionSource` (result), so the result interface is trivially mockable.

### 12. `CsvRecordParserTests` — Inconsistent cancellation token

**Problem:** The file is written with `TestContext.Current.CancellationToken` but the SUT is called with `CancellationToken.None`. The cancellation test writes the file with the xunit token then cancels a *different* CTS.

```csharp
// ❌ BEFORE (cancellation test)
await File.WriteAllTextAsync(_tempFilePath, csvContent, TestContext.Current.CancellationToken);
var cts = new CancellationTokenSource();
await cts.CancelAsync();
await Assert.ThrowsAnyAsync<OperationCanceledException>(() => _sut.ParseAsync(_tempFilePath, cts.Token));
```

```csharp
// ✅ AFTER — use the test's own token for setup, and a dedicated CTS for the SUT call
[[Fact]]
public async Task ParseAsyncCancellationRequestedShouldThrow()
{
    await File.WriteAllTextAsync(_tempFilePath, csvContent);   // fire-and-forget setup

    using var cts = new CancellationTokenSource();
    cts.Cancel();                                              // cancel *synchronously* before the call

    await Assert.ThrowsAnyAsync<OperationCanceledException>(
        () => _sut.ParseAsync(_tempFilePath, cts.Token));
}
```
