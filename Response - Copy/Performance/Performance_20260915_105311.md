# Performance Issues & Recommended Fixes

## 1. `VectorStoreRepository.UpsertBatchAsync` — Excessive Allocations in the Hot Loop

This is the most impactful issue. For every batch, the code performs multiple allocations that put pressure on the GC, especially with large codebases (thousands of documents):

```csharp
// Problem 1: String interpolation creates a new string per document
var texts = batch.Select(d => $"Context: {d.ElementName}\nCode:\n{d.Code}").ToList();

// Problem 2: ToArray() copies every vector, then SelectMany + ToList() allocates again
var points = batch.Select((d, idx) =>
        generatorService.BuildPointStructs(d.AsPoint(), generated[[idx]].Vector.ToArray(), d))
    .SelectMany(p => p).ToList();
```

**Fix:**

```csharp
// Use StringBuilder or pre-allocated buffers for the prompt strings
var texts = new string[[batch.Length]];
for (var j = 0; j < batch.Length; j++)
{
    var d = batch[[j]];
    texts[[j]] = string.Create(
        d.ElementName.Length + d.Code.Length + 20,
        $"Context: {d.ElementName}\nCode:\n{d.Code}");
}

// Avoid intermediate collections: build the point list in a single pass
var pointList = new List<PointStruct>();
for (var j = 0; j < batch.Length; j++)
{
    var vec = generated[[j]].Vector;
    // Pass the span directly if BuildPointStructs can accept ReadOnlySpan<float>
    foreach (var p in generatorService.BuildPointStructs(batch[[j]].AsPoint(), vec, batch[[j]]))
        pointList.Add(p);
}
```

If `IPointStructFactory.BuildPointStructs` accepts a `ReadOnlySpan<float>` instead of `float[[]]`, eliminate the `ToArray()` copy entirely.

## 2. `OllamaEmbeddingService` — `CancellationTokenSource` Allocation Per Call

Every single `GenerateAsync` / `GenerateBatchAsync` call allocates a new `CancellationTokenSource` and registers a `CancelAfter` timer:

```csharp
private CancellationTokenSource CreateTimeoutCts(CancellationToken parent)
{
    var cts = CancellationTokenSource.CreateLinkedTokenSource(parent);
    cts.CancelAfter(config.Value.EmbeddingOptions.Timeout);
    return cts;
}
```

In `VectorStoreRepository`, this is called **once per batch**, meaning hundreds of CTS objects and timer registrations for a large corpus.

**Fix — pool or pre-allocate a single timeout CTS per pipeline run:**

```csharp
// Cache the timeout value; create the linked CTS only when the parent isn't already linked
private readonly TimeSpan _timeout = config.Value.EmbeddingOptions.Timeout;

public async Task<ReadOnlyMemory<float>> GenerateAsync(string input, CancellationToken ct)
{
    Guard.Against.NullOrWhiteSpace(input);

    // Fast path: if the caller already supplied a token, link with a shared timer
    if (ct.CanBeCanceled)
    {
        using var linked = CancellationTokenSource.CreateLinkedTokenSource(ct);
        linked.CancelAfter(_timeout);
        return await _generator.GenerateAsync(input, linked.Token).ConfigureAwait(false);
    }

    // Slow path: no parent token — use a single-use timeout CTS
    using var cts = new CancellationTokenSource(_timeout);
    return await _generator.GenerateAsync(input, cts.Token).ConfigureAwait(false);
}
```

Alternatively, move the timeout into `HttpClient.Timeout` / `OllamaApiClient` configuration so no per-call CTS is needed at all.

## 3. `ParsingStage.ExecuteAsync` — `ConcurrentBag` → Array Materialisation

```csharp
var documents = new ConcurrentBag<CodeDocument>();
// … parallel loop fills the bag …
context.Documents = [[..documents]];   // allocates a new List + copies every reference
```

For a repo with 10 000+ code elements this is a large single allocation and a full copy.

**Fix — pre-size a `List<T>` protected by a lock, or use `Channel<T>`:**

```csharp
var documents = new List<CodeDocument>(files.Count * 2); // rough pre-alloc
var lockObj = new object();

await Parallel.ForEachAsync(files, options, async (filePath, token) =>
{
    var elements = await parseFactory.ParseAsync(filePath, token).ConfigureAwait(false);
    lock (lockObj)
    {
        documents.AddRange(elements);
    }
    task.Increment(1);
});

context.Documents = documents; // no copy needed
```

Or, for higher throughput, use a `System.Threading.Channels.Channel<CodeDocument>` with a bounded capacity to apply back-pressure.

## 4. `XmlCommentFilterStrategy.CreateFilter` — Chained Object Allocation

Every call to `CreateFilter` allocates **7 objects** (`Filter`, two `Condition`s, two `FieldCondition`s, a `Range`, a `Match`, a `RepeatedStrings`):

```csharp
public Filter CreateFilter(int sizeThreshold) => new()
{
    Must =
    {
        new Condition { Field = new FieldCondition { Key = "CommentLength", Range = new Range { Lt = sizeThreshold } } },
        new Condition { Field = new FieldCondition { Key = "Category", Match = new Match { ExceptKeywords = new RepeatedStrings { Strings = { "Tests", "Test", "tests", "test", "Testing" } } } } }
    }
};
```

If this is called per-file or per-element in a loop, that's thousands of short-lived allocations.

**Fix — cache the static parts and only vary the threshold:**

```csharp
private static readonly RepeatedStrings TestKeywords = new() { Strings = { "Tests", "Test", "tests", "test", "Testing" } };
private static readonly Match CategoryMatch = new() { ExceptKeywords = TestKeywords };
private static readonly FieldCondition CategoryField = new() { Key = "Category", Match = CategoryMatch };
private static readonly Condition CategoryCondition = new() { Field = CategoryField };

public Filter CreateFilter(int sizeThreshold) => new()
{
    Must =
    {
        new Condition { Field = new FieldCondition { Key = "CommentLength", Range = new Range { Lt = sizeThreshold } } },
        CategoryCondition   // reuse the pre-built object
    }
};
```

This cuts per-call allocations from 7 to 3.

## 5. `CsvFileQuestionProvider.LoadQuestionsAsync` — No Streaming

```csharp
var records = await csvParser.ParseAsync(fileName, cancellationToken).ConfigureAwait(false);
return records.Select(r => new Question(...));  // materialises the entire file in memory
```

For a CSV with millions of rows this loads every record into a `List` before the consumer even starts iterating.

**Fix — return an `IAsyncEnumerable<Question>` (or at least `IEnumerable<Question>` with deferred LINQ):**

```csharp
public async IAsyncEnumerable<Question> LoadQuestionsAsync(
    string fileName, [[EnumeratorCancellation]] CancellationToken cancellationToken = default)
{
    foreach (var record in await csvParser.ParseAsync(fileName, cancellationToken).ConfigureAwait(false))
    {
        yield return new Question(record.IsEnabled, record.Text, record.FileName, record.Category);
    }
}
```

If the interface must stay `Task<IEnumerable<Question>>`, at minimum use deferred `Select` without `.ToList()`:

```csharp
return records.AsEnumerable().Select(r => new Question(r.IsEnabled, r.Text, r.FileName, r.Category));
```

## 6. `VectorStoreRepository` — Unbounded `failed` List on Cascade Failure

```csharp
var failed = new List<(int Index, Exception Ex)>();
// inside catch:
failed.AddRange(batch.Select((d, idx) => (i + idx, ex)));
```

If a large batch (e.g. 64 docs) fails and *every* subsequent batch also fails, this list grows to thousands of tuples, each holding a reference to the same exception but a distinct value-type entry. In a worst-case OOM scenario (disk full, API down), this amplifies memory pressure.

**Fix — cap the failure list and log a summary:**

```csharp
const int MaxFailuresToTrack = 100;

// in catch:
if (failed.Count < MaxFailuresToTrack)
    failed.AddRange(batch.Select((d, idx) => (i + idx, ex)));
else
    logger.Warning("Failure tracking limit reached; suppressing further entries.");
```

## 7. Minor: `DataTableBuilder.ToTable()` — Per-Row `ToArray()`

```csharp
foreach (var row in _rows)
    table.AddRow(row.ToArray());   // allocates a new string[[]] for every row
```

**Fix — if Spectre.Console accepts `IEnumerable<string>`, pass the list directly:**

```csharp
foreach (var row in _rows)
    table.AddRow(row);   // List<string> already implements IEnumerable<string>
```

If the API strictly requires `params string[[]]`, this is unavoidable, but you can at least avoid the copy by storing rows as `string[[]]` from the start in `AddRow`:

```csharp
private readonly List<string[[]]> _rows = [[]];

public DataTableBuilder AddRow(params string[[]] cells)
{
    _rows.Add(cells);   // store the reference; caller must not mutate
    return this;
}
```

## 8. Minor: `ApplicationHeader.RenderBranding` — Object Allocation Per Render

Five `Text` objects plus a `Style` are created on every call. If this is rendered more than once (e.g., in a loop or a TUI refresh), cache them:

```csharp
private readonly Text _title      = new("Ragnar", Styles.Blue) { Justification = Justify.Left };
private readonly Text _subtitle  = new("Ragnar (Repository Augmented Generator & Resolver)", Styles.BoldBlue);
private readonly Text _version   = new($"Version {_versionNumber}", new Style(Color.Grey)) { Justification = Justify.Center };
private readonly Text _tagline   = new(TAGLINE, Styles.BoldSteelBlue) { Justification = Justify.Center };

public void RenderBranding()
{
    writer.Write(_title);
    writer.Write(_subtitle);
    writer.Write(_version);
    writer.WriteLine();
    writer.Write(_tagline);
    writer.WriteLine();
    writer.WriteRule();
    writer.WriteLine();
}
```
