# Technical Debt Audit — Ragnar

## 1. Configuration Bugs (High Severity)

### Environment-variable expansion in JSON won't work
Both `appsettings.Ragnar.json` and `appsettings.WebpPng.json` use `%USERPROFILE%\\source\\…` in a JSON string value. `System.Text.Json` (and ASP.NET Core's `ConfigurationBuilder`) **does not perform Windows environment-variable expansion on JSON values**. Unless you have a custom `JsonConverter` or a post-load substitution step, `SourceDirectory` will literally be `%USERPROFILE%\source\…` at runtime, causing `DirectoryNotFoundException` or `Path.GetInvalidPathException`.

**Fix:** Resolve the variable in code (`Environment.GetEnvironmentVariable("USERPROFILE")`) or use a `PathResolver` that expands it at read-time.

### Embedding port likely wrong
In `appsettings.json`, `EmbeddingOptions.Port` is **6334** (Qdrant's default) while `OllamaOptions.Port` is **11434**. If the embedding model is served by Ollama, the embedding host/port should point at Ollama (11434), not Qdrant. This will cause connection-refused errors when generating vectors.

## 2. Security / Robustness Gaps

### Path traversal in `ResponseWriter`
```csharp
var fileName = $"{details.Question.Filename}_{DateTime.Now:yyyyMMdd_HHmmss}.{formatter.FileExtension}";
var fullPath  = Path.Join(directory, fileName);
```
`Question.Filename` is user-supplied (from CSV). A value like `..\\..\\Windows\\System32` or a null-byte injection could write outside the intended directory. There is no sanitisation or `Path.GetInvalidFileNameChars` check.

### `DateTime.Now` for file naming
Using local time makes filenames non-reproducible and ambiguous across timezones. Prefer `DateTime.UtcNow` or a monotonic sequence number.

### No file-size guard on read
The file reader (shown at the top) calls `File.ReadAllTextAsync` with no size cap. A multi-GB source file will be loaded entirely into memory, risking OOM in CI or on constrained hosts.

### `VectorStoreRepository` index-unsafe access
```csharp
var points = batch.Select((d, idx) => generatorService.BuildPointStructs(d.AsPoint(), generated[[idx]].Vector.ToArray(), d))
```
If `GenerateBatchAsync` ever returns fewer vectors than inputs (a partial Ollama failure, a model swap, etc.), `generated[[idx]]` throws `IndexOutOfRangeException` *after* you've already caught the embedding exception. Add a length guard.

## 4. Correctness Bugs in Business Logic

### `PipelineRunner` log messages say "stages" (plural) for a single stage
```csharp
logger.Information("Skipping stages [[{Index}]]: {Name}", i, stage.Name);
logger.Information("Starting stages [[{Index}/{Total}]]: {Name}", …);
```
Cosmetic, but in a production log stream it creates confusion when grepping. Use "stage" (singular).

### `StopwatchExtensions.ElapsedTimeString` is width-inconsistent
- < 1 hour → `"MM:SS"` (5 chars)
- ≥ 1 hour → `"HH:MM:SS"` (8 chars)

Any table column or progress bar sized for the 5-char form will misalign. Decide on a single format or return a `TimeSpan` and let the caller format.

### `PathResolver` throws, `ResponseWriter` creates
```csharp
// PathResolver
if (!Directory.Exists(responseDir)) throw new DirectoryNotFoundException(responseDir);

// ResponseWriter
Directory.CreateDirectory(directory);   // on the *sub*directory
```
One layer *forbids* a missing directory, the next *creates* a subdirectory under it. The contract is unclear: does the caller guarantee the base exists? If so, `ResponseWriter` shouldn't be creating. If not, `PathResolver` shouldn't throw. Pick one policy.

### `VectorStoreRepository` swallows per-batch failure details
The `failed` list is populated but **never read**. The returned `UpdateResult` is binary (Completed / UnknownUpdateStatus). Callers cannot log which documents failed, retry selectively, or surface a partial-success count.

### `DataTableBuilder` has no row/column consistency check
`AddRow("A","B")` followed by `AddColumns("A","B","C")` will produce a table where some rows have 2 cells and the header has 3. Spectre.Console will render it, but the output will look broken. Add a `ToTable()` guard or an `AddRow` count validation.

### `ParsingStage` – one file failure kills the whole batch
```csharp
await Parallel.ForEachAsync(files, …, async (filePath, token) =>
{
    var elements = await parseFactory.ParseAsync(filePath, token).ConfigureAwait(false);
    …
});
```
`Parallel.ForEachAsync` propagates the **first** exception and cancels the rest. A single unparseable file (e.g., BOM-corrupted UTF-16) aborts the entire pipeline. Wrap per-file in try/catch and collect errors.

## 6. Code Smells & Maintainability

- **Inconsistent parameter naming** – `cancellationToken` vs. `ct` vs. `token` across the same solution. Pick one (`.editorconfig` / stylecop can enforce).
- **`RagnarConfig` is a bag of nested option classes** (`ApplicationOptions`, `EmbeddingOptions`, `FileLoadOptions`, `OllamaOptions`). It's injected as `IOptions<RagnarConfig>` everywhere, meaning every class that needs *one* property still depends on the whole bag. Consider per-section `IOptions<T>` registration.
- **`sealed` everywhere but `OllamaOptionsValidator` is not sealed**, and `SummarizePromptProvider` is not sealed. Inconsistent policy; pick one and apply.
- **`DataTableBuilder` is `sealed`** yet implements `ITableBuilder`. If the interface exists for abstraction, the implementation shouldn't be sealed (or the interface is unnecessary).
- **`AssemblyExtensions` uses C# 13 `extension` (static abstract) methods.** This requires .NET 10 / C# 14 compiler preview. If the project targets .NET 8 or 9, this won't compile without the right SDK. Verify your LangVersion and TargetFramework are aligned.
- **Duplicate configuration files** (`appsettings.Ragnar.json`, `appsettings.WebpPng.json`, presumably more) with near-identical structure. This will multiply with every target repository. A single `appsettings.Development.json` + a small CLI `--source-dir` / `--collection` flag would eliminate the file sprawl.

## 7. Recommended Priority Order

1. **Fix the `%USERPROFILE%` config bug** – it breaks every run.
2. **Sanitise `Question.Filename`** before building file paths – path traversal.
3. **Add per-file error isolation in `ParsingStage`** – one bad file shouldn't kill the pipeline.
4. **Guard the `generated[[idx]]` access in `VectorStoreRepository`** – latent `IndexOutOfRangeException`.
5. **Resolve the EmbeddingOptions port** (6334 → 11434, or confirm the intent).
6. **Unify the directory-existence contract** between `PathResolver` and `ResponseWriter`.

8. **Fix `PipelineRunner` log wording** and add a `Partial` status to `UpdateResult`.
9. **Strengthen the test suite** (missing assertions, temp-file hygiene, flaky `Task.Delay`).

Items 1–5 are *will-bug-you-in-production* level; 6–10 are *will-bug-you-in-three-months* level.
