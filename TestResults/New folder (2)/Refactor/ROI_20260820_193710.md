### 🟠 **#2: Inconsistent/Unvalidated XML Comment Filtering Logic**  
**Impact**: ⚠️ **HIGH** — `XmlEmptyCommentFilter` uses `Should` with *two conditions* (`Field.Match.Text = string.Empty` + `IsEmpty.Key = "Comment"`), which is **logically contradictory** and likely ineffective.  
**Root Cause**:  
```csharp

{
    new Condition { Field = new FieldCondition { ... Match = new Match { Text = string.Empty } } },

```
- ❌ `Match.Text = string.Empty` + `IsEmpty` in `Should` clause = **no-op** (Qdrant’s `Should` = OR; both conditions must be *true* for a match, but `IsEmpty` is redundant with `Match.Text = ""`).  
- ❌ No tests validate filter behavior (see `XmlCommentFilterStrategyTests` missing).

**Remediation Effort**: **Low-Medium**  
- ✅ Replace with a single `IsEmptyCondition` (Qdrant supports `IsEmpty` natively).  
- ✅ Add unit tests for filter generation (e.g., `XmlEmptyCommentFilter.Filter(QuestionCategory.XML)`).  
- ✅ Align category usage: `XML_SINGLE` → filter *single* empty comments; `XML` → filter *all* empty comments.

**Risk if Unfixed**:
