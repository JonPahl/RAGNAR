### 🔴 1. **Inefficient `LoadFolderContentsAsync` in `SummaryAgent`**
#### ❌ Problem:
```csharp
await Parallel.ForEachAsync(files, new ParallelOptions { CancellationToken = Ct }, async (file, token) =>
{
    int index = Array.IndexOf(files, file); // ❌ O(n) per iteration → O(n²) total!
    var text = await File.ReadAllTextAsync(file, token);
    contents[index] = ...;
});
```
- `Array.IndexOf(files, file)` is called inside the loop — **O(n)** per iteration → **O(n²)** overall.
- Also, `Parallel.ForEachAsync` + `async/await` inside can cause thread pool starvation under high load.

#### ✅ Fix:
Use `Parallel.For` or precompute indices:
```csharp
for (int i = 0; i < files.Length; i++)
{
    var file = files[i];
    var text = await File.ReadAllTextAsync(file, Ct);
    contents[i] = $"---\n[RESPONSE_FILE]{Path.GetFileName(file)}[/RESPONSE_FILE]\n{text}\n";
}
```
Or use `Parallel.For` if parallelism is needed:
```csharp
Parallel.For(0, files.Length, i =>
{
    var text = File.ReadAllTextAsync(files[i], Ct).GetAwaiter().GetResult();
    contents[i] = $"---\n[RESPONSE_FILE]{Path.GetFileName(files[i])}[/RESPONSE_FILE]\n{text}\n";
});
```
> ✅ **Why?** Eliminates quadratic overhead and avoids `IndexOf`.

### 🔴 4. **`ShowPrompt` uses string interpolation + `***` markers inefficiently**
#### ❌ Problem:
```csharp
public static string ShowPrompt(this string Prompt) => $"\n\n***\n[Original Prompt]\n{Prompt}\n***";
```
- Creates **multiple intermediate strings** (4+ allocations).
- For large prompts, this is wasteful.

#### ✅ Fix:
Use `StringBuilder` for large inputs or preallocate:
```csharp
public static string ShowPrompt(this string prompt)
{
    var sb = new StringBuilder();
    sb.Append("\n\n***\n[Original Prompt]\n");
    sb.Append(prompt);
    sb.Append("\n***");
    return sb.ToString();
}
```
Or even better: use `stackalloc` + `Span` for small strings (< 1KB):
```csharp
if (prompt.Length < 256)
{
    Span<char> buffer = stackalloc char[256];
    // ... write to span ...
    return new string(buffer.Slice(0, sb.Length));
}
```

> ✅ **Why?** Reduces GC pressure.

### 🔴 5. **`ExpandDirectory` throws `DirectoryNotFoundException` but doesn’t validate path length**
#### ❌ Problem:
```csharp
var fullPath = Path.GetFullPath(expanded);
if (!Directory.Exists(fullPath))
    throw new DirectoryNotFoundException(...);
```
- `Path.GetFullPath()` can throw `PathTooLongException` on long paths.
- No handling for invalid chars, null, or empty.

#### ✅ Fix:
```csharp
public static string ExpandDirectory(this string path)
{
    Guard.Against.NullOrWhiteSpace(path, nameof(path));
    var expanded = Environment.ExpandEnvironmentVariables(path);
    var fullPath = Path.GetFullPath(expanded); // may throw PathTooLongException
    if (!Directory.Exists(fullPath))
        throw new DirectoryNotFoundException($"Directory not found: '{fullPath}'");
    return fullPath;
}
```

> ✅ **Why?** Prevents unhandled exceptions in production.

### 🔴 8. **`StringExtensions.CharacterCount()` likely inefficient**
#### ❌ Problem:
No code shown, but parsing XML to count non-tag chars can be done poorly (e.g., regex).

#### ✅ Fix:
Use `XmlReader` or simple state machine:
```csharp
public static int CharacterCount(this string xml)
{
    int count = 0;
    bool inTag = false;
    foreach (char c in xml)
    {
        if (c == '<') inTag = true;
        else if (c == '>') inTag = false;
        else if (!inTag) count++;
    }
    return count;
}
```

> ✅ **Why?** Avoids regex allocations and is O(n).
