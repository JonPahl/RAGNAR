### 🔴 1. Service Locator Anti-Pattern & DIP Violation
**Locations:** `OllamaEmbeddingService`, `OllamaChatResponse`
**Smell:** Both classes use `ClientFactory.FindClient(...)` inside their methods to resolve dependencies at runtime instead of receiving them via constructor injection.
**Why it's a problem:** Hides true dependencies, makes unit testing difficult (requires mocking the factory), violates the Dependency Inversion Principle, and can lead to runtime resolution failures or incorrect lifetimes.
**Fix:** Inject the concrete clients directly into the constructor:
```csharp
// Before
public class OllamaEmbeddingService(Serilog.ILogger Logger, IOllamaClientFactory ClientFactory) : IEmbeddingService { ... }

// After
public class OllamaEmbeddingService(
    Serilog.ILogger logger, 
    IEmbeddingGenerator<string, Embedding<float>> embeddingGenerator) : IEmbeddingService 
{
    private readonly IEmbeddingGenerator<string, Embedding<float>> _generator = embeddingGenerator;
    
    public async Task<ReadOnlyMemory<float>> GenerateAsync(string input, CancellationToken ct)
    {
        var embeddings = await _generator.GenerateAsync(input, cancellationToken: ct);
        return embeddings.Vector;
    }
}
```

### 🔴 2. Improper Async Parallelism & Blocking `.Result`
**Location:** `VectorStoreRepository.UpsertBatchAsync`
**Smell:** 
```csharp
var tasks = CodeDocuments.Select(async doc => ...); // Lazy enumerable of Tasks
Parallel.ForEachAsync(tasks, ..., async (task, ct) => {
    var point = new PointStruct { Vectors = task.Result.doc... }; // BLOCKING .Result
});
```
**Why it's a problem:** `Select(async)` creates lazy tasks. When `Parallel.ForEachAsync` enumerates them, all async operations start simultaneously without flow control. More critically, accessing `.Result` inside the loop **blocks thread-pool threads**, causing starvation and potential deadlocks. It defeats the purpose of async/await.
**Fix:** Use `Task.WhenAll` to run concurrently but safely, then map results:
```csharp
var embeddingTasks = CodeDocuments.Select(doc => GenerateEmbeddingAsync(
    $"Context: {doc.ElementName}\nCode:\n{doc.Code}", Ct));

var embeddings = await Task.WhenAll(embeddingTasks);

var points = CodeDocuments.Zip(embeddings, (doc, vector) => new PointStruct
{
    Id = doc.AsPoint(),
    Vectors = vector.ToArray(),
    Payload = { doc.Dictionary }
}).ToList();

return points.Count != 0 
    ? await _qdrantClient.UpsertAsync(_applicationOption.VectorStoreName, points, cancellationToken: Ct) 
    : new UpdateResult();
```

### 🟠 5. In-Memory Directory Loading (OOM Risk)
**Location:** `SummaryAgent.LoadFolderContentsAsync`
**Smell:** Reads all files in a directory into a single `StringBuilder`. For large codebases, this causes high memory pressure and can crash the process. Also ignores LLM context window limits.
**Why it's a problem:** Poor scalability. No backpressure, no token limiting, no streaming.
**Fix:** Implement streaming/chunking and respect config limits:
```csharp
private static async IAsyncEnumerable<string> StreamFolderContents(string folder, [[EnumeratorCancellation]] CancellationToken ct)
{
    foreach (var file in Directory.EnumerateFiles(folder))
    {
        using var reader = File.OpenText(file);
        yield return $"---\n{AppDefaults.FILE_MARKER_START}{Path.GetFileName(file)}{AppDefaults.FILEMARKEREND}\n" + await reader.ReadToEndAsync(ct) + "\n";
    }
}
// Consume via IAsyncEnumerable or chunk into batches for the LLM
```

### 🔵 6. Invalid C# Syntax in Extension Methods
**Locations:** `AssemblyExtensions`, `StylesExtensions`
**Smell:** Both use invalid syntax:
```csharp
extension(Assembly Asm) { public string? InformationalVersion => ... }
```
**Why it's a problem:** This will **not compile**. Extension methods require `public static` on the class and `this` on the parameter.
**Fix:** Correct syntax:
```csharp
public static class AssemblyExtensions
{
    public static string? GetInformationalVersion(this Assembly asm) => 
        asm.GetCustomAttribute<AssemblyInformationalVersionAttribute>()?.InformationalVersion ?? "1.0.0";
}

public static class StylesExtensions
{
    public static Style EnsureValidStyle(this Style? style) => style ?? Spectre.Console.Style.Plain;
}
```

### 🔵 7. Hardcoded Paths & Enum Anti-Patterns
**Location:** `PathResolver.ResolveResponseDirectory`
**Smell:** 
- `"Response"` is hardcoded: `Path.Join(SourceDir, "Response")`
- `string.IsNullOrWhiteSpace(Category.ToString())` abuses enum `.ToString()`
**Why it's a problem:** Magic strings break refactoring and localization. Calling `.ToString()` on enums is redundant and can behave unexpectedly in certain globalization contexts.
**Fix:** 
```csharp
private const string ResponseDirName = "Response";

public string ResolveResponseDirectory(string sourceDir, QuestionCategory? category)
{
    var baseDir = category.HasValue && category.Value == QuestionCategory.Uncategorized 
        ? nameof(QuestionCategory.Uncategorized) 
        : category?.ToString() ?? nameof(QuestionCategory.Uncategorized);
    
    return Path.Join(sourceDir, ResponseDirName, baseDir);
}
```
