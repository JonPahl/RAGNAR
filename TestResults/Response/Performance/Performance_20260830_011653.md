### 🔴 1. Thread-Unsafe Collection & Blocking `.Result` (`VectorStoreRepository`)
**Issue:** 
- `embeddingGroup.Add(point)` inside `Parallel.ForEachAsync` is **not thread-safe**. Concurrent additions will cause race conditions, `IndexOutOfRangeException`, or silent data corruption.
- `task.Result.doc.AsPoint()` blocks synchronously on an async task, defeating the purpose of parallelism and risking thread-pool starvation or deadlocks.

**Fix:** Use `Task.WhenAll` to await all embeddings first, then process sequentially (network serialization usually makes sequential async faster than parallel I/O for batch upserts), or use a thread-safe collection with proper locking:
```csharp
// Replace the Parallel.ForEachAsync block with:
var embeddingTasks = CodeDocuments.Select(async doc =>
{
    var textToEmbed = $"Context: {doc.ElementName}\nCode:\n{doc.Code}";
    return (doc, await GenerateEmbeddingAsync(textToEmbed, Ct));
}).ToArray();

await Task.WhenAll(embeddingTasks); // Wait for all embeddings concurrently

var embeddingGroup = new List<PointStruct>(CodeDocuments.Length);
foreach (var result in embeddingTasks)
{
    var doc = result.doc;
    var vector = await result; // Already computed, just tuple unpacking
    embeddingGroup.Add(new PointStruct
    {
        Id = doc.AsPoint(),
        Vectors = vector.ToArray(),
        Payload = { doc.Dictionary }
    });
}
```

**Issue:**

**Fix:** Use `StringBuilder`:

```csharp
await AnsiConsole.Live(liveContainer).StartAsync(async ctx =>
```

### 🟡 3. Excessive UI Refresh Thrashing (`OllamaChatResponse`)
**Issue:** 
`ctx.Refresh();` on **every single token** overwhelms the terminal renderer, causing stuttering, high CPU usage, and flickering.

**Fix:** Throttle refreshes using a timer or token counter:
```csharp
var lastRefresh = DateTime.UtcNow;
await foreach (var token in _ollamaClient.ChatAsync(ChatRequest, Ct))
{
    // ... append to StringBuilder ...
    
    var now = DateTime.UtcNow;
    if ((now - lastRefresh).TotalMilliseconds > 50) // Max 20 FPS for terminal rendering
    {
        table.UpdateCell(0, 0, new Markup(sb.ToString(), Styles.Yellow));
        ctx.Refresh();
        lastRefresh = now;
    }
}
```

### 🟡 4. Repeated Agent Initialization (`SummaryAgent`)
**Issue:** 
`_agent.AsAIAgent(instructions: ..., tools: ...)` is called **inside `AskAgent`**. This dynamically creates a new agent instance per request, which is expensive, breaks DI lifecycles, and incorrectly mixes `IChatClient` and `AIAgent` APIs.

**Fix:** Configure the agent once in the constructor or use `IChatClient` with function invocation baked in:
```csharp
public class SummaryAgent : IDisposable
{
    private readonly IChatClient _chatClient;
    private readonly AIAgent<string> _agent; // Cache it

    public SummaryAgent(IOllamaAIClientBuilder builder, IOllamaResponse clientProvider, IPromptProvider prompt)
    {
        _chatClient = builder.WithChatClient(OllamaServiceType.Ollama).Build();
        _agent = _chatClient.AsAIAgent(
            instructions: prompt.Template,
            name: "SummarizeAgent",
            tools: [[AIFunctionFactory.Create(SummarizeContent)]]);
    }

    public async Task<string> AskAgent(string folder, string question, CancellationToken ct)
    {
        // Reuse cached agent instance
        return await _agent.RunAsync($"Read all files in {folder} and answer: {question}", ct);
    }
}
```

### 🟡 5. Inefficient Embedding Client Creation (`OllamaEmbeddingService`)
**Issue:** 
`ClientFactory.FindClient(...).AsEmbedingGenerator()` is called per request. If the factory creates a new HTTP client/generator each time, it exhausts sockets and adds significant latency.

**Fix:** Cache the generator or inject it via DI:
```csharp
public class OllamaEmbeddingService : IEmbeddingService
{
    private readonly IEmbeddingGenerator<string, Embedding<float>> _generator;
    
    public OllamaEmbeddingService(IOllamaClientFactory factory)
    {
        // Cache once in constructor
        _generator = factory.FindClient(OllamaServiceType.Embedding).AsEmbeddingGenerator();
    }

    public async Task<ReadOnlyMemory<float>> GenerateAsync(string input, CancellationToken ct) =>
        (await _generator.GenerateAsync(input, ct)).Vector;
}
```

### 🔵 6. Invalid Extension Method Syntax (`AssemblyExtensions`, `StylesExtensions`)
**Issue:** 
`extension(Type Param)` is **not valid C# syntax**. Extensions require the `static` class and `this` modifier on the first parameter.

**Fix:**
```csharp
public static class AssemblyExtensions
{
    public static string? InformationalVersion(this Assembly asm) =>
        asm.GetCustomAttribute<AssemblyInformationalVersionAttribute>()?.InformationalVersion ?? "1.0.0";

public static class StylesExtensions
{
    public static Style EnsureValidStyle(this Style? style) => style ?? Spectre.Console.Style.Plain;
```

### 🟢 7. Memory Pressure in Directory Scanning (`SummaryAgent`)
**Issue:** 
`Directory.EnumerateFiles(Folder).ToList();` loads all file paths into memory at once. For large projects, this spikes RSS memory.

**Fix:** Stream directly:
```csharp
private static async Task<string> LoadFolderContentsAsync(string folder, CancellationToken ct)
{
    var builder = new StringBuilder();
    await foreach (var filePath in Directory.EnumerateFiles(folder))
    {
        if (ct.IsCancellationRequested) break;
        using var reader = File.OpenText(filePath);
        var text = await reader.ReadToEndAsync(ct);
        builder.AppendLine($"---\n{AppDefaults.FILE_MARKER_START}{Path.GetFileName(filePath)}{AppDefaults.FILEMARKEREND}\n{text}\n");
    }
    return builder.Length > 0 ? $"{AppDefaults.CODE_BLOCK_START} {builder} {AppDefaults.CODE_BLOCK_END}" 
                             : "No items to summarize. Please ignore.";
}
```
