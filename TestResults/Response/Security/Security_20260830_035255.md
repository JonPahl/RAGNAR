#### 1. Path Traversal / Arbitrary File Read in `SummaryAgent.LoadFolderContentsAsync`
**Issue:** The `folder` parameter is passed directly to `Directory.EnumerateFiles()` without validation or canonicalization against a known safe root. An attacker controlling the input (via config, CLI, or API) could use `..` sequences to read sensitive files outside the intended directory (e.g., `/etc/passwd`, app secrets, or system configs).
```csharp
// Vulnerable Code:

```
**Fix:** Resolve the absolute path and verify it stays within an allowed root directory.
```csharp
private static async Task<string> LoadFolderContentsAsync(string folder, CancellationToken ct)
{
    var resolvedPath = Path.GetFullPath(folder);
    
    // Define a safe base directory (e.g., from config or AppDefaults.AllowedRootDirectory)
    var allowedRoot = AppDefaults.AllowedRootDirectory.TrimEnd('/', '\\') + Path.DirectorySeparatorChar;
    
    if (!resolvedPath.StartsWith(allowedRoot, StringComparison.OrdinalIgnoreCase))
        throw new UnauthorizedAccessException("Access to this path is not permitted.");

    var files = Directory.EnumerateFiles(resolvedPath).ToList();
    // ... rest of logic
}
```

#### 2. Directory & File Traversal in `ResponseWriter.WriteResponseAsync` & `PathResolver`
**Issue:** Output paths are constructed using user-controlled data (`SourceDir`, `Category`, and CSV-parsed `FileName`). If these contain path traversal sequences, `Directory.CreateDirectory()` and file writes could escape the intended output folder.
```csharp
// Vulnerable Pattern:

Directory.CreateDirectory(directory);
var fileName = $"{Details.Question.Filename}_{DateTime.Now:...}.{Formatter.FileExtension}";
```
**Fix:** Sanitize filenames, validate output paths against a base directory, and use safe path construction.
```csharp
// In ResponseWriter or PathResolver:
public string ResolveResponseDirectory(string sourceDir, QuestionCategory? category)
{
    var baseDir = string.IsNullOrWhiteSpace(category?.ToString())

    var responseDir = Path.Join(sourceDir, "Response");
    var targetDir = Path.GetFullPath(Path.Join(responseDir, baseDir));
```

### 🟡 Medium Severity Vulnerabilities

#### 3. Unbounded File Reading / DoS Risk
**Issue:** `File.OpenText(file).ReadToEndAsync()` loads the entire file into memory. Processing large files (e.g., logs, binaries, or maliciously crafted MB/GB-sized inputs) can cause `OutOfMemoryException` crashes.
**Fix:** Enforce a maximum file size limit before reading, or process in chunks if embedding generation supports it.
```csharp
var fileInfo = new FileInfo(file);
if (fileInfo.Length > _maxAllowedFileSizeBytes) // e.g., 10MB
    throw new InvalidOperationException($"File exceeds maximum allowed size: {fileInfo.Length} bytes.");
```

#### 4. Missing Input Validation on CSV Parsed Data
**Issue:** `CsvFileQuestionProvider` deserializes records and passes them directly to downstream components without validation. Malformed or malicious CSV data could trigger injection, path traversal, or prompt injection risks.
**Fix:** Apply validation attributes or a sanitizer before mapping:
```csharp
public async Task<IEnumerable<Question>> LoadQuestionsAsync(string fileName, CancellationToken ct)
{
    var records = await CsvParser.ParseAsync(fileName, ct);
    
    return records.Select(r => new Question(
        IsActive: r.IsEnabled,
        Text: SanitizeString(r.Text, maxLength: 5000),
        FileName: SanitizeFileName(r.FileName),
        Category: ValidateCategory(r.Category)
    ));
}

private static string SanitizeString(string input, int maxLength) => 
    input?.Replace("\0", "").Substring(0, Math.Min(input.Length, maxLength));

private static QuestionCategory ValidateCategory(string cat) => 
    Enum.TryParse<QuestionCategory>(cat, ignoreCase: true, out var parsed) ? parsed : QuestionCategory.Uncategorized;
```

#### 5. Broad Exception Handling & Potential Info Leakage

**Fix:** Log only structured error codes/messages in prod, and use Serilog's `Enrich.WithMachineName()`/`WithThreadId()` (already configured) but avoid raw exception serialization unless in debug mode.

### 🟢 Low Severity & Architectural Recommendations

#### 6. Unused Security Utility (`Utils.ExpandDirectory`)
**Issue:** `Utils.ExpandDirectory` safely expands environment variables and validates directory existence, but **it is never called** before passing paths to `Directory.EnumerateFiles` or `PathResolver`. This defeats its security purpose.
**Fix:** Ensure all external path inputs flow through a validated expansion/resolution pipeline at application startup or entry points.

#### 7. AI Tool Injection Considerations (`AskAgent`)
**Issue:** `AIFunctionFactory.Create(SummarizeContent)` dynamically exposes methods to the LLM. While standard, poorly constrained prompts could theoretically trick the model into calling unintended tools or bypassing guardrails.
**Fix:** 
- Use `IPromptProvider` with strict system instructions that explicitly forbid tool misuse.
- Implement a validation layer before tool execution (e.g., check if `Folder` is within allowed bounds before `SummarizeContent` runs).
- Consider using Microsoft's `AIChatClient` with `UseFunctionInvocation()` and explicit tool allowlists.

#### 8. Configuration & Secrets Management
**Issue:** The JSON configs use `%USERPROFILE%` and `localhost`. While not inherently vulnerable, hardcoding paths or relying on environment variables without validation at startup can cause runtime failures or misconfigurations in containerized/cloud environments.
**Fix:** 
- Validate all config values during DI registration (`IOptions<RagnarConfig>.Value`).
- Use `IConfiguration.GetSection()` with fallbacks and validate required fields via a custom `StartupValidator` that throws on missing/invalid critical paths or ports.
